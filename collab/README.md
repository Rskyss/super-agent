# 超级助手 · 调度手册（给 Claude 看）

> 用户说“用协作包 / 用超级助手做这个需求”时，先完整读完本文件再行动。
> 干活的 AI（Cursor、Codex、agy）读的是同目录的《规则.md》；本文件是调度员（Claude）的操作手册。
> 用户是产品经理：对用户只说产品语言（流程、画面、结果），不贴代码、不问技术问题。

---

## 一、这是什么

一个可以放进任何项目的协作包（Harness）：Claude 负责对齐需求、拆解方案、派活、验收；Cursor / Codex / agy 负责写代码、写测试、复查。
所有过程写进文件，换会话、换人都能接上。用户只在三处拍板：**需求与方案、合并、推送/上线**。

## 二、分工（谁做什么）

| 角色 | 默认人选 | 做什么 |
|---|---|---|
| 调度员 | Claude | 对齐需求、写任务卡片和拆解方案、派活、复核结果、向用户汇报 |
| 开发员 | Cursor（`agent`，auto） | 在独立副本里写代码 |
| 测试员 | Codex（gpt-6.1-sol，xhigh） | **先**按验收标准写测试 |
| 复查员 | agy（gemini-4-argon-high） | 测试通过后只读复查，写“结论：通过/不通过” |
| 看网页、真实页面实测 | Codex | 能操作浏览器、截图 |
| 搜资料 | Tavily | 只负责找来源，读正文交给 Codex |
| 简单查询（日志、汇总） | agy 的 Gemini 3.8 Flash（high） | 快、便宜；要用于决定的数字需抽查 |

**铁律：Claude 不直接改产品代码，哪怕只有一行。** 需要改就新开一张小卡派给开发员。
（来历：2026-11-04 做 CARD-002 时，Claude 直接改过一句界面文字和三个测试文件，违反了分工，事后才补记录。）

用户可以按次指定工具：`--dev-tool / --test-tool / --review-tool`（可选 cursor、codex、agy；复查可设 none）。

## 三、完整流程（按顺序，一步都不能跳）

以下命令里 `<P>` 是目标项目路径，`collab` 指**超级助手里的协作包**（源目录默认 `~/Desktop/project/super-agent/collab`；桌面窗口启动调度员时会在开场话里写明完整路径）。

> **v0.2 起协作包不再复制进项目。** 项目里只有一个 `.collab/`（施工过程，只留在本机，已在项目的不提交名单里）；结果（台账、项目说明、归档）放项目 `docs/`，跟着代码进 git。

### 0. 接入（项目里还没有 `.collab/` 时）
```
python3 collab init <P>      # 建 .collab/ 并加进不提交名单；不复制协作包；可重复执行
python3 collab migrate <P>   # 旧装法的项目（项目里有一份 collab/ 副本）：搬项目说明、加不提交名单
python3 collab migrate <P> --remove-old-package   # 用户同意后，才删掉项目里的旧协作包
```
项目必须是 git 仓库。用桌面窗口打开项目时，接入和迁移由窗口自动完成（删旧包会先问用户）。

### 1. 打开项目时先读交接（每次）
- 每次开始工作：读本手册 → 项目说明 → 台账 `docs/开发进度跟踪.md` 最近的记录 → `.collab/任务板.md`，用两三句话告诉用户项目进行到哪、有什么待办，然后等用户说需求。**只读，不改文件。**
- 代码体检（逐个找问题）只在用户要求时做。

### 1·附 项目说明（每个项目第一次）
- 读项目自己的说明（README、AGENTS.md、CLAUDE.md、package.json 等），按下面的模板写到 **`docs/项目说明.md`**（旧项目的 `.collab/项目档案.md` 仍然认，但新的都写到 docs/）：
  ```
  # 项目说明

  - 这个项目是做什么的：
  - 怎么启动：
  - 怎么测试（测试命令）：
  - 禁区（哪些不能动）：密钥文件、部署配置、别人未提交的改动……
  - 技术栈：
  ```
- 用大白话给用户看，用户说“对”之后：`python3 collab confirm-profile <P>`。没有项目说明、或还有“（待填）”会被拒绝。

### 2. 对齐需求 → 任务卡片
- 先读项目的 `docs/开发进度跟踪.md`（台账），了解进度和遗留问题。
- 按 vibe-workflow 判断大小；有歧义就用选择题问用户（只问产品问题）。修问题时先过“三问”（病根在哪一层、该不该现在改、改法是否同构）。
- 写需求文件后：`python3 collab new-card <P> CARD-xxx --requirement 需求.md`
  - **第一行标题必须是真正的需求名称**（如 `# 三处显示问题修复 · 需求共识`），右边面板直接展示它；给执行员的注意事项写在 `## 执行细节` 小节里，不要插在第一行前面。
- 任务卡片（文件 `需求卡.md`）必须有一节 `## 允许改动的范围`，逐行列出可改的文件或目录（如 `- src/components/extract/*`）。没有这一节，`run` 会直接拒绝。
- 任务卡片里写清验收要点，以及这次的越界处理模式（默认 A：程序自动撤销；B：标出让用户定；C：允许并提醒）。目前程序只实现了 A；用户选 B 或 C 时，把相关文件写进“允许改动的范围”，并由 Claude 在汇报里标出多做的部分。

### 3. 拆解方案（+ 设计稿）→ 用户批准
- 填写 `.collab/cards/CARD-xxx/方案.md`（模板五部分：要做什么、拆几步、你会看到什么结果、不做什么、需要你确认的问题）。
- 涉及界面时，先做设计稿（HTML），发布成链接给用户看；**用户确认过的设计不要再问第二遍**。
- 用户批准后：`python3 collab approve <P> CARD-xxx`（方案有空白会被拒绝；会登记台账）。

### 4. 施工（后台运行）
```
python3 collab run <P> CARD-xxx --test-command "npm test" --session-jsonl auto
```
- 顺序：测试员先写测试 → 开发员写代码 → 范围核对（越界改动由程序直接撤销，不算返工；撤销失败才转人工）→ 程序按退出码判定 →（可选 `--page-check`）→ 复查员只读复查 → 待验收。
- **断点续跑**：如果上次施工中途因退出窗口或断电中断（卡片停在 `开发中 / 待测试 / 测试中`），经用户同意后直接再次执行同一条 `run` 命令即可接着往下跑——已完成的步骤（如已交活的写测试、已交活的写代码）会自动跳过，不重复执行。
- **用谁干活**：不写 `--dev-tool / --test-tool / --review-tool` 时，按项目的团队配置（`.collab/配置.json` 里的 `team`，用户在桌面窗口「项目 → 团队配置」里亲手配）；没配时默认 Codex 写测试、Cursor 写代码、agy 复查。开工前可以先 `check` 一下连通。
- **开工必须用户亲手允许**：在 Codex 的受保护环境里直接运行 `run` 会被拒绝（什么都不做）。调度员是 Codex 时，要申请提升权限来运行 `run`，用户在聊天里点“允许”后才会开工；被拒绝就停下，告诉用户。
- 开发员（Cursor）在自动模式下**不能执行命令**：跑不了测试、删不掉文件。所以测试由程序跑、越界由程序撤销、汇报从它的回复里提取。
- 没过自动返工，最多 3 轮；同样的报错连续两次判定为原地打转，提前转人工；干活的 AI 连续 15 分钟没有任何动静（文件没变、输出也没涨），看门人会停掉它并转人工；5、10 分钟没动静时记一条“提醒”，行政在卡片对话里说。
- 复查不通过：自动把复查员最后写的结论交给开发员去改（不算返工），最多自动退回 2 次；第 3 次还不通过才转“需Claude介入”，原因里带着剩下的问题。用户可以点“接受剩下的问题，进入待确认”。
- 交接只传最后回复：流转里“回复”存干活的人最后一条回复（Codex 用 `-o` 拿），完整过程在实时输出文件里；复查结论只从最后回复里认。退出码 0 却一个字没回，算没完成（自动再试一次）。
- 写测试的只改测试：它改了原有的非测试文件，程序撤掉（还原到它动手前的样子）并记“范围”。“继续改”时它只为追加要求补测试，不整个重写。
- Cursor 当执行员时：派活前在施工副本写 `.cursor/cli.json`，只放行本卡测试命令用到的程序、关掉浏览器等插件，干完就去掉（不算改动、不进项目）。
- 每个岗位各用自己的模型和强度：`.collab/配置.json` 的 `role_models`；没单独设的用这家工具的整体设置。“开跑”记下各岗的模型（`models`），“写方案”记下调度员的模型（`model`），右栏每步右上角照着写“工具 · 模型（强度）”。

  - 派活交代开头一律加“汇报、过程说明一律用中文大白话”。结束那条、台账、归档写“测试没过返工 N 次、复查退回 M 次（、继续改 K 次）”。

  - 复查收口：这张卡之前有过复查结论的，复查交代要求每条再标【这次改的】或【原来就有的】。退回 = 【测试的问题】+ 严重 + 没标【原来就有的】的中等；其余写进 `cards/<卡>/以后再修.md`、流转记“以后再修”（`items` 大白话）。全是其余的 → 当作通过（这次复查不算退回）。连着两次退回、两次的位置有同一个文件、第二次全是新问题 → 第二次退回交代加“先找共同原因，把这一部分统一改对”。待验收时 `phase.later` 列出，点“确认没问题，放进项目”前弹窗列给用户。
  - 停下后起草“继续改”（只在真施工时；`SUPERAGENT_NO_DRAFT=1` 关）：复查退回用完转人工、且不是测试的问题/范围外/都是小问题时，用复查员那家工具、最高强度、只读，把这次开工以来几轮复查合起来找共同原因，写“第一段两句大白话 + --- + 给写代码的交代”。流转记“起草”（开始/好了/没成，行政播报）；右栏 `view.draft` 给最新没用过的草稿，点“不满意，继续改”时框是空的就预填。
  - 进度（只在真施工时；`SUPERAGENT_NO_PROGRESS=1` 关）：写代码、返工时，第一次马上算、之后有新改动（本卡测试文件以外）且离上次 ≥2 分钟，在副本里只跑本卡 test_*.py，写 `cards/<卡>/进度.json`（seq 对应那次派活）；导入就报错时总数按测试文件里 def test_ 个数算。写测试时数新写的 def test_。右栏那步标题行和说明之间一条进度条“通过 x/y”/“已写 N 项”。

- 副本会自动接上项目的依赖（node_modules）和本地配置（`.env`、`.env.local`）。
- **注意测试命令要覆盖本卡的验收测试。** 有的项目只跑特定后缀的测试文件（例如只跑 `*.test.ts`），新写的验收测试可能根本没被执行。
- 给用户看进度：`python3 collab watch <P> CARD-xxx`（每 5 秒刷新：在哪一步、已用时、最近动静；超 10 分钟没动静会提醒）。
- **流转记录（边干边记，v0.2 起）**：每张卡的 `流转.jsonl` 一行一条，按时间追加：需求 → 批准 → 开跑 → 派活 / 回复（每个执行者一对）→ 范围 → 判定 → 页面检查 → 转人工 / 结束 → 归档。
  - “派活”在**开始干活时**就记，没有对应“回复”的那条派活就是“正在干”的人；“回复”记成没成、用时、一句话摘要。
  - 派活原文、回复全文、测试输出存在 `流转/` 目录（`NNN-派活.md` 等）；执行者的实时输出写进 `流转/NNN-实时输出.log`，干完也保留。
  - 只记录不判断：派活、返工、判定规则都不受它影响。桌面窗口的右边面板就读这份记录。
  - 交接全文和实时输出只留在本机 `.collab/`，归档时不复制进项目 `docs/`（又多又大，不该进代码历史）。

### 5. Claude 复核（不信任任何 AI 的自述）
- 看 `执行记录.md`（谁做了什么）、`测试结果.md`（每轮都保留）、`返工记录.md`、`复查结果.md`、`汇报.md`。
- 自己在副本里重跑测试（以退出码为准），看改动范围，检查多余文件。
- 状态是“需Claude介入”时：读返工记录里的原因，判断是任务卡片/方案写得不清（改卡后重派），还是环境问题（先修环境）。

### 6. 用户验收
- 用大白话汇报（格式见第五节）。需要真实页面时，派 Codex 实测并截图。
- **测试素材先确认可用**：例如测试视频先在浏览器里确认能播放、确实没有字幕，再拿去测。

### 7. 合并（用户同意后）
- 先在副本里提交本卡改动，再检查和主工作区“未提交改动”有没有重叠的文件；有重叠就停下来问用户。
- 只做快进合并：`git merge --ff-only card/CARD-xxx`。合并后在主项目上重跑测试和验收测试。
- 状态改为“已合并”，登记台账。

### 8. 记录存入项目文档
命令名仍是 `archive`。左栏的“归档”是另一件事：只把已结束的卡从列表收起来，不动任何记录。

`python3 collab archive <P> CARD-xxx --feature 功能名` → 记录整理进 `docs/功能名/`（需求共识、方案、验收记录、过程记录/），不覆盖已有文件，自动登记台账。

### 9. 推送 / 上线
- **只在用户明确同意后执行**，每次都要问。
- 推送前先弄清主项目里未提交的改动是什么，确认上线版本就是测过的版本。

## 三·附、上线清单（可交给 Codex 按步骤执行，Claude 审清单和结果）

> Cursor 在自动模式下不能执行命令，做不了上线。交给 Codex 时，服务器登录信息让它从项目配置文件读取，不写进任务说明。
> 每个项目的部署方式以项目自己的规定为准（先读项目的 CLAUDE.md / AGENTS.md 里的部署规则）。

1. **发布提交**：只放已验收的内容，整理成一个提交，标题“vX.Y 一句话主题”，正文第一段是“解决问题：1.～n”。本地其他未完成的改动不进提交、不动。
2. **干净副本复测**：从发布提交新建一个干净副本，跑整包测试、验收测试、生产构建。只在本机能过、干净副本过不了的，不能上线。
3. **部署来源用干净副本**：不要从本机工作区直接同步，否则未完成的改动、协作包、本地配置会被一起带上去。
4. **备份线上数据库**：优先用数据库自带的备份方式，并做完整性检查，记下备份文件名。
5. **试推看清单**：先只看不传，逐个确认没有 `.env*`、cookies、数据库文件、协作包文件夹。
6. **正式同步** → **构建到新目录**（旧目录保留，作为退路）。
7. **切换并检查**：服务状态、主要页面和接口返回 200、版本号、重启后的错误日志。任何一项不对，立刻切回旧目录。
8. **登记并推送**：台账写上线结果（备份文件名、切回方法），再推送这一个提交；推送前确认它和上线的代码一致。
9. **清理**：删掉发布用的临时副本（里面有本地配置的拷贝，含密钥）。
10. 需要真实操作才能验证的（例如线上粘贴链接会消耗识别额度），先问用户。

## 四、什么时候必须停下来问用户

需求有歧义；方案和设计稿；越界处理选 B 时的取舍；合并前发现与未提交改动重叠；任何推送、上线、花钱（例如真实语音识别、买代理）；需要用户本人才能做的事（登录、验证码）。
技术实现细节自己决定，不问用户。

## 五、汇报格式（用户认可）

- 每条记录一小段：时间、总耗时、最慢的一步、大白话解释、有没有报错。
- 最后一句结论。推测要标明“推测”，没核对的数字要说明。
- 不贴代码、不列技术术语；说清楚“你会看到什么”和“需要你决定什么”。

## 六、踩过的坑

| 现象 | 原因 / 做法 |
|---|---|
| Cursor 说写了文件，但没有 | 命令是 `agent`（不是 `cursor-agent`），要加 `--trust`；偶发不落盘，以文件为准 |
| agy 报 `-p took "--output-format"` | 提示词必须紧跟 `-p` |
| 加 `--force` / `--dangerously-skip-permissions` 被拒 | 不需要，也不要用 |
| Codex 输出一堆 MCP 报错 | 忽略，不影响结果 |
| Codex 不肯直接用浏览器工具 | 它自己的规则要求先得到许可；任务说明里写明“允许使用浏览器自动化” |
| 副本里登录失效、页面空白 | 副本缺 `.env.local`；现已自动复制 |
| 测试全过但验收测试没跑 | 项目测试只认部分文件后缀；测试命令要把验收测试也带上 |
| 自动化浏览器里 Google 登录被拒 | 用邮箱验证码，或让 Codex 用用户已登录的 Chrome |
| “请确认你不是机器人” / 拿不到视频时长 | 先确认视频本身能播放；确认可用后再排查网络出口 |
| 长视频卡在“整理文字” | 服务器其实已存好笔记，是页面没收到完成信号；待优化（先显示原文、断线后查结果） |
| 同时跑多张卡 | 目前是串行；并行需要先处理台账和任务板同时写入的问题 |
| 开发员返工时多出 `_do_cleanup.py`、`ls` 之类的怪文件 | 它想删文件但不能执行命令；现由程序直接撤销越界改动 |

## 七、命令速查

| 命令 | 作用 |
|---|---|
| `init <P>` | 接入：建 `.collab/` 并加进不提交名单（不复制协作包） |
| `migrate <P> [--remove-old-package]` | 旧装法的项目改成新方式；加参数才删项目里的旧协作包 |
| `install <P>` | 旧命令，现在等于 `init` |
| `check <P> [--json]` | 检测连通：团队里每个人真干一件小事（临时文件夹里建一个文件），建出来才算通 |
| `confirm-profile <P>` | 用户确认项目说明（`docs/项目说明.md`）后执行 |
| `new-card <P> CARD-xxx --requirement 文件` | 新建任务卡片（状态：待对齐） |
| `approve <P> CARD-xxx` | 用户批准方案后执行（状态：待派发） |
| `run <P> CARD-xxx --test-command "..." [--page-check "..."] [--dev-tool/--test-tool/--review-tool] [--session-jsonl auto]` | 派发施工 |
| `watch <P> CARD-xxx [--once]` | 实时查看进度 |
| `status <P>` | 任务板 |
| `archive <P> CARD-xxx --feature 功能名` | 归档到 docs/功能名/ |

模型配置在 `.collab/配置.json` 里按项目覆盖（cursor、codex、codex_effort、agy）。
