# 拆解方案

## 要做什么（一句话）
真实跑卡时，写测试的人交活后先跑本卡测试，确认测试能在改代码前抓住问题。

## 拆成几步，每步做什么、产出什么
1. 方案批准后，写测试的人先看现有验收覆盖了什么，只在新测试文件里补施工单要求但还没覆盖的情况，重点检查重写途中断后恢复和命令行开关，再用本卡验收命令确认新增测试确实跑到了，并且在改代码前会因缺少对应行为而失败。
2. 给 `run_card` 加上默认关闭的 `red_check` 并原样传给 `_run_card`，命令行只有在真实派活且 `SUPERAGENT_NO_RED_CHECK` 不等于 `1` 时才打开。
3. 在写测试交活和写代码之间加一处首次跑与接着跑共用的检查，开关打开且有本卡测试命令时，只看最近一次追加要求生效后的记录，找到最近一次成功的「写测试」或「重写测试」交活，有对应检查记录就沿用，没有才用现有判定工具跑本卡测试并记下结果。
4. 检查结果没过或没跑成时，按施工单记明情况并继续原流程；第一次全过时，退回写测试的人一次，带上本卡测试命令，请对方确认新测试确实会被跑到、改代码前会失败，并说明现有代码已经做到的验收项。
5. 重写交活后再查一次，重写没交成就走原有处理，重写途中断且尚无成功交活则接着跑时重派；第二次全过就走原有转人工流程，原因记为「测试先红」，把关的人点「接着跑」后直接往下走。
6. 把开关和现有判定工具传到连续跑与接着跑两条复查退回路径，只在「补测试」成功交活且具备运行条件后查一次并记结果，全过时提醒写代码的人这批测试还没抓住问题、改完要在汇报里写清怎么确认，其余结果沿用原交代。
7. 写代码的人只跑本卡验收命令，确认各组全部通过；如果旧测试因新口径失败，在汇报里指出具体用例交把关的人判断，全量测试交程序在复查时跑。

## 你会看到什么结果
用户能在卡片记录里看到每次检查的结果：测试没过就继续写代码，第一次全过就退回重写，重写后仍全过就停下交把关的人；补测试后一跑就全过只提醒写代码的人。

## 明确不做什么
不改现有验收测试和共用测试工具，不改首次写测试的交代，不逐个测试文件检查，不检查「改测试」那一轮，不改页面、按钮、复查规矩或复查退回次数。

## 需要你确认的问题
无

## 做完后怎么看结果
打开这张卡的执行记录，看「先红检查」有没有记下每轮结果；两次全过时，看卡片是否显示「卡住了」、说明停下的原因，并只显示「接着跑」「继续改」「先不做」三个原有按钮。
