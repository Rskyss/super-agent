# 拆解方案

## 要做什么（一句话）
按第三批 D1 施工单改右栏和流转记录的说法，让测试超时后只重跑测试，并补上 Claude 亲自做卡和服务限流的显示。

## 拆成几步，每步做什么、产出什么
1. 先用现成的验收测试对照施工单，缺的检查只补到新测试文件里，再着手改代码。
2. 把右栏、左边聊天状态和流转记录里用户能看到的“调度员”按施工单换成“程序”“需要你看看”等说法，同时让老卡记录也按新说法显示。
3. 把判定测试或页面检查超时和真正没通过分开处理，超时后点“接着跑”时跳过写代码，直接重跑测试。
4. 确认复查不通过、复查格式看不懂或退满停下时，红叉都挂在复查格。
5. 把待验收和已合并时的写方案格统一显示为“方案已定”。
6. 把合并成功的短句固定为“已放进项目”，把分支名放进展开后的全文，台账照旧。
7. 在用量的鼠标提示里加上“每答完一轮才更新一次”。
8. 给 new-card 加上 --by-claude，让它写入 Claude亲自做.json，并让还没合并或放弃的这类卡显示“Claude 亲自做”，操作区不出按钮。
9. 在判断“模型没回话”之前先识别 429 或 Too Many Requests，停下时显示“服务限流”，沿用现有的换模型建议，并提示可以过一会儿再点“接着跑”。
10. 逐项完成后跑本卡验收命令，若有老测试因新说法需要调整，就在汇报里指出是哪条，交给 Claude 判断。

## 你会看到什么结果
用户在右栏、流转记录和停下说明里看不到“调度员”，测试超时后点“接着跑”只会重跑测试，复查停下时红叉挂在复查格；待验收和已合并的卡显示“方案已定”，合并记录的短句只写“已放进项目”，展开全文能看到分支名；用量提示会说明更新时机，Claude 亲自做的卡进行中没有操作按钮，碰到服务限流时会看到原因和接着跑的建议。

## 明确不做什么
不改现有验收测试和施工单第五节列出的老测试，不改跑卡规矩、复查规矩、退回次数、给工具的交代、流转记录字段名、团队设置页或行政功能，也不加施工单以外的功能；施工方只跑本卡验收命令，全部测试由程序在复查时跑。

## 需要你确认的问题
无

## 做完后怎么看结果
点按钮打开右栏，先看顶部一句话、写方案格和下方的流转记录，再把鼠标放到用量上看更新提示；有对应状态的卡时，展开合并记录看分支名，复查停下时看红叉在哪一格，Claude 亲自做的卡看底部有没有操作按钮，限流停下的卡看停下说明。
