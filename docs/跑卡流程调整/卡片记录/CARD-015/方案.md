# 拆解方案

## 要做什么（一句话）
按第三批 D2 施工单补齐粘贴内容识别、施工单标题替换、本卡进度统计和左栏完成时间。

## 拆成几步，每步做什么、产出什么
1. 先在新测试文件补齐施工单要求的用例，确认改代码前能重现问题。
2. 新增文字分格函数，识别带中英文冒号或一至三级 Markdown 标题的四种标签，忽略标签两边的加粗符号和空格，保留多行内容并跳过空内容。
3. 建卡时读取最后一条用户消息，用认出的内容覆盖模型对应格子，再按原规则查缺，没写标签时保持原样。
4. 查缺前用 existing_orders 查找引用的施工单，标题以“按施工单”开头或含路径、.md 时，换成第一个施工单的首个一级标题，读不了或没有标题就保留原名。
5. 在行政角色说明里补上施工单不用行政读、别说读不了、只说写方案时会读的要求。
6. 新增失败测试名识别函数，统一兼容两种 Python 输出格式，并仅在开工前检查没过时保存失败名单和步骤。
7. 进度计算遇到非空失败名单时照常跑完本卡命令的每一段，只统计名单里的测试并返回 own 标记，没有名单时保持原样，导入报错、超时和跑不起来仍按原方式处理。
8. 只调整 progressText，让 own 为真时显示“本卡要做的 N 项，已过 x 项”，百分比照算，其他情况保持原样。
9. 只在 list_cards 补 finished 秒数，已合并取最后一条合并记录时间，已放弃取最后一条记录时间，其他状态为空，老时间记录沿用现有换算办法。
10. 左栏新增完成时间文字，已合并显示“完成于 年-月-日 时:分”，已放弃显示“放弃于 年-月-日 时:分”，放在完成状态行下面，沿用小字颜色且不挤标题，没有时间就不显示。
11. 运行本卡验收命令，修到全部通过，若老测试存在口径冲突则保留测试并如实汇报，交活时用大白话说明结果。

## 你会看到什么结果
确认框按用户标注填写各格，卡片使用施工单标题，行政不再说读不了施工单，进度显示“本卡要做的 N 项，已过 x 项”，左栏显示完整的完成或放弃时间。

## 明确不做什么
不改已有验收测试和其他老测试；不给行政加读文件的本事；不改确认框样子、建卡以后的流程和“继续改”；不加施工单以外的功能或写法；施工方不跑全部测试。

## 需要你确认的问题
无

## 做完后怎么看结果
打开后看建卡确认框是否照粘贴内容分格、标题是否换成施工单标题，再看右栏写代码进度，以及左栏已完成和已放弃卡片下面的年月日、时分。
