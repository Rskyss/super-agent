## 三、具体做法

### 1. 清单加两样（`read_review_list`）

- 每条问题可写 `"碰上"`：只能是 `常见` / `少见` / `极巧合`。**没写不算不合格，按“常见”算**；写了别的值算不合格。
- 清单顶层可写 `"上轮核对"`：列表，每项 `{"编号": 数字, "结果": "改好了" 或 "没改好"}`。编号不是数字、结果不是这两个之一，算不合格。没有这一段不算不合格。
- 结论“不通过”、问题列表为空，但“上轮核对”里至少有一条“没改好”：**算合格**（只是上轮的没改好，没有新问题）。问题列表为空、上轮核对也没有“没改好”的“不通过”，照 C1.5 算不合格。

### 2. 复查交代（`_review_prompt`）

- 每一轮都写明“碰上”三档的意思（例：恰好在两步之间被打断才出的，算极巧合），要求每条都填（第 2 轮起也一样）。
- 每一轮都写明：**发现改坏了原来能用的功能，一律标【严重】**（方案：改坏老功能必退；程序按“严重”识别，不另设类型）。
- 第 2 轮起（这张卡之前有过“退回”的复查结论）：交代里先写一行 **`上轮退回的问题（按编号）：`**（一字不差，老测试的转换工具靠它认），下面每行一条 `N. 现象`，列完空一行；再要求复查员在清单里加“上轮核对”，按编号逐条答“改好了 / 没改好”。

### 3. 退回时编号

- 记“复查结论”（退回）时，把这次**实际退回**的问题（含按编号答没改好的上轮问题、漏答的上轮问题、新冒出的严重 / 测试写错的）按顺序编号存下，从 1 开始，下一轮交代和判定都按这个编号。每次退回都重新编号，第 3 轮只列第 2 轮实际退回的那些。

### 4. 判定（读清单）

- **第 1 轮**（之前没有“退回”的复查结论）：照 C1 口径，这次改的都退回；但 `碰上 = 极巧合`、不严重、不是测试写错的，记以后再修，不退回。原来就有的照旧。
- **第 2 轮起**：
  - 上一次退回的第 N 条：清单里答“没改好”→ 退回（退回交代里带上那条原问题的现象、位置）；**没答到的按没改好算**；答“改好了”→ 不再管。
  - 清单整份结论是“通过”且问题为空：当作都改好了，照常放行。
  - 新冒出的问题：严重的、测试写错的退回；其余（含中等、这次改的）记以后再修和台账，不退回。
- 退回给写代码的、补测试、改测试，都照 C1.5 现有的路走（测试写错派改测试，其余派补测试）。
- **保留 C1.5 现有的“整段原文已带回去的不再延期”判断**（`_later_problems` 里那段）：复查意见没解析完整、整段退回时，被整段包住的旧问题不能另记以后再修。

### 5. 退回用完（`_handle_review_reject` 那一处）

- 超过两次退回时，看剩下要退回的：
  - **都不严重、也没有测试写错** → 不停下。**先等这一轮的全部测试跑完**（和复查通过时同一步：`_FullSlot.finish`；这一轮不要因为“要改代码”而叫停全部测试）。全过 → 把剩下的记进以后再修和台账，记一条“复查结论”（通过）说明“还剩 N 件小问题已记以后再修”，进待验收。全部测试改坏老功能、超时或没跑成 → 不自动放行，停下转人工（原因写清是全部测试的问题）。
  - **还有严重的或测试写错的** → 照现在的样子处理：严重的停下转人工；测试写错的照现有规矩（退满时第一次发现测试写错，还给一次派写测试的改的机会，之后再停）。
- 停下时给用户看的话保持 C1.5 补修后的样子（大白话、严重的标出来）。
- **停下时列的“剩下的问题”、存进转人工记录的清单，都是这一轮实际要退回的全部**：包括按编号答“没改好”或漏答的上轮问题（用上轮那条原问题），不能只看这一轮清单里新写的问题。

### 6. 待验收说明（`collab/phase.py`）

- “等你确认”那一步的说明：以后再修里有这次改出来的小问题时，写“还剩 N 件小问题已记进以后再修和台账，这次不改”；只有开工前就有的问题时，照旧写“开工前就有的问题，已记进台账”。

### 7. 规则（`collab/规则.md`）

- 第六节“复查员”那一行加上：每条问题写“碰上”（常见 / 少见 / 极巧合）；退回后的复查按编号答上轮问题改好没有。

## 四、不做什么
