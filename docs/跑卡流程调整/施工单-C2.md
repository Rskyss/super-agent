## 三、具体做法

### 1. 归档放哪、叫什么（`collab/archive.py`）

- 签名改成 `archive_card(project_dir, card_id, feature, root=None, final_state=None) -> Path`。`root` 是写到哪里（默认就是项目）；`final_state` 给验收记录的“最终状态”用（默认用卡片当前状态）。
- **放哪**：用 `collab.planner.existing_orders(项目, 需求卡.md 原文)` 找卡片引用的施工单（在**项目**里找）。有 → 目标是 `root / 第一个施工单所在文件夹 / "卡片记录" / 卡号`；没有 → 照旧 `root / "docs" / 功能名`。
- **改名**：`需求卡.md` 存成 `卡片原文.md`（`_MAIN_FILES` 改成 `{"需求卡.md": "卡片原文.md", "方案.md": "方案.md"}`），不再存成“需求共识.md”。
- `以后再修.md` 加进过程记录那一组（`_PROCESS_FILES`）。
- **验收记录的“独立复查”**：先看流转里最后一条 `kind == "复查结论"`：`result` 是“通过”写“通过”，是“退回”写“不通过”；一条都没有（老卡）才照旧读 `复查结果.md` 里最后的“结论：”。
- **不重复**：每次归档把写出的文件（相对 `root` 的路径）记进卡片目录的 `归档文件.json`。再归档时，目标文件在这份清单里就**直接覆盖**，不在才按老规矩换带卡号的名字。`卡片记录/卡号/` 这个文件夹本来就只属于这张卡，里面一律覆盖。
- `root` 不是项目时（放进项目时写进副本）：**不记流转、不写台账**，由 `merge.py` 在放进项目成功后记。`root` 是项目（命令行 `collab archive`）时照旧记“归档”、写台账一行，台账里写真实的相对路径（比如 `docs/功能甲/卡片记录/CARD-001/`）。

### 2. 记录和代码进同一次提交（`collab/merge.py`）

- `_commit_work` 里，在“这张卡没有改动可以放进项目”那个检查**之后**、`git add` 之前，调 `archive_card(项目, 卡号, 标题, root=副本, final_state="已放进项目")`；出任何异常 → `_note(cdir, "记录没能存入项目文档", 原因)`，接着放进项目（不能因为记录挡住代码）。
- 归档写出的文件（读 `归档文件.json`）和代码文件一起 `_stage`、一起提交；后面检查“提交里有不该进项目的文件”时，这些记录文件算允许的。
- 删掉 `_merge` 末尾放进项目之后再调 `archive_card` 的那段。改成放进项目成功后：记一条“归档”（src 程序、dst 你、summary “记录已存入项目文档 <相对路径>/”），`ledger_add` 同样一句。
- 退回（放进去之后测试没过）时，记录跟着提交一起退回，不记“归档”。
- **观察第 36 条**：`_commit_work` 里，副本里有改动、但没被选进提交的文件（`_changed_list(副本)` 减去选中的；不算 `.collab/`、`node_modules`、缓存、密钥文件），放进项目成功后记一条 `kind="提醒"`（src 程序、dst 你），summary：“副本里有 N 个文件没带进项目：a、b”（最多列 5 个，多的写“等”），text 列全部。没有这种文件就不记。这条要记在“合并”那条**之前**（别的地方读最后一条“合并”）。

### 3. 写方案的不许猜预览地址（`collab/planner.py`）

- `_build_prompt` 里 `view_url` 那行后面加一句：“view_command、view_url 要照项目代码里真实的启动入口和地址写（先查项目里启动网页的代码和路由），不要猜；查不到就都填空字符串。”

### 4. 预览地址“找不到”不打开空白页（`desktop/preview.py`）

- `_reachable` 只用在“启动前这个地址是不是被别人占着”，不改。
- 新加一个查法：预览程序起来后，地址返回 404 或 410 → 当作“找不到”。`start` 等待循环里，程序活着且地址能连上时先看是不是“找不到”：是 → `self._give_up(mine, folder, "预览地址打不开（找不到这个页面），可以点“打开文件夹”自己看。")`；其他回应（200、500、401 等）照旧算打开了。

### 5. 开工前要存的文件（`collab/dispatch.py`、`desktop/server.py`）

- `collab/dispatch.py` 加 `files_to_save(project, card_id="") -> list`：
  - `git -c core.quotepath=off status --porcelain --untracked-files=all`（时限 5 秒，失败或不是 git 返回空列表）；改名取新名字；去掉 `.collab/` 下的。
  - **文档不算**：`docs/` 下的、任何 `.md` 文件。**例外**：这张卡 `需求卡.md` 引用的施工单（`existing_orders`）没存，算要存的。
  - 返回排好序的相对路径。`uncommitted_count` 不改（别处还在用）。
- `GET /api/clerk/uncommitted?project=&card=&token=`：返回 `{"count": len(files), "files": files}`；`card` 可以不给（不给就不看施工单），给了要过 `_CARD_ID` 检查。
- 新增 `POST /api/clerk/save_pending`，body `{project, card}`，要口令（和别的 POST 一样，不对 403）：
  - 重新算一遍 `files_to_save`（**不信页面传来的清单**）；空的直接返回 `{"ok": True, "saved": 0}`。
  - `git add -- 这些文件`，再提交，说明“开工前先存：<卡号> <标题>”，作者照 `collab.merge._identity_args` 的办法。
  - 提交没成功（比如项目的提交检查没过）→ 把暂存撤回（`git reset -q -- 这些文件`），返回 409 `{"ok": False, "reason": "没存成：" + 提交检查的输出前 200 字}`。
  - 成功 → `{"ok": True, "saved": N}`。**不改卡片状态**，开工仍走原来的 approve。

### 6. 三按钮小框（`desktop/static/panel.js`、`panel.html`、`panel.css`）

- `PanelCore` 加 `startDialogText(count)`：count 为 0 返回 `null`；否则返回“有 N 处改动还没存进项目，施工会看不到它们。”，并且在 `module.exports` 里能用到。
- `panel.html` 加一个默认隐藏的小框 `id="startBox"`：一段 `id="startText"`、一个文件清单 `id="startFiles"`（每个文件一行，最多显示 10 个，多的写“还有 N 个”）、三个按钮 `id="startSave"`“先存再开工”、`id="startGo"`“直接开工”、`id="startCancel"`“先不开工”。样式照 `reviseBox` 那一套写进 `panel.css`。
- 点“批准并开工”（`act === "approve"`）：请求 `/api/clerk/uncommitted` 时带上 `card=<卡号>`。
  - `files` 为空（或请求失败）→ 直接 `runCardAction("approve", cardId)`，不弹。
  - 不为空 → 显示小框：先存再开工 → `POST /api/clerk/save_pending`，成功再 `runCardAction("approve", cardId)`，失败把 reason 显示在小框里、不开工；直接开工 → 关框、开工；先不开工 → 关框，什么都不做。
  - 删掉原来用 `window.confirm` 问“个文件还没提交”的那段。
  - 小框开着时切了卡，关掉小框（照 `reviseBox` 在切卡时的处理）；开工的必须是点的那张卡（现有 `cardId` 写法）。
