> 用户的目标：打造一支牛逼的开发工程团队——每个岗位有规矩，换哪个模型来都能照规矩干；干得太差的试用期过不了就不用。

## 一、要做什么

| # | 现在 | 以后 |
|---|---|---|
| E1 | 有施工单的卡，写方案的（Codex 最低档）照着施工单再抄一遍允许改的文件和测试命令，每张卡多 2–3 分钟、十几万 token，还抄错过（自己加“跑全部测试”） | **有施工单就跳过写方案**：程序直接从施工单里读允许改的文件和验收命令；没有施工单的卡照旧写方案 |
| E2 | 备交接资料（Codex 最低档）每张卡都做，20–55 万 token，有施工单时和施工单重叠 | **有施工单就跳过备交接资料**；没有施工单照旧 |
| E3 | 写方案、备交接资料两个岗位在规则里没有岗位职责 | 规则里补这两个岗位的职责段 |
| E4 | 复盘发现的毛病只记在点评里 | 写进对应岗位的规则：写测试的只管结果对不对、不规定代码怎么写、假页面要像真页面；退回几件补几条、逐条写编号；返工只改退回的那件、动相邻写法先确认原有的测试和说明都在 |
| E5 | 换模型全凭 Claude 感觉 | **试用期**：新模型上一个岗位，头 3 张卡算试用；考核看交成率、平均用时、复查挑出它的问题（尤其“自己加没要求的东西”“测试写错”“改坏旁边”）；通过就在团队里写明这个岗位用它，不通过这个岗位不再用、写明原因，新版本可再试。写进开发流程规范，记录放 [流程数据](../流程数据/README.md) |

## 二、不做什么

- 不改复查规矩（11-19 刚定的新规矩照旧）。
- 不改团队设置页的样子。
- 没有施工单的卡，写方案、备交接资料照旧。
