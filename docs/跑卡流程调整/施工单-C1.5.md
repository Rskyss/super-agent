# 施工单 C1.5：复查意见固定格式（跑卡流程调整 · 第二批）

> 依据 [方案-C1.5](方案-C1.5.md)（用户 2026-11-18 批准，含第七节补充）。写给开发助手的施工方（写测试、写代码、复查）。
> 项目就是开发助手这个仓库。**验收测试已经写好**（`tests/test_flowfix_c15_acceptance.py`），施工方**不许改**；写测试的只**补充**，写进新文件 `tests/test_flowfix_c15_extra*.py`。
> 老测试已由 Claude 接上转换工具 `tests/review_fmt.py`：程序有了 `read_review_list` 以后，老测试里随手写的复查意见会自动补上同义的固定清单。**不要改这些老测试和这个工具。**

## 一、要做什么（一句话）

复查员必须在回复末尾附一段固定格式的复查清单（```json 代码块），每条问题写齐级别、来源、类型、现象、位置、证据。程序只认这份清单：格式不合格先请复查员重写一次，还不合格就保守处理，绝不自动放行。每一轮复查都要提醒老测试被改过、以及新加了“跳过”的测试。收口、补测、停下、右栏、接着跑，都只读这份清单。

- `collab/规则.md`
- `tests/test_flowfix_c15_extra*.py`（写测试的新建）

**不许改**：`tests/test_flowfix_c15_acceptance.py`、`tests/review_fmt.py`、`tests/test_review_fmt.py`、所有已接上 `listed_ask` 的老测试，以及上面没列的任何文件。

## 三、具体做法

### 1. 读清单：唯一入口（`collab/dispatch.py`）

新增 `read_review_list(text) -> (data, errors)`：
- 取回复里**最后一个** ```json 代码块，解析成对象。`data` 是 `{"结论": "通过"|"不通过", "问题": [...]}`，`errors` 是不合格原因的列表，空列表表示合格。
- 以下情况都算不合格：
  - 没有代码块，或解析不了；
  - “结论”不是“通过”或“不通过”；
  - 结论是“不通过”，问题却一条都没有；
  - 某条问题缺少“级别 / 来源 / 类型 / 现象 / 位置 / 证据”中的任何一项；
  - 级别不是“严重 / 中等 / 轻微”；来源不是“这次改的 / 原来就有的”；类型不是“功能问题 / 测试写错”；
  - 证据的“方式”不是“实跑”或“推演”；
  - 实跑缺“命令”或“输出”；
  - 推演的“对照”里没有 `文件名.扩展名:行号` 这样的位置。
- **只认清单，不从正文里猜。**

### 2. 复查交代（每一轮都一样）

- 保留现在的要求：第一行写“结论：通过”或“结论：不通过”。
- 回复末尾附 `复查清单：` 加一个 ```json 代码块，写明字段和取值。交代里必须出现以下字样（老测试也要靠它们）：
  - `复查清单`、```json、`证据`、`实跑`、`推演`、`级别`、`来源`、`类型`、`现象`、`位置`；
  - 级别写作【严重】【中等】【轻微】；来源写作【这次改的】【原来就有的】；“测试写错”对应现有的 `TEST_PROBLEM` 字样【测试的问题】；
  - “不许因为跑不了就不报”。
- `_TRIAGE_NOTE` 的意思保留，并入对“来源”的说明。
- **每一轮**都加 `_old_tests_changed_note`（去掉 `if revise_note`），以及第 5 条的“新加跳过”提醒。

### 3. 格式不合格：重写一次

- 能读出结论（`review_verdict` 是 pass 或 reject），但清单不合格时：再派复查员一次，交代以“按固定格式重写”开头，写明“不用重新复查”，附上原回复全文和不合格原因，只要求补一份合格的清单。
- 重写后合格，就用重写后的清单。还不合格：
  - 原结论是“不通过”：把**整段原文**退回给写代码的；
  - 原结论是“通过”：卡停下（转人工），原因写“复查结论格式不合格，不能自动放行”。
- 读不出结论的（比如“还没有结论”），照现在的样子处理，不触发重写。

### 4. 判定（读清单）

- 退回的：来源是“这次改的”、级别是“严重”、类型是“测试写错”，满足任意一条就退回。记进以后再修（并写台账，沿用 C1）的：来源是“原来就有的”、不严重、也不是测试写错。
- 结论写“通过”、清单里却有该退回的问题：按不通过处理。
- 记“复查结论”时，多存一个字段 `清单`（就是 data）。转人工记录也存 `清单`。
- 补测试清单、改测试清单、退回给写代码的交代，都从清单生成：每条写出现象、位置、证据。“测试写错”的派改测试，其余该退回的派补测试，两者都有就两样都派。
- 退回用完停下时：用清单判断是不是“只剩轻微的”，提示和起草“继续改”都按清单来；**有严重问题就不能说成小问题**。
- 中途打断后接着跑：从最近一条“复查结论”的 `清单` 取要改的条目。

### 5. 新加的“跳过”（老测试和本卡新写的测试）

- 新增 `_SKIP_PATTERN`，一个正则，能认出：`@unittest.skip`、`skipTest(`、`skipIf` / `skipUnless`、`pytest.mark.skip`、`pytest.skip(`、`it.skip` / `test.skip` / `describe.skip`、行首的 `xit(`。不能误认普通名字，比如 `def test_skip_button_hides`。
- 在副本里查两类：
  - 已提交的测试文件里**新增的行**命中的（和 HEAD 比）；
  - 还没提交的新测试文件里命中的行。
- 列成“文件:行号 内容”，放进复查交代，写明：“这些测试被加了跳过，逐个判断合不合理；不合理就判不通过。”

### 6. 右栏和停下提示

- `desktop/view.py`：复查格以“最后一条复查员回复之后的复查结论”为准，通过显示 done，退回显示 fail。没有复查结论的老卡照旧。
- `collab/phase.py`：停下时的问题清单（`issues`）优先读转人工记录里的 `清单`，写出级别和现象；没有清单的老卡照旧。

### 7. 三处遗留

- `_prior_reviews(cdir)`：只数“复查结论”记录。没有有效结论的那一轮不算，下一轮不降档。
- `_tester_step_done`：写测试的回复之后，还要有一条 `测试收尾` 记录（kind 写“测试收尾”，step 写对应步骤）才算完成。这条记录在 `_tester_work` 做完还原越界改动、登记测试、更新快照之后写。
- `_short_test_output`：失败块以外以“- ”开头的日志不要。每个失败块保留标题，以及调用栈里**测试文件那一行**（路径里有 `/tests/` 或文件名以 `test_` 开头）和最后几行。

### 8. 老认法降级，不删

`_review_items`、`_unparsed_serious`、`_triage`（按字符串的那个）、`_lead_tags`、`_level`、`_places` 等**保留**，函数说明里注明“只给没有清单的老卡显示和测试转换工具用，不参与放行判断”。判定一律走第 1、4 条。

### 9. `collab/规则.md`

第六节“复查员”那一行改成：第一行写结论（保留“结论：通过”字样），回复末尾附复查清单，每条问题写齐级别、来源、类型、现象、位置、证据（实跑写命令和输出，推演写对照的文件和行号）。删掉“后面逐条列出问题和依据”。
