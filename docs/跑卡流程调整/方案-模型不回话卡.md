# 方案：模型不回话卡（分清“模型没回话”和“工具在干活”，建议换模型）

> 2026-11-18 · 口径来自用户 11-18（观察记录第 41 条“用户 11-18 要求”四点、讨论-纠错与交接第 3 项）；用户同日要求 Claude 一路做完、技术问题自己定，**本方案由 Claude 按授权自批**。
> 判大小：中（跑卡流程的看门人和提醒文字）。施工交开发助手跑卡。

## 1. 你能感受到的变化

1. **5、10 分钟没动静的提醒分两种说**：
   - 工具没在跑命令、也没输出、没改文件（在等模型）：“写代码的模型已经 N 分钟没回话……多半是模型服务卡了，也可能在想很久。建议点‘停下’，在团队设置把它换成 **X（今天跑得正常的那个）** 再点‘接着跑’；也可以再等等。”
   - 工具在跑命令：“已经 N 分钟没改文件，但还在跑命令，像是在干活，可以再等等。”（不劝换模型）
2. **15 分钟被停下时**，停下说明里写“模型没回话”，并同样建议换成 X。
3. **同一个模型连续两次没回话被停下**，下一次派活给它之前，先提醒“这个模型连续两次没回话，建议先换成 X”（只提醒，照样派）。中间顺利交过一次活就重新算。
4. **千问这条路**：回复中途断流 2 分钟就由工具自己重发（最多 3 次），不用等程序停下。
5. X 怎么挑：今天（本机日期）在这个项目里顺利交过活的、和卡住的不是同一个工具+模型的，取最近的那个；一个都没有就说“换一个模型”。

## 2. 实测依据（Claude 11-18 用一个故意不回话的假服务测的）

- 服务**回了开头、之后断流**：Codex 设了“断流多久重发”后，会自己重发、到次数后报错退出。→ 第 4 条有用。
- 服务**连开头都不回**（第 41 条就是这种）：Codex 的这个设置不管用，100 秒里只发了一次请求、一直空等。→ 只能靠程序这边发现、提醒、建议换模型（第 1–3 条）。
- 所以不做“程序自动停下重派”：自动停会丢掉这一轮已读的内容，而模型也可能只是在长时间思考；改为早提醒、给出具体换哪个，由你决定。（Claude 定，见第 5 节）

## 3. 怎么做（技术，Claude 自批）

| # | 做什么 | 改哪里 |
|---|---|---|
| 1 | 千问那条路的设置加“断流 2 分钟重发、最多 3 次” | `collab/agents.py` |
| 2 | 看门人提醒和停下时，看工具底下有没有在跑的命令（插件、帮手不算）：没有 = 在等模型。提醒把这个结果一起交出去（老的一个参数的提醒照旧能用）；停下的说明写“模型没回话” | `collab/agents.py` |

| 4 | 记每个工具+模型连续没回话被停下几次（项目里一个小记录文件），顺利交活清零；派活前满两次就提醒 | `collab/dispatch.py` |

## 4. 影响面

1. 动的：看门人提醒、停下说明的文字，千问那条路的设置，派活前多一条可能的提醒。
2. 不动：15 分钟停下的时限；停下后的按钮；“被停下但本卡测试已全过就直接交复查”的规矩。
3. 行政：提醒照旧由行政在卡片对话里转述，不用改。
4. 老测试：老的提醒只收一个参数，照旧能用（验收测试里有一条专门守）。
5. 要重装开发助手才生效。和已批准文档不矛盾。
6. 证明：验收测试（见施工单）；真碰到时看提醒文字。

## 5. Claude 替你定的（事后可改）

- 不自动停下重派，只提醒并给出具体换哪个模型（理由见第 2 节）。
- “今天跑得正常的”按本机日期、本项目里所有卡片的记录算。
- 千问那条路断流 2 分钟重发（实测正常回复时最长停顿约 9 秒，留足余量），最多 3 次。
