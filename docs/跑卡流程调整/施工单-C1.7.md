# 施工单 C1.7：C1.6 复查暴露的三处小修

> 依据 [方案-C1.7](方案-C1.7.md)（用户 2026-11-18 批准）。写给开发助手的施工方（写测试、写代码、复查）。
> 项目就是开发助手这个仓库。**验收测试已经写好**（`tests/test_flowfix_c17_acceptance.py`），施工方**不许改**；写测试的只**补充**，写进新文件 `tests/test_flowfix_c17_extra*.py`。
> 第五节那项老测试的跳过条件 Claude 已在建卡前改好（用户已批准这条跳过），**不许再改**。

## 一、要做什么（一句话）

复查清单里的级别、来源、类型带不带【】都认（正式读法和兜底读法都认）；写方案的交代先读规则，并交代不要让施工方跑全部测试。

## 二、允许改哪些文件

- `collab/dispatch.py`
- `collab/planner.py`
- `tests/test_flowfix_c17_extra*.py`（写测试的新建）

**不许改**：`tests/test_flowfix_c17_acceptance.py`、`tests/test_flowfix4_round3.py`，以及上面没列的任何文件。

## 三、具体做法

### 1. 去括号放在一处（`collab/dispatch.py`）

- 加一个小函数：把一条问题的 `级别`、`来源`、`类型` 去掉两边空格和所有【】（含括号里的空格），写回这条问题。只处理这三项，其他字段不动；值不是字符串的不动。
- `read_review_list`：解析出 JSON、确认是对象、`问题` 是列表之后，**先对每条问题调用这个函数，再做现有的格式检查**。返回的清单里就是去掉括号的值。
- `_raw_list_problems`：从 JSON 里取出问题列表时，同样对每条调用这个函数后再返回。
- 去括号后的值不在允许范围里（比如“【很严重】”→“很严重”），照旧判不合格。
- 后面所有判断“严重 / 原来就有的 / 测试写错”的地方**都不要改**：它们读的是这两处返回的结果。
- 复查交代里写“【严重】【中等】【轻微】”的两处**不要改**。

### 2. 写方案先读规则（`collab/planner.py`）

- `_build_prompt` 的交代最前面加上和其他岗位**同一句**“先读规则”（用 `collab/dispatch.py` 里的 `_READ_RULES`，规则文件路径要一致）。注意 `dispatch` 和 `planner` 之间不要形成互相导入卡死：如有循环导入，把规则路径和这句话挪到两边都能导入的地方，`dispatch.py` 里的 `RULES`、`_READ_RULES` 名字保留可用。
- 在“- test_command：一条测试命令字符串。”这一行后面加一句（原文照抄）：
  `方案步骤里不要让施工方跑全部测试，全部测试由程序在复查时跑；test_command 只写本卡的测试。`

## 四、不做什么

不改后台进程清理功能（`collab/fullrun.py`）；不改复查交代的写法；不改写方案的其他内容；不改程序自己的测试命令和跑法。
