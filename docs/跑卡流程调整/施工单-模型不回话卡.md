# 施工单 模型不回话卡：分清“模型没回话”和“工具在干活”，建议换模型

> 依据 [方案-模型不回话卡](方案-模型不回话卡.md)（Claude 按用户 11-18 授权自批）。写给开发助手的施工方（写测试、写代码、复查）。
> 项目就是开发助手这个仓库。**验收测试已经写好**（`tests/test_noreply_acceptance.py`），施工方**不许改**；写测试的只**补充**，写进新文件 `tests/test_noreply_extra*.py`。

## 一、要做什么（一句话）

看门人提醒和停下时分清“在等模型”还是“在跑命令”；等模型时建议换成今天跑得正常的模型；同一模型连续两次没回话被停下，下次派活前提醒；千问那条路断流 2 分钟由工具自己重发。

## 二、允许改哪些文件

- `collab/agents.py`
- `collab/dispatch.py`
- `tests/test_noreply_extra*.py`（写测试的新建）

**不许改**：`tests/test_noreply_acceptance.py`，以及上面没列的任何文件。

## 三、具体做法

### 1. 千问断流重发（`collab/agents.py` 的 `qwen_command`）

provider 设置里加两项：`model_providers.qwtp.stream_idle_timeout_ms=120000`、`model_providers.qwtp.stream_max_retries=3`（`-c` 写法和旁边一致）。

### 2. 看门人分清两种情况（`collab/agents.py`）

- 加一个函数：给工具进程号，看它底下（所有后代）有没有“在跑的命令”——用现有的 `_process_table`、`_is_command`、`_HELPER_WORDS` 的认法：插件、帮手（以及它们拉起的子进程）不算；有一条算命令的就是“在干活”。拿不到进程表就当“在干活”（宁可不劝换模型）。
- `QuietTimeout.__init__(self, quiet_seconds, waiting=False)`，存 `self.waiting`。消息：`waiting` 为真 →“超过 N 分钟模型没回话（工具在等模型，没在跑命令、没改文件）”；否则照旧“超过 N 分钟没有任何文件变化”。
- `watched_runner`：
  - 到提醒时刻：算一次 waiting，`on_quiet` 能收两个参数就 `on_quiet(秒数, waiting)`，只收一个就照旧 `on_quiet(秒数)`（用 `inspect.signature` 判断；判断不了就按一个参数调）。
  - 没动静到上限：算一次 waiting，`raise QuietTimeout(秒数, waiting=waiting)`。
- `ask` 里捕获 `QuietTimeout` 的输出照旧 `f"看门人：{exc}，已停止"`（消息里自然带上“模型没回话”）。

### 3. 提醒和停下说明（`collab/dispatch.py`）

- 加 `_suggest_model(collab_dir, adapter, model_text) -> str`：读项目 `.collab/cards/*/流转.jsonl`，找**今天**（事件 `ts` 秒数换成本机日期 = 本机今天；11-19 起记录只记 `ts`、不记钟点，老记录没有 `ts` 的才看 `time`）`回复`、`ok` 为真、有 `reply_to` 的；用它回复的那条 `派活` 的 `tool` 和 `model`；跳过和卡住的同一个工具+模型的；有记型号的优先、同档取最近的（按 `ts` 比）（11-19 Claude 接手定：验收测试要求推荐具体型号，和“只取最近”冲突，具体型号对用户更有用），返回 `f"{tool}（{model}）"`（没 model 就只写 tool）。一个都没有返回空字符串。
- `_dispatch` 里的 `on_quiet` 改成 `def on_quiet(seconds, waiting=None, role=role, adapter=adapter)`：
  - `waiting is None`（老调用）：文字**照旧不变**。
  - `waiting` 为真：`f"{role}（{adapter}）的模型已经 {minutes} 分钟没回话（工具在等模型，没在跑命令、没改文件），多半是模型服务卡了，也可能在想很久。建议点“停下”，在团队设置把{role}换成 {X} 再点“接着跑”；也可以再等等，再过约 {left} 分钟还没动静程序会自动停下。"`；X 是 `_suggest_model` 的结果，空的就写“换一个模型（团队里别的工具或模型）”这层意思（句子里要有“换”）。
  - `waiting` 为假：`f"{role}（{adapter}）已经 {minutes} 分钟没改文件，但还在跑命令，像是在干活，可以再等等；再过约 {left} 分钟还没动静程序会自动停下。"`（不劝换模型）。
- `_worker_failed`：干活的输出里有“模型没回话”时，停下说明后面接一句“建议在团队设置把{role}换成 {X} 再点“接着跑””（X 同上；空的照上面写“换一个模型”）。

### 4. 连续没回话（`collab/dispatch.py`）

- 项目级小记录 `.collab/模型卡住.json`：`{"<工具>|<模型>": 连续次数}`。读写坏了不影响跑卡（读不出当空的，写失败忽略）。
- `_dispatch` 收到回复后：输出里有“模型没回话”→ 这个工具+模型次数加 1；`ok` 为真 → 清零（删掉这一项）。
- `_dispatch` 记“派活”**之前**：这个工具+模型次数 ≥ 2 → 先记一条 `提醒`（src 程序、dst 你、role、tool），summary：`f"{role}用的 {adapter}（{model}）连续 {n} 次没回话被停下，建议先在团队设置换成 {X}；这次照样派给它。"`（要有“连续”“换成”；X 为空时写“换一个模型”）。
- 工具+模型的写法：`adapter` + `_dispatch` 里已经算好的 `model_text`。

## 四、不做什么

不改 15 分钟停下的时限；不自动停下重派；不改停下后的按钮；不改“被停下但本卡测试已全过就直接交复查”的规矩；不改行政转述提醒的方式；Codex 自家模型那条路不加断流设置。
