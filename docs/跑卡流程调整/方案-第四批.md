# 方案：跑卡流程调整 · 第四批（岗位规矩和流程精简）

> 2026-11-19 · 依据 [需求共识-第四批](需求共识-第四批.md)（用户已批准）。技术部分 Claude 按授权自批。
> 拆法：**F1 一张卡**（E1、E2 改跑卡程序，交开发助手跑）；E3、E4（改规则文字）、E5（试用期写进规范）是文档，Claude 亲自做，不建卡。

## 一、你会看到什么变化

1. 有施工单的卡：点“确认”建卡后，方案几秒钟就出来（程序照施工单直接生成，方案里写明“照施工单生成”），不再等 AI 写 2–3 分钟。
2. 开工后右栏“交接资料”那步写“有施工单，跳过”，不再花 Codex 额度。
3. 施工单写得不全（读不出允许改的文件或验收命令）、或者卡片没有施工单：照旧让 AI 写方案、备交接资料。
4. 规则里写方案、备交接资料两个岗位有了职责；写测试、写代码两个岗位多了复盘得来的几条（E4）。
5. 开发流程规范里多了“试用期”一节（E5）。

## 二、怎么做（技术）

**F1（卡）**：`collab/planner.py`、`collab/dispatch.py`
- `planner.plan_card`：叫 AI 之前，若 `existing_orders` 找到施工单，就试着从第一份施工单里读：
  - 一句话：`## 一、要做什么（一句话）` 下第一段；
  - 允许改的文件：`## 二、允许改哪些文件` 下各条第一个反引号里的路径（到 `**不许改**` 那行为止）；
  - 验收命令：`验收命令：` 后面反引号里的整条；
  - 步骤：`## 三、具体做法` 下各个 `### ` 小标题；不做什么：`## 四、不做什么` 下第一段。
  一句话、允许改的文件、验收命令三样都读到了，就照常写 `方案.md`（开头注明“照施工单生成”）、改需求卡的允许范围、写 `开工.json`、记“方案”（来源写“程序”），不叫 AI；缺一样就照旧叫 AI。
- `dispatch.run_card`：有施工单（`existing_orders(项目, 需求卡)` 非空）就不起备交接资料，记一条“交接资料”：“有施工单，跳过（写代码、复查直接读施工单）”。

**E3–E5（Claude 亲自做）**：`collab/规则.md` 第六节补写方案、备交接资料两段，测试员、开发员段加复盘条目；`docs/开发流程规范/开发流程规范.md` 加“试用期”一节，`docs/流程数据/README.md` 写考核口径。

## 三、影响面

- 老卡不受影响；没施工单的卡完全照旧。
- 施工单格式靠 Claude 写的统一格式（第二批起都这样）；格式不对就回退到 AI，不会卡住。
- 要重装开发助手才生效（窗口里点确认建卡走的是装进去的代码）。
