# 方案：C1.8 拆成两张（C1.8a 主体、C1.8b 删兜底读法）

> 2026-11-18 · 用户定“C1.8 按推荐拆开”。原 C1.8（[方案-C1.8](方案-C1.8.md)，代码在本机分支 `c18-review-pending`）复查 3 轮 + 确认复查都没过，第 3 轮修补还带出退步。**本方案待用户批准**。
> 判大小：两张都是**中**（只动跑卡流程里“复查结果怎么处理”这一段）。都由 **Claude 亲自做**（改正在用的跑卡流程），Codex 复查，各自最多 3 轮。

## 1. 为什么要拆、拆成什么

原 C1.8 做了两件事，混在一起复查，越补越多：

| | 内容 | 复查情况 |
|---|---|---|
| ① 主体 | 复查员格式写错、重写还看不懂 → 停下交 Claude，不再从原话里猜、整段退回；删掉整段退回那一大块 | 第 1 轮提的问题都修好了，后面几轮没再挑它 |
| ② 加固 | 为了让①在“接着跑、中途打断、连续停下”时也对，一处处补“回头读复查员原话”的老读法 | 第 2、3 轮、确认复查**全在这里冒新问题**，第 3 轮修补还带出退步 |

②的病根：程序在**没有正式复查结论记录时，会回头去读复查员的原话**来判断“上次是不是退回、退回了几次”。这是 C1.5 以前的老卡留下的兜底。现在每次复查都会写正式结论，这个兜底只剩下“出错的机会”。

所以：
- **C1.8a**：只做①，加上第 1 轮那几条确认没退步的修复。
- **C1.8b**：**整块删掉“没有正式结论就读原话”的兜底**（不是再补），只认正式复查结论。②冒出的那些问题，没有了兜底就不会再发生。

## 2. C1.8a：主体

**做什么**（从分支里取，只留第 1 轮的状态）：
1. 重写后还看不懂、原结论不通过 → 停下交 Claude，原话和重写都存下，停下说明里列出原话提到的问题、标了严重的句子（只给人看）。
2. 删掉整段退回相关代码。
3. 数“退回了几次”时不把格式重写那次多算（第 1 轮严重 2，C1.6 起就有的漏洞）。
4. 第二行“结论：不通过”不能被重写翻成通过（第 1 轮中等 3，用第 1 轮的改法）。
5. 看不懂停下后点“接着跑”：重新复查，不把原话交给写代码的（第 1 轮严重 1，用第 1 轮的改法：认停下标记）。

**不做**：第 2、3 轮对老读法的补丁（停下点作废、按任何停下算起、翻案只认第一条结论行等），全部留给 C1.8b 用“删兜底”的办法解决。

**已知不足（C1.8b 解决）**：连续两次停下又中断这类罕见组合，接着跑仍可能出错。

**验收**：原 C1.8 第 1 轮那批测试全过；12 项老测试按方案-C1.8 第 3 节的处理；全部测试通过；Codex 复查**只看①和第 1 轮修复，不展开老读法**（老读法下一张卡整块删）。

## 3. C1.8b：删掉“没有正式结论就读原话”的兜底

**做什么**：
1. 判断“上次复查是不是退回、退回了几次、要交给写代码的意见”时，**只认正式的复查结论记录**；没有结论记录就当没有退回过，不再去翻复查员的原回复。
2. 删掉对应的老读法代码，以及只为它服务的补丁。
3. 正在跑的卡里如果碰到只有原回复、没有结论记录的旧状态（现在没有这样的卡）：停下交 Claude，不猜。

**为什么安全**：C1.5 以后每次复查都写正式结论；现在没有停在老状态的卡（CARD-001 到 008 都已结束）。

**验收**：原 C1.8 第 2、3 轮和确认复查提的那几种情形（连续停下、存完就中断、作废的回复被捡回、多算退回、旧日志被当结论）各有测试，全部通过——**靠删除做到，不靠补**；只为老读法写的老测试逐条登记删除或改写；全部测试通过；Codex 复查。

## 4. 顺序和分工

C1.8a → C1.8b，都由 Claude 做（不用开发助手跑卡）。每张：先写会失败的测试 → 改 → 全部测试 → Codex 复查（最多 3 轮）→ 给你看结果再放进项目。
