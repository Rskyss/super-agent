# 施工单 C1：复查规矩（跑卡流程调整 · 第二批）

> 依据 [需求共识-第二批](需求共识-第二批.md) A1–A6、[方案-第二批](方案-第二批.md)（用户 2026-11-18 批准），[任务清单-第二批](任务清单-第二批.md) 任务 1–4。写给开发助手的施工方（写测试、写代码、复查）。
> 项目就是开发助手这个仓库。**验收测试已经写好**（`tests/test_flowfix_c1_acceptance.py`），施工方**不许改**；写测试的只**补充**，写进新文件 `tests/test_flowfix_c1_extra*.py`。
> **原则：有增有删。** 被新规矩取代的旧分支、旧弹窗要删掉，不许新旧并存。

## 一、要做什么（一句话）

复查挑出的问题，这次改出来的不分轻重一律退回；只有开工前就有的（严重的除外）记进“以后再修”并写进台账，点确认时不再弹给用户；复查最终放行的右栏显示绿勾；退回时先让写测试的补测试守住、再让写代码的把同类问题一起改；退回后的复查只看改动、强度降一档；测试没过时交给写代码的只有失败项和关键几行。

## 二、允许改哪些文件

- `collab/dispatch.py`
- `collab/phase.py`
- `desktop/view.py`
- `desktop/static/panel.js`
- `tests/test_flowfix_c1_extra*.py`（写测试的新建）

**不许改**：`tests/test_flowfix_c1_acceptance.py`；Claude 已按新口径改好的 `tests/test_flowfix4_converge.py`；上面没列的任何文件。

## 三、具体做法

### 1. 收口规则（`collab/dispatch.py` 的 `_triage`）

- 退回：带【测试的问题】的；【严重】的；**没标【原来就有的】的（不分轻重）**。
- 记进以后再修：标了【原来就有的】、且不是【严重】、也不是【测试的问题】的。
- 改函数说明，写明“第二批 A1（11-18）”。

### 2. 每一轮复查都标“这次改的/原来就有的”

- 复查交代里**每一轮**都带 `_TRIAGE_NOTE`。去掉 `triage_on` 这个条件，也去掉 `_TRIAGE_NOTE` 开头的“这是改过以后的复查：”。
- 复查不通过时**每一轮**都走收口，把 `if verdict_kind == "reject" and triage_on:` 改成只看 `reject`。
- 收口后只剩“原来就有的”，就和现在一样算通过。所以第 1 轮复查只挑出开工前就有的问题时，直接放行。

### 3. 记一条“复查结论”，作为唯一依据（A3）

- 收口完成后，或者复查直接通过时，记一条流转：`record(cdir, "复查结论", src="程序", result="通过" 或 "退回", reply=这次复查回复的 seq, later=记进以后再修的条数, summary=大白话)`。
- 通过：`summary` 写“复查通过”；有以后再修时写“复查通过（另有 N 件开工前就有的问题，已记进台账）”。
- 退回：`summary` 写“复查退回 N 件”。

### 4. 开工前就有的问题写进台账（A2）

- 记进“以后再修”时，同时调用 `collab.ledger.ledger_add(项目目录, f"{卡号}：复查发现开工前就有的问题 {N} 件，这次不改：{大白话清单，用“；”隔开}")`。
- 项目目录是卡片目录往上三层（`.collab/cards/卡号` 的上上上级）。
- 大白话沿用 `_later_words`。
- 写台账失败只记一条流转，不卡住跑卡。

### 5. 右栏复查格（`desktop/view.py`，A3）

- 复查格的状态和说明，以**最后一条复查员回复之后**的那条“复查结论”为准：
  - `通过`：状态 `done`，说明用它的 `summary`。
  - `退回`：照现在的样子。
- 没有“复查结论”的老卡，照现在读复查回复，不能报错。

### 6. “等你确认”的说明（`collab/phase.py`，A2）

- 有以后再修时，`detail` 改成：`另有 N 件开工前就有的问题，已记进台账，这次不改`。删掉“点确认时会列给你看”。
- `later` 字段保留，供别处读。

### 7. 点确认不再弹窗（`desktop/static/panel.js`，A2）

- 删掉 `PanelCore.acceptConfirm`，以及点“确认没问题，放进项目”时调用它的那两行。
- 别处还在用的要一起改掉，**不留**。

### 8. 退回时先补测试守住（A4）

- 复查退回、要退回的条目里**有不是【测试的问题】的**，在派写代码的之前，先派写测试的。
- 交代必须包含“**编写自动化测试**”这几个字（老测试的假跑卡靠它认出是写测试的）。内容：针对下面这几条问题各补一条测试，写进新的测试文件，测试要能抓住这个问题（现在应该不过）；只改测试，不改产品代码。
- 写测试的动了测试以外的文件，一律还原。复用 `_tester_fix` 里“派活前拍快照、动了非测试文件就还原”的那一套，不另写一套：可以把它改成带参数的通用函数，现有的【测试的问题】分支照旧走它。
- 写测试的没交成（失败、超时），不卡住：照旧派写代码的，并记一条流转说明“补测试没成功”。
- **写代码的交代**（`_review_return_prompt`）加一句：先想清楚这几条背后的**同一类**原因，在本卡改动范围里找出同类写法一起改，不要只改被点名的那一处；写测试的已经补了测试守住这几条，跑本卡测试要全过。（必须含“同类”二字。）

### 9. 退回后的复查只看改动、降一档（A5）

- 这张卡复查退回过以后（以现有的 `_prior_reviews(cdir) > 0` 判断）的复查：
  - 交代里加：“这是退回修改后的复查：只看上一次复查以后改动的地方和它直接牵连的地方，其他部分上一轮已经复查过，不用重看。”（含“只看”二字。第 1 轮的交代里**不能**有这句。）
  - 复查员的模型设置里，`codex_effort` 取比原来**低一档**的值。档位顺序：`low, medium, high, xhigh, max, ultra`。原来没有设置或不在这个列表里，就不改。
  - 右栏复查格显示的模型强度跟着变，现有显示是读派活记录的，确认它能显示新档位。

### 10. 测试没过时只交关键几行（A6）

- 新增一个函数，把测试输出浓缩成“失败项 + 关键几行”：
  - 认得出 Python 自带测试格式（`FAIL:` / `ERROR:` 开头的块）：每个失败块保留标题行，加上它 Traceback 的最后 6 行（包括测试文件那一行和报错那一行）；末尾保留 `Ran N tests` 和 `FAILED (...)` 两行。
  - 认得出 pytest 格式：保留 `FAILED ` 开头的行和 `E ` 开头的行。
  - 都认不出：保留最后 60 行。
  - 无论哪种，最长 4000 字。
- 用在两处：测试没过退回写代码的交代（现在的“上一版测试没过，测试输出如下”），和老测试被改坏的交代（`本卡测试过了，但这些老测试没过……`）。
- 交代里加一句“完整输出在 测试结果.md”，附上卡片目录里该文件的路径。
- **完整输出照旧写进测试结果.md 和流转记录**，只是不整段塞进交代。

## 四、验收

- 验收命令：`python3 -m unittest discover -s tests -p "test_flowfix_c1*.py" && python3 -m unittest discover -s tests -p "test_flowfix4_*.py"`
- `tests/test_flowfix_c1_acceptance.py` 全过；`tests/test_flowfix4_converge.py` 全过（Claude 已按新口径改好）。
- 全部测试不因这次改动变坏。因为第 8 条多了写测试的环节，老测试的假跑卡里“第几次派活是写代码的”可能错位：只要写测试的交代含“编写自动化测试”，老的假跑卡就会认成写测试的，不会错位。如果仍有老测试因此不过，**不许改老测试**，在汇报里写明是哪个，由 Claude 判断。
- 汇报用大白话，不写文件名。
