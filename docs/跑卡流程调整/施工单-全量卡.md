## 三、具体做法

### 1. 每个文件单独限时（`collab/fullrun.py`）

- 加常量 `FILE_TIMEOUT = 300`；`FullRunner.__init__(self, timeout=FULL_TIMEOUT, workers=None, file_timeout=FILE_TIMEOUT)`，存成 `self.file_timeout`。
- `_run_files` 里每个文件的时限 = `min(self.file_timeout, 整轮剩下的时间)`。
- **单个文件超时只停它自己**：删掉“有一个超时就 `inner.set()` 把其余收掉”的做法；外面叫停（`stop`）照旧全部停。整轮上限（`self.timeout`）到了，没开始的记超时。
- 有超时时返回 `Verdict(TIMEOUT, None, 文本)`，文本每行“文件名：结果”（现有写法），**所有文件都列出来**（跑完的、超时的都列）。
- `alone`、`base` 里每个文件也用 `self.file_timeout` 限时（不超过 `self.timeout`）。

### 2. 跑的时候代码变了就作废（`collab/judge.py`、`collab/fullrun.py`）

- `judge.py` 加 `STALE = "作废"`。
- `fullrun.py` 加一个拍“指纹”的小函数：走一遍工作区，记每个文件的相对路径、大小、修改时间（纳秒）；跳过 `_EXCLUDES` 里那些（`.git`、`node_modules`、`.collab`、`__pycache__`、`*.app`、`.venv`、`venv`）和 `*.pyc`。
- `FullRunner.run`：复制副本**之前**拍一次，全部测试跑完**之后**再拍一次；两次不一样 → 返回 `Verdict(STALE, None, "跑的时候代码变了，这次结果作废，要重新跑一遍全部测试")`（不管测试本身过没过）。被叫停的照旧返回“停了”。
- `_merge` 里结果排序把“作废”放进去（排在“停了”后面、“超时”前面），别的地方用到结果的**不用改**：它们都只看是不是“过”。

### 3. 统一用开发助手自己的 Python（`collab/fullrun.py`）

- 加 `app_python() -> str`：
  1. 环境变量 `COLLAB_PYTHON` 不为空、指向能执行的文件 → 用它；
  2. 否则用登录环境找 python3：`/bin/zsh -lc 'command -v python3'`（有时限 10 秒，拿到的路径能执行才算），结果在本进程里记住，下次不再找；
  3. 都拿不到 → `sys.executable`。
  不许抛异常。
- `_safe_bin` 里的 python3 链接改成指向 `app_python()`（`node` 不变）。

### 4. “接受剩下的问题”改成后台先跑全部测试

**新建 `collab/accept.py`**，函数 `accept_remaining(project, card_id, runner=None) -> dict`：

1. 读卡片状态和流转记录。卡片不是“需Claude介入”，或最近一条“转人工”的 `cause` 不是“复查不通过”（照 `collab/phase.py` 里认复查停下的写法，含老卡没有标记、按原话认的那种）→ 返回 `{"ok": False, "reason": "这张卡现在不能这样做。"}`，什么都不改。
2. 留档的原话：用 `collab/phase.py` 里现成的 `_stop_text(project, card_id, 最近的停下记录)`，拿不到就用 `_blocked_detail(events)`。**不要调 `card_phase`**（后台跑的时候它会显示“正在跑全部测试”，拿不到原话）。
3. 找到这张卡的施工副本（现有找副本的函数，`collab/merge.py` 或 `phase.py` 里有）。副本不在 → 记一条“接受失败”，summary：“找不到改好的版本，没法跑全部测试”，返回 ok False。
4. 副本不是 Python 测试项目（`fullrun.applicable` 为假）→ 跳过全部测试，当作过。否则用 `runner or FullRunner()` 跑 `run(副本)`。
5. 结果是“过” → 卡片转“待验收”并保存；记“接受”（src 你、dst 程序、summary“接受剩下的问题，进入待确认”、text=原话）、“结束”（src 程序、dst 你、state 待验收、summary“你接受了复查剩下的问题，全部测试也过了，等你确认放进项目”）；重画任务板；`ledger_add(project, f"{card_id}：接受复查剩下的问题，全部测试通过，进入待确认")`。返回 `{"ok": True}`。
   这一段和现在 `desktop/server.py` 里 accept_issues 做的事一样，搬过来，server 里的删掉。
6. 结果不是“过” → 卡片**不动**；记一条“接受失败”（src 程序、dst 你），summary 按结果写（都要含“全部测试”）：
   - 没过：“全部测试没过，卡片留在卡住了，先看是哪项没过”
   - 超时：“全部测试有文件超时，卡片留在卡住了”
   - 作废：“跑全部测试时代码变了，结果作废，再点一次接受”
   - 其他（跑不起来、停了）：“全部测试没跑起来，卡片留在卡住了”
   text 存全部测试的输出末尾 8000 字。返回 `{"ok": False, "reason": summary}`。

**`collab/cli.py`**：加子命令 `accept-issues <project> <card>`，调 `accept_remaining`，ok 退出码 0，否则 1，把 reason 打出来。

**`desktop/clerk/tasks.py` 的 `launch`**：kind 是 `"accept"` 时，和 run、merge 一样记一条“接受开始”（src 程序、dst 程序、summary“开始跑全部测试，全过就进待确认”、pid、started）。

**`desktop/server.py` 的 accept_issues**：
- 先照旧检查 `accept_issues` 在不在 `actions` 里，不在 → 409“这张卡现在不能这样做。”（老测试 `test_refused_when_not_stopped_by_review` 要 409）。
- 然后 `launch(project, "accept", card_id, ["accept-issues", project, card_id])`；`TaskBusy`/`OSError` → 409“正在跑全部测试，等它结束再试”。
- 返回 `{"ok": True}`，**不改卡片状态**。

**`collab/phase.py`**：
- “需Claude介入”分支最前面：后台 accept 记录（`_read_backend(project, "accept")`）是这张卡、进程活着 → 返回 `{"code": "accepting", "label": "正在跑全部测试", "tone": "run", "needs_you": False, "detail": "全过就进待确认，约几分钟", "actions": []}`（照 merging 的写法）。
- 最近一条“转人工”之后有“接受失败”：detail 后面接上它的 summary（让人知道上次点接受为什么没进去）；按钮不变，可以再点。

**`desktop/view.py`**：顶部一句话跟阶段走的那几个 code（`"dropped", "interrupted", "merging", …`）里加上 `"accepting"`。
