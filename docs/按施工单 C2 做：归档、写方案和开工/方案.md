# 拆解方案

## 要做什么（一句话）
按 C2 施工单调整卡片归档、预览和批准开工，让记录跟代码一起进项目，并在开工前提醒用户存下施工要用的文件。

## 拆成几步，每步做什么、产出什么
1. 方案获批后，先按施工单第三节对照现有验收测试，把缺的场景补到 tests/test_c2_extra.py，重点覆盖重复归档、退回时一起撤销记录、漏带文件提醒、预览找不到、只剩普通文档、施工单未存、保存失败和切卡。
2. 用本卡验收命令确认新增测试能被找到，且施工前因对应功能还没改好而失败。
3. 给归档加上写入位置和最终状态两个可选参数，在主项目查本卡引用的第一份施工单，有就归档到它旁边的“卡片记录/卡号/”，没有就沿用 docs 下的功能目录。
4. 把需求卡原文存为“卡片原文.md”，把“以后再修.md”放进过程记录，验收记录优先读最后一条“复查结论”并把“退回”写成“不通过”，老卡没有这条记录时才从旧文件读结论。
5. 把归档写出的相对路径记进“归档文件.json”，重跑时覆盖本卡已写的文件、按旧规则避开其他卡同名文件，专属卡号目录直接覆盖，只有直接写到主项目时才当场记归档和台账。
6. 在放进项目流程确认有改动之后、暂存之前，把最终状态为“已放进项目”的记录写进副本，按归档清单和代码一起暂存、提交并纳入范围检查，归档出错则记下原因后继续放代码。
7. 把归档流转和台账移到放进项目成功后再记并写明真实相对路径，测试失败退回时让记录跟代码一起撤回。
8. 找出副本里有改动却没选进提交的文件，排除内部目录、依赖、缓存和密钥文件，成功后在“合并”前写一条提醒，摘要最多列五个文件，详情列全。
9. 在写方案的提示里要求先查真实的网页启动入口和路由，确认不了时把启动命令和地址都留空。
10. 在预览程序启动后的等待里识别 404 和 410，遇到就结束预览并提示可以打开文件夹，其他回应沿用原来的处理。
11. 在 collab/dispatch.py 只新增 files_to_save，最多等 Git 五秒，取改名后的新路径，排除 .collab/、普通 Markdown 和 docs 下的普通文件，把本卡引用且有改动的施工单算进去并返回排好序的清单，Git 查询失败就返回空清单。
12. 让查未存文件的接口校验传来的卡号并返回文件数和清单，新增要口令的保存接口，在服务器重算清单并只提交这些文件，空清单直接成功，提交失败就撤回本次暂存并返回 409 和最多两百字的失败原因，卡片状态留给原开工流程处理。
13. 把原来的浏览器确认框换成默认隐藏的三按钮小框，按施工单补上可供测试调用的提示文字，文件最多显示十个，切卡就关框。
14. 点批准时带卡号查未存文件，清单为空或查询失败就直接开工，有文件就显示小框，按三种选择分别处理保存成功后开工、直接开工和关闭不动，保存失败就在框里显示原因，开工始终用点击时的卡号。
15. 完工后跑本卡验收命令，旧测试如果有失败就如实报出哪一项，由程序在复查时跑全部测试。

## 你会看到什么结果
放进项目后，可以在施工单旁的“卡片记录/卡号/”里看到卡片原文、方案、验收和过程记录，卡片没有引用施工单时就到 docs 下的卡片标题文件夹找。独立复查显示实际结论，副本里有文件没带进项目时会看到提醒。预览找不到页面时会提示可以打开文件夹。批准开工时，只有代码或本卡引用的施工单还没存进项目才会弹出三个选项，普通文档有改动时直接开工。

## 明确不做什么
不改现有 C2 验收测试和施工单第五节列的老测试，不改复查规矩、命令行开工、预览端口占用检查、已归档的老记录、右栏和现有措辞，也不重做已经完成的方案第 8 条或增加施工单之外的功能。

## 需要你确认的问题
无

## 做完后怎么看结果
点按钮打开本机任务面板，选一张等着批准的测试卡，点“批准并开工”，看看未存文件清单、三个按钮和保存失败时的提示。再用只有普通文档改动的测试项目确认会直接开工，最后用预览地址找不到的测试卡确认页面会提示可以点“打开文件夹”。
