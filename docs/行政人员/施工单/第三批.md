## 30 服务商清单，每家各存一把密钥

**验收测试：** `tests/test_acceptance_30_providers.py`

**改动文件：** 新建 `collab/providers.py`、新建 `desktop/clerk/providers.py`、`desktop/server.py`、`desktop/mac/Sources/SuperAgent/main.swift`

**约定：**

- 清单放在 `collab/providers.py`，`desktop/clerk/providers.py` 只转出 `PROVIDERS`、`find`、`account_for`。协作包不能依赖 `desktop`，地址和模型名在 `collab/providers.py` 里直接写。
- 每项有 `id`、`name`、`base_url`、`models`、`thinking_off`。`name` 分别是“腾讯云”“阿里百炼”“其他”。
- `account_for(provider, base_url)`：腾讯云 `tencent`，百炼 `bailian`，其他 `other:<小写域名>`。地址不对或服务商不存在：`ValueError`。
- `GET /api/clerk/providers` 返回 `{"providers": [...]}`，要口令。
- `ClerkKey` 按账号存取：`read(account:)`、`save(_:account:)`、`delete(account:)`。
- `ClerkKey.migrateOldKey`：旧账号 `api-key` 有密钥时，按旧的 `clerkBaseURL` 判断归哪家（没有或腾讯云地址算 `tencent`，百炼地址算 `bailian`，其余算 `other:<域名>`）。存好再删旧账号，存失败不删。启动时在 `clerkReady = savedClerkKey() != nil` 之前调用。
- 保留 `.selftest` 钥匙串服务名和 `--clerk-key-file`，自测不能碰用户的钥匙串。

## 31 每个项目各一份设置

**验收测试：** `tests/test_acceptance_31_project_setting.py`

**改动文件：** `collab/config.py`、`desktop/server.py`、`desktop/mac/Sources/SuperAgent/main.swift`

**约定：**

- `load_clerk(project) -> dict | None`，`save_clerk(project, setting)` 写 `.collab/配置.json` 的 `clerk`，其他设置原样保留。只存 `provider`、`base_url`、`model`，以及 `disabled`（为真时才写）。**传进来的其他字段一律丢掉。** 腾讯云和百炼的地址以清单为准，“其他”必须是 http(s) 地址。不对就抛 `ConfigError`，旧设置不变。
- `POST /api/clerk/setting`、`GET /api/clerk/setting?project=` 返回 `{"setting": ...}`，要口令。
- 本机服务仍只有一个 `server.clerk`。不要改成多连接，也不要改 `ClerkDesk` 的用法。窗口同时只开一个项目，切项目时换连接。
- 新增 `server.clerk_project`。`/api/clerk/config` 带 `project` 时记下；`/api/clerk/clear` 清空。值不是空且和请求的项目不同时，`/api/clerk/send` 回 409，原因用大白话，不调用模型。值为空时不拦（旧测试直接设 `server.clerk`）。
- 窗口取设置的顺序：项目的 `clerk`（`disabled` 时算没配）→ 最近一次用过的（`UserDefaults` 的 `clerkLastProvider`、`clerkBaseURL`、`clerkModel`）→ 腾讯云默认。窗口启动时本机服务还没起来，直接读 JSON 文件。
- `savedClerkKey()` 按当前项目的设置取对应账号的密钥。保留 `clerkReady = savedClerkKey() != nil` 这一行。
- `func applyClerkSetting(then:)`：算出 `clerkReady`，有密钥就发 `/api/clerk/config`（`clerkForm` 带 `project`、`provider`、`base_url`、`model`、`api_key`），没有就发 `/api/clerk/clear`，完成后调用 `then`。`switchTo` 在 `project = url` 之后调用，等它完成后再 `showLeft(firstLeft()`。
- 切项目时正在回复的一轮继续用它开始时的连接，这是现状，不用改。

## 33 设置页第一行和保存流程

**验收测试：** `tests/test_acceptance_33_team_row.py`

**改动文件：** `desktop/static/team.html`、`desktop/static/team.js`、`desktop/static/team.css`、`desktop/mac/Sources/SuperAgent/main.swift`

**页面：**

- 行政是表格第一行，`data-role="clerk"`，样子和下面四行一致，去掉旧的“行政人员（可选）”区块。
- 控件：服务商下拉 `clerkProvider`；模型输入框 `clerkModel` 配 `<datalist id="clerkModels">`，能选也能手填；选“其他”才显示地址框 `clerkAddress`，并提示“这家不会关闭模型思考，可能更费钱”；状态；检测 `clerkCheck`。
- 行下面放三个小按钮：更换密钥 `clerkKey`、停用 `clerkClear`、删除这一家的密钥 `clerkForget`。
- 页面只知道服务商、地址、模型，不碰密钥。

**窗口地址：**

- `superagent://clerk-apply?provider=&base_url=&model=` 调 `func applyClerkChoice`。
- `superagent://clerk-check?...` 只测试，不保存。这一家没有密钥时先弹框要。
- `superagent://clerk-setup?...` 弹框换这一家的密钥：测试通过才存，失败留在弹框显示原因。沿用现有 `askClerk` 的非阻塞弹层，弹框只留密钥输入框。
- `superagent://clerk-clear` 停用当前项目：设置写 `disabled: true`，发 `/api/clerk/clear`，聊天改回调度员。**不删密钥。**
- `superagent://clerk-forget?...` 确认后只删这一家的密钥。当前项目正在用这一家时，同时按没有配置处理。

**“保存并返回对话”：**

1. 行政这一行没变：跳过 2–5，直接存团队。
2. 变了：页面发 `clerk-apply`，等窗口用 `window.SuperAgentTeam.clerkResult(ok, 原因)` 回话。
3. `applyClerkChoice`：这一家没有密钥就弹框要。第一次换到这一家（`UserDefaults` 的 `clerkWarned` 记过的不再问）先提醒：“这个项目的聊天记录和项目信息会发给<服务商>。”
4. 发 `/api/clerk/test`。通过才存密钥、发 `/api/clerk/setting`、记最近一次设置、发 `/api/clerk/config`。
5. 失败或取消：回 `clerkResult(false, 原因)`，留在设置页显示原因，旧设置和连接都不变，团队也不保存。
6. 成功后存团队，再走现有的 `superagent://saved`。

**不改：** 其他四行的行为和检测。
