## 45 行政模式删除对话

**验收测试：** `tests/test_acceptance_45_delete_clerk.py`

**改动文件：** `desktop/clerk/desk.py`、`desktop/clerk/tasks.py`、`desktop/server.py`、`desktop/static/nav.js`、`desktop/static/nav.css`、`desktop/static/chat.js`、`desktop/mac/Sources/SuperAgent/main.swift`

**约定：**

- `ClerkDesk.delete(project, cid)`：
  - 编号不合规、对话文件不存在、或是卡片自己的对话（索引里有 `card`）：`LookupError("这段对话已经不在了")`。
  - 正在回复：`RuntimeError`，文字含“还在回复”。
  - 顺序不能乱：先作废没确认的提议，再从内存移除已打开的对话并清掉当前标记，然后删对话文件，**最后**删索引。`_load_index` 会从对话文件把缺的条目补回来，所以文件删失败时不能先动索引。
  - 内存里那份不移除，之后的通知会把文件写回来。这是这张单最大的坑。
- 作废提议放在 `tasks.py`，走 `decide(..., "cancel")`，不要另写一套。已确认的提议和它建的卡不动。
- `desk.list` 每段对话多两项：`busy`（正在回复）、`pending`（有没确认的提议）。一次列表只扫一遍提议文件夹，不要每段对话扫一遍。
- `POST /api/clerk/delete`，内容 `{project, conversation}`：成功 `{"ok": true}`；项目不存在 400；`LookupError` 404；`RuntimeError` 和文件错误 409。
- `NavCore` 加三条规则（页面规则都放这里）：
  - `canDelete(thread, cached)`：列表是上次记住的、或正在回复，都不能删。
  - `deleteConfirm(thread, clerk)`：基础文字“删除这段对话？删除后找不回来，已提出的任务不受影响。”。非行政模式加“Codex 里的这段记录也会一起删除。”；`pending` 加“里面还有一个没确认的提议，会一起作废。”。
  - `withoutDeleted(threads, deleted)`：把删过的从列表滤掉。
- `nav.js`：
  - 每行结构改成外层 `div.row` 里并排两个按钮：原来的 `button.thread`，加 `button.rowact`（`data-delete`，`aria-label` 和 `title` 都是“删除这段对话”，垃圾桶图标）。按钮里不能再放按钮。这段写在 `drawThreads` 拼接这一行的地方，紧跟在 `button.thread` 的 `</button>` 后面，测试按这个顺序查。图标可以放变量。
  - 鼠标移上或键盘切到这一行才显示图标，同时藏起时间。`canDelete` 为假的行不放这个按钮。
  - 要记住 `fetchThreads` 回来的 `cached`。
  - 点图标：`window.confirm(NavCore.deleteConfirm(...))`，确认后发请求。行政模式走 `/api/clerk/delete`，否则走 46 号单的 `/api/chat/delete`。请求头带 `X-Chat-Token`，写法和 `chat.js` 的 `api` 一样。
  - 成功：记进已删除名单，从列表去掉，重画，`tell("superagent://thread-deleted?id=...")`。之后 `fetchThreads` 回来的列表都过一遍 `withoutDeleted`，防止旧回答把它带回来。`pendingThread` 是它时要清掉。
  - 失败：`window.alert` 显示服务返回的文字，列表不动。
  - 列表内容没变就不重画（和卡片的 `lastKey` 一样，键里要有 `busy`、`pending`、`current`）。否则每 1.5 秒重画一次，点图标会点空。
- `nav.css`：加 `.row`、`.rowact`。悬停 120 毫秒，沿用 `--t-fast`，不引入新颜色。
- `main.swift`：`superagent://` 加 `case "thread-deleted":`，调用 `window.SuperAgentChat && window.SuperAgentChat.threadDeleted(id)`（用 `jsValue`），再 `refreshNavThreads()`。
- `chat.js`：`SuperAgentChat.threadDeleted(id)`：
  - 行政模式：`mainThread` 是它就清空；没在看卡片且 `currentThread` 是它，就 `clerkOpen(null)`。正在看卡片时不打断。
  - 其他模式：`currentThread` 是它就 `switchSession("fresh", true, null)`，和“新对话”一样。

## 46 Codex 模式删除对话

**验收测试：** `tests/test_acceptance_46_delete_codex.py`

**改动文件：** `desktop/dispatchers/codex.py`、`desktop/chat.py`、`desktop/server.py`

**约定：**

- `CodexDispatcher.delete_thread(thread_id)`：发 `thread/delete`，内容 `{"threadId": thread_id}`。真实 Codex 0.167.0 已试过：对话文件删除，再列就没有了。
- `ChatSession.delete_thread(thread_id)`：
  - 不在 `list_threads()` 结果里：`LookupError("这段对话已经不在了")`。这条保护用户在 Codex 独立客户端里的旧对话。
  - 是当前对话且正在回复：`RuntimeError`，文字含“还在回复”。
  - Codex 报错或超时：`RuntimeError("没能删除这段对话，列表没有变。可能要升级 Codex。")`，不能把 Codex 的原话给用户看。
- `ChatHub.delete_thread(project, thread_id)`：没连上时 `RuntimeError`，文字含“还没连上”。删成功后更新 `THREAD_LIST_FILE`：去掉这一条；是 `current` 就改成 `None`；**列表空了也要写**。现在 `thread_list` 只在非空时才存，不处理的话重开软件它会回来。
- `ChatHub.thread_list` 连着时，每段对话多一项 `busy`（当前对话且正在回复）。不写进存的文件；没连上时不加。
- `POST /api/chat/delete`，内容 `{project, thread_id}`：成功 `{"ok": true}`；`LookupError` 404；`RuntimeError` 沿用现有的 409。要放在 `hub.get(project)` 判断之前或用 `ChatHub.delete_thread` 的判断，文字都要含“还没连上”。

## 47 卡片归档

**验收测试：** `tests/test_acceptance_47_archive_card.py`

**改动文件：** `desktop/view.py`、`desktop/server.py`、`desktop/static/nav.js`、`desktop/static/nav.css`

**约定：**

- 归档标记是卡片文件夹里一个独立的文件 `已归档.json`。不写 `状态.json`、`流转.jsonl`、台账，也不增加卡片状态。`_updated` 看的是前两个文件，这样排序才不变。
- `desktop/view.py`：
  - `list_cards` 每张卡多一项 `archived`：有标记**并且**卡现在是结束的（`tone` 是 `done` 且 `needs_you` 为假）。要用户处理的卡不能藏着。
  - `set_archived(project, card_id, on)`：卡不存在 `LookupError`；归档时卡没结束 `RuntimeError`，文字含“结束”；取消归档随时可以；重复做不报错。
  - `card_view` 打开软件时选默认卡要跳过已归档，后面判断“最新的卡已合并”的地方也一样。`cards` 还是全部，`explicit_card` 指定已归档的卡照常能看。
- `POST /api/clerk/card/archive`，内容 `{project, card, archived}`，`archived` 为 `false` 是取消归档：成功 `{"ok": true}`；项目不存在或卡片编号不合规 400；404；409。不要走 `_do_card_action`，它会先关掉预览。
- 行政的 `list_cards` 工具不过滤。
- `NavCore` 加：
  - `archivedCards(cards)`；`cardGroups` 不含已归档；`needsYou` 不用改。
  - `canArchive(card)`：有 `phase`、没归档、`tone` 是 `done`、`needs_you` 为假。不要只认“已完成”“不做了”这两个字。
  - `showArchived(open, text)`：展开了或者正在搜索。
- `nav.js`：
  - `cardRow` 同样改成 `div.row` 里两个按钮，写在 `cardRow` 函数里，紧跟在 `button.item` 的 `</button>` 后面。可归档的卡放 `button.rowact`（`data-archive`，`aria-label` 和 `title` 是“归档”）。已归档的卡放同样位置的按钮（`data-unarchive`，“取消归档”）。
  - 列表最后加“已归档 N”折叠行，默认收起，点了展开，N 是 0 时不显示。搜索时用 `showArchived` 自动展开。
  - `drawList` 里“没有卡”“没找到”的判断保持原样。全部卡都归档了，只显示这一行。
  - 归档不确认。失败时 `window.alert` 显示服务返回的文字。
  - 成功后马上重新取一次数据重画。归档的是正在看的卡：`tell("superagent://main")`。取消归档不用跳转。
  - `poll` 里判断要不要重画的键加上 `c.archived`。
  - 已归档的卡点开照常看，`keepSelected` 不用改。

## 49 放弃时删掉改好的版本

**验收测试：** `tests/test_acceptance_49_discard_copy.py`

**改动文件：** `collab/merge.py`、`desktop/server.py`、`desktop/static/panel.js`

**约定：**

- `merge.py` 里“删副本、失败时记一条”写成一个函数，放进项目和放弃都用它。`"worktree", "remove"` 整个文件只出现一次。
- 对外给一个函数，比如 `remove_copy(project, card_id)`：副本文件夹不存在就什么都不做。分支不删，和放进项目时一样。
- `server.py` 的 `discard`：卡已存成“已放弃”、流程记录写完后再删。放弃被拒绝时不删。删失败只记一条，卡还是放弃成功。
- 放弃确认框：“这次的改动不会进入项目，你的项目不会变。改好的版本也会删除。”
- 不清理以前留下的副本。
