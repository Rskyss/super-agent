## 11 验收通过（一键合并）

**验收测试：** `tests/test_acceptance_20_merge.py`

**改动文件：** 新建 `collab/merge.py`、`collab/cli.py`、`collab/phase.py`、`desktop/clerk/tasks.py`、`desktop/server.py`、`desktop/static/panel.js`

**约定：** `collab merge <项目> <卡片>`，成功退出码 0，失败 2。核心函数 `merge_card(project, card_id) -> dict`，返回 `{"ok": bool, "reason": str}`。副本路径和 `cmd_run` 一致：`<项目>-worktrees/<卡片>`。

**步骤，顺序不能换（Claude 已用真实 git 走过）：**

1. 卡片必须是“待验收”，副本必须存在，`开工.json` 必须有测试命令。
2. 在副本里提交：
   - 文件来自 `dispatch._changed_list(副本)`。只取允许范围或 `测试文件.json` 里的文件，再去掉缓存和密钥文件。**不能用 `git add -A`。**
   - 用 `git add -- 路径` 逐个加入。提交说明写 `<卡片>：<标题>`。
   - 项目没配 git 身份时，提交加 `-c user.name=超级助手 -c user.email=super-agent@localhost`。配了就用项目自己的。
   - 既没有可提交的文件，分支也没有比主项目多的提交：停止，原因写“这张卡没有改动可以合并”。
3. 用 `git diff --name-only HEAD...card/<卡片>` 取这张卡改的文件，和主项目 `_changed_list` 比较。有重叠就停止：`你的项目里这些文件也有没提交的改动：a、b。先提交或撤销后再合并。`
4. 记下主项目当前提交和分支名。
5. 试 `git merge --ff-only card/<卡片>`。
6. 不能快进时，在副本里 `git rebase <主项目当前提交>`。有冲突就 `git rebase --abort` 并停止，原因写“和项目里新的改动有冲突”。成功后在副本里重跑测试，不过就停止。然后再快进合并。
7. 在主项目跑测试。不过就 `git reset --keep <第 4 步的提交>`，确认回到原提交后停止，原因写“合并后测试没过，已退回合并前的样子”。
8. 通过后转“已合并”，记流转 `kind="合并"`，摘要 `已合并到 <分支>`，写台账。然后调用 `archive_card`，功能名用卡片标题。归档失败只记录，不影响合并结果。
9. `git worktree remove --force <副本>`。失败只记录。分支保留。

**测试命令** 和 `cmd_run` 一样用 `["/bin/bash", "-o", "pipefail", "-c", 命令]`，复用 `collab/judge.py`。不要写第二份。

**失败时：** 状态不变，记流转 `kind="合并失败"`，`summary` 写大白话原因，工具原文放 `text`。所有意外错误都走这里，不能崩溃。

**不做：** 不推送、不打版本、不处理多人协作。

**后台运行：** `launch` 新增 `kind="merge"`，启动时记流转 `kind="合并开始"`，带 `pid`、`started`。合并不自动重试。

**阶段（都在 `card_phase` 里）：**

| code | 条件 | label | tone | needs_you | actions |
|---|---|---|---|---|---|
| `merging` | 待验收，合并进程活着 | 合并中 | run | 否 | 无 |
| `merge_failed` | 待验收，最新结果是“合并失败”，或“合并开始”后进程没了且没有结果 | 合并没成功 | bad | 是 | `accept`、`revise`、`discard` |
| `review` | 待验收，其他情况 | 等你验收 | ok | 是 | `accept`、`revise`、`discard` |

- “最新”以最后一条“结束”记录为界：重新施工后，旧的合并失败不再算数。
- `merge_failed` 的 `detail` 写原因，进程没了时写“合并中途断了，可以再试一次”。
- `review`、`merge_failed` 的结果里增加 `branch`：主项目当前分支名。

**按钮：** `accept` 写“验收通过，合并到 <branch>”。`PanelCore.actionButtons` 从 `phase.branch` 取分支名。

**动作地址：** `POST /api/clerk/card` 的 `accept` 走 `launch`。已有合并在跑时回 409：`另一张卡正在合并，等它结束再试`。

**汇报模板：**

| 阶段 | 话 |
|---|---|
| `done` | 「标题」已合并。 |
| `merge_failed` | 「标题」合并没成功：原因。 |

## 14 每卡专属对话

**验收测试：** `tests/test_acceptance_22_card_chat.py`

**用户定的规矩（2026-11-06）：** 用户只和行政说话。可以在右栏看 Codex、Cursor、agy 在干什么，但不能越级指挥它们。主对话和任务对话完全分开。

**改动文件：** `desktop/clerk/desk.py`、`desktop/clerk/tasks.py`、`desktop/clerk/tools.py`、`desktop/server.py`、`desktop/static/chat.js`、`desktop/static/chat.html`、`desktop/static/chat.css`、`desktop/mac/Sources/SuperAgent/main.swift`

**对话：**

- 对话编号：`hashlib.md5(("card:" + 卡片编号).encode()).hexdigest()`。
- `ClerkDesk.open_card(project, card_id) -> str`：创建空对话，对话索引写 `card` 和 `title`，重复调用返回同一个编号。`ClerkDesk.list` 不显示卡片对话。
- `POST /api/clerk/card/open`，内容 `{project, card}`。卡片编号不合法回 400，卡片不存在回 404。返回 `{"conversation", "title", "phase", "do", "not_do", "done_when"}`，后三项从需求卡的小标题取，没有就是空字符串。
- 第一次打开时，把 `已播报.json` 写成当前最新记录号，不把历史刷一遍。

**上下文：**

- 卡片对话的系统提示在 `ROLE` 后面加：这段对话只谈这张卡；用户只和你说话，不能直接指挥执行的工具；新任务请用户回主对话提。再带上这一轮现查的 `read_card` 结果和阶段名称。
- 工具：卡片对话去掉 `propose_task`、`propose_team_change`，加 `propose_revise(text)`。主对话没有 `propose_revise`。模型调用了当前对话没有的工具时，返回“没有这个工具”。

**`propose_revise(text)`，由程序看阶段决定，不靠模型判断：**

| 阶段 | 结果 |
|---|---|
| `revise` 可用 | 生成提议，`kind="revise"`，字段 `card`、`text`。确认后走 `apply_revise`，回复“已交给开发，做完再告诉你。”；写方案类回复“已让 Codex 重写方案。” |
| 其他 | 追加到卡片 `待转达.jsonl`，一行 `{"text", "time"}`，告诉模型“已记下，这一轮结束后给用户确认”。不生成提议，不打断施工 |

- 确认时 `apply_revise` 抛错就回 409，提议保持 `open`。
- 确认框标题“还要修改？”，内容写要改的话。
- 确认或取消后清空 `待转达.jsonl`。

**巡视（`TaskWatcher._tick_card`）：**

- `待转达.jsonl` 有内容、`revise` 可用、卡片对话已存在、没有打开的 `revise` 提议时，把内容合成一张提议。重开软件后还要在。
- 进展播报：`已播报.json` 存在时，把新记录写进卡片对话。只播 `方案`、`方案失败`、`开跑`、`判定`、`转人工`、`结束`、`停下`、`合并失败`、`合并`，内容用摘要。其他记录也要移动指针。
- 主对话的一句话汇报保持不变。卡片对话和主对话的提议互不影响。

**顺序修复：** 现在确认框会显示在模型前一句话的上面。工具循环里出示确认框之前，先把已有文字存成一条回复。之后的文字用新的 `item`。实时和重开都要是“前面的话 → 确认框 → 后面的话”。

**窗口：**

- 配了行政时点卡片：右栏换卡；`POST /api/clerk/card/open`；左边切到聊天；调用 `SuperAgentChat.openCard(info)`。
- 点主对话或历史对话：`SuperAgentChat.closeCard()`，回到之前的主对话。
- 没配行政时保持现在的行为：点卡片中间不变。

**聊天页：**

- `chat.html` 新增 `id="cardHead"` 和 `id="cardInfo"`，平时隐藏。
- `cardHead` 显示标题和阶段，每 3 秒从 `/api/cards` 更新阶段。
- `cardInfo` 显示要做什么、不做什么、怎么算做完。规则放 `ChatCore.cardInfoRows(info)`，返回 `[{label, text}]`，空的项不返回。用 `textContent`，不要拼 HTML。
