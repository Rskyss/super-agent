## 11 验收通过（一键合并）

**改动文件：** 新建 `collab/merge.py`、`collab/cli.py`、`collab/phase.py`、`desktop/clerk/tasks.py`、`desktop/server.py`、`desktop/static/panel.js`

**约定：** `collab merge <项目> <卡片>`，核心函数 `merge_card(project, card_id) -> dict`，返回 `{"ok": bool, "reason": str}`。`review` 阶段增加动作 `accept`，按钮写“验收通过，合并到 <当前分支>”。

**步骤，顺序不能换：**

1. 卡片必须是“待验收”，副本必须存在。
2. 只把 `允许改动的范围` 内的改动加入副本里的提交。**不能用 `git add -A`**：副本里可能有 `.env` 和依赖链接。
3. 比较这张卡改的文件和主项目未提交改动。有重叠就停止，原因写出文件名。
4. 记下主项目当前提交。
5. 试 `git merge --ff-only card/<卡片>`。
6. 不能快进时，在副本里 rebase 到主项目当前提交。有冲突就 `git rebase --abort` 并停止。成功后在副本里重跑 `开工.json` 的测试，不过就停止。然后再快进合并。
7. 在主项目跑测试。不过就 `git reset --keep <第 4 步的提交>`，确认主项目回到原提交后停止。
8. 通过后转“已合并”，记流转和台账，调用 `archive_card` 归档，功能名用卡片标题。
9. 清理副本：`git worktree remove`。失败只记录，不影响合并结果。分支保留。

**失败时：** 卡片保持“待验收”，记流转 `kind="合并失败"`，操作条显示原因。

**不做：** 不推送、不打版本、不处理多人协作。

后台运行：`launch` 新增 `kind="merge"`。合并期间按钮禁用。合并是用户动作，不走自动重试。

## 12 还要修改

**改动文件：** `collab/state.py`、`collab/dispatch.py`、`collab/cli.py`、`collab/phase.py`、`collab/tasks.py`、`desktop/server.py`、`desktop/static/panel.js`

**约定：**

- `state.py` 允许 `待验收 → 开发中`。
- `collab revise <项目> <卡片> --text <文字>`：
  - 需求卡追加 `## 验收后追加要求`，保留以前的内容。
  - 记流转 `kind="追加要求"`。
  - 返工次数归零。
  - 转“开发中”。
- `run_card` 判断“测试已写完”和“开发已完成”时，只看最后一条“追加要求”之后的记录。这样测试员会先补测试，开发员再改。
- 允许范围不变。新要求需要改范围外文件时，程序仍会撤销，并让用户重开一张卡。
- `review` 阶段增加动作 `revise`，按钮写“还要修改”，弹出输入框，文字不能为空。
- 地址 `POST /api/clerk/card` 增加可选字段 `text`。
- `revise` 后走 07 号单的启动方式。

## 13 排队接力

**改动文件：** `collab/phase.py`、`desktop/clerk/tasks.py`、`desktop/server.py`、`desktop/static/nav.js`、`desktop/static/panel.js`

**约定：**

- `approve` 后，如果有占位的卡，卡片停在“待派发”，显示 `queued`：label“排队中”，tone `run`，`needs_you` 否，动作 `discard`。
- **占位的卡：** 阶段是 `running`、`interrupted`、`blocked`、`review` 的卡。第二张必须等第一张合并或放弃。
- 巡视线程发现没有占位的卡时，启动最早批准的 `queued` 卡。按 `批准` 记录的时间排序。
- 启动前重新检查一次，防止重复开工。`launch` 的原子记录是最后防线。
- 开工时才从主项目当前提交建副本，所以自然基于最新代码。
- 软件没开时不接力，重开后巡视线程接上。
- 卡片的测试命令来自自己的 `开工.json`。
- 写方案不占位，排队时可以继续写下一张的方案。
- 用户放弃第一张后，下一张可以开工。
- 动作地址里的 `discard` 也要支持 `queued`。

## 14 每卡专属对话

**改动文件：** `desktop/clerk/desk.py`、`desktop/clerk/tasks.py`、`desktop/clerk/tools.py`、`desktop/server.py`、`desktop/static/chat.js`、`desktop/static/chat.html`、`desktop/static/nav.js`、`desktop/mac/Sources/SuperAgent/main.swift`、`collab/tasks.py`

**对话：**

- 卡片对话编号：`hashlib.md5(("card:" + 卡片编号).encode()).hexdigest()`。
- 对话索引字段 `card` 标记。`ClerkDesk.list` 不显示卡片对话。
- 新地址 `POST /api/clerk/card/open`，内容 `{project, card}`，返回 `{"conversation": "..."}`，这个地址可以创建空对话。

**窗口：**

- 点卡片时，右栏换卡，中间调用 `SuperAgentChat.openCard(id, conversation)`。
- 点主对话或历史对话，回到原来的行政对话。
- 没配密钥时保持现在的行为：点卡片中间不变。
- 聊天页顶部显示卡片标题和阶段。

**进展播报：**

- 巡视线程把新的流转记录写进卡片对话，只播报 `开跑`、`判定`、`转人工`、`结束`、`停下`，用记录里的摘要。
- 记录到哪一条存在 `已播报.json`。
- 第一次打开已有卡时，不把全部历史刷一遍，只显示阶段。

**发话：**

| 阶段 | 用户发话后 |
|---|---|
| `planning`、`running` | 写入 `待转达.jsonl`，回复固定文字“已记下，这一轮结束后处理。”，不调用模型 |
| `review` | 行政回复，上下文带上 `read_card` 的结果；需要修改时调用 `propose_revise(text)` |
| 其他 | 行政回复，上下文带上 `read_card` 的结果 |

- `propose_revise` 用 05 号单的提议机制，`kind` 是 `revise`，确认后走 12 号单。
- 施工结束且 `待转达.jsonl` 有内容时，自动生成一张 `revise` 提议，内容是用户记下的话。用户确认后才处理。确认或取消后清空。
- `待转达` 的内容不能丢：软件重开后还要在。
- 主对话和卡片对话的提议互不影响。
