## R1 写方案能用，而且绝不白烧额度

**真实问题：** 输出格式不全，真实 Codex 直接拒绝，写方案 100% 失败。程序崩溃时没有失败记录，巡视线程会反复重跑（假工具 6 秒 11 次）。

**输出格式（`collab/planner.py`）：**

- 写完整：`type`、`properties`、`required`、`additionalProperties: false`。文本字段是 `string`；`steps`、`questions`、`allowed` 是字符串数组。八个字段都必填。

**校验：**

- 字段类型不对算失败，不许崩溃。`plan_card` 对所有意外错误都要记 `方案失败`，返回 2。
- `test_command` 要能被 `shlex.split` 解析，否则算失败。
- `allowed` 不能是 `*`、`**`，不能用通配符去匹配隐藏的敏感文件，任何一段不能以 `.env`、`.git` 开头，也不能是 `.collab`。`src/*.py`、`src/` 是合法写法。

**失败原因：** 摘要是大白话，不写工具原文。工具原文放进这条记录的 `text`。

| 情况 | 摘要 |
|---|---|
| 没找到 Codex | 这台电脑上没有找到 Codex，先安装或登录 |
| Codex 非零退出 | Codex 没有写成方案，详细原因记在这张卡的记录里 |
| 超时 | 保持现有文字 |

**提示词：** 第一句改成“你可以用只读命令查看项目，但不要修改任何文件。”

**不重跑（`collab/phase.py`、`desktop/clerk/tasks.py`）：**

- `launch(kind="plan")` 启动成功后，由 `launch` 记流转 `kind="写方案"`，带 `pid`。
- `card_phase` 必须是只读的，不许删除任何文件。清理过期记录只放在 `running()` 里。
- 判断顺序：
  1. 写方案进程活着：`planning`。
  2. 最新结果是 `方案`，且内容齐全：`plan_ready`，无论 `plan.json` 有没有残留。
  3. 最新结果是 `方案失败`：`plan_failed`。
  4. 有 `写方案` 记录或残留的 `plan.json`，进程没了，之后没有结果：`plan_failed`，原因“写方案中途断了，可以重写”。
  5. 其余：`plan_waiting`。
- 每次看到的结果要一致，不许第一次失败、第二次变成等待。
- 只有 `plan_waiting` 才能自动启动。

**项目说明不能覆盖用户内容：**

- 文件不存在，或内容和 `PROFILE_TEMPLATE` 完全相同，才让 Codex 写。
- 用户已经写过一部分时，`need_profile` 为假，绝不改这个文件。批准时沿用现有的“还有空白”提示。

## R2 判定不能被骗

**真实问题：**

- 方案的允许范围没写测试文件时，测试员写的测试会被当成越界删除，然后旧测试通过，卡片假通过。
- `true && false` 判“过”，因为命令没有经过命令行解释。
- 用户批准的方案没有交给干活的人。
- 复查不通过后点“接着跑”，开发员不改，只是再查一遍。

**测试文件（`collab/dispatch.py`）：**

- 测试员交活后，把这一步新增或改动的文件记到卡片 `测试文件.json`。
- 开发员阶段的范围检查，允许范围加上这些文件。
- 断点续跑时从 `测试文件.json` 读回。
- 开发员改动范围外的文件，仍然撤销。

**范围规则（`collab/scope.py`）：**

- `src/` 和 `src` 都表示这个目录下的全部内容。`srcx/a.py` 不算在内。
- `.env`、`.env.*`、`.git/` 下的文件，在任何目录下都算越界，`*` 也放行不了。

**测试命令（`collab/cli.py`）：**

- 判定和页面检查都用 `["/bin/sh", "-c", 命令]`，不再用 `shlex.split`。
- 退出码 127（找不到命令）算“环境错误”，不算开发员的错。改 `collab/judge.py`。

**方案交给所有人（`collab/dispatch.py`）：** 测试员、开发员、复查员的派活文字都写明方案文件路径，并要求按它做，尤其是“明确不做什么”。

**复查不通过后接着跑：**

- 上一次复查结论是“不通过”时，开发员必须重新改。派活文字带上复查意见。
- 复查员没给结论时，只重新复查，开发员不重做。
- 返工次数不增加。

## R3 开工和停下要可靠

**真实问题：** 开工失败后卡片停在“准备开工”，没有按钮。停下点两次，工具留在后台继续跑。停下可能杀错卡。PID 被别的程序占用时判断错误。Cursor 干完留下空闲进程，每次约 50MB。

**新增阶段 `start_failed`：**

| code | 条件 | label | tone | needs_you | actions |
|---|---|---|---|---|---|
| `start_failed` | 待派发，后台记录或 `开工` 记录显示启动过，进程已没了 | 开工失败 | bad | 是 | `resume`、`discard` |

- `launch(kind="run")` 记流转 `kind="开工"`，带 `pid`。
- `ready` 只表示刚批准、进程还活着。
- `approve` 成功但 `launch` 失败时，也要记录，显示开工失败。
- 汇报模板：`「标题」开工失败，可以点卡片接着跑，或者不做了。`
- `resume` 在这个阶段按普通开工启动。

**进程判断（`collab/phase.py`）：**

- 新增 `process_start(pid) -> str`：用 `ps -o lstart= -p <pid>` 读启动时间，读不到返回空字符串。
- `process_is_alive(pid, started=None)`：给了 `started` 时，启动时间不一致算没活着。
- `.collab/后台/*.json` 和 `开跑`、`写方案`、`开工` 记录都写 `started`。旧记录没有这个字段时只看 PID。
- 全项目只留这一个判活函数。删掉 `desktop/clerk/tasks.py` 的 `_pid_alive`。

**停下：**

- 只停这张卡。后台记录不是这张卡时回 409：`这张卡不是从这里开工的，请到终端里停`。这时不记“停下”。
- `collab run` 第一次收到结束信号后忽略后续信号，确保能走完收尾。
- 工具不响应结束信号时，强制结束工具后再退出。等待 `collab run` 的时间放宽到 8 秒，保证工具先被处理。
- 所有等待循环都要有上限。
- 同一张卡正在停时，第二次请求直接回成功，不再发信号。

**工具收尾（`collab/agents.py`）：** `watched_runner` 无论工具是否正常结束，都要清理它的进程组。先温和结束，再强制结束。

**耐用性：**

- `Card.save` 写临时文件后替换，不留半截文件。
- 巡视时每张卡单独捕获错误，一张坏卡不影响后面的卡。
- `list_cards` 跳过读不出来的卡。
- 建卡编号要跳过所有已存在的 `CARD-NNN` 目录，空目录也算。
- `launch` 启动子进程时去掉环境变量 `SUPERAGENT_CHAT_TOKEN`。
