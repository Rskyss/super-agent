## 01 复查员失败不算通过

**现状：** `collab/dispatch.py` 只判断复查内容里有没有“结论：不通过”。复查员报错、超时或没写结论时，卡片仍进入“待验收”。

**改动文件：** `collab/dispatch.py`

**约定：**

- 新增 `review_verdict(text: str) -> str`，返回 `"pass"`、`"reject"`、`"unclear"`。
- 用 `结论[:：]\s*(不通过|通过)` 匹配。出现“不通过”就是 `reject`；只有“通过”才是 `pass`；其他是 `unclear`。
- `review.ok` 为假，或结论是 `unclear`：调用 `_escalate`，原因写“复查员（工具名）没有给出结论，不能算通过”，返回。
- `reject` 保持现有行为。
- 复查结果仍写入 `复查结果.md`。

## 06 写方案、批准和不做了

**改动文件：** 新建 `collab/planner.py`、新建 `collab/phase.py`、`collab/tasks.py`、`collab/state.py`、`collab/cli.py`、`collab/flow.py`（只在需要时）、`desktop/clerk/tasks.py`、`desktop/server.py`、`desktop/view.py`、`desktop/static/panel.html`、`desktop/static/panel.js`、`desktop/static/panel.css`、`desktop/static/nav.js`、`desktop/mac/Sources/SuperAgent/main.swift`

### 命令 `collab plan <项目> <卡片>`

运行：

```text
codex exec --skip-git-repo-check -s read-only -m <模型> -c model_reasoning_effort="<强度>" --output-schema <临时文件> -o <临时文件> <提示词>
```

- **必须** `stdin=subprocess.DEVNULL`，否则 Codex 会一直等输入。
- 工作目录是项目。超时 15 分钟。模型和强度来自 `load_models`。
- 输出格式字段全部必填：

```json
{"summary": "", "steps": [""], "result": "", "not_do": "", "questions": [""], "allowed": [""], "test_command": "", "profile": ""}
```

- `profile`：已有项目说明时填空字符串；没有时按 `PROFILE_TEMPLATE` 的项目填写。
- 提示词要求：只读；按需求卡写大白话方案；`allowed` 尽量窄；问题要带推荐答案，没有问题时 `questions` 为空。

**校验，不通过都算失败：**

- JSON 能解析，`summary`、`test_command` 不为空，`allowed` 不为空。
- `allowed` 不能是绝对路径，不能含 `..`，不能指向 `.git`、`.env`、`.collab`。
- 需要项目说明时，`profile` 不为空且没有“（待填）”。

**成功后由程序写入：**

- 卡片 `方案.md`：沿用 `PLAN_TEMPLATE` 的五个标题，不留“（待填）”。没有问题时写“无”。
- 需求卡 `## 允许改动的范围`：已有就替换，没有就追加，逐行 `- 路径`。
- 卡片 `开工.json`：`{"test_command": "..."}`。
- 需要时写 `docs/项目说明.md`，并在流转记录里标记 `new_profile: true`。
- 流转记录 `kind="方案"`，`src="Codex"`，`dst="你"`，摘要用 `summary`。

**失败时：** 流转记录 `kind="方案失败"`，摘要写大白话原因，退出码 2。不留下半截文件。

### 后台任务

`desktop/clerk/tasks.py` 新增：

```python
def launch(project, kind, card_id, args) -> int
def running(project, kind) -> dict | None
```

- `kind`：`plan` 或 `run`。
- 记录文件：`.collab/后台/<kind>.json`，内容 `{"card": "", "pid": 0, "time": 0}`。
- 用原子创建防止同时启动两个，已有同类任务在跑时抛 `TaskBusy`。记录存在但进程已死，视为空闲。
- `running` 返回记录内容；空闲返回 `None`。
- 启动：`subprocess.Popen([sys.executable, "-B", collab目录, *args], start_new_session=True, stdin=DEVNULL)`。输出写入卡片 `后台输出.log`。
- 启动后要有线程等它结束（`proc.wait()`）。否则结束的任务会留下僵尸记录，服务还开着时一直被当成“在跑”。
- 05 号单的确认成功后，自动 `launch(plan)`。已有方案在写时，卡片显示“等待写方案”，不报错；空闲时由 08 号单的巡视线程补上。

### 卡片阶段 `collab/phase.py`

```python
def card_phase(project, card_id) -> dict
```

返回 `{"code", "label", "tone", "needs_you", "detail", "actions"}`。

| code | 条件 | label | tone | needs_you | actions |
|---|---|---|---|---|---|
| `planning` | 待对齐，写方案进程活着 | 写方案中 | run | 否 | 无 |
| `plan_waiting` | 待对齐，没有方案，也没有失败 | 等待写方案 | run | 否 | 无 |
| `plan_failed` | 待对齐，最新记录是方案失败，或写方案进程没了且没有结果 | 方案没写成 | bad | 是 | `replan`、`discard` |
| `plan_ready` | 待对齐，有“方案”记录，方案和范围齐全 | 等你批准方案 | wait | 是 | `approve`、`discard` |
| `ready` | 待派发 | 准备开工 | run | 否 | 无 |
| `running` | 开发中、待测试、测试中，且施工进程活着 | 进行中 | run | 否 | `stop` |
| `interrupted` | 开发中、待测试、测试中，进程没了 | 中断了 | bad | 是 | `resume`、`discard` |
| `blocked` | 需Claude介入 | 卡住了 | bad | 是 | `resume`、`discard` |
| `review` | 待验收 | 等你验收 | ok | 是 | 无（第二批加） |
| `done` | 已合并 | 已完成 | done | 否 | 无 |
| `dropped` | 已放弃 | 不做了 | done | 否 | 无 |

- `detail`：卡住或失败时写最近的原因。
- 判断进程要用 `.collab/后台/` 记录和 `开跑` 记录里的 `pid`，复用同一个判活函数，不要写第二份。
- 不接入 `tasks.py` 的旧卡片也要能算出阶段。

## 07 后台开工、接着跑、停下

**改动文件：** `collab/cli.py`、`collab/agents.py`、`collab/phase.py`、`desktop/clerk/tasks.py`、`desktop/server.py`

**开工：**

- `approve` 成功后，读取 `开工.json`，`launch(run)`：`run <项目> <卡片> --test-command <命令>`。
- 已有卡在施工：不开工，回 409“已有一张卡在施工，等它做完再开工”，卡片保持可批准。批准失败不能把状态改了一半：先检查，再批准。

**接着跑：**

- `collab run` 新增 `--resume-blocked`。卡片是“需Claude介入”时，转“开发中”后继续。不带这个参数时行为不变。
- `resume` 动作用它启动。中断的卡直接用现有断点续跑。
- 不自动重跑。

**停下：**

- `stop` 动作给施工进程发 `SIGTERM`。5 秒后还活着就发 `SIGKILL`。
- 工具是单独成组启动的，所以 `collab run` 收到 `SIGTERM` 时必须连带停掉正在运行的工具。
- 记流转 `kind="停下"`。卡片之后显示“中断了”。

**不要白等：** `collab/agents.py` 的 `watched_runner` 现在用 `time.sleep(poll)`，工具早结束也要等满 15 秒。改成 `proc.wait(timeout=poll)`，结束就马上继续。看门人的判断不变。

**退出软件：**

- 窗口退出和本机服务退出都不能影响施工进程。
- 重新打开后，`card_phase` 按进程真实情况显示。

- `propose_team_change(role, tool)`：`role` 是 `dispatcher`、`tester`、`developer`、`reviewer`；`tool` 是 `codex`、`cursor`、`agy`，复查还可以是 `none`。

**约定：**

- 复用 05 号单的提议机制，`kind` 是 `team`，字段 `role`、`tool`、`before`。
- 确认框标题“改团队设置？”，写“写代码：Cursor → Codex”。
- 确认后用 `load_team` 和 `save_team`，不直接写文件。
- 工具不存在或值不合法：把 `ConfigError` 的话告诉用户。
- 不运行连通检测。行政只能提醒用户去设置页点“检测”。
- `ROLE` 增加：团队没配好时，可以带用户一项一项配。
