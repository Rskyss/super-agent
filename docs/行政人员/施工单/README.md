## 分支和提交

## 红线

- **不改测试：** `tests/test_acceptance_*.py` 和 `tests/acceptance_helpers.py` 是验收标准，不许修改、跳过或删除。旧测试也不许放宽。唯一例外见 06 号单。
- **测试不合理，或者要过测试就得改单子以外的东西：** 必须停下，写进回执，告诉用户。不准绕过测试，不准顺手改产品规则，不准放宽旧测试。第一批已经出过三次这种问题：绕开 `.start(` 检查、改掉三处弹窗、删掉自动重试。
- **只改单上列出的文件。** 确实需要改别的文件，先停下说明。
- **不新增依赖。** Python 只用标准库，并兼容 3.9。页面不引入框架。
- **不花真实额度。** 用 `tests/fake_model_server.py`、`tests/fake_codex_app_server.py` 或假命令，不调用真实模型、Codex、Cursor、agy。
- **密钥：** 不读、不打印、不写入 `.env` 和钥匙串内容；不进代码、日志、模型上下文。
- **用户可见文字用大白话：** 中文，不说“接口、进程、线程、报错码”。
- **不做单上没写的事：** 不顺手重构，不改界面风格。
- **同一个问题试两次不过：** 换方法。第三次还不过就停下，在回执写清卡在哪。
- **不许假装完成：** 没跑的写“未跑”，失败的贴原文。

## 架构约定

- **同一件事只写一处。** 项目吃过“各写一套、修一处坏一处”的亏。
- **卡片现在处于什么阶段，只由 `collab/phase.py` 计算。** 页面、按钮、汇报、排队都用它，不许自己推断。
- **模型只能提议。** 确认由页面发给本机服务，不经过模型。
- **后台任务脱离窗口运行。** 不要用服务里的线程跑施工。
- **页面规则放进可测试的 `NavCore`、`ChatCore`，** 延续现有写法。
- **所有带动作的地址都要校验口令，** 延续 `_chat_allowed`。
