# 需求共识：行政人员（第一期）

状态：用户已确认方向和四项选择，2026-11-06。

## 为什么做

现在聊天窗口直接连 Codex。Codex 是开发工具，拿来聊天太重：切换要等连接、会抢对话，一句“你好啊”累计用了约 18 万 token。

行政人员是超级助手的前台和行政。你只跟它打交道：它走 API 聊天，确认有任务后才派给 Codex。

## 用户已确认

1. 行政人员由 API 模型担任，默认用腾讯云 `deepseek/deepseek-flash`，以后可换模型。
2. 第一期做聊天和派活：闲聊、查进度、解释报错、判断任务、弹“变成任务？”、确认后派给 Codex。
3. 行政能读项目说明、台账、卡片和设置。改团队设置、生成卡片前先问用户。它不能改代码，不能运行命令。
4. 新聊天默认找行政。旧 Codex 对话放单独分组，只能查看，想继续就用终端。
5. 第一次打开时，第一屏填一次密钥，存在本机钥匙串，不进项目文件。
6. 可以新开很多段对话，切换不用等。只有确认任务后才启动 Codex，后台运行，干完退出，不打开终端。
7. 自动给对话起名由行政负责。
8. 流程先后、派给谁、同时跑几张卡由程序决定，行政只提议。

## 这期不做

- 多张卡同时跑。一个项目仍然一次只跑一张，多的等下一期排队。
- 用行政替代 Codex 写方案或写代码。
- 让 Cursor、agy 也当行政。
- 把旧 Codex 对话搬进行政对话。
- 验收后的“一键合并”按钮。合并仍由你用终端让 Codex 做。

## 怎么算通过

1. 第一次打开，填好密钥后就能和行政聊天；密钥不出现在任何项目文件里。
2. 闲聊和问进度不启动 Codex。
3. 新开、切换对话不用等连接，已有内容马上显示；重开软件后对话还在。
4. 问进度时，行政的回答和卡片记录一致。
5. 说一个开发需求，弹出“变成任务？”，写清要做什么、不做什么；闲聊不弹。
6. 取消就不生成卡片；确认后生成卡片，方案批准后 Codex 才开工。
7. 派活过程在卡片里看得到，完成或失败时行政会汇报。
8. 让行政改团队设置时先确认；它无法改代码或运行命令。
9. 断网、密钥错误、额度用完时，有大白话提示，已写的话不丢。
10. 全部自动测试通过，并在真实窗口用真实模型走完一遍。
