# 需求共识：行政人员（第一期）

状态：用户已确认方向和四项选择，2026-11-06；同日修订并批准，见文末“修订”。

## 为什么做

现在聊天窗口直接连 Codex。Codex 是开发工具，拿来聊天太重：切换要等连接、会抢对话，一句“你好啊”累计用了约 18 万 token。

行政人员是超级助手的前台和行政。你只跟它打交道：它走 API 聊天，确认有任务后才派给 Codex。

## 用户已确认

1. 行政人员由 API 模型担任，默认用腾讯云 `deepseek/deepseek-flash`，以后可换模型。
2. 第一期做聊天和派活：闲聊、查进度、解释报错、判断任务、弹“变成任务？”、确认后派给 Codex。
3. 行政能读项目说明、台账、卡片和设置。改团队设置、生成卡片前先问用户。它不能改代码，不能运行命令。
4. 新聊天默认找行政。~~旧 Codex 对话放单独分组，只能查看，想继续就用终端。~~（2026-11-06 用户决定去掉这一组，记录仍在 Codex 里，想继续就用终端。）
5. ~~第一次打开时，第一屏填一次密钥~~（已修订：不弹第一屏，密钥入口放进设置）。密钥存在本机钥匙串，不进项目文件。
6. 可以新开很多段对话，切换不用等。只有确认任务后才启动 Codex，后台运行，干完退出，不打开终端。
7. 自动给对话起名由行政负责。
8. 流程先后、派给谁、同时跑几张卡由程序决定，行政只提议。

## 这期不做

- 多张卡同时跑。一个项目一次只跑一张；第二批做排队，上一张合并后下一张才开工。
- 用行政替代 Codex 写方案或写代码。
- 让 Cursor、agy 也当行政。
- 把旧 Codex 对话搬进行政对话。
- ~~验收后的“一键合并”按钮~~（已修订：放进第二批）。

## 怎么算通过

1. 打开软件不弹密钥框；在设置里填好密钥后就能和行政聊天；密钥不出现在任何项目文件里。
2. 闲聊和问进度不启动 Codex。
3. 新开、切换对话不用等连接，已有内容马上显示；重开软件后对话还在。
4. 问进度时，行政的回答和卡片记录一致。
5. 说一个开发需求，弹出“变成任务？”，写清要做什么、不做什么；闲聊不弹。
6. 取消就不生成卡片；确认后生成卡片，方案批准后 Codex 才开工。
7. 派活过程在卡片里看得到，完成或失败时行政会汇报。
8. 让行政改团队设置时先确认；它无法改代码或运行命令。
9. 断网、密钥错误、额度用完时，有大白话提示，已写的话不丢。
10. 全部自动测试通过，并在真实窗口用真实模型走完一遍。

## 修订（2026-11-06，用户已批准）

用户对照 DeepSeek 原型讨论后定：选行政这条主路，分两批做。

**路线**

1. 行政是唯一主路，所有新功能只做在行政这边。没配密钥时，聊天保持现在的 Codex 聊天，没有确认框和卡片按钮，不再做第二套。
2. 打开软件不弹密钥框。设置里有“行政人员（可选）”，可以配置、更换和停用。

**第一批：跑通完整链路**

3. 先修复查员漏洞：复查员报错、超时或没给结论，都不算通过。
4. 行政一次只问一个问题，并给推荐答案和一句话理由。
5. 确认建卡后，Codex 只读写方案和允许范围，你批准后才开工。
6. 卡片提供“批准并开工”“不做了”“接着跑”“停下”。
7. 退出软件时，施工继续在后台跑。重新打开能看到真实状态；中断的卡不自动重跑，等你点“接着跑”。
8. 需要你处理的卡片置顶显示，没有时不占地方。
9. 行政在聊天里汇报方案写好、完成和卡住。

**第二批：加上多张卡的体验**

10. 验收通过按钮：合并前检查，合并后重跑测试，失败时主项目退回原样。
11. 还要修改按钮：把新要求交给后台再做一轮。
12. 排队：可以连续建卡，上一张合并后下一张才开工。
13. 每卡专属对话：点卡片，中间换成这张卡的对话；施工中发的话先记下，这一轮结束后再处理。

**开发方式**

14. 超级助手还在打磨，开发它时不走它自己的流水线。Claude 写施工单和验收测试，用户把施工单交给 Cursor 写代码，Claude 验收。
15. 第一批做完先验收一次，再开始第二批。

**新增验收标准**

11. 复查员报错、超时或没给结论时，卡片不会进入“等你验收”。
12. 行政每次最多问一个问题，并带推荐答案。
13. 退出软件再打开，正在跑的卡显示进行中；已中断的卡显示“中断了”，点“接着跑”才继续。
14. 第二批：合并失败、测试失败或有冲突时，主项目不被改动，并说明原因。
15. 第二批：两张卡不会同时施工；第二张一定基于第一张合并后的代码开工。
16. 第二批：主对话和每张卡的对话互不串台；施工中发的话不丢，这一轮结束后提醒你处理。
