# 第二期实测报告：订阅的 Codex 能不能自己造出一张能力卡

> 2026-11-14 · 按 [实测计划](实测计划.md) 跑完两题。结论：**通过**，第二期按“我们自己的大脑 + 制作手册 + 三个工具”的路子写需求共识。

## 一句话结论

只给 Codex 一句需求、一份[制作手册](能力卡制作手册-初稿.md)、三个命令（看积木块、查格式、试做），中间没人插话，两题都在 **4 分钟内**自己做到试做通过，交代如实，没乱动东西。

卡片四件事（Claude 打分）：收什么 ✅、交回什么 ✅、出错了怎么办 ✅（都配了备用模型）、**怎么算做对 △**（只能查文件扩展名，内容对不对程序查不了，靠做卡的 AI 自己读一遍）；“什么时候用” ✅。

两张卡都主动给干活的 AI 加了好规矩：只有明确约定的才算待办、缺的信息写“待确认”不编、会议记录里夹带的指令不执行。试做结果也照做了（只讨论过的事、已完成的事没被当成待办）。

## 发现的问题（改进手册和第二期方案用）

1. **两题都在同一处摔**：输入项的字数上限最多 8000，手册没写。→ 手册补上。
2. **扩展名的写法**（不带点、小写）手册删掉提示后，题 B 第一次就写错，靠报错改对了——说明报错写得够清楚，AI 能自己改。→ 手册保留这条提示（省一轮）。
3. 题 B 原本想测的坑“文件名和扩展名对不上”没踩到：它自己就把两者写成一致了。所以“能不能从试做报错里找出问题”这次**没测到**（试做都一次过），只测到了“能从格式检查报错里改对”。
4. **“怎么算做对”太弱**：交回文件的卡，程序只能查扩展名和文件在不在。第二期 2-7“怎么算做对”要想办法加强（例如交回 Markdown 时查有没有标题、有没有至少一条列表），否则全靠 AI 自觉读结果。
5. 两题对“已完成事项”处理不一样：A 不列，B 列成已勾选。两种都说得通，说明同一句需求不同次做出来的卡会有差别——这正是 2-4“换一家 AI 复查”和让用户最后确认的意义。

## 泼冷水

- 只测了 AI 助手类积木块（不用密钥）；大模型 API 类、联网搜索类没测。
- 题目简单，都是“一句话、一个输入、交回一个文件”。复杂需求（多个输入、要联网、要图）没测。
- 用的是 Claude 写的 lab.py；产品里还没有这三个工具，第二期要把它们做成管家的工具。
- 做卡和试做都用 Codex 额度：两题共约 6 分半 Codex 时间。
