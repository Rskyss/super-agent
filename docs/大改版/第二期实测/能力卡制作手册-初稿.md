# 能力卡制作手册（初稿，给做卡的 AI 看）

> 2026-11-14 实测用初稿。改写自 `desktop/clerk/roles/积木库手册/ability.md`，按借鉴清单 A1–A8 加了“自己试、自己修、如实交代”。实测后再定稿。

## 你的任务

用户说了一句想要的能力。你要交出一张**试做真实跑通过**的能力卡片，加一段如实的交代。中间不会有人回答你的问题，自己做到底。

## 做法（按顺序）

1. **先看现场**：`python3 lab.py blocks`，看有哪些积木块、各自类别、模型名单、能不能用，以及已有哪些能力卡（别做重复的）。只用标“能用”的积木块和模型。
2. **先做一个最小能用的版本**：1–3 个输入项，交代写清“干什么、只交回什么、不要开场白”。不要一上来就做大而全。
3. **查格式**：`python3 lab.py check 卡片.json`。不过就照原因**只改那一处**，不要整张重写。
4. **真实试做一次**：`python3 lab.py trial 卡片.json '{"项名": "例子"}'`。只填好格式不算做完，必须试做通过。
5. **试做没成**：先分清是谁的问题——
   - 环境的问题（积木块不能用、超时、没登录、额度不足）：换一个“能用”的模型或积木块；都不行就停下，在交代里说清卡在哪，**不要为了绕过去去改卡片的规则**；
   - 卡片的问题（交代写得不清、交回的样子不对、检查定得太严）：照原因改一处，再试。
   最多试 5 次。第 5 次还不过就停下，交代卡在哪、试过哪些办法。
6. **试做通过后再看一眼结果**：程序只查像不像样（有没有内容、字数、文件在不在），你要自己读一遍结果，内容不对就改交代再试。
7. **交出**：把最终卡片存成 `卡片.json`，再写 `交代.md`。

## 卡片要写清的四件事，加一项“什么时候用”

| 项 | 写在哪 | 要求 |
|---|---|---|
| 收什么 | `inputSchema` | 1–10 项；项名小写英文开头，给人看的名字写 `title`；文字项必须写 `maxLength`（或 `enum`）；数字项写 `integer` 和 `minimum`、`maximum`；每项带一个 `examples` |
| 交回什么 | `output.type` | text / list / image / file 四选一，必须和积木块类别对得上（见下） |
| 怎么算做对 | `output.check` | 能核对的标准：字数上下限、几条、图多大、文件扩展名；别定得太严让好结果也过不了 |
| 出错了怎么办 | `backup_models`（这一版只有这一项） | 有第二个“能用”的模型就写一个备用；交代里写明“程序会先试主模型，不行换备用” |
| 什么时候用 | `description` | 一句话说干什么、适合什么场合（200 字以内）。以后 AI 靠这句话挑卡 |

## 每类积木块能做什么

- **联网搜索**：只能“按关键词搜资料、交回一个列表”。`how` 写 `{"kind": "search", "query": "{keywords}", "max_results": 8, "time_range": "none"}`。
- **大模型 API**：只能交回文字（写、改、翻译、总结、提取要点）。`how` 写 `{"kind": "llm_api", "system": "……", "prompt": "……{项名}……"}`；`model` 必须从名单里原样抄。
- **AI 助手（Codex、Cursor、agy）**：交给它一句话，它在临时文件夹里干活、存出一个文件或一张图。`how` 写 `{"kind": "cli", "prompt": "……{项名}……把结果存成当前文件夹里的 结果.md。存好后只回复 OK。", "output_file": "结果.md", "timeout": 300}`（timeout 30–600 秒）。交回文件时 `output.check.extensions` 要和 `output_file` 的扩展名对得上；交回图片时 `output_file` 以 .png 或 .jpg 结尾。
- **普通工具**：这一版做不了，直说。

交代（prompt）里用 `{项名}` 放用户填的内容：只能用 `inputSchema` 里有的项，必填项都要用上。

## 写对的样子

```json
{"id": "translate-en", "title": "翻译成英文", "description": "把一段中文翻译成英文，适合翻译说明、邮件",
 "block": "bailian", "model": "qwen3.7-plus",
 "inputSchema": {"type": "object", "properties": {"text": {"type": "string", "title": "要翻译的中文", "maxLength": 4000,
   "examples": ["今天天气很好，我们去公园散步吧。"]}}, "required": ["text"]},
 "how": {"kind": "llm_api", "system": "你是翻译。只输出译文，不要解释，不要开场白。", "prompt": "把下面这段中文翻译成英文：\n\n{text}"},
 "output": {"type": "text", "check": {"min_chars": 1, "max_chars": 20000}}}
```

## 说明的写法（借鉴清单 A5）

- 说它做什么、交回什么，不说内部怎么做；
- 每条事实只说一次；参数的规矩写在参数旁边；
- 关键限制放前面（例如“只能交回文字”）。

## 交代.md 要写什么

1. 做了一张什么卡，一句话；
2. 试做了几次，每次没成的原因和你怎么改的；
3. 最后一次试做的结果摘一段；
4. **哪些没验证到**（例如只试了一个例子、备用模型没试过）；
5. 不许写“已经放进能力层”——放不放由用户决定。

## 不许做的

- 只在当前文件夹里动；不改产品代码，不碰别的文件夹。
- 不在卡片、交代、文件里写任何密钥。
- 不为了让试做通过而放松检查到失去意义（例如把字数下限改成 0、扩展名改成什么都行）。
