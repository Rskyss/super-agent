## 四、各项要做什么

### 第 0 步（先做）：第 4 项遗留，确认后小条不出现

- 现象：在**刚开的新会话**里说需求 → 点“确认，建任务” → 卡建出来了（CARD-010），任务对话也记下了，但输入框上方的“任务卡小条”没出现。之前在已经有消息的会话里是能出现的。
- 怀疑原因：小条按“卡的 `来源.json` 里的 conversation 等于当前会话编号”来找卡（`src/index.ts` 里的 `sessionCards`，`src/task-session.ts` 里的 `cardsFromConversation`）。新会话在第一条消息前后，编号可能变了，所以对不上。先核实再修。
- 修好后验收：新会话里建卡，3 秒内出现小条；点“查看任务”能打开任务对话；在任务对话里问“现在到哪了”能答出真实进度；刷新后还能对上。

### 第 5 项：右栏 7 步进度 + 改要求确认条（页面 04）

- 任务对话的右栏用 DSH 右侧栏（`ctx.sidebarRightTabs` 注册一个类型，比如 kind = `superagent-progress`；参考 DSH `packages/client/ui-schedule` 怎么注册 `sidebar.right.pane.tab`）。打开任务对话时自动打开它。
- 7 步 = 两步固定（调度员写方案、你批方案）+ 流程的步骤（写测试、写代码、跑全部测试、复查、你验收）。每步显示工具 · 模型 · 强度 · 用时，最多 3 行大白话；任何时候都要有一步在转圈。数据从现有后台 `/api/view` 来（网关 `view()`），每 2 秒刷新。
- 改要求确认条：任务模式的工具 `card_change` 已经把改要求存进网关（`pendingChange` / `decideChange`）。界面在任务对话的 `conversation.input.dock` 显示“第 N 条：旧 → 新 [确认改] [算了]”。**只有进行中的卡能改**；已完成、不做了的卡，提示“这张卡已结束，要改请新建一张”。
- 验收：跑一张卡，右栏和实际一致，延迟 ≤ 5 秒；确认条“算了”什么都不变，“确认改”后卡收到修改。

### 第 6 项：方案卡、验收卡、停下卡（页面 04a / 05 / 14）

- 都贴在任务对话的 `conversation.input.dock` 上，同一时间只一张，可以收起。
- 方案卡（04a）：从网关 `plan()` 读，七行大白话（要做什么 / 分几步 / 做完你会看到 / 不做什么 / 只动这些地方 / 怎么算做好 / 问号带建议），按钮“批准，开工 / 我要改 / 先不做”（`cardAction`：approve / revise / discard）。问号不答也能批。
- 验收卡（05）：按钮“打开预览 / 没问题，放进项目 / 继续改”（accept / revise）。预览用后台现有的预览接口，先查 `desktop/server.py` 里怎么开预览，接到网关。
- 停下卡（14）：卡阶段是停下要你决定时显示原因 + “接受剩下的问题，去验收 / 按我说的改 / 再跑一次 / 先不做”（accept_issues / revise / resume / discard）；不是复查原因的停下，没有“接受”按钮。界面上一律叫“停下了 · 需要你决定”，不出现“Claude”。
- 按钮出现与否以后台返回的 `phase.actions` 为准。

### 第 7 项：左栏“对话 | 任务”（用户定的样子，必须两个标签）

- 用 DSH 的 `sidebar.workspaces`（单一位置，注册我们的组件会替换 DSH 自带的会话列表）。参考 `packages/client/ui-workspace` 的写法和 `useSessions` / `useWorkspaces` 这类标准能力。
- 对话：列出不是任务卡的会话，能新会话、切换、改名、归档。任务：按“等你处理 / 进行中 / 已完成”分组列任务卡，点开就是它的任务对话；“任务”旁的数字只数等你处理的。
- 任务卡对话不出现在“对话”里（靠网关的卡 ↔ 会话记录区分）。
- 样式用 DSH 自带的零件（`@deepseek-ai/dsh-client-ui-primitives`）和配色变量，不自己乱定颜色。
