# 接调度员与角色块 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans。沿用用户指定方式：Codex写测试/编译/走查/复查/台账，agy Gemini 4 Hydrogen写实现。下列为施工单的接口细化，不增加产品范围，不增加审批。

**Goal:** 未通过真实检测时先建卡不写方案，用户在对话确认接好调度员后自动开始方案；设置能看到两个角色并从对话更换。

**Architecture:** DSH插件只做界面和有口令的网关；Python复用现有接入提议与检测，不复制一套安装器。检测缓存以项目、工具、模型为界，角色配置只在成功后改。

**Tech Stack:** 锁定DSH 0.2.2-rc.3，TypeScript/React，Python现有后台。

**Spec:** [施工单第10项](施工单-第5到13项.md)、[页面说明12/13/13b/06](页面说明.md)。

## Global Constraints

- 不改DSH核心；确需核心改动只存补丁，不应用。
- 不碰用户真实积木库、钥匙串、旧版应用及设置；测试只用显式临时目录。
- 不提交、不推送；页面不出现Claude。
- 不让模型确认接入、装软件或执行任意页面提供的命令；仅Codex/agy订阅工具。
- 以用户连续施工授权推进，不新增计划批准等待。

## Review Focus

- 配置写了工具名但未登录：不得ready，真实检测失败保留原因。
- 工具或模型换过：旧缓存失效，不能借上次成功冒充当前成功。
- 空目录、旧真实目录：检查前拒绝；子进程明确指定新版测试目录。
- 没调度员/检测失败：确认卡仍能建卡，不启动方案，不丢用户原话。
- 同时点两次检测：同一配置只运行一次真实CLI小任务。
