# 第11–12项施工边界与验收计划

> Codex根据施工单既定方案整理，11-16。用户授权连续施工、重大阻碍可明确占位；不另增审批。

第11项沿用DSH的模型目录、模型设置和默认模型服务，增加首次配置界面。先自动验证Key、展示模型但不默认选择；用户明确选择并点确认后，实际收到非空回复，才保存凭据和模型。换服务商清空未保存信息，旧请求不得覆盖新页面。失败留页且不泄露Key。

新增CredentialProvider使用macOS Security.framework，只按自有service和account精确查询。Key经辅助进程标准输入，不经命令参数、项目文件或日志。元数据只留引用；读取记录和修改记录沿用公开Provider约定并串行。失败不回退明文。既有隔离测试配置暂兼容旧Provider；新桌面入口显式启用钥匙串Provider。测试只使用com.aisoup.superagent.test.UUID专用条目及非真实测试值，不读取或迁移用户已有条目。

Codex先写11个单元红灯（首次配置界面4、Host确认策略4、Keychain边界3），agy实现；通过后完整编译和插件测试。真实走查用全新临时DSH_HOME、受控OpenAI兼容本地测试服务和测试条目，覆盖401、取名单、不默认选、回话、保存、无明文文件、重开和更换。外部真实服务的验证另列范围，不冒称受控服务等于外部账号已验证。

第12项复用现成DSH Electron桌面运行能力，产物只在临时目录。独立bundle id、DSH_HOME、userData、日志、默认工作区、积木库，名字“超级助手”，使用已有碗图标。不得覆盖/关闭旧版、安装Applications或抢dsh默认协议。以自有启动壳加载只读DSH内核；临时runtime profile挂载插件，后台仍由插件启动。产物依赖本地仓库，明确不是可分发安装包。

Codex先写桌面目录与环境边界红灯，agy实现脚本。检查应用元数据、图标和启动参数后，实际打开本次临时.app，确认插件首次配置和旧版共存；只关闭本次自己启动的进程。核心能力缺口则仅存补丁/列占位，不改DSH核心。

第13项保留CARD-011从新界面提出、确认、批准、实际Codex/agy施工到待验收的证据；最终从新界面完成放进测试项目，回查版本、测试、轨迹和统计。再跑主仓全量和插件全量，登记每张测试卡、占位、截图和验收启动入口，停等Claude。

接口地址核对（11-16，只读官方文档，不用真实Key调用）：[DeepSeek 首次调用](https://api-docs.deepseek.com/quick_start/agent_integrations/)与[模型列表](https://api-docs.deepseek.com/api/list-models/)支持原点地址；[百炼兼容接口](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions/)说明旧dashscope域名仍可用，新的业务空间域名也可经“其他”填写；[腾讯混元兼容接口](https://cloud.tencent.com/document/product/1729/111007)给出hunyuan/v1，同时提示新服务逐步迁移TokenHub。三家真实外部账号本轮均不读取、不代登录、不实测；端到端验收使用受控本机兼容服务，不能据此宣称所有外部服务已测通。
