# 需求共识：左边改成聊天窗口（先接已有的订阅）

> 状态：✅ 口径已确认（2026-11-04）　下一步：可行性验证 → 设计稿 → 方案 → 用户批准后施工  
> 讨论过程：[讨论记录](../超级助手桌面版/讨论记录.md) 第 17、18 节

## 一句话

超级助手窗口的左边从“终端的样子”改成**正常的聊天窗口**：一问一答、左右气泡、图片直接显示。调度员可以是任何大模型，你在这里用聊天的方式交代任务，它分给执行员。**这一步只接你已有的订阅（命令行工具），API 以后再做。**

## 用户原话

1. “我想让这个窗口左边这个对话不是终端的样子，而是一个聊天界面的，我给它输入文字，比如说我让它生成图片，它会把图片贴出来……虽然我是终端登录，但是我的界面就是正常聊天窗口那种方式，左右两边的一问一答。”
2. “这是一个通用的窗口……不管是 API 也好，订阅的也好，我通过说话然后它能接到我的任务进行分配给其他做执行的，各个员工。”
3. “API 的先不做，先把咱们已有的订阅先做好。”

## 已确认的口径

| 项 | 口径 |
|---|---|
| 调度员是谁 | 任何大模型；**这一步只做订阅的命令行工具**，API 以后做 |
| 先接哪家 | **Codex 先做并实测**；Claude 随后接上，由用户亲手配置时验证（测试时不启动 Claude） |
| 接法 | 用各家给“聊天界面”用的官方接口，沿用用户现在的登录，不另配密钥 |
| 终端 | 保留，可以随时在“聊天视图 / 终端视图”之间切换 |
| 设计原则 | 调度员接入做成通用的一层，以后接 API 时聊天窗口和右边面板都不用改 |

## 第一版聊天视图要有的

1. 一问一答：你的话在右，调度员的回复在左；回复边写边出，标题、列表、代码排好版。
2. 图片直接显示在对话里（调度员画的图、它提到的图片文件）。
3. 调度员要运行命令或改文件前，弹出“允许 / 拒绝”按钮。
4. “停止”按钮：随时打断。
5. 打开项目时接着这个项目上一次的对话；开场交代照常自动发出（会标明是超级助手自动交代的）。
6. 调度员在干活时（读文件、运行命令）显示成简短的一行“在读 xxx”“在运行 xxx”，可以点开看详情，不刷屏。

## 可行性验证（2026-11-04，用 Codex 实测）

| 要验证的 | 结果 |
|---|---|
| 回复边写边出 | ✅ 一句话分 22 段陆续到达 |
| 画图并拿到图片 | ✅ Codex 画了一只坐在弯月上的橘猫，图片存成文件，消息里带着位置（设计稿里用的就是这张） |
| 运行命令前先问 | ✅ 严格模式下改文件前会问；回答“拒绝”后文件确实没建，Codex 如实说被拒绝了。默认模式下，只读小命令（如 `ls`）它判断安全就不问 |
| 中途停止 | ✅ 写了约 100 字时停下 |
| 按项目找回对话 | ✅ |
| 开场交代不再像“你说的话” | ✅ 接口有“背景交代”的位置，聊天里显示成一条“超级助手自动交代”的灰色提示，可点开看全文 |
| 用量 | 接口会报告每次对话用了多少，窗口顶部可显示 |

## 已知的冷水

- Codex 给聊天界面用的接口标着“试验中”，Codex 升级后可能要跟着改。
- 终端里现成的功能（切换模型、各种斜杠命令等）第一版不全，用不到时切回终端。
- Claude 的接法要等用户亲手配置时才能验证。

## 怎么算做完（草案，方案阶段细化）

1. 用 Codex 当调度员，在聊天视图里：问一句话 → 看到排好版的回复；让它画一张图 → 图直接显示；让它运行一个命令 → 先弹“允许/拒绝”。
2. 中途点“停止”能打断；关掉窗口再打开，能接着上次的对话。
3. 切到终端视图仍可用。
4. 右边面板照常；原有测试全部通过。
