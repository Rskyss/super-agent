# 方案：左边改成聊天窗口（先接已有订阅）

> 状态：⏳ 待用户批准　依据：[需求共识](需求共识.md)、[设计稿](设计稿-聊天视图.html)  
> 已定：“允许/拒绝”按 A——调度员自己判断，只读小动作直接做，有风险才问；每条命令都在聊天里留一行（2026-11-04）  
> 读法：第 1–5 节是产品语言；第 6 节给施工用，可跳过

## 1. 你会看到什么（对照设计稿）

- 左边默认是**聊天视图**：你的话在右，调度员的回复在左，边写边出、排好版；图片直接显示；调度员干活时只显示一行摘要（“读了 3 个文件 · 运行了 2 条命令”），点开看详情。
- 打开项目时，顶部出现一条灰色提示“超级助手自动交代：……”，可点开看全文；调度员读完交接后先向你汇报。
- 有风险的动作弹出卡片：**允许 / 这次对话都允许 / 拒绝**。
- 调度员干活时，发送按钮变成**停止**。
- 顶部显示这次对话大约用了多少。
- 左上角可以切到**终端视图**：聊天视图里还没有的功能（切换模型、各种斜杠命令），切过去用；切回来，对话接着显示。
- 右边面板不变。

## 2. “开工”一定先问你

派活开工会在项目文件夹外面建一个独立副本，按 A 的规则这一步本来就会被问到。施工时我会实测确认；如果它没问，就加一条规则让“开工”这一类命令**必须**先问。不论哪种情况，没有你点“允许”，都不会开工。

## 3. 哪些调度员用聊天视图

| 调度员 | 左边默认 | 说明 |
|---|---|---|
| Codex | 聊天视图 | 这一步做并实测 |
| Claude | 聊天视图 | 接法随后写好，你亲手配置时验证（我测试时不启动 Claude）；验证前可先用终端视图 |
| 自定义命令 | 终端视图 | 不知道它的聊天接口，只能用终端 |

## 4. 这一步不做

- 接 API（以后）。
- 在聊天视图里切换模型、斜杠命令（切到终端用）。
- 多个对话标签页（一个项目一个当前对话；需要新对话用菜单「对话 → 开始新对话」）。

## 5. 风险

- Codex 的聊天接口标着“试验中”，升级后可能要跟着改；万一哪天接不上，窗口提示你切到终端视图，不会让你卡住。
- 同一个对话不能同时在聊天视图和终端视图里开着：切换时，前一个视图会先让出这个对话。

## 6. 施工备注（可跳过）

- **统一调度员接口**放在本机数据服务里（Python）：对上给聊天页面提供“发消息、允许/拒绝、停止、历史、事件流”，对下每家一个适配器。Codex 适配器连 `codex app-server`（标准输入输出上的 JSON 消息）；以后 API 适配器接在同一层，聊天页面不用改。
- 事件统一成几类：回复片段、回复完成、动作（读文件/运行命令/改文件/画图）、请你允许、这一轮结束、用量、出错。
- 新对话：`thread/start`（项目目录、`on-request`、`workspace-write`，开场交代作为背景交代）；打开项目：按项目找最近的对话 `thread/resume`，取回历史显示，再发一轮“每次打开”的交代。
- 图片：只允许读取调度员在事件里报出来的图片文件，其他路径一概拒绝。
- 聊天页面和右边面板一样由本机数据服务提供；Swift 窗口只负责“聊天/终端”切换：切到终端时关闭聊天连接，用 `codex resume <对话编号>` 接着同一个对话；切回聊天时重新连上并取回历史。
- 开工必问的兜底：给 Codex 加执行规则，把 `collab run` 这一类命令设为必须询问。
