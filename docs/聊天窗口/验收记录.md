## 实测中发现的问题（如实记录）

| 问题 | 原因 | 处理 |
|---|---|---|
| “开工”没有弹出“允许吗？”（方案里猜它会自然被问到——猜错了） | ① 用户自己的 Codex 设置是“让 AI 审批员代答”（`approvals_reviewer = guardian_subagent`），询问根本到不了用户；② 开工命令在受保护环境里会失败，调度员就停了，不会主动申请 | ① 超级助手里的对话一律“问用户本人”（只对超级助手生效，不改用户的 Codex 设置）；② 开工命令自查：在受保护环境里一律拒绝并要求申请权限；③ 调度员守则加一句“开工直接申请权限、被拒就停”。重测：开工先弹“允许吗？”，拒绝后卡片仍待派发、没有独立副本 |
| 写到 /tmp 不会问 | Codex 把临时文件夹当作安全区 | 不改；写到个人文件夹等其他位置会问（已实测） |
| 动作摘要出现笼统的“其他 2 个动作” | 只认了读/运行/改三种 | 每种动作分别说（看文件夹、项目内搜索、搜索网页、用工具、看图片、画图），被拒绝的单独标出 |
| 一个“应该被拒绝”的测试在拒绝代码写好前跑了，卡住约 3 分钟 | 测试先于代码，且没换成假执行者 | 无残留进程；**可能真的调用了一次 Codex（在临时测试文件夹里），用掉少量额度，无法确认具体多少**。已记入长期记忆避免再犯 |
| 从终端切回聊天时报错“already has an active writer”，且状态卡在“正在连接 Codex…”不再恢复；切回聊天有空白加载过程（用户亲测发现，2026-11-05） | ① 终端视图里的 Codex 默认走电脑后台服务，关掉终端后后台服务还会继续占着对话约 60 秒；② 关掉终端视图时外层交互式 shell 忽略结束信号，子进程退不干净；③ 切到终端时先关了后台会话再清聊天网页，聊天网页在被清掉前又自动发起了一次重连；④ 聊天连接只试一次，失败后顶部状态没更新，且失败的旧会话一直留着，再点“聊天”也不会重连；⑤ 切到终端时把聊天网页整个清空，切回时重刷白纸导致黑屏等待 | ① 终端视图里的 Codex 加上 `--no-daemon`，不走后台服务，并在关闭终端时向整个进程组发挂断/结束信号，关掉即刻让出对话；② 切到终端时聊天画面原地保留不清空、只暂停轮询，再通知数据服务关闭会话；切回聊天时老记录 0 秒直接显示，顶部显示“正在同步对话…”在后台静默接手并只补新增内容；③ 聊天恢复对话遇到占用时，顶部显示“正在等对话让出来…”并自动轮询等待（最多 90 秒），超时才提示“正在别处打开”，且失败时把子进程关干净；④ 失败或断线时状态更新为“未连上 Codex”，再点“聊天”或重开时会新建会话重新连接；⑤ 修复切回聊天还没说新话时被用量事件提前触发“以上是之前的对话”分割线的问题。真窗口实测「聊天 → 终端 → 聊天」切换（[截图](截图-聊天终端来回切换.png)）；假 Codex 补上同一时间只能一方写的限制，新增 3 项测试 |

## 卡 6（Claude 聊天视图）为什么停下

官方资料显示：Claude 命令行的双向对话方式只有一行说明（官方问题单承认未写文档）；官方推荐另装 Claude Agent SDK 包、用它的“是否允许”回调，但这是新依赖，且该回调今年有多个已知问题、官方示例还要“必需的绕行办法”；按用户规矩测试时不能启动 Claude。与已批准的方案（“按官方说明写好，用户亲手验证”）不一致，故停下待用户决定。Claude 目前用终端视图（终端里本来就有允许/拒绝）。
