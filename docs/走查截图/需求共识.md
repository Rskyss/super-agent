# 需求共识：交活自动附走查截图（P1）

> 2026-11-21 用户提出（借鉴 pstack 第二轮排期 P1），状态：✅ 用户 2026-11-21 批准（原话“批准”；第 5 条按推荐：卡片里加一块显示）
> 大小判定：大（跨跑卡流程、卡片界面、复查交代、规则包多个模块；预计超过半天）。

## 用户原话（摘）

> 所以说，一和二是可以要做的。（11-20，指“大改动拆小块”和“交活自动附走查截图”）
> 继续吧。（11-21，P0 收尾后）

## 要什么（大白话）

1. 改界面的卡，写代码的交活后，程序自动按固定步骤把开发助手窗口里的网页部分点一遍，每一步截一张图，附在卡上。
2. 有设计图的，截图和设计图并排放好，你和复查员一眼就能对照“现在 vs 图”。
3. 程序只负责点和截，**不判断截图对不对**；对不对由复查员和最终验收的人（以及你）判断。
4. 这样“测试全过、页面却歪了”能在交到你手上之前被发现；走查也不再依赖哪个模型会不会截图（任何模型当架构师都能用）。

## 已查到的现状

- **程序里已经有一个“页面检查”接口**：开工时可以带一条“页面检查命令”，写代码交活后程序跑它，过了才算做完，结果记进卡片的“页面检查结果”。但它**只有命令行能用**，窗口里开工时从没带上过，所以实际一次都没用过。P1 打算在它上面接，不另起一套（三问第 3 问：和现有做法同构）。
- **“打开改好的版本”**：卡在等你确认时，程序能在卡片副本里起方案写的那条命令、打开地址给你看。走查要起页面，可以参考这一套。
- **现在的“页面检查”测试**都是在命令行里假装出一个页面跑页面脚本（规则包《测试怎么写》），看得到点完的结果，但**不出截图**，也看不到真实排版。
- **无界面浏览器能用**：这台电脑装了 Chrome 和自动点页面的工具，我刚试过，无界面打开页面、截图成功。11-17 也用无界面 Chrome 截过团队页的图。
- **设计图**：超级玩家的设计图是 `docs/借鉴DSH/页面对齐/` 下一组 png（开发助手仓库里也有一份同样的）；开发助手自己的改动多数没有设计图。
- **Codex 能看图**：它的命令可以附图片，复查时能把截图和设计图一起给它（还没实测它看图复查的效果和用量）。
- **同类做法**：pstack 的“show me your work”要求交件附走查证据（11-17 读过源码）。其他工具（Cursor、Codex 云端、Devin 等）交前端改动时附截图的具体做法，这次**没去查证**，方案阶段需要时再查。

## 不做

- Mac 外壳部分的自动截图（菜单、程序坞、图标、窗口标题）。
- 程序自动判断截图对不对、和设计图逐像素比对。
- 录屏、录动图。
- 非网页的项目。
- 两张卡同时跑（P0 已定现在做不到）。
- 不改已有的命令行测试和“页面检查”测试的写法。

## 怎么算验收通过

1. 拿一张真的改界面的卡（开发助手或超级玩家），施工单带走查脚本，正常跑卡；进待验收后，卡片里能看到每一步的截图；有设计图的那几步，截图和设计图并排。
2. 把走查脚本故意改成去点一个不存在的按钮：卡被退回写代码的，退回原因写明卡在哪一步；不会显示成“走查通过”。
3. 复查员的复查记录里有“现在 vs 图”的对照结果。
4. 走查前后，你保存的团队、模型、密钥都没变；走查没有调用任何模型。
5. 没写走查脚本的卡，跑卡过程和界面跟现在一样。
6. 全部测试通过；我在真实窗口里把“有走查截图的卡”和“没走查的卡”各看一遍。

## 泼冷水

- **写施工单更费事**：每张界面卡要多写一份走查脚本；脚本写错会误退回写代码的，和测试写错一样。
- **只管网页部分**：Mac 外壳还得人点。
- **无界面浏览器和真实窗口可能有细微差别**（字体、滚动条、窗口大小）：截图对上了，不保证真实窗口一模一样，最后仍要你在真实窗口看一眼。
- **页面要能单独起来**：开发助手和超级玩家的网页都要先起后台服务、带口令、用假数据，走查脚本得先把这些准备好。开发助手 11-17 做过一次，超级玩家还没试过。
- **复查会更贵更慢**：给 Codex 附图片会多花用量、多花时间，多少还没测。
- **改的正是容易收不住的地方**：要动跑卡流程（多一步）和卡片界面，估计 3～5 天。按 P0 的新规矩要拆成几张卡一张接一张做，方案里会写拆法。
