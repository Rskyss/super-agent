# 方案：交活自动附走查截图（P1）

> 依据 [需求共识](需求共识.md)（用户 2026-11-21 批准）。状态：✅ 用户 2026-11-21 批准（原话“批准”）。
> 大小：大。拆不拆：**拆成 2 张卡 + Claude 自己做的两块**，理由见第四节。

## 一、做完后你能感受到什么

1. 改界面的卡跑完、进“等你确认”时，中间卡片原文下面多一块“走查截图”（显示最近一次走查）：每一步一行，写这一步做了什么，左边是这次截的图，有设计图的右边放设计图；点任何一张看大图。
2. 写代码的改出来的页面要是点不动、打不开，卡会像测试没过一样退回写代码的，退回原因写“走查卡在第几步：……”，不会混进“等你确认”。
3. 复查员（Codex）每轮复查都会打开这些截图和设计图，复查结论里写“现在 vs 图”的对照：哪一步对得上、哪一步不对。
4. 走查跑完、还没跑全部测试（或走查没过）时，右栏“跑测试”那一步照现有逻辑显示走查结果（“走查过了，截了 N 张图”或“走查没过：卡在‘某某’这一步”）；全部测试跑完后，右栏照旧显示全部测试结果，不再在末尾拼接走查那句（11-21 用户定砍掉拼接，卡 A 不动右栏界面；截图在卡 B 的卡片区域看）。不新增步骤。
5. 没写走查的卡，跑卡过程和界面跟现在一模一样。
6. 走查全程不动你保存的团队、模型、密钥，不调用任何模型，不弹出窗口（在后台浏览器里截）。

**为什么用后台浏览器，不用开发助手外壳自带的截图模式**：外壳有个“启动后把三段各截一张就退出”的自测开关，渲染最真实。但它会在屏幕上弹出真窗口、跟你正在用的应用抢；只能截“刚打开”的样子，要多步点击得改 Mac 外壳；卡片副本里的外壳还得重新编译。后台浏览器不弹窗、能按任意步骤点、副本里的网页直接能用。代价见泼冷水第 2 条。

## 三、几个具体口径（需求共识里我替你定的，落到做法上）

- **截图放哪**：卡片文件夹 `走查截图/第K次/`，每跑一次走查新建一份，不清空、不覆盖、不复用（11-21 卡 A 施工单复查后改：复查退回不加返工轮数，按轮编号会冲掉旧截图）。卡片里默认显示这次交活最后一次走查。
- **步骤清单**：走查脚本跑完留一份清单：每步的名字、截图文件、对照的设计图（可不填）。程序只认清单里列的、确实在那个文件夹里的 png；设计图只认项目里的 png。
- **截图不进项目历史**：截图留在卡片文件夹（本来就不提交）；归档时只把步骤清单和“走查过没过”写进归档记录，不把图片搬进 docs，免得项目越来越大。
- **复查员看不了图怎么办**：Codex 11-21 实测能按路径打开图片看懂。换成别的复查工具看不了图的，交代里要求它如实写“看不了图、没对照”，不许编。
- **走查脚本写错**：只有写施工单、做最终验收的那个角色能改（不管哪个模型来当）。走查一直不过，照现在测试没过的上限停下转给接手的人判断；走查过了但复查员看图觉得脚本写错，记成轻微、标“走查脚本可能写错”，不退回，最终验收时改。（11-21 用户同意：原写的“走现在‘测试写错’的办法”行不通，那条路会派给写测试的，而走查脚本写测试的不许改；用户要求按角色写、不写死哪个模型）
- **超时**：用和本卡测试一样的时限。

## 六、泼冷水

1. **写施工单更费事**：每张界面卡多写一份走查脚本；脚本写错会误退回，和测试写错一样。
2. **后台浏览器 ≠ 真实窗口**：真实窗口是 Mac 外壳把左栏、中间、右栏三块网页拼在一起，用的是苹果自带的网页引擎；后台浏览器是三块分开截、用 Chrome。字体、滚动条、拼接处可能有细微差别。截图对得上不保证真实窗口一模一样，最后仍要你在真实窗口看一眼。
3. **Mac 外壳不管**：菜单、程序坞、图标、窗口标题还得人点。
4. **复查更贵更慢**：Codex 每轮要多看几张图，用量和时间会涨，涨多少没测；卡 A 跑完看实际数字。
5. **跑卡流程又多一步**：每轮多跑一次走查（起后台、开浏览器、点几步，估计几十秒到一两分钟，未实测）。
6. **超级玩家这次不做走查工具**：工具是按开发助手项目写的；超级玩家结构一样，第一次给它写界面卡时照着复制一份再调，这次不做。
7. **用时**：W0 约半天；卡 A 约 1～1.5 天（含返工）；卡 B 约 1 天；收尾半天。合计约 3～4 天，推测。

## 七、技术设计（给接手的 AI 看，用户可跳过）

- 走查命令写在施工单“## 八、验收”里：`走查命令：\`<命令>\``，和“验收命令”同样格式；planner 照施工单生成方案时一起摘出，写进开工.json 的 `walk_command`（批准前“继续改”触发 AI 重写方案时，只要卡片仍引用施工单，同样从引用的施工单取 `walk_command`）。没有引用施工单的卡不支持走查。
- `collab/cli.py run`：命令行没给 `--page-check` 时，读开工.json 的 `walk_command` 当页面检查命令；给了就以命令行为准（兼容老用法）。
- dispatch 页面检查那段：跑前建 `<卡片目录>/走查截图/第K次/`（每次新建），用环境变量把这个文件夹交给走查命令（名字在卡 A 施工单里定）；跑完读该文件夹里的步骤清单（JSON：`[{"步骤","截图","设计图"}]`），校验文件在、是 png、设计图在项目里；记一条流转（`kind="页面检查"`，多带 `walk=True`、`folder`、`result`、`reason`、`shots`）；命令过了但清单为空或截图不在 → 当没过，退回开发员。
- 复查交代复用 W0 已登记的独立交代 `复查/走查截图`（`agents/交代/复查/走查截图.md`，空位 `{步骤}`）：这次交活有通过的走查时拼在“每轮复查”交代后面，列每步的步骤名、截图绝对路径、设计图绝对路径；没有走查的卡不拼接，原样不变。
- 卡 B：`card_view` 多给一项最后一轮走查（步骤、截图、设计图）；server 新加只读看图地址，只放行 `<项目>/.collab/cards/<卡>/走查截图/**.png` 和项目里的 png；chat.js 在卡片原文那块下面画“走查截图”，样式沿用现有设计规则。
- 开发助手走查工具（W0）：放 tests/ 下，提供“起后台（临时 HOME、假项目、口令）”“按真实窗口里左栏、中间、右栏的宽度打开某段”（宽度照 Mac 外壳里的默认值，W0 时查出来写死）“截图并记一步”“写清单”。11-21 试跑脚本在会话临时文件夹里，W0 照它整理。
