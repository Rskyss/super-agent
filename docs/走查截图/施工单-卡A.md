## 一、要做什么（一句话）

施工单写了“走查命令”的卡，写代码的交活、本卡测试过了以后，程序自动跑走查命令：每次给它一个新的放截图的文件夹，跑完读步骤清单，截图记进卡片流转；走查没过、没留下截图、清单不对，都像测试没过一样退回写代码的；复查员的交代里列出这次交活的每一步截图和设计图。本单不改右栏和卡片界面（走查刚过或走查没过时右栏照现有逻辑显示走查结果，全部测试跑完后照旧显示全部测试结果，11-21 用户定砍掉末尾拼接和“正在走查”转圈）。没写走查命令的卡和现在完全一样。

## 三、具体做法

动手前先看第四节状态表和第五节原有行为清单。下面说的“走查”只指开工资料里来的走查命令；命令行 `--page-check` 给的页面检查是老用法，**一律照旧**。

几个词先说清：
- **这次交活**：写代码的最近一次交活（流转里最后一条 `kind == "回复"`、`src == "开发员"` 的记录）之后发生的事。复查退回、继续改都会有新的交活；判断“这次交活的走查”一律按流转的先后（`seq`）看，**不要用 `card.rework` 当编号**（复查退回不加它，继续改还会把它清零）。
- **走查记录**：`kind == "页面检查"` 且 `walk == True` 的流转（见 P3 第 4 条）。
- **这次交活的走查结果**：这次交活里**最后一条**走查记录。只有它通过才算“走查过了”；同一次交活里先过后又没过（比如中断后接着跑又走了一次），以最后一条为准。

### P1 照施工单生成方案时摘出走查命令（`collab/planner.py`）

- `_plan_from_order`：**只在标题含“验收”的那一节里**，找以“- 走查命令：”开头的那一行，取这一行里第一对反引号中的命令；返回的字典里多一项 `walk_command`（没有就是空字符串）。施工单写“走查：不涉及”就是没有。不要在全文里搜：别的节里哪怕有一整行“- 走查命令：`...`”也不算。
- `plan_card` 照施工单直接生成方案那条路写 `开工.json` 时：`walk_command` 不空才写进去（`{"test_command": ..., "walk_command": ...}`），空就和现在一样只写 `test_command`。
- **AI 重写方案那条路**（批准前点过“继续改”、需求卡里有“## 追加要求”，或者需要项目说明时）：AI 写完、程序写 `开工.json` 时，如果需求卡引用的施工单（`existing_orders` 认出来的第一份）验收一节有走查命令，同样把 `walk_command` 写进去。没有引用施工单的卡不支持走查。

### P2 开工时自己读走查命令（`collab/cli.py`）

- `run` 命令：命令行**没给** `--page-check` 时，读这张卡的 `开工.json`，有 `walk_command` 就把它包成 `["/bin/bash", "-o", "pipefail", "-c", <走查命令>]`，用新参数 `walk_command=` 交给 `run_card`；给了 `--page-check` 就照旧走 `page_command`，不读走查命令。
- 这样窗口里的四个开工入口（批准开工、接着跑、继续改后重开两处）都经过这一处，不用各改一遍。
- “开跑”那条流转的说明文字：给了 `--page-check` 照现在写“页面检查：<命令>”；有走查写“走查：<命令>”；两样都没有照现在写“页面检查：无”。

### P3 跑走查（`collab/dispatch.py`）

`run_card` 加参数 `walk_command=None`（一路传到现在传 `page_command` 的那些地方）。在现在跑页面检查的那段旁边，本卡测试过了（`verdict.result == PASS`）且有 `walk_command` 时：

1. **截图文件夹**：`<卡片文件夹>/走查截图/第K次/`。K = `走查截图/` 下已有的“第几次”文件夹里最大的数加 1（没有就是 1）。**每次新建，从不清空、从不复用**：走查被停下时，之前那次的命令可能还在后台写文件，用新文件夹就不会混在一起。
2. **跑**：`judge_fn(["/usr/bin/env", f"WALK_SHOTS_DIR={文件夹}", *walk_command], cwd=worktree, timeout=_TEST_TIMEOUT)`。走查命令本身原样放在后面，程序只在前面加上截图文件夹。
3. **命令过了，再检查文件夹里的 `走查.json`**（格式 `[{"步骤": "...", "截图": "01-xxx.png", "设计图": "docs/...png 或空"}]`），下面任何一条不满足都当没过：
   - 读得出、是列表、至少一条；
   - 每条是对象；`步骤` 是不空的文字；`截图` 是文字、只是文件名（不含 `/`、`\`）、以 `.png` 结尾、这个文件夹里真有这个文件，且**解析后（跟随链接）的真实位置仍在这个文件夹里**（防止一个合法名字的链接指到外面的图）；
   - `设计图` 可以没有或是空文字；有的话必须是文字，按副本（worktree）解析后在副本里面（不许 `..` 跑出去、不许绝对路径）、以 `.png` 结尾、文件真在。
4. **记录**：
   - 命令的输出写进这次的文件夹：`走查截图/第K次/命令输出.txt`（不进归档；判定只留输出的末尾最多 4000 字，就写这些，文件开头写一句“只留了末尾部分”）。
   - 往 `页面检查结果.md` 追加“## 第 K 次走查”，**只写**：结论、一句大白话原因（和下面 summary 同一句）、过了的话再写步骤清单（每步：步骤名、截图文件名、设计图）。**不写原始输出**——这个文件归档时会原样复制进项目 docs，原始输出里有本机路径。
   - 记一条流转，kind 用现有的 `"页面检查"`（这样退回、停下这些现有逻辑都自动认它），多带字段：`walk=True`、`folder="走查截图/第K次"`、`result`、`reason`（给写代码的看的原话，见第 6 条）、`shots`（每条 `{"步骤", "截图": "走查截图/第K次/<文件名>"（相对卡片文件夹）, "设计图": 原样或空}`；没过时为空列表）。
5. **`summary`（右栏会显示，所以不能有路径、命令、原始输出）**，按下面挑一句：
   - 过了：`走查过了，截了 N 张图`（N = 清单条数）
   - 命令输出里**最后一行非空行**以 `WalkError:` 或 `walk_tool.WalkError:` 开头（忽略行首空白），且里面有 `“某某”这一步`，“某某”不空、至少含一个汉字、不含 `/`、`\`、空白字符（空格、制表符等）和中文双引号 `“`/`”`、不超过 20 个字：`走查没过：卡在“某某”这一步`（不满足就用最后一种）
   - 清单问题：`走查没过：没留下截图`／`走查没过：第 n 步的截图不对`／`走查没过：第 n 步的设计图不在项目里`／`走查没过：步骤清单写得不对`
   - 超时：`走查没过：超时没跑完`；环境出错：`走查没跑起来：环境出错（不是代码的问题）`
   - 其他：`走查没过：命令报错（详情在交接里）`
6. **没过（结果是 FAIL）**：和页面检查没过一样——这一轮判定换成走查的结果（`_with_log` 那套给的日志文件换成这次的 `命令输出.txt`），退回写代码的，算一次返工（和测试没过共用现在的返工上限）。`reason` 记原话：WalkError 后面那句，或程序查出的清单问题；都没有就取输出最后一行不空的字（最多 200 字）。交给写代码的话里，除了现有的测试输出摘要，**单独加一行**：`走查没过的原因：<reason>；命令输出在 <命令输出.txt 的完整路径>`（现有摘要会丢掉不在失败块里的字，不能只靠它）。**中断后接着跑、从流转里重新拼“测试没过”交代的那条路（现有 `past_fails` 那段）也要带上这一行**（从那条走查记录的 `reason`、`folder` 取）。
   - **超时（TIMEOUT）、环境出错（ENV_ERROR）**：结果类型原样保留，照现在页面检查同样的处理（现有逻辑会停下转人工、不算返工）。走查工具遇到缺 playwright、打不开 Chrome、或本机环境拒绝绑定 127.0.0.1 端口时会以 127 退出，现有判定会把它算成环境出错，不怪写代码的；副本代码改坏导致后台服务起不来时，走查工具以 1 退出并带上后台报错，按普通失败（FAIL）退回写代码的。
7. 有 `page_command` 又有 `walk_command`：先页面检查，过了再走查。
8. **走查脚本本身写错了**：不另做机制。走查一直不过，会照现在测试没过的上限（返工 3 次）停下转人工，由接手的人（写施工单、做最终验收的那个角色，不管哪个模型来当）判断是脚本错还是代码错。走查过了但复查员看图觉得脚本写错，复查交代已要求它记成轻微、不退回（11-21 用户同意）。

### P4 复查员看截图（`collab/dispatch.py` 的 `_review_prompt`）

- 取**这次交活的走查结果**（最后一条走查记录），它通过了才接：在“每轮复查”交代后面接上 `_say("复查/走查截图", 步骤=...)`；没有（没写走查、或这次交活还没走查）就什么都不接，和现在一字不差。复查退回、写代码的重新交活后，下一份复查交代只列新的那次截图。
- `步骤` 每步一行：`第 n 步 <步骤名>：截图 <卡片文件夹/截图 的完整路径>；设计图 <副本里设计图的完整路径，没有写“无”>`。

## 八、验收

- 验收命令：`python3 -m unittest discover -s tests -p "test_walk_card_a*.py"`
- 走查：不涉及（本单不改界面，只改跑卡流程后台）

- 测试写法：照验收测试里现成的两种：直接跑 `run_card` 配假的判定（`judge_fn` 看命令里有没有 `WALK_SHOTS_DIR=` 分辨是测试还是走查）；整条流程用 `tests/acceptance_helpers.py` 的 `ProjectCase` 从命令行开工。不要逐字比对代码。
- **只跑验收命令，不要跑全部测试**（全部测试由程序在复查时跑）。
- 汇报用大白话，不写文件名。
