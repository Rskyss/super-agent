## 一、起因

2026-11-14 用户发现：agy 已经出了 Gemini 4 Hydrogen，命令行能用，但团队设置“写代码”一栏的下拉框里没有。手填“Gemini 4 hydrogen”报“模型名不对”（agy 认的是编号 `gemini-4-hydrogen-high` 这类，不认显示名）。

用户原话：“能不能有一个自己检测自己更新的？你需要硬硬地去调吗？这样子很不方便吧。”“现在这个团队和积木库的数据还没有打通吗？”

用户定的方向：现在的团队页（调度员、写测试、写代码、复查四个固定角色）只是早期为了跑流程设的，以后团队是业务流程，由能力卡片组合而成。所以**模型名单只该有一个来源——积木库**，团队页不再单独维护一份，也不再打磨团队页本身。

## 二、现状（Claude 查代码和本机数据核实）

| | 积木库 | 团队设置页 |
|---|---|---|
| Codex | 读 Codex 自己在本机存的名单（8 个） | 也读这份，会自动跟上 |
| Cursor | 问 Cursor 要（281 个） | 内置约 35 个 + 你用过的 |
| agy | 问 agy 要（18 个，**已含 Gemini 4 Hydrogen**） | 内置 13 个，**写死在代码里**，新模型要改代码 |

团队页里还有两家**不在积木库**：行政用的腾讯云、写代码用的千问 Token Plan（密钥另存一处）。

## 三、要做的

1. **积木库自己刷新模型名单**：不用你点，到时间就在后台问各家要一次最新名单。只问名单，不试模型，不花额度。
2. **团队页的模型下拉框读积木库的名单**：积木库有什么，团队页就能选什么；积木库刷新了，团队页跟着变。
3. **问不到时不变空**：没登录、断网、工具没装时，沿用上一次问到的名单；积木库从没问到过的，用现在的内置名单兜底。
4. **你当前选着的模型不丢**：哪怕它从新名单里消失了，也照样显示、照样保存，只是标一下“这家现在的名单里没有它”。

## 四、不做的

- 不改团队页的角色、布局、检测方式；团队页的“检测”照旧是在项目里跑一件小活（和积木库的检测意思不同）。
- 不把腾讯云、千问 Token Plan 接进积木库（第五节第 3 题定怎么处理）。
- 不碰能力卡片的逻辑（能力卡片本来就读积木库的名单，刷新后自动受益）。
- 不做“业务流程由能力卡片组合”的团队新形态——那是以后的事，这次只做“名单只有一个来源”。

## 五、待用户拍板

**第 1 题：积木库多久自动刷新一次？**
- A（推荐）打开积木库或团队页时，距上次超过一天就在后台刷新一次；页面先显示上次的名单，问完再更新。理由：新模型几天才出一次，一天够用；不会每次打开都等（agy 问一次约 7 秒）。
- B 每次打开都刷新。
- C 超过一小时就刷新。

**第 2 题：Cursor 的 281 个模型全放进团队页下拉框吗？**
- A（推荐）全放，下拉框能打字筛选。理由：只有一个来源，就不该另挑一份；挑哪些也会过时。
- B 只放 Cursor 标的常用几个，其他的走“其他自定义模型”手填。

**第 3 题：不在积木库的两家（行政的腾讯云、写代码的千问 Token Plan）怎么办？**
- A（推荐）这次保持现状（还是现在的固定名单），以后接进积木库时再统一。理由：接进积木库要动密钥的存放位置，范围变大；这两家的模型变得不频繁。
- B 这次一起接进积木库。

**第 4 题：新冒出来的模型要不要标个“新”？**
- A（推荐）不标。理由：这次只求名单准，标“新”要记“谁看过”，多一件事。
- B 标，看过就不再标。

## 五（补）、追问：第 2 题 B 的“常用”怎么取

- A（推荐）Cursor 名单排在最前面的 30 个 + 你用过的 + 你当前选着的。理由：和现在团队页看到的基本一样，Cursor 出新模型一般排在前面，能自动跟上；不用你维护。风险：Cursor 哪天改了排序，前 30 个就不一定是主推的。
- B 你在积木库 Cursor 的模型名单上自己勾“放进团队页”，默认勾上现在内置的那批。理由：完全由你定；代价是多一个勾选功能，新模型要你自己去勾。

**2026-11-14 用户回应（改了第 2 题的方向）：** “Cursor 里面是有很多模型的。无非就是右边它没有跟其他统一高中低……现在右边是少了一个选择框。”——问题不在模型多，而在 Cursor 把“模型 × 强度 × 快速”拼成了一个个编号，团队页没有像 Codex 那样把强度拆到右边。

Claude 用积木库存的 Cursor 名单实测拆分：281 个 → 59 个模型（如 Claude Opus 5.5 拆出 低/中/高/极高/最大，各带“快速”）。agy 也是同样拼法（`gemini-4-hydrogen-high`），一起拆。拆不开的老名字（如 `claude-4.6-opus-high-thinking`）单独成一项、右边强度框显示“—”。顺带发现：积木库读 Cursor 名单时把它末尾的一行提示“Tip:”误当成了一个模型，这次一并修掉。

据此第 2 题改为（用户截图标出 Cursor 右边缺的强度框，确认）：Cursor、agy 的下拉框只列模型（Cursor 59 个，按 Cursor 自己的顺序，主推的在前），右边加“思考强度”框，只列这个模型有的档位，“快速”作为档位后缀（如“高 · 快速”）；不再另挑“常用”。
