# 拆解方案

## 要做什么（一句话）
按 A2 施工单把 agy 和 Cursor 的 token 用量记进卡片、显示在右栏，并补齐老卡里还能从实时输出查到的每轮用量。

## 拆成几步，每步做什么、产出什么
1. 先对照 A2 施工单、已有验收测试和样本说明，只在新建的补充测试文件里补上缺的场景，重点查结果优先、坏行跳过、实时文件缓存刷新、换人多轮、老卡补数和 Cursor 等待出数。
2. 改产品代码前先跑本卡验收命令，确认相关测试确实因为功能缺失而失败。
3. 在 collab/token_usage.py 新增 usage_for(tool, output="", live=None)，让 Codex 和 Qwen 沿用先读回复、读不到再查实时输出的做法，其他不支持的工具返回 None。
4. 让 agy 优先用 result.usage，没有就把各条 step_update.usage 相加，让 Cursor 取最后一条 result 的 usage，没出结果时返回等待状态。
5. 按施工单统一换算用量，输入计入缓存读取且 Cursor 还计入缓存写入，合计只加输入和输出，思考量单列且不重复加，agy 和 Cursor 的子会话用量填 0。
6. 让按行读取跳过坏行和半截行，文件读不了或格式认不出就返回大白话原因，并按路径、文件大小和修改时间复用实时文件的读取结果。
7. 在 collab/dispatch.py 让回复和交接资料都走统一取数入口，返回 None 时省略 tokens 字段。
8. 在 desktop/view.py 去掉右栏取数对 Codex 和 Qwen 的限制，已有用量的回复用原记录，老回复缺用量时按 reply_to 找原派活的实时输出补算，在跑的轮次直接读实时输出，已回复的轮次只算一次。
9. 让每轮明细保留已有用时和用量，再用现有工具显示名加该轮派活记录的模型生成 who，没模型就只显示工具名，读不到就标记 missing 并带上原因。
10. 让站位和整张卡都统计没读到的轮数，同时让等待出数的 Cursor 在站位上显示等待状态，既不计用量也不记为缺失。
11. 在 desktop/static/panel.js 显示等待文案和逐轮明细，缺用量的轮写「用量 —（原因）」，没有 who 的旧明细沿用原样，合计在有缺失时加上「（不含没读到的 N 轮）」。
12. 改完后只跑本卡验收命令并确认整条命令通过，若发现旧断言与新口径冲突，就在汇报里写明是哪条和为什么，由复查程序另跑全量测试。

## 你会看到什么结果
右栏会显示 agy 和 Cursor 的用量，换过工具或模型的环节可以逐轮看到谁做的、用了多久和用了多少；老卡能查到的用量会补显示，查不到的会写明原因，合计旁会标出有几轮没算进去，正在跑的 Cursor 会显示「这一轮结束后出数」。

## 明确不做什么
不做行政用量，不改价格、预算、汇总页、写方案固定用 Codex 的规则或任何影响 token 消耗的设置。不改第一版已有字段及 A2 未涉及的显示，不改已有测试和样本，也不改写老卡历史。施工方不跑全量测试。

## 需要你确认的问题
无

## 做完后怎么看结果
点预览按钮打开流转面板，选一张有 agy 或 Cursor 记录的卡，查看右栏站位的用量，把鼠标停在做过多轮的站位上看每轮明细，再看右栏合计旁有没有注明漏了几轮；有正在跑的 Cursor 时，看看它是否显示「这一轮结束后出数」。
