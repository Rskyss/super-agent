# 拆解方案

## 要做什么（一句话）
按施工单给跑卡右栏加上各环节累计 token 用量和本卡合计，读取失败也不影响卡片继续跑。

## 拆成几步，每步做什么、产出什么
1. 先对照 docs/token用量/施工单-A.md、现有验收测试和样本确认数据口径，把补充测试放进新建的 tests/test_token_usage_extra*.py，并用临时 CODEX_HOME 隔离本机真实会话。
2. 新建 collab/token_usage.py，按施工单提供九个函数，从输出行首提取会话编号，优先查最近两天的会话文件、找不到再全目录查找，并缓存找到的路径。
3. 从会话文件末尾先读 256 KB，找不到有效用量就翻倍往前读，取最后一条完整且有效的累计记录，跳过坏行、未写完的行和空 info，不把多条累计记录重复相加。
4. 只读同日期目录各会话文件的第一行识别辅助会话，单独累计 children，并实现实时输出文件头部 16 KB 读取、新消耗计算和带缺失次数的合并，所有读取异常都返回可理解的结果。
5. 在 dispatch.py 的回复及两种交接资料记录中保存 Codex、千问用量，优先读返回文本、失败再读实时日志，在 planner.py 的成功方案记录中保存用量，并隔离统计异常以免影响原流程。
6. 在 desktop/view.py 的 _add_models 后汇总各站位用量，按 reply_to 排除已经回复的派活，只对尚未回复的 Codex、千问派活现读日志，确保实时值与结束记录不重复计算。
7. 把旧记录中 Codex、千问缺失的用量计为未读到，跳过 agy、Cursor，无任何统计项的站位不加 tokens 字段，并把交接资料、其他角色回复和辅助会话计入 other，再与四站用量合成本卡 total。
8. 在构造 view 时加入 tokens.total 和 tokens.other，保证两个返回分支都有数据且空卡为零，站位只新增 tokens 字段，不改变原有字段。
9. 按现有前端检查脚本实现 tokenText、tokenTitle 和 totalText，严格匹配千分位、万、亿及缺失提示格式，在环节计时后显示用量、鼠标提示中显示明细、列表下显示或隐藏合计。
10. 检查 renderFlow 和每半秒更新计时的 tick，确保计时刷新不会覆盖 token 文字，仅在确有需要时补充样式。
11. 运行指定验收命令和项目原有全量测试，确认坏输入与统计异常不挡流程，并在改好的桌面版本核对运行中更新、结束定格、返工累计及合计不重复。

## 你会看到什么结果
右栏各环节显示“已用多少 token”，写测试、写代码、复查随会话用量更新，结束后定格，写方案完成后显示；环节列表下显示本卡合计，鼠标移上去能看输入、缓存读取、输出和新消耗，读不到时显示原因。

## 明确不做什么
不显示钱或预算，不统计行政对话、agy 和 Cursor，不补算历史卡，不做汇总页，不做写方案实时用量，不改影响 token 消耗的设置，不改现有验收测试、检查脚本和测试样本，不改 allowed 以外的文件。

## 需要你确认的问题
无

## 做完后怎么看结果
打开改好的开发助手，进入一张使用 Codex 或千问跑的卡，查看右栏各环节的用量和列表下的本卡合计；运行时观察数字更新，结束后确认数字定格，再把鼠标移到环节上查看明细，只有 agy 或 Cursor 的环节不显示用量。
