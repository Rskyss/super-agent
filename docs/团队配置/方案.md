# 方案：团队配置 + 检测连通 + 整条流程真跑通

> 状态：⏳ 待用户批准　依据：[需求共识](需求共识.md)、[设计稿](设计稿-团队配置.html)  
> 读法：第 1–4 节产品语言；第 5 节给施工用，可跳过

## 1. 你会看到什么（对照设计稿）

- 第一次打开一个项目，左边先是“这个项目由谁来干？”：
  - 调度员一行：Codex / Cursor / agy / 自定义命令；
  - 执行员三行：写测试、写代码、复查（复查可选“不复查”），各选 Codex / Cursor / agy；
  - 右边面板随你的选择实时换人；写代码和复查选了同一家时，黄字提醒“复查不够独立”。
- 点“检测连通”：每人旁边先显示“检测中…”，再变成“✅ 通了 · 几秒”或“❌ 没通：原因 + 怎么办 + 重试”。同一家担任几个岗位只测一次。
- 全部通了，“保存并开始”才能点；点了以后左边换成和调度员的对话（Codex 是聊天视图，Cursor/agy 是终端视图）。
- 以后改：菜单「项目 → 团队配置…」。原来的「调度员」菜单去掉（Claude 不再出现）。
- 不是 git 的文件夹：只能选调度员聊天，执行员一栏写明“没有版本管理，不能派活”。

## 2. 检测连通具体做什么

1. 先花几秒查“装没装”：找不到这个命令，直接标红“没装”，不白等。
2. 装了的，**真干一件小事**：在一个临时文件夹里建一个文件，建出来才算通；几家同时测，最长等 2 分钟。
3. 没通时把原因翻成大白话：没装 / 没登录 / 额度用完 / 模型名不对 / 超时 / 没建出文件，并写“怎么办”。
4. 自定义命令当调度员：只能查“装没装”（不知道怎么让它干活），会写明这一点。

## 3. 整条流程真跑通（这一步的终点）

在测试项目里，用 Codex 当调度员、Codex 写测试、Cursor 写代码、agy 复查，**真跑一张小卡**：
对话提需求 → 调度员写需求卡和方案、问你 → 你同意 → 开工前弹“允许吗？” → 点允许 → 三位执行员真干活 → 右边面板一步步走 → “等你验收”。
**这一步会真的用掉三家各一些额度**（一张很小的卡，预计几分钟到十几分钟）。

## 4. 不做 / 风险

- 不做：自由加岗位、多人同岗（以后）；Cursor、agy 的聊天视图（以后，先用终端视图）。
- 风险：Cursor、agy 当调度员时“接着上次对话 + 开场交代”的写法要实测；真跑卡时执行员可能出状况（这正是要暴露的），会如实记录。

## 5. 施工备注（可跳过）

- 团队配置存在项目的 `.collab/配置.json`（只在本机）：`team: {dispatcher, tester, developer, reviewer}`；协作包、窗口、右边面板都读这一份。没有 `.collab/` 的文件夹，调度员存在窗口自己的设置里。
- 协作包：`run` 没写工具参数时按团队配置派活；新增 `check` 命令（终端也能用）：按成员检测，输出结果。
- 本机服务：读/存团队配置、在后台跑检测并逐个报告结果（同样要一次性口令）。
- 窗口：左边多一种“配置”视图；页面保存后通知窗口切到对话；菜单换成「项目 → 团队配置…」。
- 调度员命令：Codex 沿用；Cursor `agent`（带开场话进入对话、`--continue` 接着上次）；agy `agy -i`（带开场话进入对话）与 `--continue`；具体写法施工时实测。
