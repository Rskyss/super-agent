# 需求共识：选项目后先配团队、检测连通，再把整条流程真跑通

> 状态：✅ 口径已确认（2026-11-04）　下一步：设计稿 → 方案与任务清单 → 用户批准后施工  
> 讨论过程：[讨论记录](../超级助手桌面版/讨论记录.md) 第 19 节

## 用户原话

1. “Claude 的暂时不进入。你只是开发这个软件的人。然后调度员由我后面去配置，我可以配置 Codex，也可以配置 AGY 的，也可以配置 Cursor 的，甚至是以后其他的订阅平台的。”
2. “在我选择一个项目之后，应该有一个配置，就是哪个是调度员，然后可以去添加里面的每个执行员是谁，然后进行验证测试，看是不是已经通了。这是一步流程。”
3. “先把所有的流程跑通。对话，然后彼此的 agent 进行连接，跑通了之后再考虑到下一步，可以任意和增加其他的流程。”

## 已确认的口径

| 项 | 口径 |
|---|---|
| Claude | 暂不作为调度员或执行员；Claude 只负责开发这个软件 |
| 调度员可选 | Codex、Cursor、agy、自定义命令（以后加别的订阅）；Codex 用聊天视图，其他先用终端视图 |
| 执行员岗位 | **固定三个**：写测试、写代码、复查（复查可选“不复查”）；每岗选一家能自动派活的工具（Codex、Cursor、agy）。自由加岗位以后再说，存配置的方式给以后留余地 |
| 检测连通 | **真干一件小事**：每人在临时文件夹里建一个文件，建出来才算通；先花几秒查“装没装”，没装的直接标红不白等；同一家工具担任多个岗位只测一次 |
| 配置在哪 | 第一次打开项目时左边先出现团队配置；之后从菜单「项目 → 团队配置…」进入 |
| 本阶段目标 | **整条流程真跑通**：对话 → 调度员拆需求、写方案 → 你批准 → 开工（先问你）→ 执行员真干活 → 右边面板实时流转 → 等你验收 |

## 怎么算做完

1. 打开一个项目：左边先出现团队配置，选好调度员和三位执行员，点“检测连通”，每人旁边显示通没通；没通的写明原因和怎么办。
2. 保存后左边换成和调度员的对话（Codex 是聊天视图，Cursor/agy 是终端视图），右边面板显示的人和配置一致。
3. 协作包开工时默认用这里配的执行员，不用再在命令里写。
4. **真跑一张小卡**：在测试项目里用聊天告诉调度员一个小需求，它写需求卡和方案、你批准、开工前弹“允许吗？”、点允许后三位执行员真干活、右边面板一步步走到“等你验收”。
5. 原有测试全部通过。
