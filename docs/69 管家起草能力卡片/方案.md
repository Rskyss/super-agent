# 拆解方案

## 要做什么（一句话）
按施工单 69 补齐后台能力，让积木库管家能查看积木块、起草能力卡片、用例子试做，并在用户确认后放进能力层。

## 拆成几步，每步做什么、产出什么
1. 给能力运行函数增加可选的草稿参数，只允许用 trial 模式试做，先查格式和编号，沿用原来的运行、成果和记录流程，试做不写能力层。
2. 给积木库管家接上 read_block、list_abilities、propose_ability 三个工具，按施工单处理模型名单、状态、截断提示和工具记录。
3. 按第 6 节原样新增《做能力》手册，并且只在管家规矩里补上施工单指定的两处文字。
4. 增加能力草稿提议，按顺序检查卡片、密钥、积木块和模型，标明同编号替换，并在同一段对话连续三次试做失败后阻止继续出草稿。
5. 补齐草稿确认、试做结果记录、保存标记和历史事件，让重复确认及重新打开对话都能拿到正确状态。
6. 接通从指定积木块新开对话和自动打开手册，并把最近一次试做的成功或失败情况告诉管家，失败原因先打码并限制长度。
7. 在积木库的发送和提议接口接入 block 与后台试做任务，检查例子和运行占用，重复确认返回同一个任务编号，运行异常也要记下失败结果。
8. 新增保存接口，只允许保存已经试做成功的草稿，检查同编号冲突和运行占用，写入来源及试做示例，重复保存只存一次，重启后已完成的草稿仍能保存。
9. 新增验收测试，用临时资料夹和假工具覆盖施工单列出的十一类情况，包括完整流程、错误草稿、失败次数、替换、重复点击、历史恢复及行政行为不变。
10. 运行施工单指定的全部测试并复查，按指定标题做一次提交，再交给 Claude 跑全量测试和真实工具接口剧本。

## 你会看到什么结果
后台接口支持从指定积木块开对话、出示草稿、试做和保存，重新打开对话还能读回草稿、试做结果和保存状态；本单不新增页面入口，页面交互由 69b 接上。

## 明确不做什么
不改 desktop/static/ 下的页面文件，不改已有测试及其他文件，不动项目窗口的行政，不改文档；不增加草稿措辞提醒，不支持直接在草稿上改模型或文字，不恢复服务重启前尚未完成的试做；自动测试不调用真实模型、搜索或命令行工具；不提交未命名绘图.drawio，不推送。

## 需要你确认的问题
无

## 做完后怎么看结果
这张单验收后台接口，页面入口等 69b 接好后再给用户点看；复查时通过接口走一遍“开对话→出草稿→填例子试做→放进能力层”，检查保存的卡片和试做示例。
