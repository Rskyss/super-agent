# 对比记录：写代码岗位，我们现在 / 自己接着说 / T3

> 2026-11-25，Claude 跑。**样本只有一件活，每种做法一次**，只能看出明显差别。没有请独立复查看代码质量，只看测试。

## 怎么比的

- 活：CARD-022（走查截图 卡 A）写代码那一步，从当时开工前的代码（14cae69）加上当时的测试重做。交代用当时原话，只把文件夹路径换成练习文件夹。
- 模型都是千问上的 DeepSeek V4.1 Flash，强度 xhigh，用户自己的插件都关。T3 是本机已装的 0.1.11，单独的资料文件夹，“自动”权限档，使用统计关。
- 我们的做法用开发助手自己的派活命令，没有照搬窗口、看门人和把关流程，所以和真跑卡仍有差别。
- 标准答案和判卷副本放在练习文件夹外面；会话记录里，三种做法的工具调用都没有出现真项目路径。
- 先跑我们，再跑 T3，不同时跑。返工顺序：新开 → 自己接着说 → T3。
- 返工题换过：原来两条退回意见我们第一遍已满足，没活可返；改成“走查记录要写用时”“同一原因连续几次”，加 3 项测试。判卷先验过：返工前 3 项全不过，Claude 的参考答案 53 项全过。

## 结论（口径：token 或用时少两成以上，做对次数不比现在少）

- **T3 不引进。** 合计用时多 14%、token 多 46%，测试都过，没有更好。
- T3 唯一明显的好处是返工快：比新开少 29% 用时，但返工 token 是新开的 2.4 倍。
- “自己接着说”合计用时少 3%、token 多 10%，没到两成，**也不改**。它返工比新开快 14%，token 是 2 倍。
- 如果额度把缓存按很低的价算，接着说可能反而便宜；千问 Token Plan 怎么算缓存没有查，不确定。
- 差别可能有偶然成分：第一遍两边都是各做一次，模型每次走法不同；T3 多出来的 token 有一部分来自它自带的工具说明，占多少没拆。

## 过程里的问题

- 准备时第一条后台跑因为缺文件直接失败，不算数（准备那条命令被安全检查拦下，没有删除任何东西）。
- 接力脚本第一次的等待写法有错，误以为 T3 停了，自己先退出；T3 第一遍没受影响，重挂后跑完。
- 练习文件夹的 Python 版本两边可能不同（T3 一边改动了 3.9 的缓存文件，我们一边没有），没有查；三份结果用同一个 Python 判卷，都全过。
