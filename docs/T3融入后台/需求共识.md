## 已查到的现状（11-25 实测，T3 0.1.11，临时资料文件夹，练习项目，Codex 订阅）

- T3 能不开窗口在后台运行，用命令派活、等结果、接着上一次说，都通。
- **直接指到施工副本会改到主项目**：实测改了主项目，副本没动。把副本单独登记成项目后正常：改在副本，主项目没动。
- 不同模型能先后在同一份副本里干活：GPT-6.1 Sol 改完，GPT-6 Luna 读到的是改后的内容。
- 权限用“自动”档时，写用户主目录被拦，和我们现在一样；默认档不设任何限制，不能用。临时文件夹两边都允许写（第一次越界测试放在临时文件夹里，写成功了，不算数，换位置重测）。
- token 没看到省（同一件两步的小活；T3 跑 3 次，我们 2 次）：

| 做法 | 第一次 | 返工一次 |
|---|---|---|
| 我们现在（每次新开） | 6.0 万、7.7 万 | 8.0 万、10.4 万 |
| 我们自己接着上次说（Codex 自带） | 同上 | 11.9 万、5.3 万 |
| T3 接着上次说 | 8.4 万、8.4 万、8.4 万 | 11.5 万、8.6 万、8.6 万 |

- 用时 T3 短：第一次 23～26 秒对 29～41 秒，返工 13～15 秒对新开 39～46 秒、自己接着说 32～47 秒。我们这边含启动用户 Codex 插件的时间，正式跑卡有时会关插件，差距可能没这么大。
- 这件活太小，没有多少项目要重读，**不能说明真卡的情况**。
- T3 或 Codex 会在用户的 Codex 设置里记一条“信任这个文件夹”，每个登记的项目可能都有。
- 没试：千问、腾讯云的 API，agy，停下，卡住时看不看得出来，T3 对外接口里“绑定已有副本”的用法（它要人工授权，30 天一次）。
- 我们所有派活都走同一个出口，要接的话位置清楚。

## 不做

- 不换开发助手的窗口、卡片、右栏、规则包、把关流程。
- 不搬 T3 源码，不改 T3 源码。
- 不动行政聊天、写测试、复查岗位；不动超级玩家。
- 不升级、不改用户平时用的 T3；试跑用单独的资料文件夹。

## 怎么算验收通过（第一步：对比）

1. 一件写代码的活（T3 明显更好再补第二件），用三种做法各跑一次：我们现在、我们自己接着上次说、T3；每件都含一次返工。
2. 三种做法的起点相同、要求相同、模型相同（千问上的 DeepSeek）。
3. 交一张表：token、用时、测试过没过、有没有出错，附原始记录位置；样本少，结论里写明。
4. 主项目没被碰过，有前后核对。
5. 按口径 7 给结论：引进、不引进，还是只做“我们自己接着上次说”。

引进的话，再写《方案》《任务清单》给用户批。

## 泼冷水

- 小活上 T3 第一次反而多用约一到四成 token（它自带一批工具说明）。返工也没有明显省。**目前没有证据说它能让跑卡变便宜。**
- 跑卡贵和停下，train 的记录里主要是施工单没定清和复查来回，T3 管不到。
- T3 升级快，接上以后每次升级都要重新验一遍“会不会改到主项目”。
- 对比要花额度：CARD-026 写代码三次共约 833 万 token。按两件小活、三种做法、各一次返工估，大约 1000 万～2500 万，**是估计**。
- 样本只有两件，只能看出明显差别，看不出小差别。
