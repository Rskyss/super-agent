# 轻量版开发流程：需求共识（⏸ 搁置）

> **11-28 用户定搁置**：“我不是重新开发一个产品……开发助手和 Gemini 它的时间基本上是一样的吧。”数据也支持：两条路慢都慢在复查来回，开发助手本身已有复查上限。改为在开发助手上修具体毛病，见 `docs/无人值守与飞书拍板/需求共识.md`。下文留档备查。

> 11-27 用户：“我越想做自己的一个小产品小工具”“不想在 Orca 里做”“仔细看看咱们轻量版的开发助手，看看如何完成顺畅的开发流程”。
> 本文只定“做什么、不做什么、怎么算成功”，不写代码。用户批了再出《方案》。

## 一、为什么要换（这批 train 的实际证据）

| 现象 | 证据 | 病根 |
|---|---|---|
| 开发助手慢、费 | 卡 16 从 19:32 跑到 21:4x 还没放进项目，一批用掉约 2700 万 token | 程序在写测试、写代码、复查三个模型之间接力传话，每次交接都丢信息、要重读 |
| Gemini 自己写快 | 卡 17 自己写 26 分钟就到复查 | 少了接力 |
| 但复查没完没了 | 卡 17 复查 7 轮，挑的越来越边角（超长组号、空列表） | 复查不用证明、每轮从头挑、没有收手线；信里写“最多 2 轮”没人照做 |
| 规矩写了不照做 | 施工单没提交就开卡、跳过写方案、悄悄改老测试、改了范围外文件不登记 | 只靠模型自觉，没有程序拦 |
| 老毛病挡路 | 全部测试本来就不过（v0.91 留下），程序分不清是谁改坏的 | 开工前没记“改之前就不过的” |

结论：**慢在接力，乱在没规矩拦。** 轻量版去掉接力，把规矩交给程序。

## 二、一句话定位

**看不懂代码的人带着一个想法来，它帮着把想法对齐清楚，再自己从头做到完，交出一个能跑起来、验收过的产品。** 部署上线不在范围内（用户自己或让别的模型做）。

> 初衷（11-28 用户）：“让不懂开发、看不懂代码的人……能完成我的想法，帮它给落地掉，生成出一个完整能跑起来的产品。”“部署的事情我自己可以来。”“开发助手，这是个应用……要把它开发成能用。”现阶段先给用户自己用，以后再考虑普通人。

怎么做到：家里挂着一套流程，用户在外面也能发需求，最后给一张看得懂的验收单。
程序当“流程表 + 关卡”（现在该做哪步、做完了查不查得过），不当“传话员”（不在几个模型之间来回传话）。一个总管模型从头干到尾，复查和走查交给另一家。

> 第一优先（11-27 用户补）：“有时候在外面，我可以通过 Muse 或者 Codex 给它指令……就相当于我在家里主机上面挂着一台开发助手……我没有一个流程让它开发完整，这是我为什么要做开发助手的原因。”只有 Antigravity 客户端做不到这一点。

### 远程下需求、无人值守跑完
- 入口：用户在外面用 Muse、Codex 或飞书把需求发到家里电脑上挂着的总管。
- 总管按流程表一步步走；每步做完调程序检查，不过关程序不放行。
- 碰到红线（删数据、推送、对外、改规则包、花钱）停下给用户发消息；其余按《产品经理》“用户不在时”自己定、记进替你定的清单。
- 做完把验收单和走查截图发给用户。
- 合规：总管用 Codex 时远程入口随意；总管用 Gemini 时，远程只能走 Antigravity 官方远程控制，程序不反过来调 agy。

和别人的区别：Orca、T3、pstack 解决“同时开好几个 AI”，默认用的人看得懂代码、自己判对错。我们解决“看不懂代码的人也能放心验收”。

## 三、流程（五步）

```
① 对齐 ── ② 开工检查 ── ③ 写代码 ── ④ 交活检查（最多 2 轮复查）── ⑤ 真实网页走查 ── 验收单给用户
   人+总管       程序            总管/写手        程序 + 另一家复查              另一家 + 浏览器
```

1. **对齐**（用户 + 总管模型）：从一个想法开始，产品问题出成选择题给用户拍板，技术问题自己定；写需求共识和每张卡的施工单。施工单必须有：允许改哪些文件、用户能看到的验收标准、**容易漏的边角（上限、空的时候、退出的组、老数据）**、界面卡的走查步骤。
2. **开工检查**（程序）：施工单进了项目没有、该有的节齐不齐、界面卡有没有走查步骤；**先跑一次全部测试，记下“改之前就不过的”**，以后只算新改坏的。不过关不许开工。
3. **写代码**：先由**另一家**照施工单写验收测试，程序锁住，总管不许改（11-27 卡 18 Gemini 自写测试改了约 20 次，测试和代码同一个模型写等于自己判自己）；再由总管写代码。每张卡单独一个分支。程序不在中间传话。
   - **看门**：总管 N 分钟没动静，程序能重启就重启，重启不了给用户发消息（11-27 卡 18 半夜挂掉，空停 9 小时没人知道）。
4. **交活检查**（程序，一条命令）：
   - 硬关：卡的测试过没过（只看结果，不听模型自述）；全部测试和第 2 步比，有没有新改坏的；有没有改出允许范围；有没有删掉、跳过、改松老测试；有没有把密钥写进代码。
   - 复查：叫**另一家**模型（现在是 Codex）。第 1 轮交代写死“每个问题要用跑不过的测试或可复现的命令证明，证明不了的不写，标严重/中等/小”；第 2 轮只核对上轮问题改好没有。程序重跑每条证明，复现不了的自动丢掉。
   - 收手线（程序数）：严重、中等的改；小的进《以后再修》；第 2 轮还有严重的就停下找人，**不给开第 3 轮**。
5. **真实网页走查**（另一家模型 + 浏览器）：照施工单的走查步骤真点一遍，每步截图；不通的回到第 3 步改，同一处 3 次不通就停下记下。

收尾：程序生成**验收单**（产品语言）：每张卡用户能看到什么、走查截图、替你定的清单、以后再修清单、用时和 token。

**程序怎么拦住“不照做”**：在项目里装一个提交拦截——卡分支要合进主线，必须有这张卡“交活检查通过”的记录，否则合不进去。不靠模型自觉。

## 四、做 / 不做

| 做 | 不做 |
|---|---|
| 开工检查、交活检查、走查、验收单 | 派活、在模型之间接力传话 |
| 复查必须有证明、分级、最多 2 轮 | 部署上线（用户自己做） |
| 一个能用的应用窗口：发需求、看进度、停/接着跑、看验收单（沿用现有窗口，做减法） | |
| 记“改之前就不过的”，只算新改坏的 | 多副本并行、看代码界面（官方软件和 Orca 已经有） |
| 一份给总管模型读的规矩（几十行，放进项目） | 积木库、能力、团队页 |
| 支持 Python 和网页项目（train 是网页项目，现在的全部测试关只认 Python） | 自动轮换账号、借登录调模型 |

## 五、从开发助手拿什么、扔什么

- **拿**（已经被真卡磨过的）：判过没过只看结果、允许范围核对、老测试被改提醒、“改之前就不过”比对、复查意见读取、token 统计、规则包里的产品经理口径。
- **扔**：派活和接力（dispatch.py 约 4700 行）、写方案、窗口界面、积木库和能力、看门人。
- 开发助手本身：停在 v0.95 不再加功能，留着以备回看。

## 六、合规

模型都在各自官方软件里干活；小工具只叫 Codex 复查和走查（Codex 官方允许程序调用）。总管用 Gemini 时，是 Gemini 在 Antigravity 里调小工具，不是小工具调 agy。

## 七、怎么算成功（下一批真卡对比 train 0.93 批）

- 每张卡从开写到可验收：比这批少一半以上；
- 复查轮数：每张不超过 2；
- token：比开发助手接力少一半以上；
- 用户被打断次数：只剩“红线”那几类；
- 走查每步有截图，验收单用户不看代码能看懂。

## 八、要用户拍板的

1. **默认分工**：Gemini 当总管兼写代码、Codex 复查加走查；或 Codex 当总管、Gemini 复查。牵涉远程入口：总管是 Gemini 只能从 Antigravity 官方远程控制下需求，总管是 Codex 可以用 Muse、Codex、飞书。
   **推荐 Codex 当总管**（11-28）：无人值守挂了程序能重启它、token 读得到、远程入口随意；Gemini 当总管时挂了程序只能报信，用量读不到。Gemini 可以当复查或对齐需求的那一家。
2. **放在哪**（11-27 改推荐）：在开发助手里做减法，拿掉传话接力、留下流程表和关卡，当 v1.0；不另开项目（检查代码、4000 多项测试、规则包都在这里）。
3. **窗口保留**（11-28 改）：轻量版本身是个能用的应用，沿用开发助手现有窗口做减法，只留发需求、看进度、停/接着跑、看验收单。
4. **第一批拿什么试**：推荐 train 下一批需求。
