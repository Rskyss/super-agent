# 拆解方案

## 要做什么（一句话）
按施工单 71 完成列表链接、模型试用、npm 命令核对、搜索跳转和密钥识别五项修复，并通过指定测试与 Claude 复查。

## 拆成几步，每步做什么、产出什么
1. 五项修复都先在新增验收文件中写测试、确认失败，再修改代码让测试通过，页面逻辑用 Node 测试，网络情况用本机假服务模拟。
2. 在 abilities_core.js 中新增共用的 safeLink，去掉地址首尾空白后只接受 http/https，并让能力详情和聊天列表都通过它决定显示链接还是标题文字，保留摘要和原有链接属性。
3. 给模型试用查询增加连续失败计数，请求错误和 404 都计入失败，连续第三次失败就停止并提示“查不到试用结果（本机服务可能重启过），请再试一次”，查询成功就清零，并沿用现有回调恢复按钮和清理任务状态。
4. 在 npm 安装核验中检查最终命令名是否在包登记的命令清单里，不在就拒绝并按原顺序列出可用命令，未填写命令时沿用默认值，空清单及其他安装方式保持原有规则。
5. 让 _request_json 使用与 _open 相同的不跟随跳转的打开方式，保留超时、正文大小和 HTTPError 处理，确认搜索跳转时报错、跳转目标收不到请求且报错不含密钥，正常 200 响应仍能读取。
6. 在密钥识别规则中补上 pplx-、gsk_、fw_ 三种格式及原有边界要求，覆盖独立出现、夹在句中和普通短词不误判的情况，测试假密钥全部现场拼接。
7. 覆盖施工单验收中的正常、连续失败、成功后计数清零、404、npm 命令不匹配和搜索跳转等情况，并运行第 7 节全部测试，老测试失败时修代码，确认老测试本身有误则停下交给 Claude。
8. 交由 Claude 做全量验收和真实窗口走查，复查通过后以“施工单 71：精读报告第一批修复（积木库和安全加固）”为标题一次提交。
