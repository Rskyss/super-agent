# 流程修理：任务清单

依据：[方案](方案.md)。每条：先写会失败的测试 → 改到过 → 相关测试全过 → 勾掉。三批连着做，全部做完：全量 → 端到端走一遍 → Codex 分三块复查 → 改完给用户看。

## 第一批：流程

- [ ] 1. 最后回复（㉑⑳）：`ask()` 拿到最后一条回复；流转“回复”存它；复查结论从最后回复里认最后一个“结论：”。验收：带未闭合代码块、带提示词原文的长输出也认对；Codex 命令带 `-o`。
- [ ] 2. 空回复算没完成（⑳）：退出码 0 但没有任何回复文字 → 再试一次，仍空 → 没完成。验收：假工具空回复两次 → 卡住，原因写明“没有回复任何内容”。
- [ ] 3. 复查不通过自动退回（⑧）：最多 2 次，意见只给最后回复（最长 8000 字），不加返工次数；第 3 次不通过转卡住，原因带意见。验收：假复查员连续不通过 → 开发员被派 3 次、复查 3 次后卡住；中途通过 → 待验收。
- [ ] 4. 写测试的只动测试（⑱）：测试员交活后测试目录外的改动撤掉、记“范围”，不进测试文件清单。验收：假测试员改 `desktop/x.py` 和 `tests/test_x.py` → 前者被撤、后者进清单。
- [ ] 5. 继续改只补测试（⑭⑫）：`revise_card` 保留基线；测试员“补测试”提示；以前的测试文件保留。验收：追加要求后派活原文含“只为追加要求补测试”，不含整卡重写；测试文件清单保留旧的。
- [ ] 6. 只跑本卡测试（⑮）：测试员、复查员、开发员提示里写明本卡测试命令，并写“不要跑全部测试”。验收：三种派活原文都含测试命令。
- [ ] 7. 写代码的能跑测试（⑯⑰）：Cursor 派活前在副本写 `.cursor/cli.json`（放行测试命令的程序、关 MCP），该文件不算改动、不进项目；实测 Cursor 真能跑、真不开浏览器。验收：单元测试 + 一次真实 Cursor 小试。
- [ ] 8. 看门人看输出（㉓）+ 没动静提醒（⑲ 第一步）：实时输出在涨不算安静；5、10 分钟没动静记“提醒”；行政播报“提醒”。验收：假工具只涨输出不改文件 20 秒（缩短时限）不被停；不涨也不改 → 记提醒、到时限停下。
- [ ] 9. 接受剩下的问题（㉒）：状态“需Claude介入→待验收”；本机服务 `accept_issues`；阶段只在复查不通过卡住时给这个按钮；右栏按钮和确认。验收：接口测试、阶段测试、页面检查脚本。
- [ ] 10. 放进项目不误拦（㉔）：已和项目一样的文件不算越界。验收：卡片分支里有“已在项目里的测试提交” → 放进项目成功。
- [ ] 11. 已有施工单不重写方案（⑦）：认出任务卡片里的施工单路径，提示只摘范围和测试命令。验收：提示词测试。
- [ ] 12. 行政答进度读最新（⑬）：查清原因后修；卡住时说原因和下一步。验收：卡住状态下问进度的回答里有“卡住”和按钮名。

## 第二批：团队配置

- [ ] 13. 每岗位模型（①）：配置按岗位存；老配置自动迁移；派活、写方案按岗位取。验收：两个 Codex 岗位不同强度，派活命令各用各的。
- [ ] 14. 团队页按岗位显示和保存模型（①）。验收：页面检查脚本。
- [ ] 15. 保存不悄悄丢（②）、离开前问（④）。验收：页面检查脚本。
- [ ] 16. 检测到时间一定给结果（③）：查清页面没收到结果的原因后修。验收：假工具卡住 → 页面显示“没通（超时）”。

## 第三批：体验

- [ ] 17. 标题下一行“此刻在干什么”（⑪）。验收：右栏数据测试 + 页面检查。
- [ ] 18. 项目窗口行政“说了点确认却没出框”提醒（⑥）。验收：识别测试。
- [ ] 19. 代理设置（⑩）实测：有影响再修，没影响记“不修”。

## 收尾

- [ ] 20. 全量测试；端到端：用超级助手程序跑一张小卡（假工具 + 一次真实 Codex/Cursor），走复查不通过自动退回、继续改、带问题放行、放进项目。
- [ ] 21. Codex 分三块复查（流程、团队配置、体验），改完。
- [ ] 22. 文档：collab 调度手册和规则、README、试跑记录（问题状态改“已修”）、台账；完工报告给用户（含替用户定的清单）。不推送。
