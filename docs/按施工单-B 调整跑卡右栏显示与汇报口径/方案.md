# 拆解方案

## 要做什么（一句话）
按施工单 B 统一跑卡右栏的三层显示、用时用量和测试通过数，并让执行者用大白话汇报。

## 拆成几步，每步做什么、产出什么
1. 先读施工单 B 和已有验收测试，确认 Node.js 可用且没有其他测试正在运行，再记录验收与全量测试的改前结果，方便区分原有失败和本次新增失败。
2. 只在新建的 tests/test_flowfix_b_extra*.py 中补充缺失用时、用量读取失败、多轮返工、中断续跑、首次显示与刷新一致，以及测试命令回退等边界检查。
3. 在 desktop/view.py 中按角色收集全部回复，为写测试、写代码、复查补上每轮明细 history、累计用时 spent 和轮数 rounds，其中执行中或中断中的当前轮也计入轮数，没有任何用时记录时保留为空，未开始的环节不增加这些字段。
4. 把已交活环节的第二行改为只显示最后一次回复的结果，删除追加“用了几分几秒”的旧拼法，并保留其他环节原有行为。
5. 在 desktop/static/panel.js 中新增统一的 metaText，按施工单处理各状态的轮数、计时、最近动静和累计用量，缺失段直接省略，首次绘制和定时刷新都调用这一份。
6. 在 desktop/static/panel.js 中新增 stepTitle 和 totalTitle，把结果全文、每轮用时用量及用量说明放入鼠标提示，并让 totalText 只显示“本卡合计 N token”。
7. 删除被替代的 tokenText、clockText 和刷新时单独拼文字的代码，把 mmss、ago 移到与 tokenAmount 同层的位置，所有调用共用唯一实现。
8. 在 desktop/static/panel.css 中将结果文字限制为最多两行，并用已有线条颜色给本卡合计增加上方细分隔线和适当留白。
9. 在 collab/dispatch.py 中要求汇报用大白话且“不写文件名”、函数名和命令，同时将本卡测试命令传给 ProgressJob。
10. 在 collab/progress.py 中给 ProgressJob 增加默认空字符串的 test_command 参数，当按 && 拆出的每段都是 python 或 python3 的 unittest 命令时在副本中逐段执行并累计通过数，否则沿用只跑本次交出测试文件的办法。
11. 检查 ProgressJob 的启动条件，确保只有预先写好的验收测试、没有新交出测试文件时也能按本卡命令统计，并沿用原来的超时、运行失败和导入报错处理。
12. 运行指定验收命令和 python3 -m unittest discover -s tests，对照改前结果确认没有新增失败，再核对旧拼法已删除、改动未越界，并打开右栏检查三层显示和鼠标提示。

## 你会看到什么结果
右栏清楚显示谁在做、做出了什么、跑了几轮及用了多少资源，首次打开与刷新后的格式一致，没有多余分隔点，测试通过数也包含事先写好的验收测试。

## 明确不做什么
不改复查红叉、确认弹窗和“以后再修”；不改跑卡规矩、行政的话、左栏、中间对话区及正在执行时第二行的实时进展；不改已有验收测试和 Claude 已改好的四个老测试；不删未被替代的代码，不动允许清单之外的文件。

## 需要你确认的问题
无

## 做完后怎么看结果
点击打开后查看任务卡右栏，重点看多轮执行的环节：结果最多两行，下方小字没有多余的“·”，刷新前后格式一致；鼠标停在环节上查看每轮明细，停在本卡合计上查看其他用量，并核对“通过 x/y”包含预先写好的验收测试。
