## 开工前实测（11-26）

- **tsx 能出报告**：在 train 的副本里（train 本身没动）照它的全部测试命令跑，环境变量 `NODE_OPTIONS` 加上 spec 和 JUnit 两个报告开关，命令一字不改。报告里 579 个用例加 5 个带子测试的父测试，共 584 项，和屏幕汇总一致；没过的 6 项和屏幕上的一致。
- **报告里有什么**：每项都有文件、所在分组（嵌套的 describe 一层层套着）和名字；文件加载就报错时，算一项，名字是文件路径；TODO 项失败了会同时标“跳过”，不算没过。
- **node 报告的坑**：父测试的子测试都过了、父测试自己断言失败时，**报告里不记这次失败**（汇总里记了）。所以不能只数报告里标了失败的项，要拿汇总核对，对不上就停（见下面“认全”）。
- **pytest**：`PYTEST_ADDOPTS` 加 `--junitxml=… -o junit_family=xunit1`，每项带文件、行号、类名；失败、出错算没过，预期失败算跳过。
- 样例存在 `tests/fixtures/结构化报告/`（报告、屏幕输出、测试源码，路径换成 `/副本`）。

## 名单

`<项目>/.collab/已知没过.json`（不进代码仓库；全部测试读主项目这一份）：

```json
{"items": [{"file": "tests/x.test.ts", "tests": ["甲组 > 保存"], "kind": "等卡", "card": "CARD-031",
            "by": "Claude", "at": "2026-11-26 21:00", "why": "验收测试先放进项目，等卡 31 做"}]}
```

- `tests` 为空 = 整个文件；不空 = 只这几项（同文件别的项坏了照样挡）。
- 项的写法：node 是“分组 > … > 名字”；pytest 是“类 > … > 名字”（参数原样带着）；Python 逐文件跑的是“模块.类.方法”（和先红名单同一写法，子测试归到方法）。挡下来的时候程序把认出的写法原样列出来，照抄登记即可。
- 命令：`collab known-fail add|list|remove`，每次增删记台账一行；卡放进项目时自动撤“等卡 这张卡”的条目，也记台账。

## 怎么认“哪几项没过”（collab/fullrun.py）

**拆步**：项目配的全部测试命令只由 `&&` 连起简单命令时，拆开在同一份副本里按顺序各跑各的（前一步没过也接着跑），每步各自出报告；带 `| ; || ( ) $( 反引号 重定向` 这类写法的，整条当一步跑，**不用报告**（多个测试工具会写同一份报告，互相覆盖）。

**每步的结论**：
- 过了：不看报告。
- 没过、有报告：从报告读没过的项。必须**认全**才算数，否则这一步记“认不全”并写原因：
  - node：报告读得完（末尾有汇总）、取消数为 0；屏幕上只有一个“ℹ tests N”且 N 和报告一致（一步里跑了两次测试工具就会对不上）；用例数加父测试数等于汇总的项数；汇总的没过数减去报告里标了失败的用例数，差额必须全能用“含有失败子项的父测试”解释（不然就是有父测试自己失败、报告漏了）。
  - pytest：报告里失败数加出错数等于标了失败、出错的项数；屏幕上只有一行最终汇总。
  - 没过却一项也没读出：认不全。
- 没过、没报告（不是测试，或测试工具没出报告）：记成“这一步没过”，按老规矩和改之前比。

Python 项目（逐文件跑）照现有办法：失败项、导入报错、汇总数核对都不变，只是多一步对名单。

## 全部测试这一关怎么判（dispatch._FullSlot，复查时跑的那次）

1. 有任何一步“认不全” → 停下，写清哪一步、为什么。
2. 没过的项分三堆：名单里“等卡”的、名单里“偶发”的、名单外的。
3. 有“偶发”的 → 把它所在那一步（Python 项目是那个文件）单独重跑一次；重跑后它过了才算，还不过就挪进名单外。
4. 名单外没有、也没有“没报告的步骤没过” → **放行**；流转记“全量”，结果写真实的“没过”，摘要写“名单里 N 项（等卡 X）没过，不算这次改坏”。
5. 否则在改之前的版本上同样拆步再跑一次比：
   - 名单外的项改之前是过的（或改之前没有），或没报告的步骤改之前是过的 → **退回写代码的**，把这几项单独列出来（不放进会被截短的输出里）。
   - 都是改之前就不过的 → **停下**：“这几项不在名单里、改之前也不过，先登记或修好”。
   - 改之前那次认不全或没跑成 → 停下。
   - Python 项目照现有逐文件比、单独重跑分辨“测试自己不稳”的老规矩，只是比的是名单外的那些。

## 人工“接受剩下的问题”（collab/accept.py）

全部测试没过时，如果没过的全是名单里“等卡”的（没有认不全、没有没报告的步骤没过），照样接受，记录写明“名单里 N 项没过，不算”。其余照旧拦。
