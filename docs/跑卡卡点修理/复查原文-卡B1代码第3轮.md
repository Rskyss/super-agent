### 1.【严重】功能回归：一行没收尾的日志，会吞掉下一条真失败

`_UT_LINE` 比 HEAD 多匹配了 `UNEXPECTED SUCCESS`。括号里的 `[^)]*` 可以跨行。只要失败消息里有一行 `UNEXPECTED SUCCESS: cached (`，它就会一直读到下一条 `FAIL` 标题的右括号。随后 `_ut_failed` 丢弃这条“意外通过”，连真正失败的测试名也一起丢了。[fullrun.py 第 320 行](</Users/rs/Desktop/project/开发助手-worktrees/CARD-029/collab/fullrun.py:320>) · [第 327 行](</Users/rs/Desktop/project/开发助手-worktrees/CARD-029/collab/fullrun.py:327>)

我用两个版本的 unittest 各真跑了 3 个测试。`test_anchor` 一直失败，它的断言消息含上面那行文字。改前另一项失败的是 `test_old`，改后换成 `test_new`。两次汇总都是 `failures=2`。把原始输出送进各入口，结果如下。

| 入口 | HEAD `072f008` | 当前副本 |
|---|---|---|
| `_broken_by_change`、`culprits` | `['tests/test_review.py']` | `[]` |
| `tally`、无先红名单的 `ProgressJob` | 通过 1/3 | 通过 2/3 |
| `ProgressJob`，先红名单含 `anchor` 和 `new` | 通过 0/2 | 通过 1/2 |
| `_red_check_one` 写出的名单 | `test_anchor`、`test_new` | 只有 `test_anchor` |
| `failing_files`，给或不给项目根目录 | 文件下有两项 | 漏掉 `test_new` |
| 全量测试收尾 | 点名文件，退回开发 | 停在“认不出是哪几项，需要你看看” |

**改法**是直接恢复 HEAD 的失败行正则，只匹配 `FAIL`、`ERROR`，删除事后过滤 `UNEXPECTED SUCCESS` 的分支。把这对真实输出加入验收。我在内存里试了这个改法，31 份单独输入、961 对输入与 HEAD 的差异全部归零。
