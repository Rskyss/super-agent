# 需求共识：左栏列表的删除和归档

状态：2026-11-07 ✅ 用户确认方向（“可以的”）。细节口径见《方案》，批准后生效。

## 用户原话

“左边列表这一块，不管是主对话还是等待处理这个 tab 下面的这些列表，这些是可以删除的。还是叫做归档好？”

## 定下的口径

1. 主对话用“删除”：真删，找不回来，删之前要确认。
2. 等待处理里已结束的卡片用“归档”：只是从列表收起来，能找回。
3. 卡片没有“删除”。没结束的卡不能归档，不想做的继续用“放弃这个需求”。
4. “归档”只保留这一个意思。卡片放进项目时存记录的那句话改成“记录已存入项目文档”。

## 为什么这样分

- 主对话主要是聊天过程，真正要做的事会变成卡片，卡片有自己的记录。
- 卡片连着后台施工和项目里的改动。“删除”会让人以为改动也撤掉了，其实还在项目里。

## 不做

- 主对话归档、回收站、删除后撤销。
- 批量删除、批量归档。
- 删除卡片，或清理卡片占用的硬盘空间。

## 怎么算验收通过

- 行政和 Codex 两种模式下，主对话都能真删，重开软件不会回来。
- 已完成和不做了的卡能归档、能找回；其他卡没有归档入口。
- 归档和取消归档都不改变项目文件、项目文档和卡片记录。
- 真实窗口走通，测试全过，独立复查做过。
