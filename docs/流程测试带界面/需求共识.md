# 需求：开发流程的测试关带上界面测试和编译

> 2026-11-17 用户改口：暂不用超级玩家开发，改为 Claude 写需求和规划 → Codex（gpt-6.1-sol 高）写测试 → DeepSeek V4.1 Flash 写代码 → Codex（gpt-6.1-sol 极高）复查。方案见 [方案](方案.md)，任务见 [任务清单](任务清单.md)。
> 来历：起用超级玩家开发自己的前提②（台账“起用超级玩家开发自己的三个前提”一节，2026-11-17 用户批“两步走”）。

## 一、要解决的问题

“开发软件”流程现在只认后台 Python 测试：
- 第 2 步“新测试全过”：本卡测试如果是界面插件测试（`dsh-plugin/core/tests/*.spec.ts(x)`），没有地方能跑；
- 第 3 步“跑全部测试”：`collab/fullrun.py` 只跑 `tests/` 下的 Python 测试，不跑插件测试、不编译。

结果是改了界面的卡也会显示“全部通过”，其实界面部分没人验过。

界面测试和编译只能在 DSH 底座目录里跑（`~/Desktop/project/dsh-base`，约 3.7GB，锁定版本 0.2.2-rc.3）。**用户正在用的超级玩家就是从这份底座编出来的**，所以卡里的代码绝不能同步进这份原件。

## 二、做法（Claude 已实测可行，2026-11-17）

每张需要的卡用一份**底座的写时复制副本**（APFS 克隆，`cp -c -R`），所有同步、编译、插件测试都在副本里做：

| 实测项 | 结果 |
|---|---|
| 克隆 3.7GB 底座 | 24 秒，磁盘只多用约 1GB |
| 在副本上跑 `dsh-plugin/sync.sh <副本目录>` | 36 秒，编译 10/10 通过 |
| 在副本里跑 `npx vitest run packages/superagent/core/tests/` | 14 秒，423/423 通过 |
| 原件 | 没被改动（核对了修改时间） |

实测发现的三个坑，必须处理：
1. 底座里 `apps/desktop/.desktop-build/` 有 1573 个指向原件的绝对路径链接（打包产物）。克隆后要先删掉副本里的这个目录，否则编译或测试可能透过链接写进原件。删掉后编译、测试都不受影响（已实测）。
2. 有两份插件测试按“底座目录的同级目录 `super-agent`”找产品代码（`legacy-revision-ui.spec.ts` 第 14 行、`revision-rule-parity.spec.ts` 第 8 行）。副本要放在一个临时文件夹里，并在旁边放一个名叫 `super-agent`、指向**本卡施工副本**的链接，否则这 4 项测试会失败。
3. `sync.sh` 里会执行 `pnpm install`，会改副本里的 `pnpm-lock.yaml`。这只发生在副本里，没关系；但不许对原件执行。

## 三、要做到什么（验收标准）

1. **只对本项目生效**：项目里有 `dsh-plugin/sync.sh` 才启用这套做法；其他项目（比如测试项目）流程行为和现在完全一样。
2. **第 2 步能跑本卡的界面测试**：写测试的人写一条简单命令，就能跑本卡的插件测试文件。建副本、同步插件、编译都由流程负责，写测试的人不用知道副本在哪。这条命令要写进给写测试和写代码的人的说明里。
3. **第 3 步“跑全部测试”包含三样**，三样都过才算过：
   - 现有的 Python 全量（不变）；
   - 用本卡代码在副本上跑 `sync.sh`，编译全部通过；
   - 副本里插件测试全量通过。
   任何一样没过，就像现在 Python 没过一样，带着失败的那几项退回写代码。
4. **本卡没改 `dsh-plugin/` 的**，第 3 步可以跳过编译和插件测试，但卡片上要写明“本卡没动界面，没跑界面测试”，不能悄悄跳过。
5. **原件一个字节都不碰**：流程任何时候都不在 `~/Desktop/project/dsh-base` 里写东西、跑同步或编译。要有测试证明：例如把底座路径指向一个假目录，跑完后它的内容和修改时间都没变。
6. **副本会清理**：卡合入、放弃或停掉后删掉它的副本；应用启动时清掉没人用的旧副本。克隆前查一下磁盘剩余空间，不够（少于 10GB）就停下并说明原因，不硬跑。
7. **跑测试的环境仍然隔离**：现在的全量测试只给 python3、node 和系统目录，AI 工具找不到。新加的步骤可以额外放行 pnpm、npx，但仍不许找到 codex、cursor、agy、qwen 这些工具。
8. **卡片进度照现有规矩显示**：每步最多 3 行大白话，有计时；建副本、编译、插件测试各自显示在跑什么、用了多久。
9. **停工能停干净**：用户停卡或退出应用时，编译和插件测试的进程要和现在的测试进程一样被收掉。

## 四、不许碰的

- `~/Desktop/project/dsh-base` 原件；
- `dsh-plugin/` 下的产品代码（这张卡只改流程，不改界面）；
- 现有测试只许新增，不许改老测试的本意；
- 窗口外壳（`desktop/mac/`）不碰。

## 五、不在这次范围

- 合入后自动重装正在用的超级玩家（仍由 Claude 手动 `build.sh --install`）；
- 在真实窗口里自动走查界面（仍由 Claude 在你验收前补做）。

## 六、做完后 Claude 要补的验收

- 用一张**只改了一行插件代码的假卡**真跑一遍：第 2 步能跑界面测试，第 3 步出现编译和插件测试，并且故意改坏时能退回；
- 核对原件没被改、副本已清理；
- 在台账登记。
