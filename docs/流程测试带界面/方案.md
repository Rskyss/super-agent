## 1. 总体做法

新增一个模块 `collab/dshcopy.py`（“底座副本”），负责：建副本、在副本上同步编译、在副本里跑插件测试、清理。现有两处接进来：

```
第 2 步 本卡测试 ── 测试命令写 `python3 -m collab ui-test <测试文件…>` ──┐
                                                                         ├─> dshcopy：克隆底座 → 同步编译 → vitest
第 3 步 全部测试 ── _FullSlot / FullRunner：Python 全量之后 ────────────┘
卡结束 ── merge.remove_copy 顺带删本卡的底座副本；应用启动时扫掉没人用的旧副本
```

## 2. 模块 `collab/dshcopy.py`

### 2.1 什么时候启用
- `applicable(tree)`：`tree/dsh-plugin/sync.sh` 存在才启用。其他项目一律返回 False，流程行为完全不变。
- `touched_ui(worktree)`：本卡相对它的起点（施工副本 HEAD）有没有改 `dsh-plugin/` 下的文件，包括已提交和未提交的改动。没改就不跑界面部分。

### 2.2 底座原件位置
- 默认 `~/Desktop/project/dsh-base`；环境变量 `SUPERAGENT_DSH_BASE` 可覆盖（测试全靠它指向假底座）。
- 原件**只读**：本模块对原件只允许 `cp -c -R` 读取，以及读取 `package.json` 核对版本（同 sync.sh：name 为 `@deepseek-ai/dsh-root`，version 为 `0.2.2-rc.3`；不符就报“底座版本不对”，不硬跑）。

### 2.3 建副本 `make(source_tree, key, stop) -> Path`
1. 查磁盘剩余空间（`shutil.disk_usage`，看副本要放的位置）：少于 10GB 就返回明确错误“磁盘剩余不到 10GB，没建界面测试副本”，不克隆。
2. 副本放在 `<临时目录>/collab-dsh/<key>/`，里面两个东西：
   - `dsh-base/`：`cp -c -R <原件> <这里>`（APFS 写时复制，24 秒左右）；
   - `super-agent`：指向 `source_tree` 的符号链接（两份插件测试按“底座同级目录 super-agent”找产品代码）。
3. 克隆后立刻删掉副本里的 `apps/desktop/.desktop-build/`（里面 1573 个链接指回原件）。
4. 删完后检查副本里不再有解析到原件里的符号链接（`find <副本> -type l` 后逐个 `os.path.realpath`，落在原件路径下的算）；有就删掉整个副本并报错，不继续。
5. `key` 由施工副本路径算出（例如路径的短哈希 + 卡号），同一张卡重复调用复用同一份副本，不重复克隆。
6. `cp` 不支持 `-c`（不是 APFS 或不同卷）时报错，不退化成普通复制（普通复制要 3.7GB 和几分钟，不能悄悄这么做）。
7. 所有命令走 `fullrun._quick` / `run_command` 那套：有时限、自成进程组、登记在 `_GROUPS`、会响应叫停（第 9 条验收）。

### 2.4 同步编译 `build(source_tree, copy, env, stop, timeout) -> Verdict`
- 跑 `<source_tree>/dsh-plugin/sync.sh <copy>/dsh-base`。**必须显式传副本路径**：sync.sh 不带参数默认写原件。
- 结果按退出码判：0 → PASS；非 0 → FAIL，输出里截取 `run-gates: FAIL` 那几行放在最前面。
- 超时：10 分钟。

### 2.5 插件测试 `vitest(copy, files, env, stop, timeout) -> Verdict`
- 在 `<copy>/dsh-base` 里跑 `npx vitest run <文件…>`；不给文件就跑 `packages/superagent/core/tests/`。
- 传进来的文件路径是相对产品仓的（`dsh-plugin/core/tests/x.spec.ts`），要换成副本里的 `packages/superagent/core/tests/x.spec.ts`。
- 认结果：解析 vitest 的 `FAIL <文件> > <测试名>` 行和 `Tests  N failed | M passed` 汇总，给出失败文件清单；认不出就当“认不出是哪几项”，交调度员（同 Python 全量的做法）。
- 超时：10 分钟。

### 2.6 跑命令的环境
- 沿用 `fullrun.safe_env`，PATH 里只再多放 `pnpm`、`npx`（各自用 `shutil.which` 找到后做符号链接进那个小文件夹）。codex、cursor、agy、qwen、claude 仍然找不到。要有测试证明这一点。

### 2.7 清理
- `remove(key)`：删整个 `<临时目录>/collab-dsh/<key>/`。
- `sweep(active_keys, older_than=6 小时)`：删掉不在 active_keys 里、且超过 6 小时没动过的副本。应用启动时调用一次（找后台启动的入口，和现在启动时清理的地方放在一起；找不到合适入口就停下来报告，不自己发明）。
- `merge.remove_copy(project, card_id)` 删施工副本时，顺带 `remove` 本卡的底座副本。放弃、停掉的卡如果也走 `remove_copy` 就一并覆盖；不走的话在任务清单 T5 里查清并补上。

## 3. 接入点

### 3.1 第 2 步：本卡测试命令 `python3 -m collab ui-test [文件…]`
- 在 `collab/cli.py` 加子命令。当前目录就是施工副本。
- 做的事：`make`（复用本卡副本）→ `build` → `vitest(文件)`；退出码 0 = 全过，非 0 = 没过，输出给写代码的看。
- 本卡测试命令可以把 Python 和界面串起来写，例如 `python3 -m unittest discover -s tests -p test_x.py && python3 -m collab ui-test dsh-plugin/core/tests/x.spec.ts`。
- 给调度员（`planner.py` 写施工单的提示）和写测试、写代码的提示里加一句：本项目有界面插件；界面测试的测试命令用 `python3 -m collab ui-test <文件>`，不要自己去底座目录跑。只在 `applicable` 为真时加这句。
- 沙箱注意：本卡测试是在 AI 工具沙箱里跑的（只能写施工副本和临时目录）。副本在临时目录里，可以写；`pnpm install` 若要联网会被挡，sync.sh 里是 `pnpm install --no-frozen-lockfile`，副本里依赖已经装好，正常不需要联网。**这一点测试替身证明不了，留给 Claude 最终真跑验证。**

### 3.2 第 3 步：全部测试（`fullrun.FullRunner.run` + `dispatch._FullSlot`）
- `run()` 里 Python 全量照旧。之后，若 `applicable` 且 `touched_ui`：在它已经建好的那份全量副本 `copy` 上 `make(copy, key=全量专用)` → `build` → `vitest(全量)`；跑完立刻 `remove`。
- 三样结论合并：Python 没过 → 照现有逻辑；Python 过了但编译没过 → FAIL，退回写代码，交代里写“编译没过”和 `run-gates: FAIL` 那几行；编译过了插件测试没过 → 见下一条。
- 插件测试没过时，和 Python 一样区分“这次改坏的”和“改之前就不过的”：在改之前的样子（施工副本 HEAD，`base()` 已有取法）上再建一份副本跑同样那几个文件；改之前是过的才算这次改坏、退回写代码；改之前也不过的记一笔“改之前就不过，不算这次改坏”；改之前没跑成就交调度员。不做“单独重跑看稳不稳”那一步（插件测试一次十几秒，暂不需要）。
- 卡片记录（`record`，阶段名用“全量”）：
  - 跑界面部分前：“本卡改了界面，接着在底座副本上编译、跑界面测试”；
  - 每段结束写结果和用时（建副本 xx 秒、编译 10/10 xx 秒、界面测试 N/N xx 秒）；
  - `applicable` 但没 `touched_ui`：“本卡没动界面，没跑编译和界面测试”。
- 停工：`_FullSlot.stop()` 现有的 event 一并传给这几步；`kill_all_groups` 收得掉（进程都登记在 `_GROUPS`）。
- 总时限：现有 30 分钟（`FULL_TIMEOUT`）把界面部分也算进去。

## 4. 测试要求（写测试的 Codex 照这个写）

- **一律用假底座**：在临时目录造一个假 DSH（`package.json` 里 name/version 对上，几个文件，`apps/desktop/.desktop-build/` 下放指向假原件的链接），用 `SUPERAGENT_DSH_BASE` 指过去。假项目里放一个假 `dsh-plugin/sync.sh`（记录收到的参数、往参数目录里写一个标记文件、按需要返回 0/1）。vitest 用 PATH 里的假 `npx` 替身（按场景输出过/不过的 vitest 文字）。
- **测试里绝不出现真实底座路径，也不调用真的 sync.sh、pnpm、vitest。**
- 每条验收标准至少一个测试，重点：
  1. 没有 `dsh-plugin/sync.sh` 的项目：全量结果和现在逐字一样，不建副本；
  2. 原件不被写：跑完 make/build/vitest/remove 后，假原件全部文件内容和修改时间不变；sync.sh 收到的参数是副本路径，不是原件；
  3. 副本里 `.desktop-build` 已删，没有解析到原件的链接；故意留一个指向原件的链接在别处 → 报错且副本被删；
  4. 磁盘不足 10GB（替身 `disk_usage`）→ 不克隆、报明确原因；
  5. `cp -c` 失败 → 报错，不退化成普通复制；
  6. 同一张卡两次 `make` 只克隆一次；
  7. 编译失败 → 全量 FAIL，退回交代里含“编译没过”；
  8. 插件测试失败、改之前是过的 → FAIL 退回；改之前也不过 → 不退回、记一笔；
  9. 没改 `dsh-plugin/` → 卡片上有“本卡没动界面，没跑编译和界面测试”；
  10. PATH 里有 pnpm、npx，没有 codex、cursor、agy、qwen、claude；
  11. 叫停：跑到编译一半叫停，进程被收掉、副本被删；
  12. `remove_copy` 后底座副本没了；`sweep` 删超时无主的、留有主的和新的；
  13. `ui-test` 子命令：过 → 退出码 0；不过 → 非 0 且输出里有失败项；
  14. vitest 输出解析：失败文件和汇总认得出；认不出时不当成过。
- 写完先跑，**新测试必须不过**（模块还不存在），并且失败原因是“缺功能”，不是测试自己写错。

## 5. 不许碰

- `~/Desktop/project/dsh-base` 原件；
- `dsh-plugin/` 下所有文件（包括 sync.sh）；
- `desktop/mac/`；
- 老测试只许新增不许改；写代码的不许改任何测试文件。

## 6. 已知取舍

- 插件测试不做“单独重跑看稳不稳”；
- 合入后不自动重装正在用的超级玩家；
- 真实窗口走查不自动化；
- 沙箱里 `pnpm install` 能不能不联网跑通，测试证明不了，Claude 最终真跑验证。
