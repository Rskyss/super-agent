# 任务清单：第一批“别白跑”

> 依据 [方案](方案.md)（2026-11-23 用户批准）。每个任务先写会失败的测试，再改代码，做完勾掉。Claude 亲自做（改的是正在用的跑卡流程）。

- [x] **T0 基线**：在开发助手文件夹跑一遍全部测试，记下数字（改之前的样子）。
- [x] **T1 范围检查认中途新加的测试文件（⑲）**：测试员交活后，写代码交活时的范围检查用最新测试名单。验收：模拟“补测试新建一个测试文件 → 写代码交活没动它”，流转里不再出现“撤销范围外改动”“恢复开发员改动的测试文件”。
- [x] **T2 测试文件自己有错交回测试员（⑫）**：判定没过、报错位置全在测试名单里的文件时，走“只改测试”那条路；有一处在产品代码就照旧退写代码的；交回测试员最多 2 次，超了停卡转人工；测试员看出是产品没写时可回复说明、程序转回写代码的。验收：用 train 那 3 行真实报错做样本，判为交回测试员；混一行产品代码报错，判为退写代码。
- [x] **T3 接着跑先重跑测试（⑭）**：续跑时最后一次判定没过、之后有接手或从“需介入”恢复，先重跑本卡测试；过了直接进复查，没过用新报错派活。验收：模拟 train 的“接手修好 → 接着跑”，不再派“测试没过，退回修改”，直接进复查。
- [x] **T4 接着跑交代前情（⑧ ⑮）**：续跑派出的活末尾加“前情”段（停过几次、最后为什么停、接手说明原话、副本里已改的文件和已有测试、同岗位上一棒最后汇报）。验收：模拟停卡换人后续跑，派活原文里能看到这几样；第一次开跑的派活不变。
- [x] **T5 右栏总耗时（⑪）**：“本卡合计”下面加一行“干活共 X 小时 Y 分”，只算开跑到停下/转人工/待验收之间的时段。验收：用 train CARD-001 的真实流转算出约 2 小时；页面实跑检查能看到这一行；没开跑的卡不显示。
- [x] **T6 全量与复查**：全部测试全过；Codex 极高独立复查，按规矩最多 3 轮。
- [x] **T7 重装与真实窗口练习卡**（重装前先问用户，且 train 卡不在跑时才装）：练习项目里①故意带一处测试写法错误跑小卡，看到交回写测试的；②停卡、接手、接着跑，看到先重跑测试直接复查；③右栏看到总耗时。练习项目用完删掉。
- [ ] **T8 收尾**：README、验收记录、台账；本机提交（推送等用户说）。
