# 需求共识：外部项目试跑暴露的问题修复

> 来源：2026-11-23 开发助手第一次接真实外部项目（外部项目 train，CARD-001，Gemini 主导），Claude 全程只看不改，问题逐条记在 外部项目观察-train（本机笔记 docs/流程数据/外部项目观察-train.md，不进 git）（编号 ①–⑳）。
> 分工（用户 11-23 原话）：“项目 train 的事情可以 Gemini，开发助手的事情可以你来干。”

## 一、要解决什么（大白话）

开发助手在自家项目里磨得比较顺，一到外部网页项目就暴露三类毛病：

1. **白跑**：卡在死路上空转（测试文件自己写错，却一直退给改不了它的开发员；接手修好了还按旧报错再退一轮），每次白耗几分钟和上百万 token。
2. **记录和显示不说实话**：写方案标成 Codex 干的其实是程序；接手人一律写成 Claude；开发员被记成“越界改测试”其实没改；各步 token 加不出合计；没有总耗时。
3. **外部项目没兜底**：网页项目没有页面检查、没有全部测试回归，测试的假数据和真实数据表对不上也没人拦，复查连续挖出同一类设计缺口时只会一直退回写代码。

## 二、分三批（待用户选先做哪批）

| 批 | 内容 | 对应观察编号 | 大小（推测） |
|---|---|---|---|
| 第一批“别白跑” | 测试没过、报错全在测试文件自己身上时，程序认得出、交回测试员改（不再一直退给改不了测试的开发员）；停卡/接手后接着跑，先重新判定、并把前情（谁改过什么、上一棒最后汇报）交代给下一棒；范围检查认测试员登记的测试文件；Codex 干活时放开测试工具要用的临时文件夹 | ⑫ ⑭ ⑧ ⑮ ⑲ ⑦ | 中，约半天到一天 |
| 第二批“显示和记录说实话” | 写方案那行标“程序”不标模型；照施工单生成方案时把验收段抽进来；各步 token 含小帮手、被停那棒单列；本卡合计加总耗时；接手人写实际是谁、停卡状态名不写死 Claude；复查降档后显示实际档位；退回件数和原文对上 | ① ② ⑨ ⑩ ⑪ ⑬ 及两条“记” | 中，约半天 |
| 第三批“外部项目兜底” | 网页项目也能做页面检查/走查；非 Python 项目也能跑全部测试回归；测试员写假数据要对照真实数据表；复查连续挖出同一类设计缺口、或起草“继续改”范围明显变大时，建议回到方案、把产品取舍交给用户 | ③ ⑯ ⑰ ⑱ ⑳ | 大，要单独出方案 |

## 五、怎么算做完

每批单独验收：先写会失败的测试、改完全绿；全部测试全过；独立复查通过；重装后拿一张练习卡在真实窗口里把对应场景走一遍；台账登记。
