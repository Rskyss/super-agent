# 方案（等用户批准）：第三批“外部项目兜底”

> 依据 [需求共识](需求共识.md)（11-24 定稿）。一共四件事，按下面顺序一件做完、验过再做下一件。每件都先写会失败的测试再改。

## 一、网页项目也跑“全部测试”（⑯）

**用户看到的变化**
- 项目设置里多一项“全部测试命令”。train 填成：`./node_modules/.bin/tsx --test tests/*.test.ts && pnpm typecheck`。
- 每张卡复查的同时，开发助手在一份副本里跑这条命令，右栏“全部测试”一格显示结果：
  - **过了**：照常往下走。
  - **没过，但改之前是过的**：说明这次改坏了老功能，退回写代码的，交代里附上没过的那段输出。
  - **改之前就不过**：不算这次的错，卡停下，写“项目的全部测试本来就不过，先修好再用这一关”。
  - **没配命令、也不是 Python 项目**：照旧跳过，右栏写“这个项目没配全部测试，没有兜底”。（现在写的是“不是 Python 项目……最后靠人看”。）

**怎么做**
- 命令存在项目的 `.collab/配置.json`，名字叫“全部测试命令”。和团队、模型放在一起，只存在本机。
- 填写入口：第一版用命令 `collab config full-test <项目> "<命令>"` 来填，由写施工单的架构师（Gemini 或 Claude）配一次；右栏会显示正在用哪条命令。设置页里的输入框第一版不做，原因见第六节第 1 条。
- 复用现在 Python 项目的那一套“复查同时跑全量”：一样在副本里跑，一样能叫停、有超时、藏起真 AI 工具。区别有三点：
  - 副本里的 `node_modules` 直接链接到项目里那一份，不复制（几百兆）。开工建副本时已经这么做了，照用。
  - 认不出是哪一项测试没过，所以“改之前过不过”按**整条命令**比：在改之前的版本上也跑一次。不再像 Python 项目那样逐个文件单独重跑。
  - 超时用现有的 30 分钟。

**不做**：一条一条认出是哪个测试没过（各家输出格式不同）；Python 项目现在的做法不变。

## 二、要看页面的卡，不看不让放进项目（③）

**用户看到的变化**
- 施工单“验收”一节的“走查”那一行提到**原型 / 设计图 / 对照 / 看页面**的，复查和全部测试都过了以后，不进“待验收”，而是停在新状态 **“等看页面”**。
- 右栏写明：施工单要求对照哪几张图（从走查那一行里认出 `.png` / `.jpg` 文件名，列出来，点了能打开），以及走查那一行的原话。
- 按钮：
  - **“已看过，和图一致”**：卡进入“待验收”，照常点“确认没问题，放进项目”。
  - **“已看过，有出入”**：要写一句哪里不一样，再选是“退回去改”（等于“继续改”，那句话就是要求），还是“接受，照样放进项目”（那句话记进卡片和验收记录）。
  - **“不满意，继续改”**、**“放弃这个需求”** 照旧。
- 放进项目那一步也会再查一次：要看页面却没有“已看过”的记录，就不放，提示“施工单要求先看页面”。按钮和放进项目两道都拦，防止绕过去。
- 谁点都行，你点，或者你把页面交给 Codex 看完后你点。卡片记录写“谁点的、什么时候、选了哪个、写了什么”。

**不涉及的卡**：走查那一行写“不涉及”、又没提原型 / 对照的，照旧直接进“待验收”。

**已知边界**：只认施工单“验收”一节。没有施工单、由起草 AI 写的方案，没有“走查”这一行，就不拦。

## 三、同一处来回退回：要求没写清就停下定规则，做错了就换备份（⑱）

**复查员多填两栏**（交代里写清楚，复查清单检查时也会核对）：
- **“病根”**，二选一：
  - **“要求没写清”**：施工单没定这条规则，或规则之间冲突。同时写一句是哪条规则，比如“自由文字里组号怎么遮”。
  - **“做错了”**：要求写清楚了，代码没照着做。
- **“和上一轮哪条同根”**：第 2 轮起，如果这条和上一轮退回的某条是同一个病根，写上一轮的第几条；不是就留空。（现在已经有“上轮核对”，逐条写上一轮的问题修好没有，这次在它旁边补这一栏。）

**程序怎么判**（只看严重、中等这些会退回的问题）：
1. **连续两轮“要求没写清”，而且同根** → 不派写代码的去第三次，卡停在新状态 **“需要定规则”**：
   - 右栏写：是哪条规则、上一轮退了什么、这一轮退了什么。
   - 同时让起草的 AI（Codex）拟 2～3 个规则选项。复用现在“继续改”的起草，换一份交代，写进右栏。
   - 按钮：选一个选项，或者自己写一句规则 → 记成一次“追加要求”，从写代码的继续；也可以“放弃这个需求”。
   - 推送到人这件事放在下一批（飞书）。这一批由谁看到谁定：纯技术规则由写施工单的人定，影响用户体验的交给你。
2. **连续两轮“做错了”，而且同根**（或者“上轮核对”写着“没修好”）→ 下一次写代码**换成备份写代码的（Codex）**，不停下：
   - 右栏写代码那一格显示“换成 Codex（DeepSeek 同一处连续两次没改对）”。
   - 换了以后这张卡后面一直用 Codex，不再换回去。备份也连续两次没改对同一处，照现在的规矩退回次数用完就转人工。
   - 备份用哪家写在项目配置里（“备份写代码的”），默认 Codex。没配或者和现在写代码的是同一家，就不换，照常退回。
3. 只有一轮的、不同根的、或者病根没填的，照现在的规矩退回。病根没填当“做错了”处理，不会因为漏填就停卡。

**为什么这样判**：复查员最清楚每条问题是什么根子，程序不去比对文字像不像。复查员可能标错，标错的后果只是早停一次或晚停一次，最多和现在一样。

## 四、“继续改”像是重新设计时先提醒（⑳）

- 点“不满意，继续改”或者在行政那里确认修改时，开发助手先算一下：
  - 这次**新加的要改的文件**超过原允许范围的一半；或者
  - **改了验收标准**。
- 满足任意一条，确认框里加一行醒目提示：“这次修改比原施工单大很多（新加 N 个文件 / 改了验收标准），像是重新设计。建议先改施工单或者另开一张卡。”还是由你点“确认”或“先不改”，不会自动拦。
- 卡片记录写“提醒过像是重新设计，用户仍确认”，以后复盘查得到。

## 五、怎么算做完

- 每件都先写会失败的测试，再改；全部测试全过；派活原话快照只多出预期的几行。
- Codex 复查最多 3 轮。第 3 轮后还剩中等以上问题，停下问你，不自己记成取舍；第 3 轮后为了通过做的修改，补一次只看这些修改的确认复查。
- 重装后用练习项目各走一遍：
  1. 配一条会失败的全部测试命令，看到被退回；
  2. 施工单写“对照原型图”，看到卡停在“等看页面”，不点“已看过”放不进去；
  3. 用假复查员连续两轮回“要求没写清、同根”，看到停在“需要定规则”并出现选项；连续两轮回“做错了、同根”，看到第三次换成了备份写代码的；
  4. “继续改”加很多文件，看到提醒。
- 台账、README、验收记录同步。

## 六、要你定的

1. **全部测试命令第一版用命令配，不在设置页加输入框**，可以吗？设置页（team.*）里现在有一组来路不明、没提交的“团队升级复查”改动（你之前没回怎么处理），我不想在上面再叠改动。这批先用命令配，由架构师配一次就够了。等那组改动处理完，再把输入框补上。
2. **备份写代码的用 Codex，每次比 DeepSeek 贵**。只在同一处连续两次没改对时才换，train 这次的退回大多是“要求没写清”，我估计 6 张卡里只有一两张会碰到（没逐张核对过）。可以吗？
3. 顺序：一（全部测试）→ 二（看页面）→ 三（定规则 / 换备份）→ 四（重新设计提醒）。第一、二件最实用，先做。可以吗？
