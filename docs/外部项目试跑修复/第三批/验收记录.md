# 验收记录：第三批“外部项目兜底”

> 依据 [需求共识](需求共识.md)（11-24 定稿，同日按确认复查改了第 52 行）、[方案](方案.md)、[任务清单](任务清单.md)。

## 做了什么（大白话）

1. **网页项目也有“全部测试”兜底**：项目配一次全部测试命令（`collab config full-test <项目> "<命令>"`），复查的同时在副本里跑。这次改坏了原来能过的功能 → 退回写代码的并附没过的输出；改之前就不过 → 卡停下说明；一项测试都没跑（Python、node/tsx、pytest，带颜色也认）→ 不放行；没配命令 → 右栏写“没有兜底”。拿 train 真实命令在副本里试：356 项全过 + 类型检查，47 秒，train 文件没动。
2. **要看页面的卡，不看放不进项目**：施工单“验收”一节的“走查”那行提到原型 / 设计图 / 对照 / 看页面的，复查通过后停在“等看页面”；右栏列出要对照的图，点了在右栏里看大图（png、jpg、webp），这时也能“打开改好的版本”。点“已看过，和图一致”才出现“放进项目”；“有出入”要写一句，可以退回去改（只填进“继续改”框，提交了才算）或照样放（那句话进验收记录）。命令行硬放进项目也拦，不记“合并失败”。AI 写方案的卡、升级前开工的卡（回头读施工单）、“走查”加粗的写法都认。train 6 份施工单全认出，11 张图找到 10 张。
3. **同一处来回退回：要求没写清就停下定规则，做错了就换备份**：复查员每条问题标“病根”（要求没写清 / 做错了）和“同根”（上一轮第几条）。连续两轮“要求没写清”且同根 → 停在“需要定规则”，起草的 AI 拟 2～3 个规则选项；只能用“继续改”把规则写进去（没有“接着跑”按钮，终端硬接着跑也照样停，排着的无关修改也不会让它自己开工，选项原样整份发出去会被退回“先挑一个”）。连续两轮“做错了”且同根（含上一轮“没改好”）→ 下一次写代码换成备份 Codex，这张卡后面都用它，报错、停卡说明写实际干活的工具。
4. **“继续改”像重新设计时提醒**：新加的要改文件超过原范围一半、或改了验收标准，右栏确认框和行政确认框都提醒“像是重新设计”；仍确认就在卡片里记一笔（批准方案前、施工中排队的修改也记）。
5. **测试副本的环境**：名字像密钥（KEY、TOKEN、SECRET、PASSW、CREDENTIAL）的设置不带；任何地址里的“账号:密码@”去掉；其余照带（和人自己跑测试一样）。Python 项目的全部测试也用这一套。

## 已知取舍（不做或没做全）

- 第 2 轮复查起中等问题进“以后再修”、不退回（现有规矩 ㉘，待用户定要不要改）：同根的中等问题碰不到“停下定规则”。
- 同一个仓库里几个包互相链接时，全部测试可能测到主项目里的旧代码：根子在开工时整个链 node_modules（改动前就这样，本卡测试也受影响），少见，单独立项。
- 规则选项删头去尾、留下两个冲突的仍能发：程序判断不了人挑没挑，挑规则这一步靠人。
- 测试副本按名字拦密钥，拦不全（如名字写成 DB_PASS）：同一个角落连续四轮冒新的，定成两条简单规矩后接受边界。
- 升级前“放进项目做到一半”的老卡可能卡在“要先看页面”又没按钮。
- 施工单里 `01..06.png` 这种简写认不出图，右栏写明“找不到”。
- 停下时判定测试另开的进程组不跟着停（第二批就记的，单独立项）。
