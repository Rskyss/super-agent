## 一、你会看到的样子

### A 显示：一眼看懂

**右栏每一步**（7 步都一样）：

```
✓ 调度          Codex · gpt-6.1-sol（低）
  派活后盯进度，有人卡住会叫你

◌ 写代码        agy · Gemini 3.8 Flash（高） · 退回返工
  在改代码：已读 23 个文件、改了 4 处
  刚跑完本卡测试，1 项没过，正在照着改
  已干 12:40 · 刚刚有动静
```

- 右上角：**工具 · 模型（强度）**，和团队设置里这个岗位配的一致。调度那步也有（现在只写 Codex，㉗ ㊳）。
- 说明最多 **3 行**，超出的收起来，鼠标停上去看全文。
- 写的是**大白话概括**，不出现命令、代码、文件路径、原始输出（㊷）。干活的人自己说的话（Codex 会说“我先看现有代码……”）照样显示，同样最多 3 行。
- 正在干的那步一律有“已干多久 · 多久前有动静”，**调度写方案那步也有**（㊳）。
- 进入新一轮时，上一轮的红叉收进“交接”历史，不再挂在流程里误导（㉞）。

**中间标题下那一行**：同样规矩，最多 3 行、大白话、带计时。

**轮次说法**（㉝）：复查退回后改完，写“复查退回后第 1 次改完：测试全部通过”，不再和第一次一模一样。

**行政在卡片对话里**（㉞）：
- “5 分钟没动静”“10 分钟没动静”合并成一条，只更新那一条，不刷屏。
- 复查不通过时说挑出了什么：“复查挑出 2 件事：① 积木块编号写错也能出草稿；② 积木块信息太长时结尾提醒被截掉。已退回 agy 改（第 2 次，最多 2 次）。”

**“接受剩下的问题”确认框**（㊲）：每条一句你能看到的现象；复查员原话折叠在“看原文”里。

### B 提速：质量不降，少走弯路

1. **开工时备交接资料**（㉚ ㊺）：调度员在写测试的同时（不占额外时间），读施工单和要改的代码，写一份“改哪里、现在怎么写、相关规矩、哪些老测试会跟着变”交给写代码的。返工、换人时直接再给一次。资料每张卡现做，不复用。
2. **单条命令设时限**（㊹）：干活的人自己跑的命令，本卡测试 5 分钟、其他 2 分钟，到时只掐那一条，并告诉它“这条命令卡住被停了，换个办法”；它接着干，不用整个停掉。
3. **测试写错时找写测试的改**（㊻）：复查员的结论里能写“这条是测试的问题”；程序把这条交给写测试的去改（只改测试），改完再让写代码的接着做。不再逼写代码的迁就错测试。
4. **停下时说清为什么不过**（㊱）：自动退回用完后停下时，调度员看几轮复查意见，归到四种之一并给对应按钮：
   - 同一问题反复出现 → “可能是这个模型做不动，建议换写代码的人或模型”（按钮：去团队设置）
   - 每轮冒新问题 → “施工单没写准，建议补单或拆小”（按钮：继续改）
   - 要改范围外的文件 → “需要多改一个文件”（按钮：继续改，带上要加的文件，要你点头）
   - 只剩小问题 → “剩下的都是小问题”（按钮：接受剩下的问题）
   - 轮次按整张卡累计显示，不因“继续改”清零。

### C 干活环境

1. **派活不带插件**（㉘ ㊶）：Codex 派活时把你配的插件逐个关掉（只对这一次，不改你的设置；已实测能关）。agy 只有“这一次的设置”开关，能不能关插件**要施工时实测**；关不了就记已知取舍，并在派活交代里写“不要用浏览器和外部插件”。Cursor（⑰ 当时只处理了权限，没关插件）一并查。
2. **老测试不启动真工具**（㉛）：找出那个会在后台用真 Cursor、真 agy 干活的老测试，换成假工具；以后跑全部测试前后自动查一次有没有残留的真工具进程。
3. **时好时坏的老测试修稳**（㊸）：“两次确认同时到”那项，连带 68 时记的“后台小程序偶发超时”，查清原因修稳。

## 二、泼冷水（风险和做不到的）

- **提速多少没打包票**：交接资料能省掉大半“找地方”的来回，我估计写代码能省一半左右，是推测。69 接着跑那一段就是实测，数字会写进试跑记录。
- **大白话靠翻译规则**：程序把“读文件、改文件、跑命令”翻成大白话是靠写好的对照表，碰到没见过的动作只能写“在干活”。干活的人自己说的话里仍可能带代码名（比如“CARD-003 的新接口”），只能限行数，不能逐字改写。
- **复查挑出的事要写成大白话**，靠在交代里要求复查员每条先写一句“用户能看到的现象”。它不照办时，行政只能说“复查挑出 N 件事”，原话在“看原文”里。
- **agy 关插件可能做不到**：见上。
- **掐命令可能误掐**：真有正经命令要跑 2 分钟以上（比如它自己想跑全部测试，按规矩本来就不该跑），会被掐掉。被掐后它会收到说明，换办法继续。
- **交接资料多花调度员额度**：调度员用低档读代码，和写测试同时进行，不拖时间；每张卡多花一次调度员调用。
- **第二批（行政、流程规矩）这次不做**：行政仍会读一下文件才建卡（㊴）、多问一句（㊵）；施工中途补允许范围仍要靠“继续改”时我手动处理（㉟）。

4. ㊱ 的四种判断由调度员（低档）来做，判断不出时只列出剩下的问题，不瞎归类。

## 四、怎么算做完

- 每条修法先写测试、看它不过，再改到过；全量通过（真工具藏起来跑，前后查没有残留进程）。
- Codex 独立复查通过（按 A、B、C 三块分开复查）。
- 真实窗口里接着跑 69：右栏 7 步都有模型和计时、说明不超过 3 行没有代码、行政不刷屏、交接资料生成了、派出去的 Codex 没带插件。截图给你看。
- 记下 69 后半段的数字（写代码总用时、来回次数、读文件次数），和前半段对比。
- 台账、试跑记录（各条改“已修”）、调度手册和规则同步。Mac 窗口外壳如有改动要重装。
