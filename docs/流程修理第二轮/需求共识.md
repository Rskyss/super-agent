## 一、修完后你能感受到的变化

1. **右栏和标题一眼看懂**：每一步右上角都写“谁 · 什么模型（强度）”，正在干的那步都有“已干多久 · 多久前有动静”；说明最多 3 行大白话，比如“在看本机服务里确认按钮那段，准备加试做”，不再整屏代码。
2. **行政像人一样汇报**：每次交接一句话说清“发生了什么、下一步是什么”；同类提醒合并成一条，不刷屏；复查不通过会说挑出了哪几件事；确认框里是大白话，原话折叠在“看原文”里。
3. **写代码更快，质量不降**：开工前先备好一份“要改的地方在哪、现在怎么写的”交接资料，写代码的不用满世界找；它自己跑的单条命令卡住会被及时掐掉，不再白等十几分钟。
4. **停下时说清为什么不过、该怎么办**：同一问题反复出现、每轮冒新问题、要改范围外的文件、只剩小问题——分别给对应的出路按钮。
5. **干活的人只带本单要用的东西**：派出去的 Codex、agy 不再带上你电脑上的浏览器、操作电脑、数据库等十几个插件。
6. **测试更可靠**：跑全部测试时不会偷偷启动真的 AI 工具花额度；时好时坏的那几项老测试修稳。

## 三、拍板的题（用户 11-13 原话“全部推行”：5 题都按推荐）

定下的：分两批（先 A+B+C）；交接资料由调度员开工前现做；本卡测试命令 5 分钟、其他命令 2 分钟算卡死；派活时插件全关；Claude 直接改、Codex 独立复查。

1. **分几批？**
   - **推荐：分两批**。第一批 A + B + C，做完让下一张卡（69b）跑一遍、记数字对比；第二批 D + E 之后再定。理由：第一批改的是显示和派活，第二批改行政和规矩，混在一起出问题分不清是哪块。
   - 或：一次全做完。
2. **交接资料谁来做？**
   - **推荐 A：调度员开工前现做**。调度员（Codex）读施工单和要改的代码，写一份“改哪里、现在怎么写、相关规矩”给写代码的。多花调度员几分钟，但每张卡都能用，换人、返工时直接复用。
   - B：Claude 写施工单时顺手附上。只对 Claude 写的施工单有效，你以后自己提的需求用不上。
   - 不管选哪个，资料都是每张卡开工前现做，不复用旧的，避免过期资料把它带偏。
3. **单条命令的时限多长？**
   - **推荐：本卡测试命令 5 分钟，其他命令 2 分钟**。本卡测试命令正常约 2 分钟跑完，留出余量；它自己写的验证小脚本正常几秒就完，2 分钟足够判断卡死。
   - 或：统一 3 分钟。
4. **派活时插件全关吗？**
   - **推荐：全关**。施工单要求“不重新调研”，写代码、写测试、复查都用不到搜索、浏览器、数据库；带着反而可能弹窗、拖慢启动。
   - 或：留下搜索类，别的关。
5. **谁施工？**
   - **推荐：和第一轮一样，Claude 直接改、Codex 独立复查**。改的正是派活和显示的程序，用正在改的流程改它自己，出了问题分不清是旧毛病还是新改的。
   - 或：交超级助手自己跑。

## 四、怎么算做完

- 每条修法先写测试、看它不过，再改到过；全量通过（真工具藏起来跑，跑完查没有残留进程）。
- Codex 独立复查通过。
- 在超级助手真实窗口里看一张真卡（69b）：每一步右上角和计时都在；说明不超过 3 行、没有代码；行政不刷屏；派出去的工具没带插件。
- 69b 记下和 69 一样的数字（写代码总用时、来回次数、读文件次数），对比是否变快。
- 台账、试跑记录（问题状态改成“已修”）、调度手册和规则同步。
