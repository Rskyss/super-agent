## 1. 一句话

先让协作包**边干边记**，再做一个 **Mac 桌面窗口**，把记录实时地、动态地放出来。你不用问调度员，打开窗口就知道现在谁在干、到哪一步、有没有卡住、它们之间说了什么。

## 2. 打开窗口你会看到什么（对照设计稿第三版）

> 设计稿演变：第一版信息全铺开，用户评价“太复杂、没有设计感”；第二版改成横向线路图；第三版按用户草图定为**左边终端、右边竖排进度加标签页**（2026-11-04）。

**左右宽度**：中间有一条分隔条，拖动即可调整左右宽度，窗口记住你上次的宽度；双击恢复默认（左边约六成）。两边各有最小宽度，不会被拖没。

**左边：终端**——**你和调度员一对一的对话**
- 就是一个真终端，里面运行调度员（现在是 Claude）。你现在在终端里看到和能做的一切都原样在：所有数据、确认提示、中途打断。
- 左边只有你和调度员；调度员和干活的人之间的对话，在右边的“交接”里。
- 全程记录：往上翻就能看到整段对话；每次对话也会完整存在电脑上。对话特别长时，调度员会把较早的内容压缩成摘要再继续（今晚就发生过一次），但存在电脑上的完整记录不受影响；重要的决定仍以项目里的文档和台账为准。
- 打开窗口时可以**接着上一次的对话**聊，终端里聊过的内容不会丢。
- **谁当调度员由你亲手选**（2026-11-04 用户要求）：窗口顶部菜单「调度员」里选 Codex / Claude / 自定义命令，选了就记住；没选之前左边只是普通终端，不启动任何 AI。换人就是让左边启动另一个命令行工具。

**右边：流转面板**，顶部是卡片名、一句话“现在”、大号计时、第几轮/返工几次；下面三个标签页：
1. **流程**：从上往下一条竖线，七站依次是 你 → Claude 调度 → Codex 写测试 → Cursor 写代码 → 程序跑测试 → agy 复查 → 你验收。正在干活的那一行发光，写它此刻在干嘛、干了多久、几秒前有动静；交接时光点沿竖线往下走，做完的路段变绿；测试没过时光点变红往回走，那一段闪红；超过 10 分钟没动静变黄提醒“可能卡住了”。点头像看这个人的全部交接。
2. **交接**：每一次交接一条（派活原文、回复全文、测试结论、返工原因、复查结论），点开看全文；可以只看某一个人的。
3. **卡片**：这个项目的所有卡片和结果，做完的卡可以从头回放。

配色：深色底，琥珀色 = 正在干，绿色 = 完成，红色 = 没过。

只看不点，拍板仍在聊天里说。窗口开不开、关不关，都不影响干活。

## 3. 协作包要补的“边干边记”

| 现在 | 改成 |
|---|---|
| 每一步做完才记 | 开始时记一条（谁、接到什么任务），结束时再记一条（回了什么、用了多久、成没成） |
| 派活原文不保存 | 原文全部保存 |
| 测试员的回复不保存，开发员只留一句汇报 | 所有执行者的回复全文保存（汇报照旧单独提取） |
| 实时输出跑完即删 | 存进卡片文件夹，窗口显示最近几行 |
| 调度员这边的节点（建卡、批准方案、开跑、归档）只记在台账 | 同时写进这张卡的流转记录 |

**只加记录，不改派活方式。** 返工、看门人、范围控制、判定规则都不动。旧卡片没有新记录，窗口也能显示，只是细节少一些（只有状态和已有的结果文件）。

## 4. 这一步不做

- 自己做聊天界面（左边用真终端代替，不再需要）
- 排班、按钮（第二步）
- ~~在窗口里切换调度员~~：用户要求提前到这一步，已做（菜单「调度员」，用户亲手选）
- Windows 版
- 像素办公室之类的形象（远期）

## 5. 谁来施工：建议用超级助手自己来做

把这一步拆成 3 张卡，**由超级助手按 v0.1 的流程自己施工**：Claude 调度，Codex 先写测试，Cursor 写代码，agy 复查。理由：

- 守住“调度员不亲自写产品代码”的分工，这也是你一直要求的“分配下去”。
- 顺便在一个新类型的项目上再验证一次 v0.1。
- 有个好处：第 1 张卡做完后，后面卡片的流转都会被完整记下来。窗口做好后打开，第一眼就能回看这个窗口自己是怎么被做出来的。

代价：比我直接写慢一些，也要用掉 Cursor、Codex、agy 的额度。三张卡大约要跑 1–2 小时（**这是估计**，以实际为准）。

## 6. 施工备注（可跳过）

- **窗口**：用 Mac 自带的开发工具做一个原生小应用（本机已有），右半边显示本机页面；应用启动时带起一个只服务本机的数据小服务，关窗口即停。
- **左边终端**：用成熟的终端组件（和 VS Code 内置终端同一类，Claude 在其中运行正常），不自己造；默认在项目目录里启动 `claude`，可选“接着上一次的对话”；启动哪个命令做成可配置，为第二步换调度员留口子。这是这一步技术上最难的部分，卡 3 先做一个最小的可行性验证再铺开。
- **数据**：数据小服务只读项目的 `.collab/`，不写；页面每 1–2 秒刷新。
- **记录格式**：每张卡新增一份按时间追加的流转记录（一行一条，带时间、谁、对谁、类型、摘要、全文位置），全文和实时输出各自存文件；格式在第 1 张卡里写死并写进调度手册，窗口只认这份格式。
- **在超级助手自己的仓库上跑协作包**：协作记录目录加进忽略清单，不进 git；施工仍在独立副本里，不碰主目录。
- **判定**：第 1、2 张卡用单元测试；第 3 张卡用“应用能编译 + 启动后数据小服务能应答”作为判定。
- **验收前**：Claude 复核每张卡；全部完成后请 Codex 打开窗口，在沙盒项目上跑一张真实的小卡，截图给你看。
