## 一、用户原话整理

1. “现在在终端 CLI 里聊，能不能做成一个界面，直接在界面里聊，并且能看到你跟下面几个人说话的进度和流转的进度？前提是不是网页？是一个窗口。”
2. “我需要一个桌面的窗口，以后我的主角分配官可能是 Codex，也可能一些人用千问。”
3. “我可以来指定谁是调配员，谁干什么，然后他们就能够按照我的配置去跑。就像我是一个老板，我可以命令谁去做什么、主要是哪些事情。……当然现在是针对我，在如何开发上面去做一个调整。V0.1 已经上线了。”

4. “agent 的各种角色，是不是也可以理解为一个模型，里面给他设置不同的 prompt？比如 Codex 有一个专门负责写文章内容，后面还有一个做内容分析的，同一个大模型通过不同的 prompt 分成不同的定位，一层一层走下去，比一个大模型一条链路一个对话走下去是不是要稳很多？”（2026-11-04，理念讨论，答复要点：岗位 = 一家 AI + 一份岗位说明 + 能看到什么 + 能做什么 + 怎么验收；拆开更稳的前提是每一层之间有检查）

## 二、一句话

一个**桌面窗口**（自己的图标、独立窗口，不是浏览器网页）：你像老板一样**排班**（谁当调度员、谁写代码、谁写测试、谁复查、各自主要负责什么），然后在窗口里**和调度员聊天**提需求，旁边实时看到**调度员给谁派了什么活、谁在干、走到哪一步、回了什么**。

## 三、你会怎么用

1. 打开桌面窗口，选一个项目。
2. **排班**：四个岗位（调度员 / 写代码 / 写测试 / 复查），每个岗位选一家 AI；可以给岗位补一句你的要求。保存后，这个项目以后默认用这套排班。
3. **聊天**：在左边和调度员说需求。调度员按协作包的流程对齐、写方案，要你拍板的事在聊天里问你。
4. **看流转**：右边显示流程条（对齐 → 方案 → 测试 → 开发 → 复查 → 等你验收）、谁在干、已用时、最近有没有动静、返工次数；每次派活和回复都有一句话摘要，点开能看全文。
5. 拍板（批准方案、同意合并、同意上线）仍在聊天里跟调度员说。

## 四、已定口径

| 项 | 口径 |
|---|---|
| 形态 | 桌面窗口，不是浏览器网页 |
| 调度员 | 可以由你指定，不绑定 Claude |
| 进度区 | 只看不点（2026-11-04 按推荐默认，用户未反对） |
| 对话显示 | 每条一句话摘要，点开看全文（同上） |
| 范围 | 只服务你自己、只服务“开发”；普通人自由分工、非开发场景留在远期设想 |
| 与 v0.1 关系 | 协作包继续当发动机；终端用法保留，两套入口读写同一份记录 |
| 调度员权限 | 调度员能做的事事先划好：写需求文档、运行协作包、读记录；**不给改产品代码的权限**（铁律从靠自觉变成靠权限） |

## 六、要先说清楚的

1. **Codex 当调度员还没试过。** 方案阶段的第一件事是小试：让 Codex 读调度手册、按流程走一个小需求，看它能不能守规矩。试不通就如实告诉你。
2. **千问能不能接进来没实测**；它的命令行版本存在，但能否这样调用不确定。
3. **聊天是我们自己做的**，一开始不会有官方窗口顺手（中途打断、长回复显示等要慢慢磨）。
4. **看不到 AI 逐字思考的过程**：三家工具输出方式不同，有的干完才给结果。保证能看到的是派了什么活、谁在干、到哪一步、有没有动静、回了什么。
5. **工作量**：这是一个完整的小应用（窗口 + 聊天 + 进度 + 排班），比 v0.1 的任何一步都大。计划分两步交付：先出“窗口 + 排班 + 进度”，再把聊天放进来。

## 七、怎么算做完（草案，定稿时细化）

1. 不碰终端：打开窗口 → 选项目 → 排班并保存 → 跟调度员说一个小需求 → 看到流转 → 在聊天里批准 → 跑完看到“等你验收”。
2. 把调度员从 Claude 换成另一家后，同样的流程能走通，进度区能看出是谁在调度。
3. 换了写代码的人，下一张卡就由新的人写，进度区显示得出来。
4. 调度员在窗口里改不了产品代码（由权限保证，不靠它自觉）。
5. 终端里的协作包用法照常可用。

## 八、第一步：流转可视化（2026-11-04 用户要求先落实）

### 为什么先做这个

用户原话：“你跟我说你已经派出去运行了，其实我是看不到的。他那边发生什么情况，我也不知道。”——现在派活以后，用户只能等 Claude 转述，没有任何直接反馈。

### 核查发现（决定了这一步不能只做界面）

| 现状 | 后果 |
|---|---|
| 每一步做完才记一行 | 测试员还在写时，记录只显示“开发中”，分不清谁在干 |
| 派给执行者的任务原文没保存 | 看不到“调度员对它说了什么” |
| 测试员的回复没保存；开发员只留一句汇报 | 看不到“它回了什么” |
| 执行者的实时输出写在临时位置，跑完即删 | 看不到“它这会儿在干嘛” |

所以第一步分两半：**协作包学会边干边记** + **桌面窗口把记录动态地放出来**。

### 用户会看到什么

> 2026-11-04 用户画草图定布局：**左边是终端（和调度员聊天），右边是竖排的整体进度，上面有标签页**。左边直接嵌真终端运行调度员（不自做聊天界面），可接着上一次的对话聊。

1. 一个桌面窗口（自己的图标，独立窗口）：左边终端，右边流转面板（标签页：流程 / 交接 / 卡片）。
2. **流程线在动**：你 → 调度员 → 测试员 → 开发员 → 程序检查（范围 + 测试）→ 复查员 → 等你验收。正在进行的那一站在跳动，交接时连线上有东西在流；没过时，“退回开发员”那条回路会亮起来。
3. **正在干活的人头上有气泡**：在干什么、干了多久、多久前有动静；超过 10 分钟没动静变黄提醒“可能卡住了”。（第一版设计稿把每个人的卡片都铺开，用户评价太复杂，已改）
4. **流转记录默认收起**：底栏只显示最近一次交接；点开后是按时间排列的每一次交接，每条一句话摘要，点开看全文；点某个人只看他的。
5. 有实时输出的工具，能看到它最近吐出的几行；干完才给结果的工具，显示“工作中，结束后显示回复”。
6. 窗口只看不点；拍板仍在聊天里说。

### 怎么算做完（第一步）

1. 派一张真实的卡，打开窗口，**不问 Claude**也能说出：现在谁在干、到第几步、干了多久、最近有没有动静。
2. 每一次交接（派活原文、回复全文、测试结论、返工原因、复查结论）都能在窗口里点开看到。
3. 卡片跑完后再打开，能完整回看这张卡是怎么流转的。
4. 窗口关掉再打开，状态不丢；窗口开不开，都不影响协作包干活。
5. 终端用法照常；v0.1 的测试全部通过。
