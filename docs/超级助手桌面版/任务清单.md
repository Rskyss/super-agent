## 卡片

### 卡 1：协作包边干边记

- **做什么**：每一步开始、结束都写进这张卡的流转记录；派活原文、回复全文、测试结论、范围核对、返工、复查结论、转人工都记；执行者的实时输出存进卡片文件夹；建卡、批准方案、开跑、归档也写一条。
- **允许改动**：`collab/` 里与派活、调用执行者、命令入口相关的文件，新增一个读写流转记录的文件；`tests/`；调度手册里记录格式那一节。
- **怎么算做完**：用假执行者跑一张卡，流转记录里按顺序出现“开始写测试 → 写完 → 开始开发 → 写完 → 范围核对 → 判定 → 复查 → 待验收”；原文、全文都能找到；跑到一半时能读出“谁正在干”；原有 118 项测试全部通过。

### 卡 2：流转数据服务和流转页面

- **做什么**：一个只服务本机的数据小服务，读项目的协作记录，整理出“现在一句话 / 流程线各站状态 / 团队卡片 / 流转记录 / 顶部数字”；页面按已批准的设计稿实现，每 1–2 秒刷新；能选项目、选卡片，能回看做完的卡。
- **允许改动**：新增 `desktop/`（数据服务 + 页面）；`tests/`。
- **怎么算做完**：用夹具记录（进行中、没过退回、复查中、等你验收、旧卡片没有新记录）分别能得出正确的状态和文案；超过 10 分钟没动静会给出“可能卡住”；数据服务只读不写；页面能打开。
- **依赖**：卡 1（记录格式）。

### 卡 3：Mac 桌面窗口（左终端 + 右流转面板）

- **做什么**：一个 Mac 应用，有自己的图标，双击打开窗口。左边是真终端，在项目目录里运行 `claude`（可选接着上一次的对话）；右边显示流转页面。启动时带起数据小服务，关窗口即停。附“生成应用”的步骤，写进使用说明。
- **先做可行性验证**：最小版本只证明一件事：窗口左边的终端能正常运行 `claude`（能输入、能显示、能中途打断）。验证不通过就停下来报告，不硬做。
- **允许改动**：`desktop/` 下的窗口外壳、终端组件和生成脚本；README 的使用说明。
- **怎么算做完**：生成脚本能编译出应用；左边终端能启动并运行命令；启动后数据小服务能应答；关闭后服务和终端里的程序都退出。
- **依赖**：卡 2。
