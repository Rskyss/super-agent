# 讨论记录：从“看得见、能调配”到超级助手桌面版

> 相关文档：[需求共识](需求共识.md)、[远期设想](../普通人可视化编排/远期设想.md)

## 1. 还记得“看得见、能调配”那件事吗

**用户**：“那么现在超级助手已经弄完了，那你还记得我之前跟你说一个可以看到他的动态、可以进行调配，给你举了几个例子的事情吗？”

**Claude 要点**：
- 记得三件事：想有个小窗口看几个 AI 干活（看不到就不知道是不是卡死了）；能把订阅的 AI 安到不同岗位；例子是 ring_hyacinth 的像素办公室和 OpenAI Devs 的流程线。
- 发现另一个窗口已经做了一版本机“指挥台”网页（岗位板 + 进度 + 待办），测试 130 项通过，还在改，没进 GitHub。
- 直说的问题：例子里最有看头的动画部分被砍了；点“同意合并”后页面显示“已合并”，但代码并没有合进去。

## 2. 远期想法：普通人自己给 AI 分工

**用户**：“其实我的想法是因为很多普通人也不太会技术，但他们会去用各种的 agent，订阅了各种 agent。那么我们随着 DeepSeek 的 super agent 这个逻辑来，让普通人经过不动技术那一端，通过自己的想法把 agent 自己调配组合起来，比如说哪个 agent 适合做图片，哪个 agent 适合去做分析，哪个 agent 适合做内容。他可以自己去调整，调整完以后，通过前端完整配置就可以自动运行起来。让 super agent 变得更简单。”

**Claude 要点**：方向成立（痛点真实，能复用现有成果）；四盆冷水：非代码工作没有自动裁判、不是所有订阅都能被程序调用、普通人不知道谁擅长什么（要给模板）、规模大得多；建议路线：写代码团队作第一个模板 → 选一个非代码场景跑通“谁来把关” → 再放开岗位。

## 3. 现阶段先自用

**用户**：“刚才我跟你说的这是我未来想去做这么一个事情，那么现在阶段肯定是我自己用好了才去做那个事情。”

**结果**：写入 [远期设想](../普通人可视化编排/远期设想.md)，现阶段不做。

## 4. 删除试玩的指挥台

**用户**：“本地那个是我自己拿着玩的。你可以全部删除。现在我授权你把关系到现在前端东西全部都给删掉。”

**结果**：指挥台网页、测试、引擎里的座位改动、7 份相关文档全部删除；删前核对过其他项目没有残留；测试回到 118 项；台账留了删除记录；用户最早的原话搬进了远期设想。

## 5. 新需求：在窗口里聊天，并看到流转

**用户**：“现在我们在终端的 CLI 里面去聊，那么我可以做成一个界面，让我直接在界面里面聊，然后能够看到你跟下面几个人在说话的一个进度和他流转的进度吗？这个前提是不是网页？是一个窗口。”

**Claude 要点**：不必是网页。聊天可以用 Claude 官方桌面版，进度可以做成 Claude 聊天旁边的面板；看不到 AI 逐字思考的过程；面板功能是抢先体验版。

## 6. 必须是桌面窗口，调度员不绑定 Claude

**用户**：“因为我需要一个桌面的窗口，以后我的主角分配官可能是 Codex，也可能一些人用千问。”

**Claude 要点**：Claude 里的面板不再合适，要做我们自己的桌面应用；进度区天然不挑调度员（读的是同一套记录）；聊天区要自己做，最费劲；建议分两步：先“窗口 + 进度”，再把聊天放进来。

## 7. 像老板一样排班

**用户**：“我可以来指定谁是调配员，谁干什么，谁干什么，然后他们就能够按照我的配置一样去跑，就像我真人一样，我是一个老板，我可以命令谁去做什么，主要是哪些事情。就是给他分成一个一个普通人能够按照他自己的工作方式去到这里面去配置，当然现在你是针对于我，在如何开发上面去做一个调整，那 V0.1 其实你已经上线了。”

**结果**：写出 [需求共识](需求共识.md) 草稿（v0.2），台账登记“对齐中”。

## 8. 岗位 = 同一个模型 + 不同的 prompt？

**用户**：“这个 agent 的各种角色，那么我后面是不是也可以理解为一个模型，里面给他设置不同的 prompt。举个例子，比如说 Codex 有一个就专门负责写文章内容的。那么他们一个链路走下去，因为有个 prompt 会给他控制住，然后后面还有一个内容分析的，就是一个大模型通过不同的 prompt 去给他分类成不同的定位，然后这样子可以一层一层的走下去，比一个大模型一条链路一个对话这么走下去是不是要稳很多？”

**Claude 要点**：
- 对：岗位 = 一家 AI + 一份岗位说明。更完整地说是五样：谁来做、岗位说明、能看到什么、能做什么、怎么算做完。
- 更稳的原因：每层从干净状态开始；一份说明只管一件事；出错能定位、能单独重来。
- 反而不稳的情况：交接丢信息；错误一路传下去（稳不稳取决于层与层之间有没有检查站）；同一模型换说明盲区相同（复查最好换一家）；更慢更费额度。
- 对 v0.2 的建议：岗位说明整份可看可改（第 2 题）；允许一家占多个岗位，复查与写代码同一家时提醒（第 3 题）；调度员候选（第 1 题）待定。

## 9. 先落实“看得见的流转”

**用户**：“现在你可以把我跟你聊天记录先记下来。然后先把那一步做了，就是流程界面的动态，就是可视化看的流程在运动，然后走到哪一步了，然后我也可以实时观察到你们之间扭转的进度是什么样子的。因为现在来看的话，就是你跟我说你已经派出去运行了，其实我是看不到的。他那边发生什么情况，我也不知道的。所以说有一个反馈，一个动态，前端的一个展示可以给我看到，先把这个东西给落实掉。”

**结果**：本记录落盘；v0.2 第一步定为“流转可视化”（见需求共识第八节）。

## 10. 设计稿第一版：太复杂

**用户**：“现在页面看上去太复杂了，下面的信息太多了，一点丝毫都没有前端的设计感。”

**结果**：第二版改成“地铁线路图”：主画面只突出流程在动，正在干活的人头上冒气泡，其余信息收起。

## 11. 用户画草图：左边终端聊天，右边竖排进度加标签页

**用户**（附草图：左边是终端聊天，右边是竖着的进度面板）：“我左边就是像终端这样窗口，我跟那个在聊天，这里面都有各种数据。然后右边就是刚才你说的进度，从上至下的，然后还有几个 tab，这样子方式会比较好一点。左边是输入的过程，右边是整体的进度，你看这样子行不行的，这样是不是要重新做一个界面的，终端它的聊天的这些信息能不能导入到客户端里面去？”

**Claude 要点**：
- 布局可以，比之前的好；右边是同样的元素改竖排加标签页（流程 / 交接 / 卡片），左边是新加的。

- 终端聊天能导入：Claude 的每次对话都存在本机，窗口里的终端可以接着上一次的对话聊；Codex 也有接着聊的功能（较有把握）；千问未查。
- 出了第三版设计稿（同一链接）。

## 12. 左右能拖；左边是和主要的人的全程对话

**Claude 要点**：

## 14. 测试时不用 Claude，调度员由用户亲手配置

**用户**（施工中途）：“到时候你做测试的时候不要登录 claude，用 codex 作为主要人就好，claude code 不参与，必须我亲手来配置就好。”

**Claude 理解并落实**：
- 窗口加「调度员」菜单：Codex / Claude / 自定义命令，由用户亲手选，选了就记住；**没选之前左边只是普通终端，不启动任何 AI**。
- “接着上一次的对话”按调度员分别处理：Codex 用 `codex resume --last`（只找当前项目文件夹里的对话，已查过帮助确认），Claude 用 `claude --continue`。
- Claude 自测时用一次性的测试开关，不改用户选的调度员，测试里不启动 Claude。
- 右边面板的“调度”一站显示用户选的那位；没告诉面板时只写“调度员”，不乱猜。

## 15. 客户端直接打开文件夹，不再往每个项目里放协作包

**用户**：“我觉得超级助手如果变成这种客户端的方式的话，就可以选择一个目录，打开那个目录，然后就会自动会有它的文件里面的项目文件里面的代码和东西，然后它就进行审查，然后查看。然后在自己这里也会留一个该项目的文件记录。它每打开一个项目就会在自己的文件包里面存一个，这样就不用每次把这个超级助手放在每个项目里面啦，单独打开它，选择到的一个文件就能自动关联起来了。”

**Claude 要点**（状态：💡 对齐中，待用户拍板）：
- 方向对：几十个项目不用各放一份协作包，升级一次全部生效；项目保持干净；客户端启动调度员时可以自动把调度手册交给它（顺带解决 Codex 不知道规矩的问题）。
- 要先想清楚：① 结果（台账、验收、归档）是项目自己的历史，建议仍写进项目 `docs/`，只把施工过程放在超级助手这里；② “自动审查”每次都做太费额度，建议只在第一次打开时起草项目说明；③ 项目文件夹改名或挪位置后要能认出来，用项目自己的版本记录来认。
- 待拍板：审查指什么（A 第一次起草项目说明 / B 每次体检 / C 说了才做）；记录放哪（A 过程在超级助手、结果在项目 / B 全在超级助手）。
- 建议顺序：先验收 v0.2 第一步，再为这件事写方案（会影响所有项目的安装方式，含已装项目的迁移）。

## 16. 打开项目时读台账；记录放项目里更好

**用户**：“刚才你说的是每次审查还是第一次？那我能不能够超级助手一选择那个项目的时候，也会像他们自己用 agent 一样会读取相关的台账、记录什么的。记录放在哪，你觉得放在超级助手里面好，还是放在项目里面好？我觉得放在项目里面是会好一些的。这个你来综合分析一下。”

**核查事实**（视频项目）：台账、归档的需求/方案/验收已进 git；协作包 `collab/`（100K）和过程记录 `.collab/`（13M，大部分是页面检查工具）没进 git，但也没写进忽略清单，有被误提交的风险。

**Claude 要点**（待用户确认）：
- “看”分三档：每次打开读交接（台账、项目说明、进行中的卡片，花费很少）；第一次打开熟悉项目、起草项目说明；代码体检只在用户要求时做。Claude 和 Codex 都不会主动读台账，由客户端启动调度员时交代。
- 同意用户：记录放项目里。分层：结果（台账、项目说明、做完的需求/方案/验收）进项目 `docs/` 和 git；过程（卡片、交接全文、实时输出、页面检查工具）留在项目 `.collab/`、写进忽略清单、不进 git；超级助手只记打开过的项目和每个项目选的调度员；协作包本身不再放进项目。
- 由此撤回上一节“过程放超级助手里”的建议；文件夹改名的担心也基本消除。

## 17. 左边能不能是聊天窗口，图片能直接显示

**用户**（附截图：在窗口左边自己输入 codex 启动并提问）：“如果说我想让这个窗口左边这个对话不是终端的样子，而是一个聊天界面的，我给它输入文字，比如说我让它生成图片，它会把图片贴出来……就是虽然我是终端登录，但是我的界面就是正常聊天窗口那种方式，就是左右两边的一问一答那种方式。这个可以做到吗？”

**核查事实**：Codex 有官方给“聊天界面”用的接口（app-server，Codex 自己的桌面版就用它，标着“试验中”）；Codex 的“生成图片”“看图片”功能都是开启的；Codex 另有官方桌面版（`codex app`）。

**Claude 要点**（待用户决定）：
- 能做：用你现在的 Codex 登录，左边做成一问一答的聊天视图，回复边写边出、排好版，图片直接显示，运行命令前给“允许/拒绝”按钮，有“停止”，能接着上次对话。
- 冷水：接口在试验中，Codex 升级可能要跟着改；终端白送的功能要重做，第一版不如终端全，建议保留终端、加“聊天视图/终端视图”切换；工作量比做窗口还大；先只接 Codex（测试不启动 Claude）。
- 另一个选择：聊天用 Codex 官方桌面版，超级助手窗口只看进度。
- 截图里的小发现：用户是在左边自己输入 codex 启动的，所以标题显示“还没选调度员”、开场交代没有发出；用菜单选一次即可。

## 18. 窗口是通用的：调度员可以是订阅，也可以是 API

**用户**：“因为这是一个通用的窗口。针对于不同的项目，我这里可能会换不同的大模型，有可能是订阅的，有可能是后面 API 的。比如后面接入 ChatGPT 的 API，那它其实这个界面都没有啊。那就调度员就是我想跟你达成共识，就是我通过不管是 API 也好，订阅的也好，我通过说话然后它能接到我的任务进行分配给其他做执行的，各个员工。”

**Claude 整理的共识**（待用户确认）：调度员可以是任何大模型（订阅的命令行工具或 API）；用户在左边用聊天方式交代任务，调度员按协作包流程拆好、分给执行员；窗口通用，每个项目可选不同调度员。

**Claude 要点**：
- 上一节选项 B（用 Codex 官方桌面版聊天）不成立：API 没有界面，聊天窗口必须自己做。
- 关键：订阅工具自带“手”（读写文件、运行命令），API 只会说话。要让 API 当调度员，超级助手要给它配工具：读项目文件、只能写 `docs/` 和 `.collab/`、运行协作包命令——不给改代码的手，铁律由工具保证。
- 三层结构：聊天窗口 → 统一的调度员接口（订阅工具 / API）→ 协作包派给执行员；右边面板不变。
- 冷水：API 按用量付费，要显示花费；模型强弱影响调度质量（能保证不越线，保证不了调度得好）；给 API 配手是目前最大的一块工作；API 密钥只存本机钥匙串，绝不进项目和 git。
- 待确认：① 共识对不对；② 先做聊天窗口 + Codex 订阅（接口设计成通用的），第二步接 API（推荐）还是先接 API；③ API 先接“OpenAI 兼容格式”（覆盖 ChatGPT 及提供同格式的服务，具体名单动工前查证）。

## 19. Claude 不进入；选项目后先配团队并检测连通

**用户**：“Claude 的暂时不进入。你只是开发这个软件的人。然后调度员由我后面去配置，我可以配置 Codex，也可以配置 AGY 的，也可以配置 Cursor 的，甚至是以后其他的订阅平台的。所以说在我选择一个项目之后，应该有一个配置，就是哪个是调度员，然后可以去添加里面的每个执行员是谁，然后进行验证测试，看是不是已经通了。这是一步流程。”

**结论**：卡 6（Claude 聊天视图）取消；Claude 暂不作为调度员选项。

**Claude 要点**（待用户拍板）：
- 流程：选项目 → 团队配置（调度员：Codex / agy / Cursor / 自定义；执行员：写测试、写代码、复查各选一家）→ 检测连通（每人旁边 ✅ 或 ❌ 加原因）→ 保存 → 开始对话；之后可从菜单改。
- 已查：Cursor（`agent --continue`）和 agy（`agy --continue`、`-i` 带开场话进入对话）都能在终端视图里当调度员；聊天视图目前只接了 Codex。
- 直说：执行员必须是协作包能自动派活的工具（目前 Codex、Cursor、agy）；自定义命令只能当调度员。
- 待拍板：① 岗位固定三个（推荐）还是可自由加；② 检测连通做“真干一件小事”（推荐，每人花一点额度、全部一两分钟）还是只查装没装、登没登；③ 配置页第一次打开项目时出现在左边，之后从菜单进入（默认）。
**Claude 核查发现**：协作包现在每一步都是做完才记、派活原文和多数回复没保存、实时输出跑完即删——要先让协作包“边干边记”，界面才有真东西可看。
