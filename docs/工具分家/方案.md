# 方案：工具分家（给施工的人看）

> 依据 [需求共识](需求共识.md)。施工：Claude 亲自做（动的是正在用的两个工具）。

## 1. 开发助手另立一份代码
- `git clone ~/Desktop/project/super-agent ~/Desktop/project/开发助手`，新建分支 `dev-assistant`（起点 = 当前 super-play 最新提交）。独立仓库，不是施工副本，和超级玩家互不牵连。
- 从 `开发助手/desktop/mac/build.sh --install` 重新打包。外壳里编进去的源目录位置（只在 --source-root 时用）随之指向新文件夹。
- 开发助手打开的项目改为 `超级玩家/super-agent`（最近打开列表里的旧位置去掉）。

## 2. 超级玩家搬进一个文件夹
先关掉超级玩家和开发助手、确认没有卡在跑，再整体挪（同一块硬盘内挪动是改名，瞬间完成）：
`super-agent`、`super-agent-worktrees`、`dsh-base`、`dsh-base-home` → `~/Desktop/project/超级玩家/`

挪完要改的写死位置：
| 位置 | 改法 |
|---|---|
| 插件里后台代码的默认位置（dsh-plugin/core/src/index.ts 的 DEFAULT_REPO） | 改成 `~/Desktop/project/超级玩家/super-agent` |
| 同步脚本和两个补丁脚本的默认底座位置（sync.sh、apply_root_config.py、apply_desktop_brand.py） | 改成 `~/Desktop/project/超级玩家/dsh-base` |
| 底座里的依赖和打包产物（有指回旧位置的绝对链接） | 在新位置重新装依赖（pnpm install）、重新同步编译 |
| 超级玩家的启动器和启动设置（app-bootstrap/config.json、SuperAgentLocal） | 用插件自带的生成脚本（dsh-plugin/core/scripts/local-desktop.mjs）按新位置重新生成；先备份旧的 |
| 施工副本的登记（git worktree） | `git worktree repair` |
| Codex 记住的项目位置、Claude 这个项目的长期记忆 | 按新位置补登记 / 把记忆文件夹搬过去 |
| 台账、文档里的旧路径 | 历史记录不改，只在台账加一条“已搬家”说明；说明文档（README）里的用法路径更新 |

## 3. 验证
- 全部测试（每文件一个进程、6 个同时跑）在新位置通过；
- 超级玩家：干净环境打开，首页、任务页正常，后台进程来自新位置；
- 开发助手：干净环境打开 `超级玩家/super-agent`，卡片记录、团队分工在，后台来自应用自带那份；
- 旧位置下不再有任何进程在用。

## 4. 风险和退路
- 底座重装依赖失败 → 超级玩家暂时打不开。退路：挪回原位置（改名即可），旧启动器有备份。
- 挪之前做一次完整备份清单（记下每个文件夹的提交号），出问题按清单还原。
