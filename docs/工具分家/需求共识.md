# 需求共识：开发助手和超级玩家彻底分家

> 2026-11-17 用户：“这就是两个工具，一个是专门给我开发的，还有那个超级玩家，也就是延续下来会一直开发的。”“把超级玩家就是一个目录，开发助手也是个目录。”

## 两个工具的定位
| | 开发助手 | 超级玩家 |
|---|---|---|
| 是什么 | 专门用来开发的工具（DSH 融合前的旧版） | 一直开发下去的产品（DSH 融合版） |
| 改不改 | 很少改，只在开发流程本身要改进时改；改完重新打包，平时冻结 | 天天改，开发助手的每张卡都放进它的代码 |
| 谁改 | Claude 亲自改（改正在用的跑卡流程，属危险类） | 开发助手跑卡（调度/写测试 Codex、写代码 DeepSeek、复查 Codex） |
| 代码 | 自己一份，自己一条线 | 自己一份，super-play 这条线 |

## 目录
```
~/Desktop/project/
├── 开发助手/            开发助手的代码（独立一份，单独一条线 dev-assistant）
└── 超级玩家/
    ├── super-agent/            超级玩家的代码
    ├── super-agent-worktrees/  卡的施工副本
    ├── dsh-base/               DSH 底座
    └── dsh-base-home/          DSH 底座的独立设置
```
应用本体位置不变：`~/Applications/开发助手.app`（从“开发助手”文件夹打包）、`~/Library/Application Support/超级玩家/`。测试项目 `~/Desktop/dsh-实测/测试项目` 不动。

## 验收
1. 两个文件夹按上图放好；`~/Desktop/project` 下不再有散落的 super-agent、dsh-base 等。
2. 超级玩家打开正常：首页、任务页、跑一次已有的对话，后台和界面都来自新位置。
3. 开发助手从“开发助手”文件夹重新打包，打开 `超级玩家/super-agent` 项目正常，团队分工、密钥、卡片记录都在。
4. 两边任一处写死的旧位置都改掉（列在方案里），全部测试照常通过。
5. 改超级玩家的代码不会影响开发助手，反过来也一样。

## 连带调整
- 第一张卡（流程测试带界面）：跑测试这一关是开发助手执行的，改进应做进**开发助手的代码**，不是超级玩家的。分家后重新规划；Codex 写好的 45 项测试照用。
