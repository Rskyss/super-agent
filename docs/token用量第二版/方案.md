## 技术设计（写给施工的 AI；你可以跳过）

**取数模块 `collab/token_usage.py`（只加，不改已有函数行为）**
- `usage_for(tool, output="", live=None)`：统一入口。`codex`/`qwen` → 走现有 `usage_from_text` / `usage_from_log`；`agy` → 读 `stream-json` 行：有 `event == "result"` 且 `result.usage` 就用它，否则把所有 `step_update.usage` 相加（在跑时）；`cursor` → 找最后一条 `type == "result"` 的 `usage`（驼峰字段），没有就 `ok=False, reason="这一轮结束后出数"`，并带 `pending=True`（在跑）。其他工具 → `None`（不算失败）。
- 换算：agy `input = input_tokens + cache_read_tokens`，`cached = cache_read_tokens`，`output = output_tokens`，`reasoning = thinking_tokens`；Cursor `input = inputTokens + cacheReadTokens + cacheWriteTokens`，`cached = cacheReadTokens`，`output = outputTokens`，`reasoning = reasoningTokens`；`total = input + output`，`children = 0`。返回结构与现有一致（`ok/total/input/cached/output/reasoning/children`）。
- 读实时输出：大文件只从尾部找 `result`；找不到再整份按行累加；按（路径、大小、修改时间）缓存结果，补数时不反复读。
- 任何异常都返回 `ok=False` 和原因，不往外抛。

**记录（`collab/dispatch.py`）**
- `_tokens_for` 和备交接资料那段：去掉“只有 Codex 壳”的判断，改调 `usage_for`；`None` 时不写 `tokens` 字段（同现在）。

**右栏（`desktop/view.py`、`desktop/static/panel.js`）**
- `_add_tokens`：去掉三处 `tool in ("codex", "qwen")`；“回复”事件没有 `tokens` 时，按 `reply_to` 找对应“派活”的 `live` 文件现算（老卡补数）；在跑的派活一律用 `usage_for(tool, live=...)`。
- 每轮明细 `history[i]` 加 `tool`、`model`（取自对应“派活”事件）和 `missing`（没读到时为 true、带 `reason`）；`pending` 的不算没读到。
- 合计结构加 `missing`（没读到的轮数）；`panel.js` 合计行有 `missing` 时加“不含没读到的 N 轮”；鼠标提示每轮写“工具 · 模型 · 用时 · 用量”。

**行政（B 卡）**
- `client.chat` 返回里除 `tokens` 外加 `usage`（`prompt_tokens`、`completion_tokens`、`prompt_tokens_details.cached_tokens`，没有就不带）。
- `desk.py`：每次 `client.chat` 后累加到这段对话；每回答完 `emit({"type": "usage", "total": N})`；累计数写进对话记录（新 `role: "usage"` 行，读回时恢复成最后一个值，不当作消息）；起标题那次也加。

**测试设计**：取数模块用按真实结构做的小样本（agy 在跑 / 跑完、Cursor 跑完 / 在跑 / 无结果、格式不认识、文件不存在）；右栏用假卡片记录 + 假实时输出（含换人、老卡没有 tokens 字段）；行政用假接口。测试里不依赖本机真实记录；C1.5 对数由 Claude 验收时手工做。
