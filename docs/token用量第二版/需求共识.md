## 2. 要做成什么样（你能看到的）

1. **团队里能选的四种工具（Codex、千问、agy、Cursor）都有数**，不论放在写方案、写测试、写代码还是复查。
2. **数字和人对得上**：一个环节换过人，这一行的合计照实加上所有人；鼠标停留时**每一轮写清是谁（工具 · 模型）、用了多少**。
3. **在跑的时候**：Codex、千问、agy 随做随涨；**Cursor 只在一轮结束时才报数**，跑的时候写“这一轮结束后出数”，不显示 0。
4. **读不到就老实说**：某一轮没读到，写“有 N 轮没读到”，合计后面注明“不含没读到的”，**不显示 0、不乱编、不挡卡片往下走**。
5. **本卡合计**包含所有工具。
6. **老卡补数**：已跑完的卡，原始记录还在的，打开就显示补上的数（只是重新读一遍记录，不花额度）；记录已经没了的写“读不到”。
7. **行政**：每段对话顶部显示这段对话累计用了多少 token，每回答一次往上加（沿用第一版共识第 5 条）。

## 3. 数字怎么算（沿用第一版口径）

**合计 = 输入 + 输出，输入里包含缓存读取**；详情分项写输入、其中缓存读取、输出。四种工具报数的写法各不相同（agy、Cursor 把缓存读取单独报，Codex 算在输入里），都换算成这同一个口径，才能互相比、能相加。

1. **C1.5 写代码**：千问三轮仍是 **9,886,042**；agy 两轮按上面口径从原始记录读出（第 3 轮约 564.6 万、第 4 轮约 325.6 万，**最终数以《方案》核实口径后为准**），这一行合计 = 几轮之和，鼠标停留每轮写对工具。
2. **Cursor**：拿一份真实 Cursor 记录（超级玩家仓库 CARD-001 第 13 条）读出它报的数，换算结果与手算一致。
3. **C1.6 写代码（agy）**：跑的时候数字一格一格涨；结束后定格，等于 agy 最后报的总数（换算后）。
4. **读不到**：记录缺失、格式不认识、读取出错三种情形，都显示原因、卡片照常走。
5. **行政**：对话顶部显示累计，回答一次加一次；重开应用后同一段对话的数还在。

## 7. 泼冷水（风险和我不确定的）

- **agy 的“思考”部分算没算进输出，我不确定**：它报的总数正好等于输入加输出，思考是包含在输出里还是另算，要在《方案》阶段查清；结论会影响 agy 的数字差多少。
- **Cursor 报的“输入”是否已含缓存读取，我不确定**：从数字比例看像是不含（缓存读取是输入的 8 倍多），《方案》阶段要用实测确认，否则 Cursor 的数会重复或漏算。
- **依赖各家工具自己的记录格式**，工具升级可能变；变了就显示“读不到”，不会让卡出错。
- **数字是工具自己报的**，没法核对它报得准不准。
- 做完要重装开发助手才生效，重装要你先退出应用。
