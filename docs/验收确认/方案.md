# 方案：做完后让用户真的能验收

状态：2026-11-07 ✅ 用户批准。代码交给 Cursor，Claude 写施工单和验收测试。

## 用户看到什么

**写方案时：** 方案里多一项“做完后怎么看结果”。用户批准方案时能看到。

**开工前：** 项目有没提交的文件时提醒：“你的项目有 N 个文件还没提交，这次施工看不到它们，改好的版本里也没有。先提交，或者继续。”

**做完时，右栏上方：**

> **做完了，请你确认**
> 你应该看到：（方案里的验收标准）
> 在哪看：（方案里写的说明）
>
> [打开改好的版本]
> [确认没问题，放进项目] [不满意，继续改] [放弃这个需求]

**点“打开改好的版本”：**

- 网页类项目：程序在改好的副本里启动，浏览器自动打开，按钮变成“关闭预览”。
- 没有启动方式的项目：打开文件夹。
- 启动失败或端口被占：用大白话说明，并提供打开文件夹。

**点“放弃这个需求”：** 确认框写“这次的改动不会进入项目，你的项目不会变。”

**改好的版本不在了：** 状态写“改好的版本不在了”，只给“放弃这个需求”，并说明可以重新提这个需求。

**放进项目失败：** 顶部和流程都写“没能放进项目”和原因，不再写“做完了，等你验收”。

## 风险

- **预览会在你的电脑上运行命令。** 命令由 Codex 写进方案，用户批准时能看到，点按钮才运行。批准后模型不能再改。
- **依赖要借用。** 副本没有依赖文件夹，程序把项目里的 `node_modules` 链接过去。已实测 `chrild`：另一份副本这样能启动，首页和入口文件都正常。启动工具可能改写共用的缓存，只影响下次启动速度。
- **依赖不同步。** 这张卡新增依赖时，预览可能启动失败，提示后可以打开文件夹。
- **端口冲突。** 项目本身开着时，预览可能启动不了，会明说。
- **看到的不是工作区现状。** 副本从最后一次提交开始，没提交的文件不在里面。`chrild` 现在有 451 个，所以要先提交，否则预览和施工都可能缺文件。
- **Codex 可能写错启动方式。** 只影响预览，不影响施工和合并，可以打开文件夹自己看。
