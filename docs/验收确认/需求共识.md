# 需求共识：做完后让用户真的能验收

状态：2026-11-07 ✅ 用户确认。

## 用户原话

“验收通过合并到主线的时候出现这样子的。还要修改、不做了，这个东西有点让人误解。什么东西算验收。”
“把一些老的错误改不了的东西就去除掉嘛，免得影响开发。反正以后是正常的就可以了。”

## 验收是什么

用户亲眼确认结果符合要求，同意放进项目。程序测试和 AI 复查都不算验收。

## 要做什么

1. 做完时，卡片上写明“你应该看到什么”和“在哪看”。
2. 有“打开改好的版本”，用户不用懂命令就能看到结果。
3. 三个按钮用大白话：确认没问题，放进项目 / 不满意，继续改 / 放弃这个需求。放弃时说清楚改动不会进入项目。
4. 改好的版本不在了，就不给确认按钮，直接说明情况。
5. 放进项目失败时，流程和顶部说法一致，提示不用内部词。
6. 卡片标题到处一致。
7. 项目有没提交的文件时，开工前提醒：这次施工看不到它们。

## 不做

- 不为老卡写兼容。老卡不能处理的，标记完成或放弃，不影响以后。
- 不替用户判断结果好不好。
- 桌面软件等不能在浏览器打开的项目，这期只打开文件夹，并写明怎么看。

## 怎么算做完

- 真实项目（`chrild` 游戏）走一遍：做完 → 打开改好的版本 → 浏览器看到结果 → 确认 → 进入项目。
- 不满意继续改、放弃、副本不在、端口被占、启动失败，每种情况都有明确提示，没有卡死。
- 确认、放弃、切项目、退出后，预览都关掉，没有残留。
