## 中等问题：自动创建阶段仍可能覆盖用户后续导航

位置：`dsh-plugin/core/src/client/TaskSidebar.tsx:441`；`dsh-plugin/core/src/client/index.ts:285`、`:289`、`:290`。

当前左栏在归档RPC返回后检查有没有切到其他主会话，然后调用`handleNewChat()`。此后`startChat`还会异步等待status及createChatSession，却在创建完成后无条件openSession；导航检查没有覆盖这段等待。

可触发顺序：

1. 归档当前普通对话，归档RPC成功；此时没有其他主会话，自动startChat开始。
2. 默认聊天的创建请求仍在等待时，用户打开另一个对话。
3. 创建请求完成，迟到的openSession把用户从另一个对话带到新首页。

影响：自动恢复首页覆盖用户较新的明确导航，未满足归档中途切走不抢导航的要求。现有“等待归档期间切走”测试只覆盖归档RPC未返回的阶段。

复现证据：临时目录`/private/tmp/superagent-review-home-race/`。`race.spec.tsx`渲染实际TaskSidebar，并从当前index.ts提取实际startChat函数体、用TypeScript转译执行；只将远端status/create接口替换为受控接口。归档成功后挂起create，切到other并更新主会话快照，再完成create。期望导航记录`['other']`，实测为`['other','new-home']`，断言失败。它是组件与实际函数体的受控复现，未声称在浏览器窗口中已经发生该竞态。

命令：

```sh
cd /private/tmp/superagent-review-home-race
node /Users/rs/Desktop/project/dsh-base/node_modules/vitest/vitest.mjs run --config /private/tmp/superagent-review-home-race/vitest.config.mts
```

输出：1个测试失败，`expected [ 'other', 'new-home' ] to deeply equal [ 'other' ]`。仓库产品与测试未为此复现做任何修改。

可复用公开能力：`ui.layout.beginNavigation(): AbortSignal`，DSH `packages/client/ui-layout/src/client/service.ts:81`；原生`packages/client/ui-workspace/src/client/navigation.ts:310-321`已示范在异步connectBlank之后检查navigation.aborted，避免较早操作覆盖后续导航。建议在自动恢复全过程中保留同等导航取消语义，而非只在归档RPC完成时检查一次。
