### 1. 00b未选模型时遗漏明确规定的小字

位置：`dsh-plugin/core/src/client/FirstUseSetup.tsx:488-498`。

触发：Key验证通过、模型列表出现，但用户尚未亲自选模型。

实际：只有灰色确认按钮，缺少旁边“先选一个模型”。00b深浅并排图均可确认。此句不只出现在草图，`docs/DSH改版/页面说明.md:109`明确规定“没选之前确认是灰的，旁边小字先选一个模型”。它属于内容要求，不能按尺寸或对齐自由省略。应在未选时显示，选中后收起。按钮左右对齐本身未作为问题。

### 2. 再次粘贴同一Key不会重新验证，反而清掉当前状态

位置：`dsh-plugin/core/src/client/FirstUseSetup.tsx:149-155`、`:181-185`、`:244`。

触发：第一次模型查询因临时网络故障失败，网络恢复后用户按说明再次粘贴完全相同的Key。

实际：handleKeyChange增加generation并清空模型、选择和错误，但apiKey的值没有改变，验证effect的依赖不变，loadModels不会再执行。页面从错误状态变成既无错误也无模型/确认，用户必须改变Key字符或切服务商才可能恢复。同一Key在成功后重新粘贴也会清空列表而不重新读取。

受控复现直接渲染当前真实FirstUseSetup：第一次loadModels reject，后续准备返回有效模型；重复paste同Key后，期望请求总数2，实际仍为1，断言失败。未改产品或仓库测试。

复现文件：`/private/tmp/superagent-review-home-race/onboarding-repaste.spec.tsx`。命令：

```sh
cd /private/tmp/superagent-review-home-race
node /Users/rs/Desktop/project/dsh-base/node_modules/vitest/vitest.mjs run --config /private/tmp/superagent-review-home-race/onboarding.config.mts
```

输出：1个测试失败，`expected vi.fn() to be called 2 times, but got 1 times`。这是组件受控复现，未冒充真实窗口已经发生该故障。修复应使同值再次粘贴成为明确的重新验证动作，同时维持旧请求隔离。
