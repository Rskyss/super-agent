## 一、运行中改要求（对照 04）

**图上的流程**：任务正在跑 → 你在任务对话里说“汇总别放最上面” → 超级玩家回“可以，这要改验收标准第 3 条，你确认了我再交给调度员，等复查这一轮跑完顺手改，不影响已经通过的测试” → 确认条“确认改 / 算了” → 点确认改。

**现在的问题**：点“确认改”，后台直接拒绝“现在不能修改”。后台原来的做法是：跑着的时候只把你的话记下来，等这一轮跑完再弹确认条——所以跑着时点确认，根本没有地方接。

**改成**：
1. 跑着时点“确认改”：后台把这条**已确认的修改**存下来，确认条变成“已确认，这一轮跑完生效”，不再报错。
2. 调度员在下一个**自然停顿点**取走它：复查这一轮结束、回去改代码之前（复查没过要返工时，把新要求和复查意见一起交给写代码的；复查过了、全部测试过了，也先按新要求再走一轮写代码 → 测试 → 复查）。生效时任务对话里出一句“你的修改已生效：验收标准第 3 条改成……”，右栏、轨迹都记一笔。
3. 万一这一轮跑完就停下了（等你验收、停下等你决定）还没被取走：沿用现有的“接着改”做法自动生效并重新开工，不让你再点一次。
4. 已通过的测试不重跑白做：只按改了的那条补测试、改代码。
5. 同一张卡跑着时你连续确认好几条：按顺序排队，一起生效。
6. 点“算了”：什么都不存。

## 二、看改动（对照 05t 轨迹）

**现在的问题**：后台只记“改了哪几个文件”，不记每一步具体改了什么，所以轨迹里“写代码”那几行没有“看改动”。

**改成**：每次“写测试”“写代码”（含返工）这一步结束时，把这一步改的内容存一份进这张卡的资料里，轨迹那一行出现“看改动”，点开看到这一步改了哪些文件、每个文件改了哪几行。旧卡没有这份记录的，照旧不显示，不假造。

## 三、本次运行（对照 04/05 右栏底）

右栏最底下一行：“本次运行 · 改了 N 个文件 · 守住 N 条规矩”。

- **改了 N 个文件**：用后台已有的“改动范围正常（N 个文件）”那条记录，这张卡最新一次的数。
- **守住 N 条规矩**：图上没定义，**Claude 推荐**算成“这次跑完自动检查通过了几项”：改动没超出方案说的范围、没偷偷改原有测试、没碰受保护的文件……通过几项写几。点开能看到是哪几条。没检查过的不显示这半句。
