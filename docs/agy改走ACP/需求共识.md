1. 开发助手叫 agy 干活（写测试、写代码、复查、团队检测）时，不再用 Google 点名不支持的“无界面一次性命令”（`agy -p`），改走 Google 官方给第三方程序开的门（`agy acp`，T3 Code 走的同一条路）。
2. 用户看到的一切不变：卡片实时进度、看门人（卡住提醒）、token 用量、报错原因、团队检测，照常工作。

## 已查到的现状

- 开发助手里叫 agy 只有一个出口（派活时拼出 `agy -p … --output-format stream-json`），实时进度、用量、报错、看门人认“在跑哪条命令”，都读它吐出来的那种格式。
- 本机 agy 1.5.14 自带 `agy acp`。11-22 实测：握手、开会话都不花额度；开会话就能拿到全部可选模型（含现在用的 Gemini 4 Neon 高）；跑一件小活（建一个文件）14 秒完成，过程逐步吐出、写文件前会来问权限、最后报出用量（约 2.4 万 token）。
- ACP 自带四种权限档：默认（每步都问）、自动批改文件、**自动（改文件和安全命令自动批，不可逆操作才问）**、只做计划。
- 登录方式里除了个人 Google 账号，也认 Gemini API 密钥——以后真想彻底合规，可以只换登录方式，不用再改接法。

## 不做

- 不改超级玩家、w2、IP。
- 不改团队页的模型列表（ACP 能现拿模型列表，这次不用）。
- 不改界面，不改卡片流程、关卡规则。
- 不删本机 agy 包装壳。

## 怎么算验收通过

1. 跑卡时派给 agy 的活，进程里看到的是 `agy acp`，没有 `agy -p`。
2. 团队检测 agy 那一行照常“通了”。
3. 一张真卡里 agy 当写测试员跑完：卡片实时进度能看到它在干什么、token 用量有数、看门人能认出它在跑测试。
4. 故意给一个不存在的模型名，卡片上显示 agy 自己说的原因，不是“没有回复任何内容”。
5. 老测试全过。

## 泼冷水

- **合规只是更近一步，不是彻底合规。** 接法和 T3 一样了，但跑卡仍是程序自动派活、没人盯着；论坛上给 T3 放行的前提是“单人、人在场”。封不封号仍由 Google 判，说不准。
- 新办法多了一个“翻译”环节（开发助手 ⇄ agy），多一个地方可能出错；agy 每次升级如果改了 ACP 的说法，要跟着修。
- 权限选了全部自动批：agy 做的任何操作都不拦，安全性和现在一样，没变好也没变差。
- 现在 agy 是开发助手自己的写测试员，改它的时候不能再拿它给自己写测试，这张活由别人写测试（方案里定）。
