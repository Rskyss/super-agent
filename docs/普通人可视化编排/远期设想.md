# 远期设想：让普通人用自己的订阅组一支 AI 团队

> 记录时间：2026-11-04　状态：💡 远期方向，**现阶段不做**  
> 现阶段口径（用户原话）：“现在阶段肯定是我自己用好了才去做那个事情。”

## 最早的需求（2026-11-04 上午，原对齐稿摘录）

1. 不想只在终端里看黑框，想看见 agent 们的流程和状态，可以有轻微交互；看不到动静，就不知道它是不是卡死了。
2. 交互重点不是跑起来后一路点按钮，而是**灵活切换自己订阅的模型和工具，把它们安排到不同岗位**（例如 Claude 当调度，Cursor、Codex 当执行），排好后按这个安排开工。
3. 目的：让普通人、不懂技术的人也能把超级助手玩透，放进任何项目里完成工作。

参考过的例子：
- ring_hyacinth 的像素办公室（Star Office UI）：AI 干活时去工位、闲置时去休息区、出错时去故障区，头上有气泡写着正在做什么；第二版加了“昨日工作小记”，支持手机访问。资料整理见 `docs/多agent协作包/参考/ring_hyacinth_post*.txt`。
- OpenAI Devs 的一条帖子：有一条流程线，能看出走到哪一步了（当时没有整理成文档）。

> 2026-11-04 曾按上面的需求做过一版本机“指挥台”（岗位板 + 进度条 + 待办）。用户说明那是自己拿来试玩的，当天全部删除（网页、测试、引擎里的座位改动、相关文档）。

## 用户的设想（同日晚上补充）

很多人不懂技术，但订阅了好几家 AI。顺着 DeepSeek 超级助手“调度 + 执行”的思路，让普通人不碰技术，按自己的想法给 AI 分工：哪个适合做图、哪个适合做分析、哪个适合写内容，自己调整；在页面上配置好后，整套自动跑起来。目标：让超级助手更简单，不只服务写代码。

## 当时的判断（2026-11-04，供以后启动时参考）

**成立的地方**
- 痛点真实：多订阅用户现在要自己在各家 AI 之间复制粘贴、当传话的人。
- 有现成的引擎可以复用：超级助手已经能按“调度 + 执行”分工跑通写代码；以后做成可以自己起名、自己指定由谁来做的岗位，是在这个基础上往外扩。

**要先想清楚的四件事**
1. **谁来判断做得好不好**：写代码有测试当裁判，可以自动返工；写内容、做图、做分析没有自动裁判。不能退回“让 AI 评 AI”，需要用户在更多环节点头，或者事先把标准写成能检查的条件。
2. **不是所有订阅都能被调用**：目前能自动调用的是带命令行版本的几家（Claude、Codex、Gemini、Cursor）；只有网页版或 App 的订阅程序接不进去，模拟点网页不稳定，还可能违反使用条款。做图类工具能不能用订阅直接调用，当时未核实。
3. **普通人不知道谁擅长什么**：应该提供现成的团队模板，用户只需要换人，不需要自己画流程图。这也是和市面上拖拽搭流程的工具（扣子、Dify、n8n 等）的区别。
4. **规模大得多**：每多一种场景，就多一套“怎么交接、怎么验收”的规矩要设计。

**建议路线**
1. 把“写代码团队”作为第一个模板（已能跑）。
2. 选一个用户自己用得上的非代码场景做第二个模板，跑通“谁来把关”。
3. 两个模板都跑通后，再让岗位可以自由增减。

## 2026-11-07 用户把方向提前（待拍板）

用户原话大意：场景以后再想。现在的目标是把业内能接的 CLI 都接进来，存成一个“元素库”；需要时把它们组合起来，由行政（客服）串联去办一件事。例：搜地图时导入高德。第一批要做到导入流程顺利、简单。

Claude 的判断：
- 这和当天上午确认的“造工具的工坊”定位不同，属于本文的远期方向提前，要用户确认是否现在做。第 4、5 批仍待验收；这是大需求，要走需求共识、方案、任务清单。
- 元素分两类：大脑（Codex、Claude Code、Gemini、Cursor、agy，用订阅）和工具插头（高德、飞书、GitHub 等）。高德官方没有 CLI，提供的是 MCP Server（2025-03 上线，lbs.amap.com/api/mcp-server），要高德开放平台开发者账号、实名认证和 Web 服务 Key。只认 CLI 会漏掉大部分服务。
- 建议行政当前台（聊清需求、推荐元素、请用户点头），由一个强大脑装上插头去串联。行政用的便宜模型串多工具不可靠（见 ../按需求大小调配/多模型协作调研.md）。Codex 本身支持装 MCP，元素库主要管存放、检测、按需装给大脑。
- 冷水：注册和实名认证省不掉，只能引导；需要在本机运行的插头要额外的运行环境；装太多插头费额度、易出错，要按需装；会动手的工具（打车、发消息、付钱）必须弹窗确认；多工具串联有被外部内容带偏的风险；Claude 桌面版、Trae、Cursor 已能装工具串联，我们的差异只在多家订阅的大脑放在一起，加一个说大白话的前台。
- 建议第一批：元素库页面（AI 助手和工具插头两栏；推荐清单一键添加、粘贴官方配置；检测按钮；密钥进钥匙串）→ 行政推荐元素、用户点头后装给负责的大脑 → 用“高德加 Codex 规划周末路线并写成文档”在真实窗口验收。

### 2026-11-07 用户补充

用户明确：最终要接入各平台、各种能力的订阅（CLI 或 API）并串联起来。第一步要解决的是把所有能力都收进超级助手：像积木块，可以灵活调用；以后按不同流程和想法，取需要的积木组合。现在接的 Codex、Cursor、agy 是写死的。

Claude 的补充判断：
- 积木统一说清五件事：能做什么、怎么接进来、要不要密钥、能不能用（检测）、会不会替用户动手。
- 收三种接口：AI 助手 CLI、工具插头 MCP、只有 API 的平台。只有 API 的，由超级助手先造一个转接头，“造工具”和“收积木”在这里接上。
- 目标是“三种形式都能收”，不是逐个平台去接；预先放进去的只挑几家用户用得上的。
- 第一步至少要真用上一次：团队设置改为从积木库里选，再加一个“高德加 Codex”的真实组合。
