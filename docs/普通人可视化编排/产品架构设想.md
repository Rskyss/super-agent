# 产品架构设想

**状态：** 💡 用户提出的整体方向（2026-11-07），还不是已批准的方案。以后每批方案都要说明自己落在哪一层。讨论过程见 [远期设想.md](远期设想.md) 末尾。

## 用户原意

收集能力：把各订阅平台、产品的 CLI 或 API 导进积木库，形成各种各样的能力，并保持每块都能用。再把这些能力串起来，为业务服务。

## 分层

```
前台（行政）：听用户说要办什么，推荐用哪些积木，请用户点头
    ↓
业务 ← 串联 ← 积木库 ← 收集能力
       ↑                 ↑
     把关         授权和花费（贯穿每一层）
       全程留痕
```

| 层 | 做什么 | 现在有没有 |
|---|---|---|
| 收集能力 | 判断一个订阅或平台能不能收；导入它的 CLI、插头（MCP）或 API | 没有，Codex、Cursor、agy 是写死的 |
| 积木库 | 每块积木按统一规格说清五件事：能做什么、怎么接、要不要密钥、能不能用、会不会替用户动手；定期检测，坏了用大白话说明 | 只有“检测”按钮 |
| 串联 | 把几块积木按流程接起来 | 只有写代码这一条，写死的 |
| 业务 | 写代码、出行规划、写稿等 | 只有写代码 |
| 前台 | 聊清需求，推荐积木，请用户点头 | 有（行政）。串联交给强的 AI 助手，不交给行政用的便宜模型 |
| 把关 | 每条串联写明哪一步由用户点头，或者按什么条件检查 | 只有写代码的测试 |
| 授权和花费 | 会动手的积木先问用户；看得到花了多少额度、费用 | 有确认弹窗，没有花费统计 |
| 全程留痕 | 谁做了什么都有记录 | 有 |

## 要记住的事实和判断

- 不是每个订阅都有 CLI。有 CLI 的主要是写代码类的 AI（Codex、Claude Code、Gemini、Cursor）；服务类平台多数提供 MCP 或 API（例如高德只有 MCP）；不少订阅只能在网页或 App 里用，收不进来。具体是哪几家，要逐家核实。
- 只有 API 的平台，由超级助手先造一个转接头再收。
- “保持能用”是长期的活：平台会升级，密钥会过期，额度会用完。
- 让 AI 评 AI 靠不住，非代码业务要单独设计“把关”（证据见 ../按需求大小调配/多模型协作调研.md）。
- 先后顺序：积木库 → 用一次真实组合验证 → 自由串联 → 通用的把关和花费。

## 例子：豆包 C 端订阅（2026-11-07 核实）

- 用户问能不能把手机上订阅的豆包“反向弄出来”画图、做视频。结论：不收。豆包用户协议（2026-09 版）第 5.1.1 条禁止使用未经授权的插件、外挂、第三方工具，第 5.1.2 条第（9）项禁止反向工程。另有封号、随版本失效的风险；超级助手自带这个功能，等于对外发放违规工具。
- 替代：火山引擎“火山方舟”开放同系列模型（画图 Seedream、视频 Seedance；Seedance 2.0 于 2026-04-14 开放接口，纯生成约 1 元一秒）。需要火山引擎账号、实名认证和 API Key，按用量另付费，豆包会员额度不通用。已有非官方的开源 MCP（github.com/nsmao-com/seedream-mcp），用前要看过代码；也可以由超级助手造转接头，作为“只有 API 的平台”的第一个例子。
- 规则：C 端订阅只有官方给了 CLI、MCP 或 API 才收；没有就找同一家的官方开放平台替代，不做破解，也不模拟点击。

## 安装积木的流程设想（2026-11-07）

用户原意：用户不用手动装。想装什么、或者不知道该用什么时，问行政（DeepSeek）；行政告诉他有哪些选择，并协助安装。动手的可能是行政，也可能是行政指派的 Codex。

Claude 的建议分工：
- 推荐装什么：行政。只给建议，不动手（行政不能运行命令是有意设的安全线）。
- 推荐清单里的积木：程序按事先测过的固定步骤装，不靠 AI 临场发挥。
- 清单外的积木：派 Codex 照官方说明装，有风险的动作照样弹窗。
- 注册账号、实名认证、付钱、复制密钥：用户亲手做，行政一步步带。
- 装完：程序自动检测并试用一次，成功才放进积木库。

流程：用户提出 → 行政列出选择（是否官方、要不要钱、要准备什么）→ 用户点“帮我装”，出现安装单（装什么、从哪来、要准备什么、会不会替你动手、谁来装）→ 需要亲手做的由行政带 → 程序或 Codex 安装，右栏显示进度 → 试用成功，放进积木库。

规矩：
- 密钥只填专门的密钥框，存进钥匙串，不在聊天里贴（行政聊天内容会发给用户选的服务商）。
- 装之前先亮出来源，官方和网友做的分开标；推荐清单里的事先看过代码。
- 没试用成功不算装好。
