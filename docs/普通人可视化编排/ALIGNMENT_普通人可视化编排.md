# ALIGNMENT：普通人可视化编排（让非技术用户玩透 Super Agent）

> 阶段：① 对齐 🔄 进行中（2026-11-04）  
> 灵感来源：DeepSeek Harness《Super-agent 设计探索》；用户对「排座位 / 可视化」的澄清  
> 现有底座：`collab/` 协作包（终端向、调度员+执行员已跑通）

---

## 一、原始需求（用户原话整理）

1. 不想只在终端里看黑框，想看见 agent 们的流程和状态；可有轻微交互。
2. 交互重点不是跑起来后一路点按钮，而是：**灵活切换自己订阅的模型/工具，把它们安到不同位置**（例如 Claude 当调度，Cursor/Codex 等当执行）；排好后按这个配置跑。
3. 做这件事的目的：让**普通人、不懂技术的人**也能把 Super Agent **玩透**——通过手动调整、安置角色，**放进任何项目里去完成工作**。

---

## 二、需求理解（产品语言）

### 一句话

做一个「看得见、拖得动」的超级助手外壳：普通人打开界面 → 把自己已有的 AI 订阅安到座位上 → 选一个项目 → 用大白话提需求 → 看进度与结果；底层仍用现有协作包干活。

### 用户会经历什么

1. **安装/接入**：把超级助手挂到某个项目上（尽量少步骤、少术语）。
2. **排座位**：看到调度席、执行席（写代码 / 测 / 复查等），把自己订阅的 Claude、Cursor、Codex、agy…拖到或点选到位置。
3. **说需求**：用大白话；系统帮写成可验收的需求卡，用户确认。
4. **看热闹**：跑起来后主要看「谁在干、到哪一步、卡没卡住、要不要我拍板」。
5. **拍板**：只在方案、合并、上线等关口出现「需要你处理」。

### 和 DeepSeek 文章的关系

| DeepSeek 文章 | 我们这一版想给普通人的 |
|---|---|
| Router / Worker 双层 | 画面上的「调度席 / 执行席」，可手动安置 |
| 省人的注意力 | 普通人不用懂终端、不用记命令 |
| 团队云端、飞书/GitHub 常驻 | 个人电脑、任意本地项目、先可拖可看 |
| 研究原型偏工程 | 产品外壳偏「能玩、能调、能完成工作」 |

### 和现有协作包的关系

- **不推倒重来**：`collab/` 继续当发动机（派活、返工、看门人、归档）。
- **本需求做外壳**：编排界面 + 进度展示 + 普通人引导；排座位的结果写入项目里的配置，再驱动现有 `run`。
- 原第一版共识里「面向普通人的引导 / 产品化」曾标为不做；**本任务正式把它提成下一阶段主目标**。

## 三、边界确认（初稿，待拍板）

### 明确想做

- 可视化「座位图」：谁当调度、谁当哪类执行。
- 开跑前可调整；开跑后按配置执行（过程中以观看为主）。
- 进度与「需要你处理」用普通人能懂的话展示。
- 目标是「丢进任意项目」——先支持已是 git 仓库、且本机已装好对应工具的项目。

### 明确先不做（建议，待确认）

- 把 Claude/Cursor/Codex/agy **原版聊天窗完整嵌进**同一页面（官方一般不支持）。
- 云端常驻、监听群聊主动揽活（文章里团队规模部分）。
- 自动帮用户购买/登录各家订阅。
- 像素办公室宠物形象（可作以后彩蛋，不挡第一版）。

### 已知限制（要对用户诚实）

- 「放进任何项目」仍依赖：项目能用版本管理、本机已登录对应 AI 工具、项目有办法自动验对错（或由调度员帮译成可检查标准）。
- 普通人「玩透」的是**编排与验收**，不是各家工具内部的高级调试。

## 四、待用户拍板（选择题）

### Q1. 第一版最想先交付哪一层？

- **A（推荐）**：座位编排 + 简单进度条 +「需要你处理」列表（能玩起来）
- **B**：只要座位编排（配置可视化），进度仍可暂时用现在的文字进度
- **C**：座位 + 进度 + 各 agent 对话回放（像看会议纪要）

### Q2. 调度席能不能换人？

- **A（推荐）**：执行席完全自由换；调度席默认 Claude，可换但界面要提示「调度员不宜亲自改产品」
- **B**：所有席位完全自由，谁都可以当调度
- **C**：第一版调度席锁死 Claude，只开放执行席

### Q3. 「普通人」第一批用户画像？

- **A**：就是你自己 + 少数会装 Cursor/Claude 的产品朋友（先自用打磨）
- **B**：完全小白（从没装过开发工具）——则安装引导要做成产品主路径，工期明显更长
- **C**：先 A，文档里为 B 留口子

### Q4. 和现有「协作包第一版」的关系？

- **A（推荐）**：协作包引擎继续打磨；可视化编排作为**并列的新产品阶段**（本目录文档）
- **B**：暂停引擎杂项，全力做可视化
- **C**：先把引擎再补一轮再开可视化

### Q5. 换座位的时机？

- **A（推荐）**：开跑前可换；同一张需求卡中途只影响「下一轮返工用谁」（若支持）
- **B**：仅开跑前，跑起来到结束都不能换
- **C**：随时热切换当前正在跑的角色（实现难、风险高，不推荐第一版）

## 五、成功长什么样（草案，共识阶段再定死）

普通人能在**不碰终端命令**的前提下：

1. 给一个项目「装上」超级助手；  
2. 自己排好调度/执行座位；  
3. 提一件小事并看懂进度；  
4. 在需要时点「同意方案 / 同意合并」；  
5. 感觉「我在指挥一个 Super Agent」，而不是「我在敲开发命令」。
