# 拆解方案

## 要做什么（一句话）
按施工单 B，把行政每次回答和起标题时收到的 token 用量加到这段对话里，存进记录，并显示在对话顶部。

## 拆成几步，每步做什么、产出什么
1. 先在 tests/test_token_b_extra.py 补现有验收没守住的场景，覆盖无效用量、旧记录、起标题和下一次回答先后交错，以及用量行接在末尾后还能认出原来那条行政提醒。
2. 先跑本卡验收命令，确认功能还没写时，相关测试会按预期失败。
3. 在 desktop/clerk/desk.py 给每段对话留一个累计数，初始留空，每次只把大于零的整数加进去，缺失值、布尔值、小数和字符串都跳过。
4. 在回答循环每次拿到模型结果后、以及起标题拿到模型结果后，各走同一个累计入口，哪怕标题最后为空也照常计入已收到的有效用量。
5. 把同一段对话的累加、用量事件和写记录排好顺序，避免起标题和下一次回答同时回来时漏加或把总数写倒，并沿用已删除对话的保护。
6. 每次加完就发一条带累计数的 usage 事件，并用 _record_line 追加一条 role 为 usage、total 为累计数的记录。
7. 重开时让 _read_lines 读出有效用量行，在 _conversation 里用最后一条有效记录恢复累计数，读完只发一次带 history 标记的用量事件，用量行既不进模型消息，也不影响最后一条行政提醒的识别。
8. 在 desktop/static/chat.js 新增并导出 ChatCore.headerUsage，顶部改用它，无有效数字时留空，小于一万用千分位，一万到不足一亿用一位小数加「万」，一亿起用一位小数加「亿」。
9. 施工结束后只跑本卡验收命令，若发现老测试与新口径冲突，就报出具体测试和失败现象，交给复查判断。

## 你会看到什么结果
服务商报了用量后，用户会在对话顶部看到「本段对话 N token」，重开同一段对话时数字还在，继续聊会从原来的数字往上加，从未收到有效用量的对话顶部留空。

## 明确不做什么
不统计「改要求拆分」和「连通检测」的用量，不改卡片右栏，不折算费用，不改行政调模型的方式，不改 tests/test_token_b_acceptance.py、tests/token_b_chat_check.js 和 tests/acceptance_helpers.py。

## 需要你确认的问题
无

## 做完后怎么看结果
点「打开改好的版本」，在预览里的行政对话发一句话，等回答和标题出来后看对话顶部，再切走并点回同一段、刷新页面、继续问一句，确认数字还能看到并继续增加；预览副本要配好会返回用量的行政模型，才能用真实回复看到数字。
启动：python3 -B desktop/server.py --port 18754 --token token-b-local-preview
