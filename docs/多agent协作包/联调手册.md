# 联调手册：Codex / agy / Cursor(agent) 命令行调用

> 给其他电脑、其他 agent 看的。照着这里的命令，能复现"三家都能连上、指定模型、写文件"。
> 最后验证：2026-11-04，本机（macOS）。模型名会随官方更新变化，先按第 4 节核对。
> 一键验证：`bash 联调冒烟测试.sh [工作目录]`（同目录），输出 PASS/FAIL。

## 2. 每家的调用方式（已实测）

所有命令都在**工作目录**里执行（文件会写到当前目录）。

### 2.1 Codex（测试员 / 备选写码）

```bash
codex exec --skip-git-repo-check -s workspace-write \
  -m gpt-6.1-sol -c model_reasoning_effort="xhigh" \
  "在当前目录创建文件 xxx.txt，内容为 XXX，然后只回复 DONE" </dev/null
```

- `-s workspace-write`：允许写当前目录。
- `-m` 指定模型，`-c model_reasoning_effort=` 指定推理强度。
- 启动时会打印 Supabase MCP 的认证报错（`rmcp ... AuthRequired`），**不影响结果**，解析输出时忽略 stderr 即可。
- 本次模型参数实测通过：`gpt-6.1-sol` + `xhigh`。

### 2.2 agy（开发 / 备选）

```bash
agy -p "在当前目录创建文件 xxx.txt，内容为 XXX，然后只回复 DONE" \
  --model gemini-4-argon-high --output-format json
```

- **提示词必须紧跟在 `-p` 后面**。如果写成 `agy -p --output-format json "..."`，会报 `-p took "--output-format" as its prompt`。
- 输出是 JSON，关键字段：`status`（SUCCESS / ERROR）、`response`（回复文本）、`usage`。
- **派活用 `--output-format stream-json`**（2026-11-12 补修 ㉙）：每走一步吐一行 `{"event":"step_update",...}`（开始用工具那行带 `tool_name` 和 `tool_info.parameters`，如 `read_file`/`edit_file` 的 `Path`、`run_command` 的 `CommandLine`），最后一行 `{"event":"result","result":{"status":..,"response":..,"error":..}}`。程序只认这最后一行：SUCCESS 取 `response`，否则当没回话，失败原因取 `error` 第一行。积木库检测和能力卡片运行仍用 `json`。实测样本见 `tests/agy_stream_sample.jsonl`。
- `status` 可能是 `ERROR` 且 `error: interrupted`（权限或中断），此时要检查文件是否已生成，并视为失败重试。
- **不要用 `--dangerously-skip-permissions`**：在本项目的权限环境里会被拒绝（"Safety Bypass Flag"）。默认模式已够用。
- `--mode auto` 在当前账号上不可用，会回落默认模式并打印警告，不要依赖它。

### 2.3 Cursor CLI（开发）

```bash
agent -p --trust --model auto --output-format json \
  "在当前目录创建文件 xxx.txt，内容为 XXX，然后只回复 DONE" </dev/null
```

- 命令是 **`agent`**。`cursor-agent` 是另一个入口，之前用它的测试结论作废。
- `--trust`：跳过工作区信任确认。不加会卡在 "Workspace Trust Required"，并且不写文件。
- **不需要 `--force`**。`--force` 会被权限分类器拒绝，不要为了"写文件"去加它。
- **偶发不稳定**：首次运行可能回复"已创建文件"，但文件没落盘。实测一次失败、一次成功。调用方必须检查文件是否真的存在，失败就重试。

## 3. 怎么判断"真的成功"

**不要相信 AI 的回复文字**。三家都出现过"说已创建、实际没写"的情况。判断标准只有一条：

```bash
test -f xxx.txt && [ "$(cat xxx.txt)" = "XXX" ] && echo OK
```

这和方案里"过没过由固定程序判定"的原则一致。

## 4. 换模型时怎么核对名称

模型名会变，换之前先列一遍：

```bash
agy models          # 列出 gemini-4-argon-low/medium/high 等
agent models        # 列出 gpt-5.6-sol-xhigh、gpt-5.3-codex-xhigh、auto 等
```

Codex 的模型名不能用列表查，只能在 `~/.codex/config.toml` 的 `model = "..."` 看默认值，或直接用 `-m` 试一次。

本次使用的模型：

| 角色 | 工具 | 模型 | 备注 |
|---|---|---|---|
| 测试员 | Codex | `gpt-6.1-sol`，xhigh | 用户指定 |
| 开发 | agy | `gemini-4-argon-high` | 用户只说"gemini 4.0 argon"，档位 high 是我选的，待确认 |
| 开发 | Cursor(agent) | `auto` | 用户指定 |

## 5. 已知坑（踩过的）

| 现象 | 原因 | 处理 |
|---|---|---|
| `cursor-agent` 写文件"成功"，文件不存在 | 用错命令，应为 `agent` | 统一用 `agent` |
| Cursor 卡在 Workspace Trust Required | 没加 `--trust` | 加 `--trust` |
| agy 报 `-p took "--output-format"` | `-p` 后面没跟提示词 | 提示词紧跟 `-p` |
| agy 被拒绝 "Safety Bypass Flag" | 用了 `--dangerously-skip-permissions` | 去掉它 |
| Cursor 说"已创建"但没文件 | 偶发不稳定 | 检查文件，失败重试 |
| zsh 报 `no matches found: *_x.txt` 并中止整条命令 | 通配符没匹配到文件，zsh 默认报错 | 删除前不用通配符，改用明确文件名（`rm -f 具体文件名`） |
| Codex 输出一堆 MCP 报错 | 全局配置里的 Supabase MCP 需要登录 | 忽略 stderr；不影响结果 |
