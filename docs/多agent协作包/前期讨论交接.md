## 从 DeepSeek Super-agent 文章借鉴的要点

- **双层架构**：调度员（Claude）只负责对接用户和派活；执行者之间上下文隔离，只向调度员汇报，不直接面对用户。
- **调度员不配执行工具**。文章实验：只在提示词里写"可以派活"，5 次一次都没派；写"优先派活"，5 次里仍有 1 次自己干了。所以必须在权限上锁死。
- **订阅直通**：后续消息直接发给负责的执行者，不经调度员转手，实验中调度员的消耗省了 37%。对应到这里：返工在测试员和开发之间直接来回。
- **快慢两条路**：能用固定规则判断的事交给程序，比如测试过没过、超时没有，不交给 AI。
- **能塞进上下文的少塞，其余放在外面按需读**：汇报只写摘要（百字封顶），全文留在文件里。任务有编号，汇报里写相关任务的编号，需要时顺着编号往回查，这样 Claude 换新窗口也能接上进度。
- **提前行动**：Claude 规划需求时，可以让 Codex 先去摸底（复现问题、跑现有测试）。
- **看门人**：监控卡住或原地打转的执行者，交给程序或 Codex 做，不交给 Claude。
- **不学的部分**：放到云端常驻、监听群聊、自动提交。

## 设想的结构（写方案时细化）

- **协作区**（放在被试用的项目里）：任务板、每张卡一个文件夹（需求卡 / 汇报 / 测试结果 / 返工记录）、项目档案（怎么启动和测试、哪些地方不许碰、用了什么技术，由 Claude 读完项目起草、用户确认）。
- **入口文件**：Codex、Cursor、agy、Claude 进项目时各自先读的文件，只写"去读协作区"，不在里面写规则。
- **写权限分开**：Claude 只写需求卡，开发只写汇报，测试员只写测试结果，谁都不改别人的那份。
- **存档**：需求卡和验收记录跟代码一起存档；返工过程中的临时文件不存。

## 完整流程（8 步）

用户提需求 → ① Claude 对齐需求，写需求卡（【关口1：用户确认】）→ ② Claude 拆卡、指派、排先后 → ③ 程序派发，开发在各自的副本里干活（Claude 不干等）→ ④ 开发交活，写百字汇报 → ⑤ Codex 按验收标准测试，由程序判定过没过 → ⑥ 没过就直接退回开发，最多 3 轮，超过才升级给 Claude → ⑦ Claude 看汇报和测试结论做最终验收，合并后整体再测一遍 → ⑧【关口2：用户看效果】，上线由用户决定。

## 产品化方向（第一版不做，但别把路堵死）

- 面向不会开发的普通人：**用户装了几家就用几家**，只有 Claude 也能跑。
- 给别人用时，倾向做成自带全部东西的包，或做成 Claude Code 插件：装一次，进项目说"初始化"就能用。（给自己用时想过"公共底座 + 项目协作区"两半拆分，给别人用要反过来，因为简单比好维护重要。）
- 最难的一环：把用户的大白话翻译成能自动判断的验收标准。
- 动手前自动存版本、一键恢复，锁死不许碰的地方。
- 动手做产品化之前，先调研市面上有没有类似的开源项目（还没做）。
