# 开发助手 vs 单模型+复查：对比方案（卡 17）

> 用户 11-27 原话：“所以我觉得现在流程有严重的问题，每次都这么慢，而且消耗token很多，如果用单模型+复查时间都没这么久吧，那么这个开发助手的还有什么用”；“可以，你跟Gemini协调以下，如何开发，进行对比，b路你就让Gemini来写，最后给我一个结论”。

## 比什么
同一份施工单（train `施工单-17-四角纯名称与工作表拖拽排序.md`）、同一个起点提交（卡 16 放进项目之后的最新提交），两路各做一遍：

| | A 路：开发助手 | B 路：单模型 + 复查 |
|---|---|---|
| 谁做 | 开发助手照常：Codex 写测试 → agy Gemini 4 Hydrogen（极高）写代码 → Codex 复查 | Gemini（当前 PM 那个会话）自己写测试、写代码 |
| 复查 | 程序自动派 Codex | Claude 派一次 Codex 复查，档位和 A 路的复查一样；不通过 Gemini 改，最多 2 轮 |
| 在哪做 | 卡片副本（train-worktrees/CARD-017） | 单独副本 `train-worktrees/B-017`（分支 `compare/b-017`），**不放进项目** |
| 放进项目 | 照常（Gemini 看页面后） | 不放，比完删副本 |

## 记什么（两路一样的口径）
1. **用时**：从开工到“验收测试全过 + 复查通过”。A 从流转记录算；B 由 Gemini 每一步记开始/结束时间（北京时间）。人等人的时间（等拍板、等用户）单列，不算进去。
2. **token**：A 从流转记录读；B 是 Gemini 自己的用量，Antigravity 读得到就记，读不到写“读不到”（这项可能比不了，结论里会说明）。复查的 token 两边都能读。
3. **人工插手次数**：谁、为什么。
4. **质量（盲评）**：两路都过了以后，Claude 把两份改动标成 X、Y（不说哪个是哪个），交 Codex 用同一段话各复查一次，数严重/中等问题；再互换跑对方的验收测试（A 的测试跑 B 的代码、B 的测试跑 A 的代码），看谁的测试更严、谁的代码更稳。
5. 卡 17 的验收测试：A 路照常由 Codex 写；B 路由 Gemini 自己写。

## 规矩
- B 路不看 A 路的测试和代码，A 路也不看 B 路的（两边都在各自副本，互不同步）。
- B 路做的时候 Gemini 照样要盯 A 路（A 路是程序自动跑，Gemini 只在要拍板、看页面时出手）。
- 两路都不推送、不碰 58010/58020 数据库（施工单本来就不许）。

## 结论怎么下（写给用户）
用时、token、人工插手、盲评问题数四项对照，再加一句判断：哪类卡该走哪条路。只比一张卡，样本小，结论会写明“只是一次”。
