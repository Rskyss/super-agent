# 积木库管家 · 需求共识（定稿）

> 2026-11-10 起草；同日用户回“按照你的推荐把几个东西全部落地掉，测完之后跟我说，我亲自再来点击”：4 题都按推荐（1A 2A 3A 4A），并授权一口气做完、做完再请他亲自点。✅ 定稿。

## 一、起因

用户在积木库里说“帮我接进小红书 cli”，积木库的 AI（当时叫“行政”）没给出可用的答案，只让用户去贴官网链接。Claude 查到的情况：

- 联网搜索是好的：Tavily 密钥已经存好，用同样的搜索词真搜能搜到东西。
- 小红书**没有官方命令行工具**。网上能找到 3 个别人做的：redbook（搜索、分析，会读 Chrome 里的小红书登录）、xhs-cli（运营数据、发帖填表，可以用 npm 装）、xiaohongshu-cli（靠破解接口，有封号风险，安装方式这一轮不支持）。
- 规矩里写着“找到的不是厂商官网就请用户贴官网链接”。没有官方版本的工具，按这条规矩永远走不下去。
- 它先说“我搜一下”，然后反过来问用户。用户看不出它其实可能已经搜过了。界面上搜索这一步只显示成“另有 N 个动作”。
- 它调用了哪些工具、拿到什么结果，程序没有保存下来，所以没法确认这次到底搜没搜。
- 另外，它问过“要不要设成默认的联网搜索”，产品里并没有这个设置，是它编出来的。

用户由此提出：一个 AI 的规矩和脚本越积越多，迟早会乱。

## 二、讨论过程和拍板

- 用户最初设想：前台一个负责接待的 AI，后台按模块（命令行工具接入、API 接入……）各放一个 AI，前台派活给后台。
- Claude 建议先不这样拆。理由：AI 之间传话会丢信息；每多一道转手，就更慢、更费额度；出了问题更难查；真正动手装、检测的本来就是程序；小红书这次是规矩缺了一条，拆开也修不好。
- 改用的做法：**一个 AI，规矩分成几本手册，办哪类事才翻哪本**。以后遇到下面任一情况，再把某本手册交给一个后台 AI：
  - 某类活要跑很久
  - 某类活需要换更强或更便宜的模型
  - 几件事要同时进行
- 用户同意（“可以的，那按照你的来”）。
- 用户确认两个 AI 各管一边，因为本来就是两个不同的页面：
  - **行政**：在项目窗口，跟用户聊需求、建任务卡。这次不动。
  - **积木库管家**：在积木库窗口，跟用户聊，负责把积木接进来，以后还要负责把能力做出来。

## 三、这次要做的

1. **改名**：积木库窗口里的 AI 从“行政”改叫“积木库管家”，包括页面上显示的名字、头像上的字、输入框提示，以及它对自己的称呼。项目窗口的“行政”不变。
2. **规矩拆成手册**：管家只常带几条基本规矩：怎么跟用户说话、先体检、自己不能装、用户没确认不说“装好了”、不知道就直说不编造。其余按类别分成手册，判断出要办哪类事才翻开对应的那本：
   - 《接命令行工具》：查装没装、核实名单、读帮助说明、起草接法卡、登录
   - 《接大模型 API》
   - 《联网搜索和网上安装》：搜官网、读网页、从网上装
   - 以后做能力层，再加《做能力》
3. **没有官方版本的工具**：搜完发现官方没有，就直接告诉用户“官方没有”，再列出别人做的几个（最多 3 个）。每个说清：
   - 谁做的
   - 能干什么
   - 风险（比如会读浏览器里的登录、靠破解接口、可能封号）

   最后推荐一个，附一句理由。用户选定后照常出“从网上装”的卡，卡上标明“非官方”。
4. **搜完必须说结果**：用了联网搜索，回话里必须先说搜到了什么，再提问。不能装作还没搜。
5. **聊天里看得见它做了什么**：搜网上、读网页这些步骤在聊天里用大白话显示出来（例如“搜了网上”“读了 1 个网页”），不再笼统写成“另有 N 个动作”。
6. **把每一步存下来**：每一步用了哪个工具、查了什么、结果的大意，都存进这段对话的记录。下次出问题能查清楚，不用靠猜。密钥照旧不能出现在记录里。

## 四、明确不做

- 不拆成多个 AI，后台不放第二个 AI。
- 不动项目窗口的“行政”。
- 不加“默认联网搜索”这类新设置。
- 不新增能接入的工具种类，也不新增安装方式：pip、Homebrew 第三方仓库这一轮仍然不支持。
- 手册不在界面上给用户看，也不让用户改。
- 老的聊天记录不回头改名、不补记录。

## 五、怎么算验收通过

- 积木库窗口里看不到“行政”两个字，全部显示“积木库管家”；项目窗口照旧是“行政”。
- 用真实的管家（用户配置的模型）说“帮我接进小红书 cli”：
  - 它要先搜，然后告诉你官方没有，列出别人做的几个，各带一句风险，再给推荐。
  - 用户选 xhs-cli 后，出“从网上装”的卡，卡上标“非官方”，确认后能装上。
  - 这条按问题 2 的答案调整。
- 聊天里能看到“搜了网上”这一步。打开这段对话的记录，能查到搜索词和结果大意。
- 用户说“接 DeepSeek”这类大模型 API、“接 Codex”这类现成工具，管家照旧能办成，不比现在差。
- 同一类事不会翻错手册。例如接 API 时，它不会去搜网上安装。

## 六、拍板记录（4 题，用户 2026-11-10 全选推荐 A）

**问题 1：聊天里显示“它做了什么”，要多细？**

- A（推荐）：显示一行大白话，比如“搜了网上 · 读了 1 个网页”，点开能看到搜索词和找到几条。完整记录另外存着，排查问题时用。理由：既看得见，又不刷屏。
- B：只显示一行，不能点开。

**问题 2：靠破解接口、冒充登录的工具，管家能不能帮你接？**

先说明冲突：之前定过“只能在网页或 App 里用的订阅，不破解、不模拟点击”。小红书这类别人做的工具，几乎都是靠你的登录状态或者破解接口在用。

- A（推荐）：可以接。管家列出来时标红，写明“破解接口 / 读你的浏览器登录，可能封号”，你确认了才装。理由：
  - 用的是你自己的账号，风险你说了算。
  - 之前“下载脚本直接运行”你也选了标红后照样能用，口径一致。
- B：只列出来告诉你有这些，不帮你接，守住“不破解”。这样小红书目前接不了。

**问题 3：“非官方”怎么判断？**

- A（推荐）：以下情况都算非官方：网址不是厂商自己的网站，比如个人 GitHub 或第三方介绍站；或者安装包的发布者不是厂商。管家拿不准时按“非官方”处理。理由：宁可多提醒，不要漏提醒。
- B：只有管家有把握时才标“非官方”。

**问题 4：和“沙盒接入”的整体验收谁先？**

沙盒接入还差一次你在场的整体验收。

- A（推荐）：先做这次的管家改造，再一起做整体验收。理由：管家的规矩要重写，现在验了改完还得再验一遍。
- B：先把沙盒接入验收掉，再做管家改造。
