# 施工单 68b：统一叫法

依据：[能力层/需求共识.md](../能力层/需求共识.md) 第二节“统一叫法”表（用户 2026-11-10 定，1A、2A）、[能力层/方案.md](../能力层/方案.md) 第一节 5 和技术设计“统一叫法”、[能力层/任务清单.md](../能力层/任务清单.md) 第 3 项和 2026-11-11 的拆单说明。

## 这张单做什么（产品话）

以后只有两样东西叫“卡片”：积木库里的**能力卡片**、项目窗口里的**任务卡片**。其他原来叫“卡”的，在用户看得见的地方、管家和调度员说话时一律改名：

| 原来叫 | 改成 |
|---|---|
| 安装卡、接入卡、提议卡（管家在聊天里出的、等用户点确认的框） | **提议**（安装提议、接入提议） |
| 接法卡 | **接法说明**（“接法卡全文”→“接法说明全文”，“这张接法卡坏了”→“接法说明有问题”） |
| 体检卡 | **体检结果** |
| 管家说的“出卡”“没出卡” | **出提议**、**没出提议** |
| “那一块”“哪一块”“一家平台一块”（基础层里的一样） | **积木块**（“那个积木块”“一家平台一个积木块”） |
| 项目窗口的“需求卡” | **任务卡片** |

用户感受到的变化：积木库窗口详情里看到“接法说明全文”“接法说明有问题”；聊天里动作摘要写“出了 1 个提议”；管家说话时说“提议已经弹出来了”而不是“提议卡”；项目窗口的调度员说“任务卡片”。功能一点不变。

**不改的（程序内部名字，用户看不见）：** 文件名（`需求卡.md`、`cards/` 文件夹、`.json`）、页面元素编号（`healthCard`、`detailCard`）、函数和变量名（`card`、`proposal`、`list_cards`…）、工具名（`propose_*`）、命令行子命令（`new-card`）、记录里已经存下的旧数据。Mac 窗口外壳（`desktop/mac/`）里没有这些字，不动，不用重装。

**不改的文档：** 旧施工单、旧方案、验收记录、回执、台账是当时的记录，保持原样。

## 2. 旧记录兼容（只有这两处允许留旧字）

只有下面两处为了认旧数据、认 AI 的旧说法可以留旧字，**这一行要带注释“旧叫法”**（测试按这三个字放行，别处出现“旧叫法”三个字会被测试拦下）：

- `desktop/static/chat.js` 动作摘要那一行：新旧动作名都认，例如 `[/^(?:出提议|出卡)/, "出了 {n} 个提议"], [/^(?:没出提议|没出卡)/, "{n} 次没出成提议"]  // 旧叫法：以前的记录里是“出卡”`。新旧两种动作名在同一段里要合并计数（一段里 1 个“出卡”加 1 个“出提议”显示“出了 2 个提议”）。
- `desktop/clerk/desk.py` 第 3 节识别用的词表。

## 3. “说了出提议却没出”的识别（`desk.py` 的 `claims_card`、`points_at_card`）

改名以后管家会说“提议已经弹出来了”“安装提议出好了”，现在的识别只认“提议卡/接法卡/安装卡/卡片/确认框”，会漏掉。要求：

1. **新说法要认出来**：带“提议”的那些说法（如“安装提议已经弹出来了”“接入提议出好了，点确认就行”“我已经给你出了一个提议”“新的提议出来了：腾讯云”“提议已弹出，请点确认”“提议就在上面”“填进提议里”）。
2. **旧说法照样认**：模型还可能说“提议卡”“接法卡”“安装卡”，现在认的全部继续认（原有测试一条不能坏）。
3. **“提议”当动词时不能误认**：“我提议你先装 Node。”“我提议先查一下电脑。”“我提议给你换个模型。”都不算说出了提议；问句（“要我出一个提议吗？”）、说以后的事（“等提议出来了再填密钥”）、说提议里的内容（“提议里的命令已经出错了”）也不算，和现在对“卡”的规矩一样。
4. 提醒管家的那段话（`_CLAIM_REMINDER` 和点名旧卡的那段）改成新叫法：“你刚才说已经出了提议或确认框……用户什么提议都看不到。要出提议就现在调用对应的工具；不需要，就如实告诉用户刚才没有出提议。”
