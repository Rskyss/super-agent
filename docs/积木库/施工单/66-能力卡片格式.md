# 施工单 66：能力卡片的格式和存放

依据：[能力层·需求共识](../能力层/需求共识.md)、[能力层·方案](../能力层/方案.md)（尤其技术设计“能力卡片字段”“存放”）、[能力层·任务清单](../能力层/任务清单.md) 第 1 项。
验收测试：`tests/test_acceptance_66_ability_cards.py`（Claude 写，**不准改**）。

## 用户能感受到的变化

这张单没有界面，也不真跑任何东西。做完以后，程序认得“能力卡片”：基础层某个积木块的一种固定用法，写明用哪个积木块、哪个模型、你要填什么、交回什么、怎么算干成了。写错的卡片用中文说清哪里错。第一次打开能力层时，自动放进三张预置的能力卡片：搜资料、写文章、出图。

## 只新建这一个文件

- `collab/abilities.py`

别的文件（`collab/blocks*.py`、`desktop/`、页面、任何测试）都不动。要用 `blocks` 里的东西就 import，不要复制一份。

## 要做的

### 1. 基本的东西

- `class AbilityError(BlockError)`：所有拒收都抛它，原因用中文写，**原因里要带上出问题的那个字段名或值**（测试会查，比如“maxLength”“who”“最近十年”）。
- `OUTPUT_LABELS = {"text": "文字", "list": "列表", "image": "图片", "file": "文件"}`
- `TIME_RANGES = {"不限": "none", "最近一天": "day", "最近一周": "week", "最近一个月": "month"}`
- 位置都在 `blocks.home(root)` 下：卡片 `能力层/<编号>.json`，运行记录 `记录/能力/<编号>.jsonl`，成果 `成果/<编号>/<运行编号>/`。

### 2. `validate_ability(card) -> dict`

返回补齐默认值的新卡，不改传进来的那份。检查顺序：**是不是一组字段 → 有没有密钥 → 顶层字段 → 模型 → inputSchema → how → output**（测试里有的卡同时错两处，按这个顺序报第一处）。

**顶层**，只认这些字段，多一个就拒收并说出名字：`id title description block model backup_models inputSchema how output source example_run`

| 字段 | 规则 | 默认 |
|---|---|---|
| `id` | 同积木块编号规则（`blocks._ID`：小写字母、数字、横线，最长 40） | 必填 |
| `title` | 去掉空白后 1–20 个字；报错说“名字” | 必填 |
| `description` | 去掉空白后 1–200 个字；报错说“说明” | 必填 |
| `block` | 同积木块编号规则；报错说“积木块” | 必填 |
| `model` | 规则同 `blocks._MODEL`；报错说“模型” | 见下 |
| `backup_models` | 文字列表，最多 2 个，每个合模型名规则，不重复，不能和 `model` 一样；没有 `model` 时必须为空；报错说“备用”（模型名本身不合规则时说“模型”） | `[]` |
| `source` | `builtin` 或 `clerk`；报错说“来源” | `clerk` |
| `example_run` | `null` 或运行编号（`\d{8}-\d{6}-[0-9a-f]{4}`）；报错说“示例” | `null` |

- 密钥：整张卡用 `blocks._has_secret` 查，查到就拒收，原因里有“密钥”。
- 模型：`how.kind` 是 `llm_api` 时 `model` 必填；`cli` 时可写可不写（不写就用积木块自己的，**不要补默认值**）；`search` 不许写 `model`，`backup_models` 也必须是空的。

**inputSchema**（MCP 工具的写法，只收一个小子集，别的关键字一律拒收并说出名字）

- 顶层只能有 `type`（必须是 `"object"`）、`properties`、`required`。
- `properties`：1 到 10 项（报错说“1 到 10”）。项名：`[a-z][a-z0-9_]{0,31}`，报错说“项名”。
- 每一项：
  - `type` 只能 `"string"` 或 `"integer"`（报错里同时写出 string 和 integer）；
  - `title` 必填，去掉空白后 1–20 个字；`description` 可选，最多 100 个字；
  - **string**：可用 `title description maxLength enum default examples`。`maxLength` 和 `enum` 至少有一个；`maxLength` 是 1–8000 的整数（`True` 不算整数）；`enum` 是 2–10 个不重复、1–20 个字的文字；
  - **integer**：可用 `title description minimum maximum default examples`。`minimum`、`maximum` 必填，都是 0–100000 的整数，`minimum` 不大于 `maximum`；
  - `default`：类型要对，要在范围里（字数不超过 `maxLength`、在 `enum` 里、在最小最大之间）；
  - `examples`：最多 3 个，每个都按 `default` 的规则查。
- `required`：可不写（补成 `[]`）；写了必须是列表、不重复、每个都在 `properties` 里；报错说“required”或说出那个名字。

**how**（只三种 `kind`，报错时写出 search、llm_api、cli）

| kind | 只认的字段 | 规则 |
|---|---|---|
| `search` | `kind query max_results time_range` | `query` 是模板；`max_results` 是 1–20 的整数（报错说“1 到 20”），或 `"{项名}"`：那一项必须是 integer（否则说“整数”），且最小最大都在 1–20 里；`time_range` 是 `none day week month` 之一（报错说“time_range”），或 `"{项名}"`：那一项必须有 `enum`（否则说“时间范围”），且每个选项都是 `TIME_RANGES` 的键（否则说出那个选项）。默认 `max_results=8`、`time_range="none"` |
| `llm_api` | `kind system prompt` | `prompt` 是模板，必填；`system` 是模板，可选 |
| `cli` | `kind prompt output_file timeout` | `prompt` 是模板，必填；`output_file` 必填，规则同 `blocks._DONE_FILE`（报错说“文件名”）；`timeout` 是 30–600 的整数（报错说“timeout”），默认 300 |

- **模板**：去掉空白后不能为空（报错说“交代”）；最长 4000 个字（报错写出 4000）；里面的 `{…}` 只能是 `properties` 里的项名，`{}` 或不认识的名字都拒收（空的说“占位”，不认识的说出名字）。
- **必填项必须用上**：每个 `required` 里的项，至少出现在某个模板里，或被 `max_results`、`time_range` 引用；否则拒收并说出项名。

**output**

- 只认 `type`、`check` 两个字段。`type` 只能四种，报错写出“文字、列表、图片、文件”。
- 和 `how.kind` 对得上：`search` 只交回列表（报错说“列表”），`llm_api` 只交回文字（报错说“文字”），`cli` 交回文字、图片或文件（不能交回列表）。
- `check` 可不写，按类型补默认，只认下面这些字段：

| type | check 字段 | 规则 |
|---|---|---|
| text | `min_chars max_chars` 或 `min_ratio max_ratio of` | 两组不能混用（报错说“字数”）；固定值是 1–100000 的整数，下限不大于上限（说“字数”）；倍数是大于 0、不超过 10 的数（说“倍”），写了倍数就必须写 `of`（说“of”），`of` 必须是 integer 项（不在就说出名字，是 string 就说“整数”）；都不写也行 |
| list | `min_items` | 1–50 的整数（说“条”），默认 1 |
| image | `min_side` | 16–4096 的整数（说“宽高”），默认 256；`how.output_file` 必须以 `.png`、`.jpg`、`.jpeg` 结尾（报错写出 png） |
| file | `extensions` | 必填（说“extensions”），1–5 个，每个是 `[a-z0-9]{1,8}`（带点的说“扩展名”）；`how.output_file` 的扩展名必须在里面（报错说出它的扩展名） |

### 3. `fits_block(card, block, models=None, models_complete=True) -> list`

先 `validate_ability(card)`，再对照积木块（`block` 是 `blocks.validate_card` 过的积木块）：

- `card["block"]` 必须等于 `block["id"]`，不等就拒收并说出两个编号。
- 类别对得上（用 `blocks.category(block)`）：`search` 配 search，`llm_api` 配 llm_api（报错写“大模型 API”），`cli` 配 agent（配普通工具 tool 时报错写“AI 助手”，说明普通工具不接交代）。
- `models` 是这家的模型名单（列表）时：主模型和备用模型都要在名单里；不在时 `models_complete=True` 就拒收并说出模型名，`False` 就不拒收，返回提醒文字列表（每条带上模型名）。`models` 是 `None` 不查。
- 没问题返回 `[]`。

### 4. 存取

- `save_ability(card, root=None)`：校验后写 `能力层/<编号>.json`（写法照 `blocks.save_card`：先写临时文件再替换）。不碰 `基础层/`。
- `load_ability(id, root=None)`：读、校验，文件名和卡里编号对不上就拒收；编号不合规则直接拒收（不能读到别的文件夹）。
- `list_abilities(root=None)`：按文件名排序；坏文件单独一项 `{"id": 文件名, "problem": 原因}`，不影响别的。
- `remove_ability(id, root=None)`：只删卡片文件，记录和成果留着；没有这张就拒收。
- `add_run(id, record, root=None)`、`runs(id, root=None, limit=None)`：写法照 `blocks.add_record` / `blocks.records`（要有 `type`、不能有密钥、自动加 `time`），只是位置在 `记录/能力/<编号>.jsonl`。能复用就复用，不要整段复制。
- `new_run_id()`：`年月日-时分秒-4 位十六进制`，比如 `20261111-120000-ab12`，同一秒连着调用也不重复。
- `result_folder(id, run_id, root=None)`：返回 `成果/<编号>/<运行编号>/` 的路径，只算路径不建文件夹；编号和运行编号不合规则就拒收。

### 5. 三张预置卡片 `BUILTIN_ABILITIES` 和 `ensure_builtin(root=None)`

字典，键是编号，值是卡片（不写 `source`）。内容照方案第二节：

- **`search-web`「搜资料」**：积木块 `web-search`。项：`keywords`（关键词，string，maxLength 200，必填，给一个例子）、`count`（条数，integer 1–20，默认 8）、`period`（时间范围，enum `不限 最近一天 最近一周 最近一个月`，默认 `不限`）。how：`search`，`query` 为 `{keywords}`，`max_results` 为 `{count}`，`time_range` 为 `{period}`。交回列表，至少 1 条。
- **`write-article`「写文章」**：积木块 `bailian`，模型 `qwen3.7-plus`，备用 `["qwen3.6-plus"]`。项：`topic`（主题，maxLength 200，必填，给一个例子）、`words`（大概字数，integer 100–20000，默认 800）、`notes`（参考资料，maxLength 8000，可不填）。how：`llm_api`，`system` 要求只交回正文、不写开场白；`prompt` 用上三项。交回文字，字数在 `words` 的 0.5 到 2 倍之间。
- **`draw-image`「出图」**：积木块 `codex`，不写模型。项：`scene`（画面描述，maxLength 1000，必填，给一个例子）、`shape`（画幅，enum `横版 竖版 方形`，默认 `横版`）。how：`cli`，`prompt` 照实测用过的写法：“用你自带的 $imagegen 出图功能画一张图：{scene}。画幅：{shape}。把图片存成当前文件夹里的 输出.png。存好后只回复 OK。”；`output_file` 为 `输出.png`；`timeout` 300。交回图片，宽高都不小于 256。
- 每张卡的必填项都要有 `examples`，例子本身要能通过 `prepare`。

`ensure_builtin(root=None) -> list`：**只在 `能力层/` 文件夹还不存在时**把三张写进去（`source` 为 `builtin`），返回写了哪些编号；文件夹已经在就什么都不做、返回 `[]`。这样你移出的预置卡片不会自己冒回来，改过的也不会被覆盖。

### 6. `prepare(card, inputs) -> dict`

先 `validate_ability(card)`，再按 inputSchema 查 `inputs`：

- `inputs` 必须是一组字段；有不认识的项就拒收并说出名字。
- 必填项没填或只有空白：拒收，原因里用那一项的 `title`（比如“主题”）。
- string：超过 `maxLength` 拒收（说出上限数字）；有 `enum` 时必须是其中之一（说出 `title`）。
- integer：必须是整数（`True` 不算，`"100"` 不算），在最小最大之间；错了说出 `title`。
- 没填的用 `default`；没有默认值的可选项：模板里替换成空，`values` 里 string 记 `""`、integer 记 `None`。

返回：`{"kind": …, "values": {每一项的最终值}, …}`，再按 kind 加：

- `llm_api`：`system`（没写就是 `""`）、`prompt`；
- `search`：`query`、`max_results`（整数）、`time_range`（`none/day/week/month`，引用的 enum 按 `TIME_RANGES` 换过来）；
- `cli`：`prompt`、`output_file`、`timeout`。

替换只做一遍：填进去的内容里就算有 `{words}`，也原样保留，不再替换。

### 7. `check_output(card, result, values) -> (bool, str)` 和 `image_size(path)`

先 `validate_ability(card)`。`values` 是 `prepare` 返回的 `values`。通过返回 `(True, "")`，不通过返回 `(False, 中文原因)`：

- **text**（`result` 是文字）：不是文字或只有空白 →“没有内容”。字数 = 去掉所有空白后的字符数。倍数：下限 = `ceil(值 × min_ratio)`，上限 = `floor(值 × max_ratio)`；`of` 那一项是 `None` 时不查倍数。不够时原因里有实际字数和下限，超过时有实际字数和上限。
- **list**（`result` 是列表，每条 `{"title", "url", "summary"}`）：不是列表 → 不通过；空 →“一条都没有”；不够 → 写实际条数和要求；某条没有标题 →“第 N 条没有标题”；`how.kind` 是 search 时每条的 `url` 必须以 `http://` 或 `https://` 开头，不是就“第 N 条没有链接”。
- **image**（`result` 是文件路径）：不存在 →“没有找到 <文件名>”；`image_size` 认不出 →“<文件名> 不是 PNG 或 JPG 图片”（文件头都不对时）或“打不开”（半截文件）；任一边小于 `min_side` →“图片太小：宽×高，要求宽高都不小于 N”（乘号用 `×`）。
- **file**（`result` 是文件路径）：不存在、是空文件（原因里有“空”）、扩展名不在 `extensions` 里，都不通过。

`image_size(path) -> (宽, 高) 或 None`：只读文件头。PNG 读 IHDR；JPEG 从头往后找 SOF 标记（`FFC0`–`FFCF`，除了 `FFC4 FFC8 FFCC`）读高和宽；读不全、读不出都返回 `None`，不抛错。不要为此装任何图片库，也不要调用系统命令。

## 复查第 1 轮要改的（2026-11-11）

Codex 和 Claude 的复查员各查了一次，结论都是不通过，没有严重问题。下面每一条都由 Claude 复现过。验收测试新增了 `ReviewRound1` 一组（12 项，改前全不过），**仍然不准改测试**。

**这一轮允许改的文件：** `collab/abilities.py`；`collab/blocks.py` 只许做第 10 条那一处。

1. **花括号**：模板里只许出现成对、不嵌套、名字已声明的 `{项名}`。嵌套（`{who{notes}}`）、单独的 `{` 或 `}` 一律拒收，原因里写“花括号”。
2. **写错类型的成员不能崩**：`backup_models`、`enum`、`required`、`check.of` 里出现列表、字典这类值时，先查类型，抛带字段名的中文 `AbilityError`，不能抛 `TypeError`。所有用 `set(...)`、`in` 之前都先查成员是文字。
3. **搜索引用的项必须有值**：`max_results`、`time_range` 用 `{项名}` 引用的那一项，必须是必填或者有 `default`，否则拒收并说出项名。
4. **记录接口的拒收一律抛 `AbilityError`**：`add_run` 缺 `type`、有密钥、存不下，`runs` 的 `limit` 不对。
5. **密钥检查要查真正写出去的内容**：`add_run` 先把记录转成 JSON 再读回来（元组会变成列表），对读回来的内容做密钥检查，通过了才写。
6. **PNG 文件头要完整**：至少要有完整的 IHDR（前 33 个字节，含校验码位置）才读宽高，否则返回 `None`。JPEG 的 SOF 段也要完整读到高和宽才返回。JPEG 往后找 SOF 最多找文件前 64KB。
7. **出图、出文件的结果不是路径时不能崩**：`check_output` 拿到 `None`、数字、列表等，返回 `(False, 中文原因)`。图片检查只读需要的字节（`open(...).read(...)`），不要 `read_bytes()` 把整个文件读进内存；不要和 `image_size` 重复判断文件头。
8. **报错说对范围、用中文类别名**：`fits_block` 的类别不对时，用 `blocks.CATEGORY_LABELS` 的中文名说积木块是什么（“联网搜索”“普通工具”“AI 助手”“大模型 API”），不出现 `search`、`tool`、`agent`、`llm_api` 这些内部叫法；“写文章的能力卡片……”改成“大模型 API 的能力卡片……”。类别不对的报错里不用带积木块编号。
9. **运行编号真的不重复**：同一秒内记住已经发出的全部后缀（加锁），重复了就重抽；这一秒的后缀用完就等到下一秒。
10. **记录读写不整段照抄**：在 `collab/blocks.py` 加两个按路径的函数 `append_jsonl(path, record)`、`read_jsonl(path, limit=None)`，把 `add_record` / `records` 里写文件、读文件的那段挪进去，`add_record` / `records` 改成调用它们，行为一点不变（原有测试要全过）。`abilities.add_run` / `runs` 也调用它们，`abilities.py` 里不再自己 `open(path, "a")`。
11. **`ensure_builtin` 不留半套，也不怕同时打开**：先把三张写进积木库资料夹里一个临时文件夹，全写成功了再一次改名成 `能力层/`；改名时 `能力层/` 已经在了（另一个窗口抢先了），就删掉临时文件夹、返回 `[]`；中途出错也要删掉临时文件夹，再把错误抛出去。不能在积木库资料夹里留下临时文件夹。
12. **写文章的交代**：不填参考资料时交代里不出现“参考资料”几个字。做法：`prompt` 只写主题和字数，末尾直接接 `{notes}`；在 `system` 里说明“如果用户在要求后面附了资料，请参考它”。
