# 57 号单：积木库页面（中）——聊天里的安装、接入提议卡

任务清单第 7 项拆成三张（2026-11-09 用户定）：56 绑定页、左栏、聊天（已完成）；**57 提议卡**；58 体检卡、基础层详情。

验收测试：`tests/test_acceptance_57_block_proposals.py`（规则层由它调 `tests/chat_blocks_check.js` 用 node 跑）。

## 要做什么

积木库行政会出三种提议（54、55 号单已经做好后端）：

| 种类 `kind` | 是什么 | 用户点确认后 |
|---|---|---|
| `install` | 按核实名单装一个工具 | 本机服务开始安装，卡片下面实时滚动安装输出，装完显示成功或原因 |
| `connect` | 把一个 CLI 接进基础层 | 本机服务按接法卡检测，通过后卡上出“放进基础层”按钮 |
| `connect_api` | 把一个大模型 API 接进基础层 | 卡上有密钥框；填好点“检测”，通过后出“放进基础层” |

现在聊天页把这三种都画成“变成任务？”，内容是空的。这张单把它们画对，并接上安装输出、检测结果、密钥框、放进基础层。

## 用户能感受到的

1. 跟行政说“帮我装 Codex”，聊天里出现**安装提议卡**：装什么、来源链接、会执行的那一行命令（原样）、大概多久、要先有什么。点“确认安装”，卡片下面像终端一样滚动输出，装完写“codex 装好了。跟行政说一声，它会接着帮你接进基础层”，或者失败原因和怎么办。
2. 接一个 CLI：**接入提议卡**写接什么；行政起草、没核实过的，标“未核实，有风险”，原样亮出要运行的完整命令；要替换基础层里同编号那块的，写明会替换谁。点确认后显示“正在检测…”，通过显示“检测通过 · 4.2 秒”和“放进基础层”按钮，点了显示“已放进基础层”，左栏基础层几秒内出现它。
3. 接大模型 API：卡上写服务商、模型、地址，下面一个**密钥框**，旁边一句“密钥只填在这里，别贴在聊天里”。没填就点“检测”，卡上直接提示“请先在密钥框里填好密钥”，不发请求。
4. 刷新页面、切到别的对话再切回来：已确认的卡还能看到结果（超级助手没重开过的话）；超级助手重开过，结果没了，就说一句怎么办。

## 规则层 `ChatCore`（`chat_blocks_check.js` 逐条测）

加进 `ChatCore` 的返回对象里，原有的一个都不能少。

| 函数 | 做什么 |
|---|---|
| `isBlockKind(kind)` | `install`、`connect`、`connect_api` 为真，其余为假 |
| `Model.apply` 的 `proposal` | 积木库三种：除了现有字段，把事件里的 `install、tool、label、command、source、needs、minutes、block、name、verified、preview、replaces、provider、model` 中**有的**拷进 `b.info`（对象）。项目窗口的提议不加 `info`（或是空对象），其余字段照旧 |
| `blockCard(b)` | 打开状态的卡上显示什么，返回 `{title, rows, warn, needsKey, confirmText}`，`rows` 是 `[{label, text, code}]`（`code` 为真用等宽字） |
| `blockDoneTitle(b)` | 处理过的卡的标题：确认了 → `已确认安装：<label>` / `已确认接入：<name>`；`cancelled` → `好的，先不做。`；`replaced` → `已换成新的提议` |
| `jobView(job)` | 把 `/api/blocks/job` 的回话变成卡片下面显示的：`{state, text, lines, canSave}` |

`blockCard` 各种的内容：

- `install`：标题含 `label`；行依次是 `来源`（source）、`会执行的命令`（command，`code: true`）、`大概要多久`（`约 N 分钟`）、`要先有`（`npm` → `npm（装 Node 时自带）`，`brew` → `Homebrew`，没有 `needs` 就不要这一行）。`confirmText` 是 `确认安装`，不要密钥。
- `connect`：标题含 `name`。没核实（`verified` 为假）：`warn` 写“未核实，有风险：确认前看清要运行的完整命令”，加一行 `要运行的完整命令`（preview 原样，`code: true`），`confirmText` 是 `看过了，确认检测`。核实过的：`warn` 为空，没有完整命令那行，`confirmText` 是 `确认并检测`。有 `replaces` 加一行 `会替换`：`基础层里的「<replaces>」`。
- `connect_api`：标题含 `name`；行依次是 `服务商`（`tencent` → 腾讯云，`bailian` → 阿里百炼，`other` → 其他，不认得的原样）、`模型`、`地址`（`info.block.base_url`），有 `replaces` 加 `会替换`。`needsKey` 为真，`confirmText` 是 `检测`。

`jobView` 的规矩：

| 情况 | state | text |
|---|---|---|
| `job` 是 `null`（找不到结果） | `lost` | “这次的结果没留下来（超级助手重开过）。可以在左边基础层里看，或者跟行政说重新提议” |
| 没做完，安装 | `running` | `正在安装…`，`lines` 是 `tail` |
| 没做完，检测 | `running` | `正在检测…`，`lines` 是空 |
| 做完有 `error` | `fail` | error 原文 |
| 安装成功 | `ok` | `reason` 加“。跟行政说一声，它会接着帮你接进基础层”；`canSave` 为假 |
| 检测通过 | `ok` | `检测通过 · <seconds> 秒`；`saved` 为真时加“ · 已放进基础层”，`canSave` 为假；否则 `canSave` 为真 |
| 不成功 | `fail` | `reason` 加“。”加 `how`（没有 how 就只写 reason）；都没有写“没成功，原因没查出来，跟行政说一声” |

`lines` 一律是数组（安装用 `tail`，没有就空）。

## 页面层（`chat.js` 里 `renderBlock` 的提议卡分支和点击处理）

只在 `ChatCore.isBlockKind(b.proposalKind)` 时走新画法，原来的分支不动。

### 打开状态

- 标题用 `blockCard(b).title`；每一行照现有 `.rows` 的写法（`<div><span>标签</span><p>内容</p></div>`），`code` 为真的内容放进 `<code>`。**所有内容一律用 `textContent` 放**，不拼进 innerHTML。
- `来源` 是 `https://` 开头的，做成链接（`href` 只放这个地址，`target="_blank"`、`rel="noopener"`）；不是就当文字。
- `warn` 不为空时，用醒目颜色显示一行。
- `needsKey` 时加密钥框：`<input type="password" autocomplete="off">`，旁边那句“密钥只填在这里，别贴在聊天里”。
- 按钮：`confirmText` 和“先不做”，沿用现有的 `data-prop="confirm"` / `data-prop="cancel"`。

### 点确认

- `connect_api`：密钥框是空的 → 在卡上显示“请先在密钥框里填好密钥”，**不发请求**。不空 → 请求体里加 `api_key`。
- 发 `POST /api/clerk/proposal`（现有写法）。回话里有 `job` 就开始跟进这个任务（下面）。
- 请求成功后清空密钥框。`connect_api` 的密钥另外只在页面内存里按提议编号留一份，等“放进基础层”用（见下），出错时密钥框不清，改了再点。

### 跟进后台任务

- 页面层按提议编号记着 `{job, view, saved}`（不放进 `model`：切对话时 `model` 会重建）。
- 每 1 秒 `GET /api/blocks/job?id=<job>&token=<token>`，拿回话过 `jobView`，更新这张卡（`model._touch` 那张卡再 `render()`），做完就停。同一个任务只跑一套。
- 卡片已确认、页面里又没记着任务的（刷新页面、翻历史）：`GET /api/blocks/job?proposal=<提议编号>&token=<token>` 一次；404 就用 `jobView(null)`。每张卡只问一次。
- 已确认的卡：标题用 `blockDoneTitle(b)`，下面：
  - `lines` 不空：`<pre class="prop-output">`，每行一条，用 `textContent`，最多显示 50 行，自动滚到最底下。
  - 结果一行，`ok` 绿、`fail` 红、`running`/`lost` 灰。
  - `canSave` 时一个按钮“放进基础层”。点了按钮先变成“放进中…”不能再点，`POST /api/blocks/save {job}`：成功 → 显示“已放进基础层”，不成功 → 显示服务器给的错误、按钮恢复。
- 已取消、被替换的卡照现在的样子，只有标题。

### 放进基础层之后，密钥交给 Mac 窗口

`connect_api` 保存成功、回话里有 `key_account`，并且页面内存里留着这张卡的密钥时：

- 找 `blocksKey`：先看 `window.webkit.messageHandlers.blocksKey`，没有再看 `window.parent.webkit.messageHandlers.blocksKey`（聊天页在积木库页面里是嵌进去的），有就 `postMessage({account: key_account, key: 密钥})`，让窗口存进钥匙串（窗口那边第 8 项接）。在浏览器里两边都没有，就跳过。
- 不管有没有交出去，都**马上把内存里那份删掉**。卡片被取消、被替换、检测没通过时也删掉。

### 发请求

GET 带 `token` 查询参数（照 `imageUrl` 的写法）；POST 用现有的 `api()`。

### 密钥的规矩

- 密钥只在密钥框、那一次请求、和等着交给窗口的那份内存里出现。**不存** `localStorage`、`sessionStorage`、cookie，**不放进地址**，**不打印**（整个文件不出现 `console.log`），不放进 `model`，不写进任何显示的文字。

## 样式（`chat.css`）

- `.prop-output`：等宽字（`--font-mono`），背景用 `--bg-side`，圆角，最高约 12 行、超出可滚动，长行自动折行。
- 结果行、警告行、密钥框沿用现有的颜色变量（`--ok`、`--bad`、`--dim` 等），**不写死色值**。规则见 `docs/界面改版/设计规范.md`。

## 本机服务加一点（`desktop/server.py`）

`GET /api/blocks/job`：

1. 除了 `id`，也认 `proposal=<提议编号>`：按 `server.blocks_proposal_jobs` 找到任务。找不到（编号不对、提议没确认、超级助手重开过、任务被清掉）一律 404 加中文 `error`。
2. 回话加两项：`job`（任务编号，按 `proposal` 找到时页面要靠它点“放进基础层”）、`saved`（`bool(job.get("saved"))`）。

其余接口不动。
