# 59 号单：Mac 客户端里的积木库窗口

任务清单第 8 项拆成两张（2026-11-09 用户定）：**59 积木库窗口**（入口、单独的窗口、密钥存钥匙串、打开时自动连上行政）；60 存过的密钥哪里都不用再填（绑定、重新连上、详情检测、接入 API 的提议卡）。

验收测试：`tests/test_acceptance_59_blocks_window.py`（施工前 14 项不通过，另 2 项守住左栏规则和项目窗口原有的东西）。Claude 写单时用一份临时参考实现验过：16 项全过、`swift build` 编得过、没有新警告（参考实现已删）。

## 用户能感受到的

1. **两个入口。**
   - 菜单栏“窗口”里加两项：“积木库”、“项目窗口”（原有的“最小化”留着）。
   - 项目窗口左栏最底下（项目名和齿轮那一行）加一个“积木库”按钮。
2. **积木库是单独一个窗口**，标题“积木库”，暗色，默认 1100×760，最小 760×480，记住上次的大小和位置。里面整个是积木库页面（56–58 号单做的 `blocks.html`）。
   - 已经开着时再点入口：把它拿到最前面，不开第二个。
   - 和项目窗口同时开着，互不影响：项目窗口切项目、开新对话、刷新右栏，积木库照常；积木库里绑定、聊天、检测，项目窗口照常。
3. **打开时自动连上行政。** 绑过行政、钥匙串里有这家的密钥：用户看不到“重新连上行政”那张卡，直接进聊天。钥匙串里没有（比如从没在这台电脑填过）：显示那张卡，填一次。
4. **密钥存进钥匙串。** 在积木库里绑定行政、在聊天的接入提议卡里接大模型 API、在基础层详情里检测 API，只要检测通过，这把密钥就存进钥匙串（和项目窗口同一套账号：腾讯云一把、阿里百炼一把、其他按地址分开），下次打开窗口用它自动连上。项目窗口里同一家用的也是这把。
5. **关窗口（用户 2026-11-09 定）。**
   - 关积木库窗口：只关它自己。
   - 积木库开着时关项目窗口：项目窗口只是藏起来，积木库照常用；项目窗口里的对话、终端在后台照常跑。菜单“窗口 → 项目窗口”把它叫回来。
   - 两个窗口都关了，退出超级助手。只开着项目窗口时关掉它，和现在一样直接退出。
6. **本机服务重启**（菜单“面板 → 刷新右栏”在服务停了时会重启它，端口会变）：积木库窗口跟着重新加载、重新自动连上。服务停了：积木库窗口里也写“本机服务停了，可以用菜单「面板 → 刷新右栏」再试一次”。
7. 积木库窗口里的确认框（移出基础层、删对话）弹在积木库窗口上。

## `BlocksWindow.swift`

`final class BlocksWindow: NSObject, NSWindowDelegate, WKScriptMessageHandler, WKUIDelegate, WKNavigationDelegate`，由 `AppDelegate` 持有一个（`lazy var blocks = BlocksWindow(app: self)` 或类似写法，对 `AppDelegate` 用弱引用）。

- **`func show()`**：窗口没建就建（`NSWindow(...)`，`isReleasedWhenClosed = false`，`appearance` 暗色、`backgroundColor` 和项目窗口同色，`setFrameAutosaveName(selfTest ? "SuperAgentBlocksSelfTest" : "SuperAgentBlocksWindow")`，`title = "积木库"`），然后 `makeKeyAndOrderFront`。窗口每次从关着变成开着都 `load(...)` 一次；已经开着就只拿到前面，不重载。
- **网页视图**：`WKWebViewConfiguration` 的 `userContentController.add(<弱引用转发>, name: "blocksKey")`。直接 `add(self, ...)` 会互相拉住、窗口关了也放不掉，要用一个只弱引用 `BlocksWindow` 的小转发对象。`uiDelegate`、`navigationDelegate` 指向自己。加载前不闪白（照 `makeWeb` 的 `drawsBackground` 写法）。
- **`func load(port: Int?, token: String)`**：
  1. 没有端口：显示“正在启动本机服务…”（照 `AppDelegate.message` 的样子），等端口。
  2. `GET http://127.0.0.1:<port>/api/blocks/state?token=<token>`。
  3. 回话里有 `setting`、`connected` 为假、`key_account` 不空，并且 `ClerkKey.read(account: key_account)` 读到密钥：`POST /api/blocks/connect`，JSON `{"api_key": 密钥}`，带 `X-Chat-Token` 头（照 `postLocal`）。**不带 `check`**：自动重连不发测试话，不多花额度（55、56 号单约定）。不管成没成都往下走。
  4. 加载 `http://127.0.0.1:<port>/static/blocks.html?token=<token>`。
  - 第 2、3 步出错（服务没回话、回话不是 JSON）：直接走第 4 步，页面自己会显示该显示的。
  - 读出来的密钥只在这次请求里用，不存进任何变量以外的地方，不打印。
- **`func serverStopped()`**：窗口开着时显示“本机服务停了，可以用菜单「面板 → 刷新右栏」再试一次。”
- **`func windowWillClose(_:)`**：加载 `about:blank`（停掉页面每几秒的查询），然后告诉 `AppDelegate`（`blocksWindowClosed()`）。
- **确认框、提示框**：实现 `runJavaScriptConfirmPanelWithMessage`、`runJavaScriptAlertPanelWithMessage`，照 `AppDelegate` 的写法，但弹在 `webView.window` 上（积木库窗口），没有窗口就 `completionHandler(false)` / `completionHandler()`。回调一定要调用，不然页面会卡住。
- **`userContentController(_:didReceive:)`**（收 `blocksKey`）：
  - 只收 `message.webView` 就是积木库这个网页视图的；`message.frameInfo.securityOrigin` 的 `host` 是 `127.0.0.1`、`port` 是当前端口（聊天页嵌在积木库页面里，同源，也算）。别的一律丢掉。
  - `message.body` 是字典，`account`、`key` 都是文字。`key` 去掉首尾空白后不空、不超过 500 个字、不含换行；`account` 过 `static func isValidAccount(_:)`。不合格就丢掉，不报错、不弹框。
  - 合格：`ClerkKey.save(key, account: account)`。
  - 不打印、不写 `UserDefaults`、不放进任何显示的文字。
- **`static func isValidAccount(_ s: String) -> Bool`**：`"tencent"`、`"bailian"`，或 `"other:"` 加主机名（小写字母、数字、点、横线，1–253 个字）。和 `collab/providers.py` 的 `account_for`、`main.swift` 的 `clerkAccount` 算出来的一致。
- **`superagent://` 地址**：积木库页面不用，`decidePolicyFor` 遇到 `superagent` 一律取消、不做事。

## `main.swift`

- **菜单**：`buildMenu` 里“窗口”改成三项：“最小化”（原样）、“积木库”（`openBlocks(_:)`）、“项目窗口”（`showProjectWindow(_:)`）。快捷键不加。
- **左栏入口**：`decidePolicyFor` 的 `switch url.host` 加 `case "blocks": blocks.show()`（放在 `clerk-` 那条过滤之后不受影响，`blocks` 不以 `clerk-` 开头）。
- `@objc func openBlocks(_:)`：`blocks.show()`。
- `@objc func showProjectWindow(_:)`：`window.makeKeyAndOrderFront(nil)`。
- **关项目窗口**：加 `func windowShouldClose(_ sender: NSWindow) -> Bool`：`sender === window` 并且积木库窗口正开着（`isVisible`）→ `window.orderOut(nil)`，返回 `false`；其余返回 `true`（照旧：最后一个窗口关了就退出）。
- **`func blocksWindowClosed()`**：项目窗口没在显示（`!window.isVisible`）→ `NSApp.terminate(nil)`。
- **项目窗口的委托不管积木库窗口**：`AppDelegate` 现有的 `NSWindowDelegate` 方法（`windowDidResize` 等）开头加 `guard (notification.object as? NSWindow) === window else { return }`。积木库窗口的委托是 `BlocksWindow` 自己，按理不会进来，这一行是兜底。
- **端口交给积木库窗口**：`serverSaid` 拿到端口后（和 `openAfterServer` 同时），积木库窗口开着就 `blocks.load(port:token:)`；`serverStopped` 里调 `blocks.serverStopped()`。
- 别的一行不改：项目窗口的菜单项、聊天、终端、右栏、行政设置都照旧作用于项目窗口。

## 左栏入口（`nav.*`）

- `nav.html` 的 `<footer class="foot">` 里，在齿轮前加 `<button class="blocks-btn" id="blocksBtn" type="button">积木库</button>`。
- `nav.js`：`$("blocksBtn").addEventListener("click", function () { tell("superagent://blocks"); });`，照齿轮那一行写。
- `nav.css`：样式照 `.gear`（灰字、悬停变亮、不写死色值，只用 `theme.css` 变量和现有的写法），项目名过长时项目名省略，按钮不被挤掉。

## 走查用的开关（已经有，照用）

- `--clerk-key-dir <文件夹>`：密钥存临时文件、不碰钥匙串（`ClerkKey.testFile`）。积木库窗口走的也是 `ClerkKey`，自动就支持。
- 环境变量 `SUPER_AGENT_BLOCKS_HOME`：积木库资料夹换成临时的。本机服务继承应用的环境，自动就支持。
- 加一个 `--open-blocks`：启动后本机服务起来时顺手打开积木库窗口，方便走查截图。

## 要留意的

- 聊天页嵌在积木库页面里（iframe），它交密钥时先找自己的 `window.webkit.messageHandlers.blocksKey`，没有再找父页面的（57 号单）。两种都要能收到，`securityOrigin` 判断两种都是 `127.0.0.1:<端口>`。
- `AppDelegate` 现有的确认框弹在 `window`（项目窗口）上；积木库窗口千万别把 `uiDelegate` 指给 `AppDelegate`，项目窗口藏着时弹框会卡死页面。
