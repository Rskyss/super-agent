# 56 号单：积木库页面（上）——绑定页、左栏、聊天

任务清单第 7 项的前一半。验收测试：`tests/test_acceptance_56_blocks_page.py`（规则层由它调 `tests/blocks_page_check.js` 用 node 跑）。

## 要做什么

一个新页面 `desktop/static/blocks.html`，以后 Mac 的“积木库”窗口就加载它（第 8 项）。这张单做三块：

1. **绑定页**：第一次打开，中间只有一张卡“先绑定一个大模型，它会当你的行政”。
2. **左栏**：上面“聊天”（新对话、对话列表、删除），下面“基础层”（每一块的名字、类型、状态）。
3. **中间**：和行政的聊天。**直接复用现有聊天页** `chat.html` 的行政模式，用 iframe 嵌进来。

提议卡里的安装输出区、密钥框，体检卡，基础层详情，是 57 号单的事，这张单不做。

## 用户能感受到的

在浏览器里打开 `/static/blocks.html?token=<口令>`：没绑过时看到绑定卡；填好服务商、模型、密钥，点“检测”，通过后进入聊天，左栏有对话和基础层。

## 规则层 `BlocksCore`（`blocks_page_check.js` 逐条测）

| 函数 | 做什么 |
|---|---|
| `startView(state)` | 没有 `setting` → `"bind"`；有 `setting` 但 `connected` 为假 → `"reconnect"`；连上了 → `"main"`。`state` 是空的按 `"bind"` |
| `bindRequest(form, providers)` | 表单变成请求体。去掉首尾空格。认得的服务商**不带 `base_url`**；`other` 带上，必须 `https://` 开头。不对时返回 `{ok:false, error:中文}`，错误里分别要有“密钥”“模型”“服务商”“地址”或“https://” |
| `modelChoices(providers, id)` | 这家服务商建议的模型名列表，没有就空 |
| `bindResultText(result)` | 通过 → `"绑定好了"`；不通过 → 原因加怎么办；都没有也要说一句 |
| `statusText(block)` / `statusClass(block)` | `ok/fail/never` → `能用/不能用/没检测过`，类名 `ok/bad/idle` |
| `kindText(kind)` | `cli` → `CLI`，`llm_api` → `大模型 API` |
| `chatUrl(home, token)` | `/static/chat.html?` 加上 `project=home`、`token`、`clerk=1` |
| `esc(s)` | 把 `& < > " '` 换成实体，对话标题和积木名字一律先过它再放进页面 |
| `deleteConfirm(thread)` | 删除对话前问的那句话，带上对话标题和“删除” |

## 页面层

### 打开时

1. 从地址取 `token`。没有就整页显示“请从超级助手窗口打开积木库”，什么都不请求。
2. `GET /api/blocks/state?token=...`，按 `startView` 显示对应的一页。

### 绑定页（`bindCard`）

- 元素：服务商下拉 `bindProvider`（腾讯云、阿里百炼、其他）、模型 `bindModel`（`<input list>` 配 `<datalist>`，建议来自 `modelChoices`）、地址 `bindAddress`（只在“其他”时显示）、密钥 `bindKey`（`type="password" autocomplete="off"`）、按钮 `bindCheck`、结果 `bindResult`。
- 卡上写明一句：行政要的是**按用量付费的 API 密钥**，ChatGPT 这类会员**订阅**不能直接用。
- 点“检测”：先过 `bindRequest`，不对就在 `bindResult` 显示错误，不发请求。对了就 `POST /api/blocks/bind`，按钮变成“检测中…”且不能再点。
- 通过：
  1. 在 Mac 窗口里（`window.webkit && window.webkit.messageHandlers && window.webkit.messageHandlers.blocksKey` 存在时）调 `postMessage({account: 返回的 key_account, key: 密钥})`，让窗口存进钥匙串（窗口那边第 8 项接）。在浏览器里没有这个，就跳过。
  2. **清掉密钥框**（`bindKey.value = ""`），页面不再留着密钥。
  3. 进入聊天页。
- 不通过：`bindResult` 显示 `bindResultText`，密钥框不清，改了再测。

### 重新连上（`reconnect`）

绑过、但这次密钥还没交给本机服务（比如浏览器里刷新了页面）。显示同一张卡，标题换成“重新连上行政”，服务商和模型按 `setting` 填好并锁住，只要填密钥，点按钮走 `POST /api/blocks/connect`。卡上另有“换一个行政”，点了解锁，按绑定页走。Mac 窗口里这一步由窗口自动完成，用户一般看不到。

### 聊天页（`main`）

- **左栏** `side`：
  - “聊天”：`newChat` 按钮、对话列表 `threads`。每 1.5 秒 `GET /api/clerk/list?project=<home>&token=...` 刷新。点一段 → 调 iframe 里的 `SuperAgentChat.openThread(id)`；“新对话” → `SuperAgentChat.startFresh()`。每段有删除按钮：先 `confirm(deleteConfirm(...))`，再 `POST /api/clerk/delete`，然后 `SuperAgentChat.threadDeleted(id)`。
  - “基础层”：列表 `blocksList`，每 5 秒 `GET /api/blocks/list` 刷新。每一块显示名字、`kindText`、状态点（`statusClass`）和 `statusText`。还没有积木时显示“还没有接进来的工具，跟行政说一声就行”。点一块先不做事（详情是 57 号单）。坏掉的卡（`broken`）列在最后，显示“这张接法卡坏了”。
- **右上角** `settingsBtn`“行政设置”：回到绑定卡（可以换服务商、模型），旁边有“返回”。
- **中间** `chatFrame`：`<iframe>`，HTML 里不写 `src`，拿到 `state.home` 后由脚本设成 `chatUrl(home, token)`。iframe 和本页同源，可以直接调它的 `SuperAgentChat`。

### 发请求

照 `team.js` 的写法：POST 带 `X-Chat-Token` 头（`encodeURIComponent(token)`）和 JSON；GET 把 `token` 放在查询里。请求失败显示中文，比如“没连上本机服务，请稍后再试”。

### 密钥的规矩

- 密钥只在密钥框和那一次请求里出现。**不存** `localStorage`、`sessionStorage`、cookie；**不放进地址**；**不打印**（整个文件不出现 `console.log`）。

## 本机服务加一点（`desktop/server.py`）

`GET /api/blocks/state` 的返回再加两项：
- `home`：积木库资料夹的完整路径（`str(blocks.home())`），页面拿它拼聊天地址。
- `providers`：`desktop.clerk.providers.PROVIDERS` 里每家的 `id`、`name`、`base_url`、`models`（只这四个字段）。
