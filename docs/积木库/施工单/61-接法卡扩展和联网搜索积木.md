# 施工单 61：接法卡扩展和“联网搜索”积木

依据：[沙盒接入·需求共识](../沙盒接入/需求共识.md)、[沙盒接入·方案](../沙盒接入/方案.md)（尤其技术设计“接法卡新增”）、[沙盒接入·任务清单](../沙盒接入/任务清单.md) 第 1 项。
验收测试：`tests/test_acceptance_61_card_kinds.py`（47 项，Claude 写，**不准改**）。

## 用户能感受到的变化

这张单没有界面。做完以后，基础层的“接法卡”能描述两类命令行工具和一种新积木：

- **AI 助手**（Codex 这类，交代一句话它自己干活）：和现在一样；
- **普通工具**（给它一条具体命令、它返回结果）：用一条只查不改的“检测命令”判断能不能用；
- **联网搜索**：预置 Tavily 一张，行政以后靠它上网。

卡里可以写“这个工具要哪几把密钥、交给工具时叫什么名字”，但只记名字，不记密钥本身。

## 只改这两个文件

- `collab/blocks.py`
- `collab/blocks_env.py`（只为“没有查版本命令的工具”那一处）

别的文件（`blocks_check.py`、`blocks_install.py`、`desktop/`、页面、测试）都不动。

## 要做的

### 1. CLI 卡新增四项：`role`、`probe`、`ok_words`、`secrets`

- `role`：`"agent"`（AI 助手）或 `"tool"`（普通工具）。**不写就当 `"agent"`**，并补进返回的卡里——用户基础层里已有的老卡一个字都不用改。别的值、不是文字，都用中文拒收。
- **agent**：规则和现在完全一样（`run` 要有 `{prompt}`、`model`、`done_when` 默认值……）。写了 `probe` 或 `ok_words` 就拒收。
- **tool**：
  - 不许写 `run`、`model`、`done_when`（它不接交代），也**不许补** `done_when` 默认值；
  - `probe` 必填：1 到 20 个参数的文字列表；不许有任何 `{…}` 占位；每个参数和 `run` 走**同一套**检查（常见字符、单个最长 500 字、不能写密钥开关、不能关安全限制）。把现在 `_check_cli` 里逐个检查参数的那段抽成一个函数，两边共用，不要复制一份；
  - `ok_words` 选填：1 到 5 个字样，每个去掉空白后至少 2 个字。
- `version_args`：两类都多允许一种写法 **空列表 `[]`**，意思是“这个工具没有查版本的命令”。不写仍默认 `["--version"]`；其他写法照旧拒收。
- `login_check`：两类都能写，规则不变。
- `secrets` 选填，两类都能写：
  - 1 到 5 项的列表，每项**恰好** `{"env": …, "label": …}` 两个字段（多一个字段，比如 `value`，就拒收）；
  - `env`：大写字母开头，只有大写字母、数字、下划线，2 到 64 个字；不许重复；
  - `env` 不许是能改变程序运行方式的名字。精确拒收：`PATH HOME SHELL USER LOGNAME TMPDIR PWD OLDPWD ENV BASH_ENV ZDOTDIR IFS NODE_OPTIONS NODE_PATH LANG TERM EDITOR VISUAL PAGER BROWSER HTTP_PROXY HTTPS_PROXY ALL_PROXY NO_PROXY`；以这些开头的也拒收：`DYLD_ LD_ PYTHON NPM_CONFIG_ HOMEBREW_ GIT_ SSH_ LC_ PERL RUBY JAVA_ SUPER_AGENT_`；
  - `label`：显示名，去掉空白后 1 到 20 个字。
  - **注意：** 现在的“卡里不能有密钥”检查会把字段名 `secrets` 当成密钥拒收（名字里有 secret）。要让 `secrets` 这个字段名本身放行，但它里面的值照旧要过密钥检查（`label` 写成 `sk-…` 这种要拒收）。

### 2. 新积木种类 `kind: "search"`

- 字段只有：`id kind name provider key_account source note`，多写别的（比如 `base_url`、`command`）就拒收。
- `provider` 只能是 `tavily`；`key_account` 必须和预置的一样（`tavily`），改了就拒收。搜索地址写在程序里，卡里没有地址。
- 预置一张：`SEARCH_PRESETS = {"tavily": {"id": "web-search", "kind": "search", "name": "联网搜索 · Tavily", "provider": "tavily", "key_account": "tavily"}}`。
- 种类不认识时的中文提示要写出三种：`cli`、`llm_api`、`search`。
- **不要**把它放进 `BUILTIN`：体检、行政的模板都在遍历 `BUILTIN`，那里只该有命令行工具。

### 3. 新增的几个函数

| 函数 | 做什么 |
|---|---|
| `search_card(provider)` | 返回检查过的预置搜索卡，`source` 为 `builtin`；不认识的名字用中文报错 |
| `category(card)` | 返回 `agent` / `tool` / `llm_api` / `search` |
| `CATEGORY_LABELS` | `{"agent": "AI 助手", "tool": "普通工具", "llm_api": "大模型 API", "search": "联网搜索"}` |
| `probe_args(card)` | 普通工具的检测命令：`[command] + probe`，原样不替换；不是普通工具就报错 |
| `secret_account(card_id, env)` | 钥匙串账号名 `cli:<编号>:<env>`；编号、名字都按上面的规则检查，不合格报错 |

### 4. 改这几个老函数

- `build_args`：只给 AI 助手用；普通工具、联网搜索都报错。
- `command_preview`：普通工具显示检测命令（`probe_args`），加引号的规则和 AI 助手一样。
- `is_verified`：普通工具、联网搜索一律返回 `False`；AI 助手比对的固定字段加上 `role probe ok_words secrets`——预置卡加了 `secrets` 就不算核实过，要亮命令让用户确认。

### 5. 体检（`blocks_env.py`）

- 基础层里 `version_args` 为空的工具：找到了程序也**不去运行它**，版本留空，`note` 写“这个工具查不了版本”；查登录照旧。
- 联网搜索不是命令，不进体检（现在只取 `kind == "cli"` 的卡，保持这样即可）。
