## 用户能感受到的

1. **体检卡固定在聊天上方。** 每次打开积木库（包括第一次绑定行政成功后）自动体检一次，几秒钟。体检中写“环境体检：正在检查…”。
   - 基础层里接的工具都正常：收成一行，例如“环境体检：基础层里的 1 个工具都正常 · 没装：Homebrew、Cursor、agy”。
   - 基础层里接的工具没了、没登录、查版本出错：自动展开，一项一项列出来，打勾或打叉，打叉的写做什么用、怎么办（例如“Codex 还没登录：在终端里登录一次，行政会告诉你命令”）。
   - Node、Homebrew、git 和没接进基础层的工具，照样列出、打叉，但**不会逼着展开**（用户 2026-11-09 定：只看基础层里的）。
   - 卡上有“展开 / 收起”和“重新检查”。手动收起或展开后，到下一次体检结果出来前都按用户的来。
   - 体检本身出错：写“环境体检没做成：<原因>”，可以点“重新检查”。
2. **点左栏基础层里的一块，中间换成它的详情**（聊天先藏起来，不是关掉）。左栏那一块高亮。详情上方有“返回聊天”；点左栏任何一段对话或“新对话”也回到聊天。
   - 写着：名字；类型（CLI / 大模型 API）；状态（能用 / 不能用：原因和怎么办 / 没检测过）；上次检测的时间和用时。
   - CLI 还写：命令、版本、登录（版本和登录来自最近一次体检）、来源（预置接法，核实过 / 行政起草，没核实）。
   - 大模型 API 还写：服务商、模型、地址、密钥存在哪个账号（`key_account`）。
   - “接法卡全文”可以展开看，不能改（要改跟行政说）。
3. **“检测”按钮：再测一次。**
   - 核实过的 CLI：直接测。
   - 没核实的 CLI：详情里用醒目颜色写“未核实，有风险：检测前看清要运行的完整命令”，亮出完整命令，按钮是“看过了，确认检测”。
   - 大模型 API：详情里有密钥框（和 57 号单的一样），旁边写“密钥只填在这里，别贴在聊天里”（用户 2026-11-09 定）。没填就点，写“请先在密钥框里填好密钥”，不发请求。
   - 检测中写“正在检测…”，“检测”“移出基础层”都点不了；结果出来写“检测通过 · 4.2 秒”或原因，状态和左栏跟着更新。
4. **“移出基础层”：先确认**（用户 2026-11-09 定）。弹“把「Codex」移出基础层？不会卸载工具，也不删密钥。要用时跟行政说一声就能再接回来。”点确定才移出，然后回到聊天，左栏里没有它了。
5. 左栏里坏掉的接法卡也能点：详情写“这张接法卡坏了：<原因>”，只有“移出基础层”。

## 规则层 `BlocksCore`（`blocks_detail_check.js` 逐条测）

加进 `BlocksCore`，原有的一个都不能少、不能改行为。

### `healthView(scan, blocks)`

`scan` 是体检结果（`/api/blocks/job` 回话里的 `result`：`{time, items}`），还没有就是 `null`；`blocks` 是 `/api/blocks/list` 回话里的 `blocks` 数组。返回 `{state, expand, line, rows}`：

- `rows`：体检的每一项一行，按原顺序，`{name, label, ok, text, fix, why}`。
  - `ok`：`status` 是“有”、`login` 不是“没登录”、`note` 为空。
  - `text`：“有” → 版本（没有版本写“有”），`login` 是“已登录”加“ · 已登录”，是“没登录”加“ · 没登录”，有 `note` 再加“ · <note>”；“没有” → “没有”；“找不到” → “装了，但超级助手找不到”。
  - `fix`：用项目里的 `fix`；`fix` 为空但有 `note` 时写“跟行政说一声，它会帮你查”。
  - `why`：原样。
- 要处理的项：`ok` 为假，**并且** `name` 是 `blocks` 里某块 CLI（`kind` 是 `cli`）的 `id`。
- `state`：`scan` 是 `null` → `loading`；有要处理的 → `problem`；否则 `ok`。`expand`：只有 `problem` 为真。
- `line`：
  - `loading`：`环境体检：正在检查…`
  - `problem`：`环境体检：基础层里有 K 个工具要处理：A、B`（A、B 用 `label`，顿号隔开）
  - `ok`：基础层里在体检名单中的 CLI 有 n 个时 `环境体检：基础层里的 n 个工具都正常`；n 为 0 时 `环境体检：基础层里还没有工具`。然后，`status` 是“没有”、又不在基础层里的项，按顺序加 ` · 没装：X、Y`（用 `label`）；没有就不加。

### `detailView(d, scanItem)`

`d` 是 `/api/blocks/detail` 的回话；`scanItem` 是最近一次体检里 `name` 等于这块编号的那一项，没有就是 `null`。返回 `{title, rows, status, needsKey, needsApprove, preview, warn, checkText, cardText}`：

- `title`：`card.name`。
- `rows`：`[{label, text, code}]`（`code` 为真用等宽字）：
  - 都有：`类型`（`CLI` / `大模型 API`）。
  - CLI 接着：`命令`（`card.command`，`code: true`）；`版本`（`scanItem.version`，没有写 `还没查到`）；`登录`（`scanItem.login`，`scanItem` 有但 `login` 为空写 `查不了`，没有 `scanItem` 写 `还没查到`）；`来源`（`d.verified` 为真 `预置接法，核实过`，否则 `行政起草，没核实`）。
  - 大模型 API 接着：`服务商`（`tencent` → 腾讯云，`bailian` → 阿里百炼，`other` → 其他，不认得的原样）；`模型`；`地址`（`card.base_url`）；`密钥账号`（`d.key_account`）。
  - 最后都有：`上次检测`：有 `d.last_check` 时 `<时间> · 用了 <seconds> 秒`（时间是 `last_check.time` 把 `T` 换成空格）；没有写 `没检测过`。
- `status`：`{cls, text}`。没有 `last_check` → `{idle, 没检测过}`；`ok` 为真 → `{ok, 能用}`；否则 `{bad, 不能用：<reason>}`，有 `how` 再加 `。<how>`。
- `needsKey`：大模型 API 为真。`needsApprove`：CLI 且 `d.verified` 为假。`preview`：`needsApprove` 时是 `d.preview`，否则空字符串。
- `warn`：`needsApprove` 时 `未核实，有风险：检测前看清要运行的完整命令`，否则空。
- `checkText`：`needsApprove` 时 `看过了，确认检测`，否则 `检测`。
- `cardText`：`JSON.stringify(d.card, null, 2)`。

### `checkView(job)`

把检测任务的回话变成详情里显示的 `{state, text}`：

| 情况 | state | text |
|---|---|---|
| `job` 是 `null` | `lost` | `这次检测的结果没留下来（超级助手重开过），再点一次检测` |
| 没做完 | `running` | `正在检测…` |
| 有 `error` | `fail` | error 原文 |
| `result.ok` | `ok` | `检测通过 · <seconds> 秒` |
| 不成功 | `fail` | 有 `reason`：`reason`，有 `how` 再加 `。how`；没有 `reason` 有 `how`：只写 `how`；都没有：`没成功，原因没查出来，跟行政说一声` |

### `removeConfirm(name)`

`把「<name>」移出基础层？不会卸载工具，也不删密钥。要用时跟行政说一声就能再接回来。`

## 页面层

### 体检卡

- `blocks.html` 的 `.stage` 里，`topbar` 和 `chatFrame` 之间放 `<section id="healthCard">`，里面：`#healthLine`（那一行字）、`#healthToggle`（展开 / 收起）、`#healthRecheck`（重新检查）、`#healthRows`（展开时的清单）。
- 进入聊天视图时（`showMainView`，第一次进、绑定成功后进都算）体检一次：`POST /api/blocks/scan` 拿到 `job`，每 1 秒 `GET /api/blocks/job?id=<job>&token=<token>`，做完拿 `result`。**同一时间只跑一次体检**：正在查时再点“重新检查”或再进聊天视图，不另起一次。从详情回到聊天**不**重新体检。
- 画法：`healthView(最近的体检结果, 最近的基础层列表)`。基础层列表每次刷新（56 号单的 5 秒循环）后也重画一次体检卡，不重新体检。
- 展开状态：新的体检结果出来时，按 `expand` 定；用户点了“展开 / 收起”就按用户的，直到下一次体检结果出来。
- 清单每行：打勾或打叉、`label`、`text`；打叉的另起一行写 `why` 和 `fix`。所有内容一律 `textContent`。
- 体检任务出错（回话有 `error`，或请求失败）：`#healthLine` 写 `环境体检没做成：<原因>`；任务找不到（404）写 `环境体检没做成：超级助手重开过，点“重新检查”`。“重新检查”能点。
- 体检中“重新检查”点不了。

### 详情

- `blocks.html` 的 `.stage` 里加 `<section id="blockDetail" hidden>`，里面：`#detailBack`（返回聊天）、`#detailTitle`、`#detailStatus`、`#detailWarn`、`#detailRows`、`#detailPreview`（没核实时的完整命令，`<pre>` 或 `<code>`）、`#detailKeyBox`（含 `<input id="detailKey" type="password" autocomplete="off">` 和那句“密钥只填在这里，别贴在聊天里”）、`#detailCheck`、`#detailRemove`、`#detailResult`、`<details id="detailCard">`（`<summary>接法卡全文</summary>` 加 `<pre>`）。
- 点左栏 `.block-item[data-block]`：藏起 `#healthCard` 和 `#chatFrame`（`hidden`，不改 `src`，聊天不重载），显示 `#blockDetail`，`GET /api/blocks/detail?id=<编号>&token=<token>`，用 `detailView(回话, 体检里同名的那项)` 画。左栏那一块加 `on`；5 秒刷新重画左栏时高亮不能丢。
- 点左栏 `.block-item[data-broken]`：详情只写 `这张接法卡坏了：<原因>`（原因来自 `/api/blocks/list` 的 `broken[].problem`）和“移出基础层”，别的都藏起来。
- 回到聊天：`#detailBack`、左栏任何一段对话、“新对话”。显示 `#healthCard`、`#chatFrame`，藏起 `#blockDetail`，清空 `#detailKey`，左栏去掉高亮。
- 详情取不到（404）：写 `基础层里没有这一块了`，只留“返回聊天”。
- 所有内容一律 `textContent`，接法卡全文放 `<pre>` 的 `textContent`。

### 检测

- 点 `#detailCheck`：
  - 大模型 API：`#detailKey` 去掉首尾空格后是空的 → `#detailResult` 写 `请先在密钥框里填好密钥`，**不发请求**。不空 → `POST /api/blocks/check {id, api_key}`。
  - 没核实的 CLI：`POST /api/blocks/check {id, approved: <detailView 的 preview>}`，就是页面上亮出来的那条。
  - 核实过的 CLI：`POST /api/blocks/check {id}`。
- 发出后 `#detailCheck`、`#detailRemove` 都点不了，`#detailResult` 写 `正在检测…`。请求成功后清空 `#detailKey`；请求出错写服务器给的错误、两个按钮恢复、密钥框不清。
- 回话里的 `job`：每 1 秒 `GET /api/blocks/job?id=<job>&token=<token>`，用 `checkView` 写进 `#detailResult`（`ok` 绿、`fail` 红、其余灰），做完就停，同一时间只跟一个。做完后重新取一次详情（状态、上次检测会变），并马上刷新一次左栏。两个按钮恢复。
- 跟进时网络出错：2 秒后再问，不放弃；404 用 `checkView(null)`。
- 检测中用户离开详情（回聊天或点了别的块）：停止跟进，回来时重新取详情就行。
- **大模型 API 检测通过后**，把这次填的密钥交给 Mac 窗口：照 56 号单 `saveKeyToMac` 的写法（`window.webkit.messageHandlers.blocksKey.postMessage({account: d.key_account, key})`），没有就跳过。这样 57 号单里“密钥没带上”的块，在详情里填一次、检测通过就补上了。交完（或没交成）马上把页面内存里那份删掉；检测没通过、离开详情时也删掉。

### 移出

- 点 `#detailRemove`：`window.confirm(BlocksCore.removeConfirm(名字))`，坏卡用编号当名字。取消就什么都不做。
- 确定：`POST /api/blocks/remove {id}`。成功 → 回到聊天，马上刷新左栏。出错 → `#detailResult` 写服务器给的错误（比如“正在检测这一块，等检测完再移出”）。

### 密钥的规矩（和 56、57 号单一样）

密钥只在密钥框、那一次请求、和等着交给窗口的那份内存里出现。不存 `localStorage`、`sessionStorage`、cookie，不放进地址，不打印（整个文件不出现 `console.log`），不写进任何显示的文字。

## 样式（`blocks.css`）

- 体检卡：在聊天上方，不挡聊天；收起时只占一行。打勾用 `--ok`，打叉用 `--bad`，说明文字用 `--dim`。
- 详情：和聊天区同宽居中，行的写法可以照聊天页提议卡的 `.rows`（标签小字灰色，内容正常字）。
- 风险提示、`fail` 结果用 `--bad`；`ok` 用 `--ok`；正在检测用 `--dim`。
- 接法卡全文、完整命令用等宽字（`--font-mono`）、`--bg-side` 底，能横向折行。
- **不写死色值。** 规则见 `docs/界面改版/设计规范.md`。

## 要用的接口（都已经有，不改）

| 接口 | 用来 |
|---|---|
| `POST /api/blocks/scan` → `{job}` | 体检；结果在任务的 `result`：`{time, items: [{name, label, kind, status, version, login, why, note, fix, path}]}` |
| `GET /api/blocks/job?id=` | 体检、检测的进度和结果：`{job, kind, done, result, error}`；找不到 404 |
| `GET /api/blocks/list` | 左栏：`{blocks: [{id, name, kind, verified, status, reason, time, seconds}], broken: [{id, problem}]}` |
| `GET /api/blocks/detail?id=` | 详情：`{card, verified, preview, key_account, last_check, last_install}`；没有这块 404 |
| `POST /api/blocks/check {id, approved?, api_key?}` → `{job}` | 检测。没核实的 CLI 不带 `approved` 会 400；API 不带密钥会 400 |
| `POST /api/blocks/remove {id}` | 移出；正在检测时 409 |
