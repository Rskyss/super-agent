# 60 号单：存过的密钥哪里都不用再填

任务清单第 8 项的下半（2026-11-09 用户定拆两张，59 已提交 e8c8727）。**Claude 直接施工**（用户 2026-11-09 定）。

验收测试：`tests/test_acceptance_60_saved_keys.py`（本机服务 + 页面接线 + Mac 窗口文字检查）和它调用的 `tests/blocks_saved_keys_check.js`（页面规则）。原有测试一项不改。

## 用户能感受到的

1. **四个要填密钥的地方**：绑定行政、重新连上行政、基础层详情里检测大模型 API、聊天里“接入大模型 API”的提议卡。只要这一家的密钥钥匙串里有（不管是在项目窗口还是积木库里存的），填密钥的地方就换成一行 **“已保存的密钥”** 加一个 **“换一把”**（用户 2026-11-09 定）：
   - 直接点“检测”：用存的那把；
   - 点“换一把”：出现输入框，填了用新的；检测通过后新的存进钥匙串，替换旧的；
   - 存的那把没通过（过期、额度用完）：照常用大白话说原因，并自动展开输入框，提示“存的这把没通过，可以换一把”。存的那把不删（可能只是网断了）。
2. **绑定页换服务商时跟着变**：选腾讯云，腾讯云有存的就显示“已保存”；换成百炼，百炼没存就显示输入框。“其他”按填的地址分开算。
3. **项目窗口里新存、删掉的密钥，积木库马上跟着变**：项目窗口里删掉某家的密钥，积木库里那一家就变回输入框。
4. 页面上、地址里、记录和文件里，任何时候都看不到密钥本身。

## 怎么做（用户 2026-11-09 定：打开时交给本机服务暂记）

- **Mac 窗口 → 本机服务：** 积木库窗口每次加载前，把钥匙串里本应用存的所有密钥（账号名合法的）一次交给本机服务：`POST /api/blocks/keys`，`{"keys": {"tencent": "...", "other:api.x.com": "..."}}`，**整份替换**（钥匙串里删掉的，服务里也没了）。只在积木库窗口开着时交；项目窗口存、删密钥后，积木库开着就再交一次。
- **本机服务只记在内存里**（`server.blocks_saved_keys`），不写文件、不进记录、不出现在任何返回内容里。`/api/blocks/state` 多返回 `saved_accounts`（只有账号名，排好序）。
- **四个接口没带密钥就用存的：** `bind`（按服务商和地址算出账号）、`connect`、`check`（用卡上的 `key_account`）、积木库提议卡确认 `connect_api`（用提议里那一块的 `key_account`）。带了就用带的。都没有：照旧报“要先填密钥”这一类错。
- **钥匙串是唯一的来源，本机服务自己不记**：检测通过后，页面照旧把密钥交给 Mac 窗口存进钥匙串（59 号单的 `blocksKey`）；钥匙串一变，Mac 窗口再交一次整份给本机服务，再叫页面重新取状态，别处就显示“已保存”。存不进钥匙串的（账号名不合 59 号单的规则）就不显示“已保存”，和实际一致。这样 55 号单“不带密钥不能重连”的原有测试也不用改（Claude 写单时发现的冲突，2026-11-09）。
- 浏览器里走查（没有 Mac 窗口）：什么都不会显示“已保存”，和现在一样。

## 改哪些文件

### `desktop/server.py`

- `make_server` 里加 `server.blocks_saved_keys = {}`。
- `POST /api/blocks/keys`：`keys` 必须是字典；每个账号过 `blocks_window` 同一套规则（`tencent`、`bailian`、`other:` 加小写字母数字点横线 1–253 个字）；密钥去首尾空白后不空、不超过 500 字、不含换行。不合格的那一条丢掉（不报错）。整份替换后返回 `{"ok": true, "count": N}`，**不回显账号以外的东西**。
- `GET /api/blocks/state`：加 `saved_accounts`。
- 取密钥统一走一个小函数：带了用带的，没带用 `blocks_saved_keys.get(账号, "")`。
- `bind`：先算账号，再取密钥；都没有 → 400 “要选服务商、填模型和密钥”（原话不变）。
- `connect`：没带也没存 → 400 “没有密钥”（原话不变）。
- `check`（`llm_api`）：没带也没存 → 400 “要先填密钥”（原话不变）。
- `_blocks_proposal` 的 `connect_api`：没带也没存 → 400 “请先在密钥框里填好密钥”（原话不变）。
- 本机服务**不**自己记住页面带来的密钥。

### `desktop/static/blocks.js`、`blocks.html`、`blocks.css`

- `BlocksCore.accountFor(provider, baseUrl)`：`tencent`、`bailian` 原样；`other` → `"other:" + 地址的主机名小写`，地址不对返回 `""`。
- `BlocksCore.bindRequest(form, providers, saved)`：第三个参数是已保存账号的列表。密钥空、但这一家已保存 → 照样通过，`body` 里**不带** `api_key`，另给 `useSaved: true`。不传 `saved` 时和原来完全一样（56 号单的检查不改）。
- 绑定页和详情页的密钥框旁边各加一行：`<div class="saved-key" hidden><span>已保存的密钥</span><button type="button">换一把</button></div>`。有存的：显示这一行、藏输入框；点“换一把”：藏这一行、显示输入框并聚焦。
- 绑定页：换服务商、改地址时重新判断。重新连上：用 `state.key_account` 判断。
- 存的那把没通过：显示原因，再加一句“存的这把没通过，可以换一把”，并展开输入框。
- 加一个 `window.blocksKeysChanged()`：重新取一次状态，按新的 `saved_accounts` 重画绑定页、详情页的密钥行（输入框里已经填了字的不动）。Mac 窗口交完密钥后调它。
- 样式：照密钥输入框的高度和圆角，灰字；“换一把”照 `.gear` 那种文字按钮；只用 `theme.css` 变量。

### `desktop/static/chat.js`

- 积木库里的“接入大模型 API”提议卡：画卡时向 `/api/blocks/state` 取 `saved_accounts`（这张页面已经有口令）。提议里那一块的 `key_account` 已保存 → 显示“已保存的密钥 / 换一把”，点“检测”不带密钥；否则照旧输入框。
- 检测没通过且用的是存的：卡片上说“存的这把没通过，可以换一把”并展开输入框。
- `ChatCore.blockCard` 的 `connect_api` 结果多给 `keyAccount`。

### `desktop/mac/Sources/SuperAgent/main.swift`、`BlocksWindow.swift`

- `ClerkKey.accounts() -> [String]`：钥匙串里本服务的所有账号名（只取属性，不取密钥）；`--clerk-key-dir` 时列文件夹里的文件名。
- `ClerkKey.save`、`ClerkKey.delete` 成功后发通知 `ClerkKey.changed`（`Notification.Name("SuperAgentClerkKeysChanged")`）。`main.swift` 别处一行不改。
- `BlocksWindow`：
  - `func syncKeys(then:)`：积木库开着、有端口时，读出所有合法账号的密钥，`POST /api/blocks/keys`（带 `X-Chat-Token`），完了再调 `then`（成没成都调）。密钥只在这次请求里用。
  - `load` 改成：先 `syncKeys`，再走 59 的“问状态 → 自动重连 → 加载页面”。自动重连可以不带密钥（服务里已经有了），也可以照旧带；二选一，写进回执。
  - 收到 `ClerkKey.changed` 通知（项目窗口存、删密钥，积木库自己存密钥都会发）：积木库开着就 `syncKeys`，交完后 `evaluateJavaScript("window.blocksKeysChanged && window.blocksKeysChanged()")`。

## 不做

- 不改项目窗口填密钥的地方。
- 不把密钥写进任何文件；本机服务重启后要等 Mac 窗口再交一次（59 号单已有的“服务重启后积木库跟着重连”就会交）。
- 不做“删除这一家的密钥”按钮（项目窗口已有）。
