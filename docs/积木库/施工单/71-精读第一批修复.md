## 1. S6 列表链接只认网页地址

- `safeLink` 放在 `AbilitiesCore` 里（页面公共层），能用 node 直接测。`abilities.js` 和 `chat.js` 的列表结果都用它，不各写一份判断。
- 判断：`String(url || "").trim()` 后匹配 `/^https?:\/\//i` 就返回去掉空白后的地址，否则返回 `""`。`"#"`、空、`javascript:`、`JAVASCRIPT:`、`data:`、`file:`、前面带空白的 `  javascript:` 都返回 `""`。
- 没链接时显示的字：`item.title || item.url || "无标题"`，放进 `<span>`；摘要（`summary`/`snippet`）照旧显示。
- `chat.js` 里“来源”那段（约 1115 行，已经只认 https）不动。

## 2. C8 试用不一直转圈

`pollModelTrialJob(jobId, cardId, onDone, onError)` 加第 5 个参数“已连续失败几次”（默认 0）：

- **算失败**：请求出错（连不上、本机服务回 404 或其他非 2xx，都会走现在的 `.catch`）。
- **不算失败、计数清零**：查到了结果（不管 `done` 是真是假）。
- 失败后照旧隔 1 秒再查；**连续第 3 次失败**就不再查，调 `onError(new Error("查不到试用结果（本机服务可能重启过），请再试一次"))`（没传 `onError` 就调 `onDone(那个错误)`，和现在 `j.error` 的处理一样）。按钮恢复、清掉 `activeTrials[cardId]` 都沿用现有 `onError` 回调里的写法，不另写。
- `done` 为假时照旧隔 0.5 秒再查。同一个任务不会被同时查两次（沿用现有 `activeTrials`）。

## 3. C12 npm 命令名核对

在 `verify_install` 的 npm 分支、算出 `command` 之后：

- `package["commands"]` 不为空，且 `command` 不在其中 → `raise BlockError("装好后的命令名不在这个包登记的命令里：这个包登记的是 a、b")`（命令按 `package["commands"]` 的顺序用“、”连起来）。
- `package["commands"]` 为空 → 照旧（只做现有的命令名格式检查）。
- 管家没写命令名、程序用包里登记的默认值时，自然在里面，照旧通过。
- Homebrew、脚本安装不变（它们的信息里没有命令名清单，见方案泼冷水第 1 条）。

## 4. S1 联网搜索不跟随跳转

- `_request_json` 改用 `urllib.request.build_opener(_NoRedirect, urllib.request.HTTPSHandler(context=ssl.create_default_context()))` 打开（和 `_open` 同一个办法），不再用 `urllib.request.urlopen`。
- 被跳转时拿到的是 3xx 状态：联网搜索（`_post_json`，约 373 行调用处）现有的“不是 200 就报联网搜索出错”照旧生效，报错里不能带密钥。
- `_get_json` 也走 `_request_json`（npm、另一处查询），一并不跟随跳转：遇到 3xx 按现有的“不是 200”处理。这是有意的。
- 超时、正文大小上限、`HTTPError` 的处理不变。

## 5. S5 补三种密钥格式

在 `_SECRET_TEXT` 里加（前面同样不能紧挨字母数字，照 `sk-` 那条的写法）：

- `pplx-[A-Za-z0-9]{20,}`
- `gsk_[A-Za-z0-9]{20,}`
- `fw_[A-Za-z0-9]{20,}`

**测试里的假密钥一律现拼**（例如 `"pplx-" + "a1" * 12`），不要在测试文件里写成一整串（GitHub 推送会被密钥扫描拦，50 号单的教训）。

## 6. 验收（写测试的人写进 `tests/test_acceptance_71_readfix.py`）

**不许跑真的大模型、搜索、Codex、Cursor、agy，不许真联网。** 页面纯函数和页面逻辑用 node 跑（照 `tests/test_acceptance_68_abilities_page.py`、`tests/blocks_page_check.js` 的写法）；网络用本机假服务（照 `tests/test_acceptance_62_blocks_web.py` 的写法）。至少覆盖：

1. **S6**：`safeLink` 对 http、https、大写 HTTPS 返回原地址；对 `#`、空、`javascript:`、`JAVASCRIPT:alert(1)`、`  javascript:x`、`data:`、`file:` 返回空。能力层详情和聊天的列表结果：网页地址出 `<a>`，其他出 `<span>` 且显示标题；两个页面都调用了 `safeLink`。
2. **C8 正常**：假接口第一次回 `done:false`、第二次回结果 → 调 `onDone`，不出错。
3. **C8 出错**：假接口连续出错 3 次 → 调 `onError`，文案是第 2 节那句；只出错 2 次、第 3 次回 `done:false`、之后再出错 2 次 → 不调 `onError`（中间那次清零了）。
4. **C8 找不到**：本机服务对这个任务回 404 → 也算失败，3 次后停。
5. **C12**：假 npm 信息登记了 `["foo", "foo-cli"]`：命令名 `foo-cli` 通过；`ls` 报错且报错里列出 `foo`、`foo-cli`；不写命令名照旧取默认值；包里没登记命令（`commands` 为空）时命令名照旧只查格式。
6. **S1**：本机假服务对联网搜索请求回 302 跳到另一个本机假地址：跳转后的地址**收不到任何请求**（更收不到密钥），结果报联网搜索出错，报错文字里没有密钥；假服务正常回 200 时照旧拿到结果。
7. **S5**：现拼的 `pplx-`、`gsk_`、`fw_` 假密钥被认出（单独一段、夹在一句话里都算）；`task-configuration`、`gsk`、`fw_x`（太短）这类普通词不误认。

**出错情况**：上面 3、4、6 就是“服务出错/找不到”的情况，必须有。
