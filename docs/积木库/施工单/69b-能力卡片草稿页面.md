# 施工单 69b：能力卡片草稿的页面

依据：[能力层/方案.md](../能力层/方案.md) 第一节第 4 点；[69 号施工单](69-管家起草能力卡片.md)（后台和管家已做完、已放进项目，这张单只接页面）。

**这张单只改页面，后台一行不改。** 69 已经提供了全部接口（见第 3 节），施工方照着接；接口不够用就停下说明，不要自己改后台。

## 这张单做完后的样子（产品话）

1. 积木库窗口里，在基础层点一个积木块看详情，按钮那一排多一个 **“提取能力卡片”**。点了：回到聊天、开一段新对话，替用户发出第一句“我想从「积木块名字」提取能力卡片”，管家知道说的是哪个积木块（普通工具类的积木块不显示这个按钮）。
2. 管家出草稿后，聊天里出现一个 **“能力卡片（草稿）「标题」”** 框，里面：
   - 一句话说明、用哪个积木块、用哪个模型（有备用模型也写上）、交回什么（文字 / 列表 / 图片 / 文件）。
   - 和能力层里同编号的卡重名时，醒目写“放进能力层后会替换原来的「标题」”；有提醒（warns）逐条列出。
   - AI 型（大模型 API、AI 助手）把 **“交代原文”** 亮出来（系统提示 + 交代，或给 AI 助手的那句话），试做前能看到程序要交给它什么话；联网搜索型写“搜什么”。
   - **试做框**：按“你要填什么”一项一项出输入框，用卡片里的 examples 预先填好；按钮“试做” “先不做”。
3. 点“试做”：按钮变“正在试做…”并有计时；程序真跑一次，结果显示在草稿下面（文字直接显示、列表逐条、图片显示出来、文件给个“在访达里打开”）。例子填错（缺必填项等）直接在框里说原因，草稿还开着可以改了再点。
4. 试做成了：显示结果和“放进能力层”按钮；点了变“已放进能力层”，左栏能力层列表里出现这张卡。
5. 试做没成：显示没成的原因，下面一句“跟管家说哪里不对，它会改了重新出草稿”；没有“放进能力层”按钮。
6. 关掉窗口再打开、或切到别的对话再切回来：草稿、试做结果、是否已放进，都照原样显示回来；正在试做的接着显示进度。
7. 项目窗口（主窗口）的聊天、行政、卡片，一切不变。

## 1. 基础层详情：“提取能力卡片”（`blocks.js`）

- 详情按钮那一排（和“检测”“移出基础层”同一排）加按钮“提取能力卡片”。类别是普通工具（`role == "tool"`）的积木块**不显示**；没检测过、检测没过的照样显示（管家会说先去检测）。
- 点了：隐藏详情、显示聊天（照“← 返回聊天”的办法），调用聊天页暴露的新方法 `SuperAgentChat.startFromBlock(积木块编号, 积木块名字)`（第 2 节）。左栏对话列表随后出现这段新对话。
- 聊天页正在回话（`isWorking()` 为真）时，按钮先不可点，旁边一句“管家还在回话，等它说完再点”。

## 2. 聊天页（`chat.js`）

### 2.1 从积木块开对话

`SuperAgentChat.startFromBlock(blockId, blockName)`：只在积木库管家模式（`butlerMode`）下可用。新开对话（和“新对话”按钮一样清空当前），发 `/api/clerk/send`，body `{conversation: "", text: "我想从「名字」提取能力卡片", block: blockId}`；回来的 `conversation` 当成当前对话、开始轮询（照 `clerkSend` 从空白发第一句的写法）。接口回 400（积木块不存在）就在聊天里显示错误，不留空对话。

### 2.2 能力卡片（草稿）框

事件 `type: "proposal"`、`kind: "ability"`（69 的 `event_from_proposal`）带：`id`、`state`（open / confirmed / cancelled / voided）、`ability`（整张卡片）、`name`、`block_name`、`warns`、`replaces`、`trial`（`ok`、`status`、`reason`、`run_id`、`seconds`、`model`）、`saved`。

画法（文字都用大白话，和能力层详情页一个口径；能复用 `AbilitiesCore` 的就复用）：

- 标题：`能力卡片（草稿）「name」`。
- 一句话说明（`ability.description`）；`用哪个积木块：block_name`；`用哪个模型：ability.model`（有 `backup_models` 写“备用：…”；联网搜索写“不涉及”）；`交回什么：`用 `AbilitiesCore.outputText`。
- `replaces` 有值：醒目一行“放进能力层后会替换原来的「replaces」”。`warns` 逐条列。
- 交代原文：`AbilitiesCore.promptText(ability)` 有内容就显示在一个可展开的框里，默认展开。
- `state == "open"`：试做框——`AbilitiesCore.formFields(ability.inputSchema)` 出输入框，examples 预填；按钮“试做”“先不做”。
  - 点“试做”：`AbilitiesCore.collectInputs` 收集；本地就能判断的缺项直接在框里提示、不发请求。发 `/api/clerk/proposal` `{conversation, id, decision: "confirm", inputs}`：
    - 400：把原因显示在框里，框保持可改（提议还开着）。
    - 409（正在用）：显示原因。
    - 200 带 `job`：按钮变“正在试做…”+ 计时，每 1.5 秒查 `/api/blocks/job?proposal=<id>`（照现有积木块检测的轮询写法），做完显示结果。
  - 点“先不做”：照现有提议的“先不做”。
- `state == "confirmed"`：
  - 还没有 `trial` 且查得到任务：显示“正在试做…”接着轮询；查不到（超级助手重开过）：显示“这次试做的结果没留下来（超级助手重开过）。跟管家说再出一次草稿。”
  - `trial.ok` 为真：结果区（用 `AbilitiesCore.resultView`，图片用 `/api/abilities/file?id=<卡片编号>&run=<run_id>&name=<文件名>`，文件给“在访达里打开”沿用能力层详情页的办法）；`saved` 为假时按钮“放进能力层”，`saved` 为真显示“已放进能力层”。
  - `trial.ok` 为假：显示没成的原因（`trial.reason`），下面“跟管家说哪里不对，它会改了重新出草稿”，不显示“放进能力层”。
- 点“放进能力层”：发 `/api/abilities/save` `{proposal: id}`；200 → 显示“已放进能力层”（`repeat: true` 也一样）；409 → 原因显示在框里（例如“能力层里已经有同编号的能力卡片：跟管家说重新起草”）。
- `state == "cancelled"`：“先不做了”；`voided`：照现有提议“已失效”。
- 重开对话、切换对话：只靠事件里的 `state`、`trial`、`saved` 画，不靠页面内存；正在试做的接着轮询。
- 别的提议（安装、接入、项目窗口的任务卡片……）的画法一行不变。

## 3. 用到的接口（69 已有，不要改）

| 接口 | 用途 |
|---|---|
| `POST /api/clerk/send` 多收 `block` | 从积木块开新对话；积木块不存在回 400 |
| `POST /api/clerk/proposal`（积木库）`decision: "confirm"` + `inputs` | 试做；回 `{ok, state: "confirmed", job}`；例子不对 400；正在用 409；重复点回同一个 `job` |
| `GET /api/blocks/job?proposal=<id>` | 试做进度和结果 |
| `POST /api/abilities/save` `{proposal}` | 放进能力层；没试做成 409；同编号冲突 409；重复点回 `repeat: true` |
| `GET /api/abilities/file` | 试做出的图片、文件 |
