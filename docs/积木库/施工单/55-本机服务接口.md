## 硬规矩（违反任何一条都不算完成）

1. **密钥只在内存里用。** 不出现在任何返回内容、记录、文件里；不写钥匙串（钥匙串由 Mac 窗口管，第 8 项）。返回给页面的只有“钥匙串账号名”`key_account`。
2. **找命令的路径、装到哪里、积木库资料夹的位置，只由程序定。** 页面传来的 `path`、`prefix`、`root`、`project`（`/api/blocks/*` 里）一律不认。
3. **积木库的行政和项目窗口的行政各用各的模型连接。** 项目窗口的 `/api/clerk/config`、`/api/clerk/clear` 碰不到积木库的；积木库的聊天不能被“这句话属于另一个项目”拦住。
4. **项目窗口的行为一个字都不能变**，原有测试全过。
5. 所有 `/api/blocks/*`（GET 和 POST）都要口令，和 `/api/clerk/*` 一样用 `_chat_allowed`。

## 本机服务加的东西（`desktop/server.py`）

`make_server` 里加四个属性（测试会替换它们）：

| 属性 | 默认 | 做什么 |
|---|---|---|
| `server.blocks_clerk` | `None` | 积木库行政的模型连接 |
| `server.blocks_client_factory` | `None` | 造模型连接的函数 `(base_url, model, api_key) -> client`。`None` 时用 `blocks_check._default_client`（它按服务商决定关不关“思考”）。绑定、检测 API、积木库行政都用它 |
| `server.terminal_path` | `desktop.shell_path.terminal_path` | 取登录终端的 PATH，返回字符串或 None |
| `server.blocks_jobs` | `{}` | 后台任务：编号 → 状态 |

`ClerkDesk` 要能按资料夹取模型连接：构造时多一个可选参数 `blocks_client`（取积木库连接的函数），`is_blocks_home(project)` 时用它，否则用原来的。服务端写成 `ClerkDesk(lambda: server.clerk, blocks_client=lambda: server.blocks_clerk)`。不传 `blocks_client` 时行为和现在完全一样（54 号单的测试就是这样用的）。

**积木库资料夹不存在时**，第一次用到（`/api/blocks/*` 或 `project` 是积木库资料夹的 `/api/clerk/*`）由服务端建好资料夹本身（`mkdir(parents=True, exist_ok=True)`），不建卡片目录。

**找命令的路径**：每次体检、检测、安装前现取一次：`path = shell_path.merged_path(os.environ["PATH"], server.terminal_path() or "")`。安装成功后把这个合并后的路径写回 `os.environ["PATH"]`，这样刚装好的工具不用重开超级助手就能找到。

### 后台任务

- 任务状态：`{"kind": "scan"|"check"|"install", "done": bool, "result": dict 或 None, "error": str}`，接入检测的任务另外记住要保存的接法卡、`replaces`、是不是大模型 API。
- 编号用 `uuid.uuid4().hex`。跑完 `done=True`；出了 `BlockError` 这类中文错误，放进 `error`，`done=True`。
- `GET /api/blocks/job?id=` → `{"kind","done","result","error"}`；安装任务另带 `"tail": blocks_install.output_tail()`（最后 50 行，已打码）。不认得的编号 404。

### 接口

| 地址 | 参数 | 返回 |
|---|---|---|
| `GET /api/blocks/state` | | `{"setting": 行政设置或 null, "key_account": str, "connected": bool, "installing": bool}`。`setting` 是 `load_clerk(积木库资料夹)`；`key_account` 用 `providers.account_for`；`installing` 是 `blocks_install.installing()` |
| `POST /api/blocks/bind` | `provider`、`model`、`api_key`，`other` 另带 `base_url` | 见下“绑定” |
| `POST /api/blocks/connect` | `api_key` | 重新打开窗口时，Mac 从钥匙串取出密钥交过来：按保存的设置建连接，**不再测**。没绑定过 409，密钥空 400 |
| `GET /api/blocks/list` | | `{"blocks": [...], "broken": [{"id","problem"}]}`。每块：`id`、`name`、`kind`、`verified`、`status`（`ok`/`fail`/`never`，按最近一次检测记录）、`reason`、`time`、`seconds` |
| `GET /api/blocks/detail` | `id` | `{"card": 接法卡全文, "verified", "preview", "key_account", "last_check", "last_install"}`。CLI 的 `preview` 是 `blocks_check.preview(卡, path)`（用户检测前要看的完整命令）；大模型 API 的 `key_account` 是卡上的。编号不合法 400，没有 404 |
| `POST /api/blocks/remove` | `id` | `blocks.remove_card`。只是不再列出，不卸载、不删密钥、不删记录。不合法 400，没有 404，正在检测 409 |
| `POST /api/blocks/scan` | | `{"job"}`。后台跑 `blocks_env.scan(root=资料夹, app_path=os.environ["PATH"], terminal_path=终端路径, record=True)`，`result` 就是它的返回 |
| `POST /api/blocks/check` | `id`；CLI 没核实的要 `approved`；大模型 API 要 `api_key` | `{"job"}`。见下“检测” |
| `POST /api/blocks/save` | `job` | 见下“放进基础层” |

编号合法性用 `blocks._ID`（或 `blocks._check_id`）。

### 绑定（`POST /api/blocks/bind`，同步返回）

1. 参数检查，不对就 400，**不连模型**：密钥空、模型空、服务商不认得、`other` 没有 `https://` 开头的地址。
2. 认得的服务商用它自己的地址，页面传的 `base_url` 不理（密钥不能被发到别处）。
3. 拼一张临时的大模型 API 接法卡（编号随便取，比如 `clerk`），调 `blocks_check.check_api(卡, 密钥, need_tools=True, record=False, client_factory=...)`：先发一句话，再测会不会用工具。
4. 通过：`save_clerk(积木库资料夹, {provider, model, base_url})`，`server.blocks_clerk = 用同一个工厂造的连接`，返回 `{"ok": true, "reason", "how", "key_account"}`。
5. 不通过：不保存、不连上，返回 `{"ok": false, "reason", "how"}`（状态 200）。

### 检测（`POST /api/blocks/check`）

- 卡不存在 404。大模型 API 没带密钥 400。CLI 没核实（`blocks.is_verified` 为假）又没带 `approved` 时 400（文字里有“确认”）。
- 后台跑：CLI 用 `blocks_check.check_cli(卡, root=资料夹, approved=..., path=路径, terminal_path=终端路径)`；大模型 API 用 `check_api(卡, 密钥, root=资料夹, client_factory=...)`。两者都会写检测记录。
- `check_cli` 因为“确认的命令和现在要跑的对不上”抛 `BlockError` 时，任务的 `result` 写成 `{"ok": false, "status": "changed", "reason": "要跑的命令和你确认时看到的不一样", "how": "跟行政说重新提议，确认新的完整命令"}`。

### 提议卡确认后（改 `/api/clerk/proposal`）

只在 `project` 是积木库资料夹时多做下面这些，项目窗口原样。

- 用户点确认、提议是 `connect_api` 时：先用 `tasks.load_proposal` 看一眼；请求里没有 `api_key` 就 400（文字里有“密钥框”），**提议保持未处理**，用户填好密钥再点确认。
- 照旧调 `desk.decide_proposal`。确认后按 `kind` 开后台任务，返回里加 `"job"`：
  - `install`：开始前 `blocks_install.installing()` 为真就 409（“正在安装别的工具，等它装完再装”）。后台调 `run_install(编号, root=资料夹, path=路径)`，**不传 prefix**。
  - `connect`：后台检测 `block`，`approved` 用 decide 返回的 `approved`。
  - `connect_api`：后台检测 `block`，密钥用请求里的 `api_key`。
- 同一个提议重复确认（decide 返回 `repeat`）：**不开新任务**，返回第一次的任务编号（服务端记住“提议编号 → 任务编号”；记不到就返回空字符串）。
- 先不做（取消）照旧，不开任务。

### 放进基础层（`POST /api/blocks/save`）

- 任务编号不认得 404；不是接入检测的任务、还没做完、检测没通过：409。
- 卡的编号在基础层里已经有了：提议带 `replaces` 的就覆盖；没带的，说明提议之后别处存了同编号的卡，409（“要重新提议”），不覆盖。
- `blocks.save_card(卡)`，返回 `{"ok": true, "id", "key_account"}`（大模型 API 才有 `key_account`，Mac 窗口按它把密钥存进钥匙串）。
- 同一个任务保存两次，第二次也返回 200，不报错。
