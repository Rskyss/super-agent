# 施工单 67：能力卡片的运行

依据：[能力层·需求共识](../能力层/需求共识.md)、[能力层·方案](../能力层/方案.md)（技术设计“运行”）、[能力层·任务清单](../能力层/任务清单.md) 第 2 项。上一张：[66 号单](66-能力卡片格式.md)（`collab/abilities.py`，格式、填内容、查结果都在那里，这张单直接用）。
验收测试：`tests/test_acceptance_67_ability_run.py`（Claude 写，**不准改**）。

## 用户能感受到的变化

这张单还没有界面。做完以后，程序能真的“用一次”一张能力卡片：按卡片去调联网搜索、大模型 API 或 Codex 这类 AI 助手，拿回结果，由程序查结果像不像样，存好成果和记录。出了问题分清是哪一类：

| 类别 `status` | 什么情况 | 用户以后在页面上看到的意思 |
|---|---|---|
| `ok` | 跑完了，结果查过合格 | 成了 |
| `format` | 跑完了，结果不合格（字数不够、一条都没有、图没存出来、图太小） | 没成，写明程序查到的情况 |
| `model` | 模型不通：额度用完、没开通、模型名不对、这家名单里没有这个模型 | 写出平台原话；有备用模型就问要不要换 |
| `block` | 积木块的问题：被移出基础层、上次检测没通过、没存密钥、密钥不对、找不到命令、没登录、搜索额度用完 | 劝去基础层检测那个积木块 |
| `error` | 其他：超时、断网、平台临时出错 | 稍后再试 |

**不自动换模型**（用户 2026-11-10 定）：模型不通时只告诉你备用模型是哪个（`next_model`），你点了才换，换也只管这一次。

## 只改这几个文件

- 新建 `collab/abilities_run.py`
- `collab/blocks_web.py`：只改 `search` 一个函数（见第 5 条）
- `collab/abilities.py`：只改预置卡片“写文章”的 `prompt` 一处（见第 6 条）

## 要做的

### 1. `run(ability_id, inputs, root=None, *, model=None, kind="run", keys=None, search_fn=None, client_factory=None, runner=None, path=None, codex_images=None) -> dict`

参数：

| 参数 | 意思 | 不传时 |
|---|---|---|
| `model` | 这一次改用哪个模型。**只能是卡片 `backup_models` 里的一个**，否则抛 `AbilityError` | 用卡片的 `model`；卡上没写（命令行工具）就用积木块自己的 |
| `kind` | `"run"`（用一次）或 `"trial"`（试做），写进记录的 `type`；别的值抛 `AbilityError` | `"run"` |
| `keys` | 钥匙串交来的密钥：`{钥匙串账号名: 密钥}`，和本机服务里的 `blocks_saved_keys` 同一个样子 | 当作空 |
| `search_fn` | 调联网搜索的函数，`search_fn(query, key, max_results, time_range)`，**按位置传这四个** | `blocks_web.search` |
| `client_factory` | 造大模型连接的函数，`client_factory(base_url, model, key)`，返回的东西有 `chat(messages)` | 照 `blocks_check._default_client` 的做法造 `ModelClient`（按服务商定要不要关思考），但**超时用 120 秒**（写长文要时间） |
| `runner` | 跑命令行工具的函数，`runner(args, folder, timeout) -> (退出码, 输出文字)` | `functools.partial(watched_runner, poll=0.5, quiet_limit=timeout + 5)`，照 `blocks_check.check_cli` |
| `path` | 找命令用的 PATH | `os.environ["PATH"]` |
| `codex_images` | Codex 自己存图的文件夹 | 环境变量 `CODEX_HOME` 下的 `generated_images`，没有就 `~/.codex/generated_images` |

**会直接抛 `AbilityError`、不写记录的情况**（这些是“没开始跑”）：卡片不存在或坏了；`prepare` 拒收了填的内容；`model` 不在备用模型里；`kind` 不对；**这张卡正在跑**（同一张卡同时只跑一次，原因里写“正在”；别的卡不受影响，照 `blocks_check._OneAtATime` 的做法，但用自己的一份登记，不要和积木块检测共用）。

**其余情况都要返回结果、写记录**。返回：

```python
{"run_id": …, "ok": bool, "status": "ok|format|model|block|error", "reason": 中文, "how": 中文,
 "model": 这次用的模型或 None（搜索没有模型）, "seconds": 数字, "output": 见下, "next_model": 备用模型或 None,
 "platform_said": 平台或工具的原话（打过码、截短）或 "", "files": [成果文件夹里的文件名]}
```

- `run_id` 用 `abilities.new_run_id()`。
- `output`：文字卡是完整文字；列表卡是 `[{"title","url","summary"}]`；图片、文件卡是成果文件名（`output_file`）；没拿到结果是 `None`。
- `next_model`：只在 `status == "model"` 时给。这次用的是主模型 → `backup_models[0]`；用的是 `backup_models[0]` → `backup_models[1]`（有的话）；再没有就 `None`。

### 2. 跑之前先查积木块

按这个顺序，查出问题就 `status="block"`，**不去跑**：

1. `blocks.load_card(卡片的 block)` 读不到 →“这张能力卡片用的积木块「…」已经移出基础层”，how 劝去基础层重新接上。
2. 积木块最后一条检测记录（`blocks.last_record(编号, root, type="check")`）的 `status` 不是 `ok`、`quota`、`listed` →“积木块「名字」上次检测没通过：<那条记录的 reason>”，how 里有“检测”二字，劝去基础层点它检测一次。没有检测记录就照常跑。
3. `abilities.fits_block(卡片, 积木块)`（不传名单）拒收 → 用它的中文原因。

然后查模型名单（只对大模型 API）：最后一条检测记录里有 `models` 且少于 400 个（400 个及以上算“可能没拿全”，不查），这次要用的模型不在名单里 → `status="model"`，原因写“<积木块名字> 的模型名单里没有 <模型>”，给 `next_model`，**不去调用**。

### 3. 三种跑法

**联网搜索**（`how.kind == "search"`）

- 密钥：`keys[积木块的 key_account]`，没有或是空的 → `block`，原因里有“密钥”。
- 调 `search_fn(query, key, max_results, time_range)`，参数来自 `abilities.prepare`。
- 结果每条 `{"title","url","snippet"}` 换成 `{"title","url","summary"}`。
- `blocks_web.SearchError` 的 `status` 是 401、403、429、432、433 → `block`（密钥不对或额度用完，都是积木块的事）；别的 `BlockError` → `error`。

**大模型 API**（`how.kind == "llm_api"`）

- 密钥：`keys[积木块的 key_account]`，没有 → `block`，**不去造连接**。
- `messages`：`system` 不为空时第一条是 `{"role":"system"}`，最后一条是 `{"role":"user","content": prompt}`。
- 拿回 `reply["text"]` 当结果。
- 出错（`ModelError`，看它的 `code`）：
  - 400、402、403、404、429 → `model`（403 按 11-11 定的口径算“这个模型没开通”，不算密钥坏了）；
  - 401 → `block`，how 里写积木块的名字，劝去基础层检测或换密钥；
  - 别的代码、没有代码（超时、断网）→ `error`。
  - `platform_said`：照 `blocks_check._words(exc, key)` 的做法取平台原话，先打码再截短。

**命令行工具**（`how.kind == "cli"`）

- 用 `blocks_env._which(积木块的 command, path)` 找程序，找不到 → `block`，原因里写出命令名（如“电脑上找不到 codex”）。
- 参数：`blocks.build_args(积木块, prompt, 这次的模型或 None)`，第一个换成找到的完整路径。**不改命令、不加参数、不经过 shell。**
- 新建临时文件夹（前缀 `能力运行-`），在里面跑，**跑完一定删掉**（用 `blocks_env.remove_folder`），超时、出错也删。
- 跑完先找 `output_file`：
  - 临时文件夹里有 → 拿它；
  - 没有，且卡片交回图片 → 去 `codex_images` 里找**这次开始运行之后**修改过的 `.png/.jpg/.jpeg`（包括子文件夹），取最新的一张拿来，`reason` 里写“Codex 把图存到了别处，已拿回来”；**运行开始前就在的图一律不拿**。
- 拿到文件就交给 `abilities.check_output` 去查（不管退出码）；没拿到文件：
  - 退出码不是 0：输出像没登录（照 `blocks_check._explain` 认“没登录”的那几个说法）→ `block`；`blocks_check.is_quota(输出)` 或输出说模型不存在 → `model`；其他 → `error`；
  - 退出码是 0 → `format`，原因“没有找到 <output_file>”。
- 超时（`subprocess.TimeoutExpired`）、看门人（`QuietTimeout`）→ `error`，原因里有“超时”或“没有动静”。
- `platform_said`：输出最后一行，先打码（`blocks_check._mask`，会去掉邮箱、像密钥的字）再截短到 160 字。

### 4. 成果和记录

- **成果文件夹**：`abilities.result_folder(编号, run_id, root)`，只在拿到结果时建。文字存 `结果.txt`（完整），列表存 `结果.json`，图片、文件按 `output_file` 的名字复制进来。`files` 列出里面的文件名。
- **记录**：每次（除了第 1 条说的“没开始跑”）都 `abilities.add_run`，字段：`type`（run/trial）、`run_id`、`ok`、`status`、`reason`、`model`、`seconds`、`inputs`、`output`、`platform_said`。
  - `inputs`：`prepare` 得到的 `values`，文字先打码（`blocks_check._mask`，连同这次用的密钥本身）再截到 500 字；
  - `output`：文字打码后截到 2000 字；列表、文件名原样（列表各字段也打码）；
  - 返回给调用方的 `reason`、`how`、`platform_said`、`output` 同样不能带这次用的密钥。
- **不写积木块的检测记录**，不改基础层。

### 5. `blocks_web.search(query, key, max_results=5, time_range=None)`

- `max_results` 允许 1–20 的整数（`True` 不算），别的抛 `BlockError`；发给 Tavily 的 `max_results` 就是它，返回最多这么多条。
- `time_range` 是 `None`、`"none"`、`"day"`、`"week"`、`"month"` 之一，别的抛 `BlockError`；是 `day/week/month` 时 payload 里带 `"time_range"`，`None` 或 `"none"` 时**不带这个字段**。
- 老的叫法 `search(query, key)` 行为完全不变（最多 5 条、不带时间范围），管家的联网搜索照旧。

### 6. 预置卡片“写文章”的交代

`prompt` 改成参考资料前空一行：`写一篇关于{topic}的文章，约{words}字。` 后面接两个换行再接 `{notes}`。66 号单的测试要照旧全过。（66 号单验收时发现：填了参考资料时，资料直接贴在“约 600 字。”后面，模型可能分不清要求和资料。）

### 第 2 轮补充（Codex 第 1 轮复查查出，Claude 核实后定，2026-11-11）

只改 `collab/abilities_run.py`。测试在 `tests/test_acceptance_67_ability_run.py` 末尾的 `Round2`。

1. **成果文件里不能有这次用的密钥。** 文字、列表先打码再查、再存、再返回（存的、返回的、记录的是同一份打过码的内容）。文件成果：复制前读一下，里面有这次用的密钥就不存，算 `error`，原因写“成果里带了密钥，没有保存”。
2. **不跟着文件链接走。** 临时文件夹里的成果、Codex 图片文件夹里的图，是链接（symlink）的一律不拿；解析后的真实位置必须还在那个文件夹里。
3. **运行前就在的图一律不拿，按“有没有这个文件”判断，不只看修改时间。** 开跑前记下 Codex 图片文件夹里已有的图（路径），跑完只在新出现的图里取最新一张。
4. **不传 `client_factory` 时要能真建出大模型客户端。** 服务商查法用 `collab.providers.find`（`collab.blocks` 里没有 `find_provider`，现在每次都失败）；`timeout=120`，`thinking_off` 照服务商设置。
5. **命令行工具交回文字时读文件正文。** 文字卡：读 `output_file` 的内容（UTF-8）去查、返回完整文字、存成 `结果.txt`。
6. **拿到结果就存，不管合不合格。** 这是第 4 节“只在拿到结果时建”的本意：格式不对（`format`）也照存，用户花了额度，自己看要不要。什么都没拿到（空列表、没有文件、出错）才不建文件夹。
7. **存成果失败不往外抛。** 结果处理、查结果、存成果都包在统一的收尾里：出错算 `error`，原因是中文，照常写记录、放开“正在跑”，之后能再跑。

### 第 3 轮补充（Codex 第 2 轮复查查出，Claude 核实后定，2026-11-11；最后一轮）

病根是一个：**安全检查自己出错时被当成“没问题”放行**（`except Exception: pass`），处理过程也没有统一兜底。只改 `collab/abilities_run.py`，测试在末尾 `Round3`。

1. **安全检查出错按“不安全”处理。** 文件成果查密钥时读不了（任何错误）→ 不复制，返回 `error`，原因中文（如“没法检查成果里有没有密钥，没有保存”）。建议按块读，不要整份读进内存。
2. **运行前的图片清单记不全，就不去 Codex 图片文件夹拿图。** 记清单出错 → 这次只认临时文件夹里的成果；临时文件夹里没有就按“没有找到”处理，`reason` 里说明没去图片文件夹找的原因。
3. **开跑之后的处理统一兜底。** 从拿到结果起，读文件、打码、查结果、存成果，任何一步抛错都返回 `error`（中文原因）、照常写记录、放开“正在跑”。查结果正常说“不合格”的仍是 `format`。命令行文字卡读文件出错也是 `error`，不是 `format`。不要在每一步各写一份 try，用一个外层兜底。
4. **空文字不算拿到结果。** 大模型或命令行交回的文字去掉空白后是空的 → `format`，不建成果文件夹，`files` 为空。
5. **全文件不准有“吞掉异常什么都不做”的写法**，除非吞掉的方向是更保守的（比如某张候选图读不了就跳过它）。
