# 施工单 68：能力层页面

依据：[能力层/方案.md](../能力层/方案.md) 第一节“你会看到什么”1–3、技术设计“本机服务”；66、67 号单做好的 `collab/abilities.py`、`collab/abilities_run.py`。

## 这张单做什么（产品话）

积木库窗口左栏“基础层”下面多一组“能力层”，列出三张预置能力卡片（搜资料、写文章、出图）。点一张进详情：看它干什么、用哪个积木块和模型、要填什么、交回什么、怎么算干成了；填好点“开始”真跑一次，结果显示在下面（文字能复制、列表带链接、图片直接显示，旁边“在访达里打开”）；模型不通时问“要换成备用模型再试一次吗？”，点了才换；下面列最近几次；可以换主模型、备用模型；可以移出能力层。

**不在这张单：** 统一叫法改名（拆到下一张 68b）；管家起草能力卡片（69）。

**做完停下给用户测**（方案第七节）：真实窗口里三张卡各用一次，故意填一个不通的模型看提问。

## 1. 本机服务 `/api/abilities/*`

- 口令、出错的写法和 `/api/blocks/*` 完全一样：GET 带 `token`，POST 带 `X-Chat-Token`，没口令 403；`AbilityError`（它是 `BlockError` 的子类）回 409，除非下面另写；读写资料夹出错回 500 “积木库资料夹读写出错，请检查磁盘和权限”。在 `do_GET`、`do_POST` 里照 `/api/blocks/` 的样子加一个分支，**不改原有分支**。
- 资料夹一律用 `self._blocks_home()`，页面传的路径不认。
- 每个接口开头调一次 `abilities.ensure_builtin(home)`（第一次打开时写进三张预置卡片，已经有就什么都不做）。
- 编号先用 `blocks._ID.fullmatch` 查，不对回 400 “编号不对”；卡不在回 404 “能力层里没有这张能力卡片”。

### GET `/api/abilities/list`

```json
{"abilities": [{"id", "title", "description", "block", "block_name", "model", "kind", "output_type",
                "status", "status_reason", "last_time"}],
 "broken": [{"id", "problem"}]}
```

- 按 `abilities.list_abilities(home)` 的顺序；坏卡片进 `broken`。
- `block_name`：积木块的 `name`；积木块不在基础层时用编号。
- `model`：卡上的 `model`；命令行卡片卡上没写时用积木块的 `model`；搜索卡片是 `null`。
- `kind`：`how.kind`（search / llm_api / cli）。`output_type`：`output.type`。
- `status` 三种，按顺序判：
  1. `"unusable"`（不能用）：积木块不在基础层（`status_reason` “用的积木块「<编号>」已经移出基础层”）；或积木块最后一次检测（`blocks.last_record(积木块, home, type="check")`）没通过，且状态不是 `quota`、`listed`（“积木块「<名字>」上次检测没通过”）；或 `abilities.fits_block` 报错（原因用它的话）。
  2. `"failed"`（上次没成）：最近一条运行记录（`abilities.runs(id, home, limit=1)`）`ok` 是假，`status_reason` 是那条的 `reason`。
  3. `"ok"`（能用）：其他，包括还没用过。`status_reason` 为空。
- `last_time`：最近一条运行记录的 `time`，没有为空。

### GET `/api/abilities/detail?id=`

```json
{"ability": 卡片原样, "block": {"id", "name", "exists", "kind"}, "status", "status_reason",
 "models": [积木块最后一次检测拿到的模型名单], "example": 试做示例那条记录或 null,
 "runs": [最近 10 条记录，新的在前], "running": true/false, "job": "正在跑的任务编号" 或 ""}
```

- `status`、`status_reason` 和列表里同一套算法（写成一个函数两处用）。
- `models`：只有大模型 API 的积木块才有，取 `blocks.last_record(积木块, home, type="check")` 的 `models`；没有就 `[]`。
- `example`：卡上 `example_run` 不为空时，在记录里找 `run_id` 相同的那条；找不到为 `null`。
- `running`：`abilities_run.is_running(id)`。`job`：这张卡上次开的任务还没做完就给编号（存在 `server.abilities_jobs` 里：卡片编号 → 任务编号），页面重新打开详情时接着跟。

### POST `/api/abilities/run`

请求 `{"id", "inputs": {...}, "model": 可选，备用模型名}`。

- 先在请求里同步查，不开任务、不写记录：卡在不在；`model` 给了但不在卡的 `backup_models` 里 → 400 “这个模型不是这张卡的备用模型”；`abilities.prepare(card, inputs)` 报错 → 400，原话（中文）给页面；`is_running(id)` 为真 → 409 “这张能力卡片正在用，等这次跑完”。
- 都过了开后台任务：`self._blocks_job("ability", work)`，返回 `{"job": 编号}`，并记进 `server.abilities_jobs[id]`。页面用现有的 `/api/blocks/job` 轮询，任务做完 `result` 就是 `abilities_run.run` 的返回原样。
- `work` 里调：
  ```python
  abilities_run.run(id, inputs, home, model=model, kind="run",
                    keys=dict(self.server.blocks_saved_keys),
                    search_fn=self.server.abilities_search_fn,
                    client_factory=self.server.blocks_client_factory,
                    runner=self.server.abilities_runner,
                    path=os.environ.get("PATH", ""),        # 先调 self._blocks_path()，和检测用同一份路径
                    codex_images=self.server.abilities_codex_images)
  ```
  `make_server` 里加三个默认 `None` 的属性：`abilities_search_fn`、`abilities_runner`、`abilities_codex_images`（测试和走查时换成假的），再加 `abilities_jobs = {}`、`blocks_open = None`（见“在访达里打开”）。
- 密钥只用 Mac 窗口交来的 `blocks_saved_keys`，**页面不能带密钥**（请求里带了 `api_key` 之类也不理）。没有存的密钥，`run` 自己会判成“积木块的问题”，告诉用户去基础层填。
- 任务里 `run` 抛 `AbilityError`（比如两次几乎同时点，第二次被挡住），`_blocks_job` 会把原话放进 `error`，页面照样显示。

### POST `/api/abilities/model`

请求 `{"id", "model", "backup_models": [...]}`，改主模型和备用模型，只能从名单里选。

- 只有 `how.kind` 是 `llm_api` 的卡能改，别的 400 “这张卡这一版不能换模型”。
- 名单是 detail 里那份 `models`；名单是空的 → 409 “还没有模型名单：先去基础层检测「<积木块名字>」”。
- `model` 必须在名单里；`backup_models` 是列表、最多 2 个、不重复、不含主模型、每个都在名单里；不合格 400，原因写清楚是哪一个。
- 合格就把卡片的 `model`、`backup_models` 换掉，别的字段原样，用 `abilities.save_ability` 存（它会再校验一次）。返回 `{"ok": true, "ability": 存好的卡片}`。
- 正在跑也可以改：这次运行已经读过卡片，不受影响。

### POST `/api/abilities/remove`

请求 `{"id"}`。正在跑 → 409 “这张能力卡片正在用，等这次跑完再移出”。否则 `abilities.remove_ability`，记录和成果留着，返回 `{"ok": true}`。

### GET `/api/abilities/file?id=&run=&name=`

把成果文件交给页面显示（图片的 `<img src>`、点开文字）。

- `run` 用 `abilities.result_folder(id, run, home)` 算文件夹（它会查运行编号的格式，不对回 400）。卡片已经移出能力层也能看（记录和成果还在）。
- `name`：只能是普通文件名（不能有 `/`、`\`、不能以 `.` 开头、最长 100 字），不对 400。
- 文件必须在这个文件夹里、是普通文件、**不是文件链接**，解析后的真实位置还在这个文件夹里；不满足一律 404 “没有这个成果文件”。
- 内容类型按扩展名：`.png` image/png，`.jpg`/`.jpeg` image/jpeg，`.txt` text/plain; charset=utf-8，`.json` application/json; charset=utf-8，其他 application/octet-stream。用现有的 `self._send`。

### POST `/api/abilities/reveal`

请求 `{"id", "run"}`，在访达里打开这次的成果文件夹。

- 页面**只给编号**，文件夹由程序用 `result_folder` 算；文件夹不存在 404 “这次没有成果文件夹”。
- 打开用 `self.server.blocks_open(文件夹路径字符串)`；它是 `None` 时用 `subprocess.run(["/usr/bin/open", 路径], check=False, timeout=10)`。返回 `{"ok": true}`。
- （和方案技术设计的差别：方案写“交给 Mac 窗口外壳打开”，这里改成本机服务直接调系统的 `open`。网页仍然拿不到任意路径，路径只由程序从编号算出来；好处是不用改 Mac 窗口外壳、不用重装。）

## 2. 规则层 `AbilitiesCore`（`abilities.js` 上半）

不碰页面、不发请求，node 直接检查。全部函数挂在 `AbilitiesCore` 上：

| 函数 | 做什么 |
|---|---|
| `esc(s)` | 和 `BlocksCore.esc` 一样转义 HTML。 |
| `statusView(item)` | 列表、详情顶上的状态：`ok` → `{cls: "ok", text: "能用"}`；`failed` → `{cls: "warn", text: "上次没成"}`；`unusable` → `{cls: "idle", text: "不能用"}`。 |
| `subText(item)` | 左栏小字：`block_name`，有 `model` 时加“ · <model>”，比如“阿里百炼 · qwen3.7-plus”“Tavily”。 |
| `outputText(type)` | text/list/image/file → 文字/列表/图片/文件。 |
| `checkText(output, inputSchema, kind)` | “怎么算干成了”的大白话（见下表）；`kind` 是卡片的 `how.kind`。 |
| `formFields(inputSchema)` | “你要填什么”的表单项，按 `properties` 的顺序：`{name, title, kind, options, value, placeholder, required, min, max, maxLength}`。`kind`：有 `enum` → `"select"`（`options` 就是 `enum`）；integer → `"number"`；string 且 `maxLength > 200` → `"textarea"`；其他 `"text"`。`value`：有 `default` 用它，没有空字符串。`placeholder`：有 `examples` 写“例如：<第一个例子>”，没有空。 |
| `collectInputs(fields, raw)` | 把页面填的（`raw`：项名 → 字符串）变成请求里的 `inputs`：去掉前后空白；空的可选项不放进去；必填项空着 → `{ok: false, error: "请填写「<title>」"}`；数字项不是整数或超出 `min`–`max` → “「<title>」要填 <min> 到 <max> 的整数”；文字超过 `maxLength` → “「<title>」最多 <maxLength> 个字”；都对 → `{ok: true, inputs}`（数字项是数字，不是字符串）。 |
| `resultView(result, card)` | 一次运行的结果怎么显示（见下表）。 |
| `runsView(records)` | 最近几次：按给的顺序，每条 `{time, ok, text, model, reason}`。`time` 从 `"2026-11-11T17:40:05"` 变成 `"11-11 17:40"`；`text` 成了是“成了”、没成是“没成”；`model` 没有为空；`reason` 成了为空。 |
| `promptText(card)` | “交代原文”：`llm_api` → `system` 和 `prompt` 两段，中间空一行，前面各加“系统：”“要求：”；`cli` → `prompt`；`search` → 空字符串（不是 AI 型，不显示这一块）。 |
| `removeConfirm(card)` | “把「<title>」移出能力层？记录和成果都留着。” |
| `canChangeModel(card)` | `how.kind` 是 `llm_api` 才是 `true`。 |

`checkText` 的说法：

| 情况 | 说法 |
|---|---|
| text，`min_chars`、`max_chars` 都有 | “有内容，字数在 X 到 Y 之间” |
| text，只有 `min_chars` / 只有 `max_chars` | “有内容，不少于 X 字” / “有内容，不超过 Y 字” |
| text，`min_ratio`、`max_ratio`、`of` | “有内容，字数在你填的「<of 那项的 title>」的<下限>到<上限>之间”；倍数 0.5 说“一半”，1 说“一样多”，2 说“两倍”，3 说“三倍”，其他说“<数> 倍” |
| text，没有字数限制 | “有内容” |
| list | “至少 N 条，每条都有标题”（N 是 `min_items`，没写为 1）；`kind` 是 search 时后面加“和链接”。 |
| image | “存出了图片，是 PNG 或 JPG，宽高都不小于 N”（N 是 `min_side`，没写 256） |
| file | “存出了文件，不是空的，扩展名是 <extensions 用“、”连起来> 之一” |

`resultView(result, card)` 返回 `{tone, head, said, tip, ask, body}`：

| `result.status` | `tone` | `head` | 其他 |
|---|---|---|---|
| ok | `"ok"` | 有 `model`：“用了 <model> · <秒>”；没有：“用时 <秒>” | `body` 见下 |
| format | `"bad"` | “没成：<reason>” | 拿到了成果（`files` 不空）照样给 `body`，让用户自己看 |
| model | `"warn"` | “模型不通：<reason>” | `said`：`platform_said`（空就空）；有 `next_model` → `ask: {model, text: "要换成 <next_model> 再试一次吗？"}`；没有：大模型卡 `tip` “可以在上面的模型下拉框换一个再试。”，其他卡 `tip` “这张卡没有备用模型。” |
| block | `"bad"` | “积木块的问题：<reason>” | `tip`：`how`；不给重试 |
| error | `"bad"` | “没成：<reason>” | `tip`：`how` |

- 秒数：四舍五入到整数，“12 秒”；不到 1 秒写“不到 1 秒”。
- `body`：`{type, text}`（文字，完整）/ `{type: "list", items: [{title, url, summary}]}` / `{type: "image", name}`（文件名，页面拼 `/api/abilities/file` 地址）/ `{type: "file", name}`。`output` 是空的（`null`）时 `body` 为 `null`。
- 没有的字段一律给空字符串或 `null`，不要 `undefined`。

## 3. 页面

### 左栏

- “基础层”那一组下面加一组，标题“能力层”，列表容器 `id="abilitiesList"`。
- 每张一行：名字（`title`）、小字（`subText`）、状态点和状态字（`statusView`）。坏卡片一行：编号 + “这张能力卡片坏了”，点开只显示原因。
- 一张都没有时写“还没有能力卡片”。
- 列表和基础层一起刷新（基础层每次重新取列表时，能力层也取一次 `/api/abilities/list`）。

### 切换（`blocks.js` 只加这两处）

- `blocks.js` 里加 `window.BlocksStage = { closeBlock: function () {...} }`：作用是把基础层详情关掉、取消左栏基础层的高亮、作废路上的检测请求（就是现在 `backToChat` 前半做的事，但**不**把聊天显示出来）。能力层打开一张卡时调它。
- `blocks.js` 打开基础层详情（`openDetail`、`openBrokenDetail`）和回到聊天（`backToChat`）时，调一次 `window.AbilitiesPage && window.AbilitiesPage.close()`，把能力卡片详情关掉、取消能力层的高亮。
- 同一时间中间只显示一样：聊天、基础层详情、能力卡片详情三选一。

### 能力卡片详情（`id="abilityDetail"`，一开始 `hidden`）

从上到下：

1. “← 返回聊天”（`id="abilityBack"`）、标题（`id="abilityTitle"`）、状态（`id="abilityStatus"`，`statusView` + 原因）。
2. 一句话说明（`description`）。
3. 一组行（照基础层详情 `.detail-row` 的样子）：
   - “用哪个积木块”：积木块名字；积木块不在基础层时写“（已经移出基础层）”。
   - “用哪个模型”：大模型卡片是下拉框（`id="abilityModel"`，选项是 `models`；名单是空的就只显示当前模型，旁边小字“先去基础层检测「<积木块名字>」，拿到模型名单后才能换”）；“备用模型”两个下拉框（`id="abilityBackup1"`、`id="abilityBackup2"`，多一个“不用”的空选项）；下面一个“保存模型”按钮（`id="abilitySaveModel"`），点了发 `/api/abilities/model`，成了提示“已保存”，失败显示原因。命令行卡片只显示模型名字和小字“这一版不能换”；搜索卡片这一行不显示。
   - “交回什么”：`outputText`。
   - “怎么算干成了”：`checkText`。
4. “试做示例”：有 `example` 就显示那次填的内容和结果（用 `resultView`），没有写“还没有试做示例”。
5. “用一次”（`id="abilityForm"`）：按 `formFields` 一项一行（标题 + 输入框，必填项标题后加“*”），下面“开始”按钮（`id="abilityRun"`）。点了先 `collectInputs`，不对就在按钮旁显示原因、不发请求。发出后按钮变“正在用…”并禁用，轮询 `/api/blocks/job`（1.5 秒一次，照基础层）；做完恢复。详情重新打开时 `running` 为真、有 `job` 就接着跟，按钮照样是“正在用…”。
6. 结果（`id="abilityResult"`）：按 `resultView` 显示。
   - 文字：整段显示（保留换行），旁边“复制”按钮（`navigator.clipboard.writeText`，失败提示“没复制成，请手动选中复制”）。
   - 列表：一条一条，标题是链接（`target="_blank" rel="noopener"`），下面摘要。
   - 图片：`<img>`，地址 `/api/abilities/file?token=…&id=…&run=…&name=…`（用 `URLSearchParams` 拼）。
   - 有成果文件夹（`files` 不空）时多一个“在访达里打开”按钮，发 `/api/abilities/reveal`。
   - 模型不通且有 `ask`：显示问题和两个按钮“换这个试”（`id="abilityTryBackup"`）、“先不试”。点“换这个试”用**同样的输入**再发一次 `/api/abilities/run`，带上 `model`；点“先不试”把问题收起。**不自动换。**
7. “最近几次”（`id="abilityRuns"`）：`runsView` 一行一条，没有写“还没用过”。每次运行做完重新取一次详情。
8. “交代原文”（`<details id="abilityPrompt">`，`<summary>交代原文</summary>`，默认折叠）：`promptText` 不为空才显示。
9. “移出能力层”按钮（`id="abilityRemove"`）：先 `window.confirm(AbilitiesCore.removeConfirm(card))`，确认了才发 `/api/abilities/remove`，成了回到聊天、刷新列表。

### 页面纪律（照基础层）

- 页面里**没有任何密钥输入框**，请求里不带密钥。
- 不用 `localStorage`、`sessionStorage`、`indexedDB`、`document.cookie`；不 `console.log`。
- 用户填的内容、模型名、平台原话、结果文字一律经 `esc` 或 `textContent` 放进页面，不直接拼进 HTML。
- 换卡、离开详情：路上还没回来的请求回来后一律不管（照基础层 `checkGen` 的做法），免得旧卡的结果画到新卡上。
