# 施工单 68c：命令行工具按整家接

依据：试跑记录 ⑤（用户 2026-11-11 提出，11-12 定口径和做法）；[能力层/方案.md](../能力层/方案.md) 第一节第 2、3 点（大模型 API 的做法，这单照搬到命令行工具）。

## 这张单做什么（产品话）

积木库里的命令行工具（Codex、Cursor、agy）现在只认一个写死的模型：agy 的默认模型 Gemini 4 Argon 没额度，整个 agy 就被标成“额度不足”，其实它的 Gemini 3.8 Flash 能用。改成和大模型 API 一样“按整家接”：

1. **基础层点开 Codex / Cursor / agy**：显示“这家的模型 N 个”和完整名单（问工具自己要，不花额度）。每个模型前一个点：绿“能用”、黄“额度不足”、红“不能用”、灰“没试过”，后面写上次试的时间和一句原因；每个模型后面一个按钮“试这个模型”。
2. **点积木块的“检测”**：先拿名单，再只试卡上写的默认模型（用户 2026-11-12 定：只试一个，别的点了才试）。
3. **一个模型没额度，只标这个模型**，整家照样算接上（黄“已接上”），不再整家标“额度不足”。只要有一个模型试过能用，整家就是绿“能用”。
4. **能力层里用命令行工具的能力卡片**：主模型、备用模型都从这家的名单里选（和 API 卡片一样的下拉框，选项里带状态），不再写“这一版不能换”。

**不在这张单：** 团队设置（项目窗口里那页，已经能每个岗位选模型）；管家起草的命令行工具（不是 Codex、Cursor、agy 这三个预置的）照旧只认卡上的模型；管家提取能力卡片（69）。

## 1. 拿模型名单（`blocks_check.py`）

只对预置的三个（卡的 `id` 是 `codex` / `cursor` / `agy`，且 `command` 和预置一样）：

| 工具 | 怎么拿 | 输出长什么样 |
|---|---|---|
| agy | 跑 `agy models` | 第一行 `Fetching available models...`，之后每行 `模型名<TAB>显示名` |
| Cursor | 跑 `agent models` | 第一行 `Available models`、空行，之后每行 `模型名 - 显示名`，有一行带 `(current, default)` 之类的后缀 |
| Codex | 不跑命令，读 `~/.codex/models_cache.json`：`models` 里 `visibility == "list"` 的 `slug`（和 `collab/config.py` 的 `load_model_options` 读法一样，能复用就复用） | |

- 只要模型名（`_MODEL` 规则能过的），去重、保持原顺序。
- 跑命令：stdin 关掉，60 秒超时，在临时文件夹里跑，用和检测一样的程序路径查找。拿不到（没装、超时、退出码不为 0、一个名字都没认出来）就退回 `collab/config.py` 里 `MODEL_OPTIONS` 的内置名单，并在结果里标 `models_from: "builtin"`（页面写“名单是内置的，可能不全”）；拿到了标 `models_from: "tool"`。
- 管家起草的命令行工具、普通工具（`role == "tool"`）：不拿名单，行为和现在完全一样。

## 2. 检测、单个模型试用、状态（`blocks_check.py`、`blocks.py`）

- **检测（不带 model）**：预置三个之一时，先拿名单，再按现在的办法试卡上的 `model`。结果照现在写进 `type: "check"` 记录，另外多带 `models`（名单）、`models_from`、`model`（试的是哪个）。
  - 试的模型通了：`ok: true`，`reason` 写“通了 · N 秒，这家有 M 个模型”。
  - 试的模型没通时，**只有两种情况**算 `ok: false, status: "listed"`：① 只是额度不足；② 名单是工具自己报出来的（agy、Cursor 跑 `models` 成功）且失败是这个模型的问题。工具跑不起来、命令找不到、跑完没建出文件、名单来自内置或 Codex 缓存时，一律照旧 `fail`，原因照旧写、不加“已接上”前缀（2026-11-12 Claude 改严：原先写“不管来自工具还是内置”，导致工具坏了也显示已接上）。
  - 原写法（作废）：试的模型额度不足或不通，但工具装好了、拿到了名单（不管来自工具还是内置）：`ok: false, status: "listed"`，`reason` 写“已接上：这家有 M 个模型。默认的 X 额度不足（或：没通，原因……）”，`how` 写“可以在下面的名单里试试别的模型”。
  - 没装、没登录：和现在一样（`missing` / `fail`），不拿名单也行。
- **单个模型试用（带 model）**：`model` 必须在这块最近一次检测的名单里，否则报错不跑。照检测的办法跑一次小活（只把 `{model}` 换成这个），结果写一条 `type: "model_check"` 记录：`{model, ok, status(ok/quota/fail), reason, how, seconds, time}`。**不写 `check` 记录**（不改整块最近一次检测）。同一块同时只跑一个（检测和试用共用现在的“一次一个”）。
- **`blocks.model_status(card_id)`**：返回 `{模型名: {status, reason, time}}`，取每个模型最新的一条，来源是 `model_check` 记录和 `check` 记录里试的那个 `model`，谁新用谁。
- **整块的状态**（基础层列表的点、能力层“积木块能不能用”的判断）：最近一次 `check` 是 `ok`，或者它之后有任何一条 `model_check` 是 `ok` → “能用”；否则照现在的规矩（`listed`、`quota` 算接上，其余不通）。

## 3. 本机服务（`desktop/server.py`）

- `POST /api/blocks/check`：多收一个可选的 `model`。带了且是预置三个之一 → 单个模型试用；不在名单里回 400“这个模型不在这家的名单里，先检测一次拿名单”。不带 → 照旧。没核实过的卡带 `model` 回 400。异步、轮询的方式和现在的检测一样。
- `GET /api/blocks/detail`、`GET /api/blocks/list`：命令行工具也带上名单和 `model_status`（API 积木块已有的字段名照用，加 `model_status`、`models_from`）；列表里的 `models` 个数对命令行工具也算。
- 能力层：
  - 能力卡片详情：现在只有 `llm_api` 才给 `models`，改成预置的命令行工具也给，并带 `model_status`。
  - `POST /api/abilities/model`：现在只许 `llm_api`，改成预置的命令行工具也许，校验规矩一样（主模型、备用模型都要在名单里，备用最多 2 个、不重复、不含主模型）。

## 4. 页面

- **基础层详情（`blocks.js`）**：命令行工具在现有几行（版本、登录、来源）下面加：
  - “这家的模型”：`M 个`；名单来自内置时加“（内置名单，可能不全）”；还没检测过写“点一次‘检测’后显示名单”。
  - 名单：一行一个模型，前面状态点（用现有 `.dot` 的颜色：能用 ok、额度不足 warn、不能用 bad、没试过 idle），模型名，上次时间和一句原因，最后“试这个模型”按钮。正在试时这一行显示“正在试…”，同一块别的按钮和“检测”按钮都不能点；试完刷新这一行和整块状态。
  - 整块状态那一行照第 2 节；`listed` 的说法照 API 积木块现在的写法。
- **能力卡片详情（`abilities.js`）**：命令行工具的卡片删掉“这一版不能换”，和 API 卡片用同一套主模型、备用模型下拉框；选项文字后面带状态（例：“gemini-3.8-flash-high · 能用”“gemini-4-argon-high · 额度不足”“… · 没试过”）。还没名单时写“先去基础层检测「agy」拿模型名单”。
- 样式沿用现有颜色、字号、`.dot`、`.detail-row`，不改现有样式。

## 验收

- 新测试 `tests/test_acceptance_68c_cli_models.py`，**不许跑真的 agy、Cursor、Codex**（用假的程序或替换掉执行函数），至少覆盖：

  5. 管家起草的命令行工具、普通工具行为不变（不拿名单）。
