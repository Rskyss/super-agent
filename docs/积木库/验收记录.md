- **走查发现并已修的问题**
  - 行政（deepseek-flash）说“提议卡已经弹出来了”却没调用出卡工具，用户看不到卡（7 次里 3 次）。改为：积木库里，行政这样说、这一轮却没真出卡、对话里也没有还在等确认的卡，程序提醒它一次，让它真出卡或如实说没出。改后在真实窗口里要了 6 次卡，都出来了；其中一次行政又说了“卡都摆着”其实没出，程序提醒后它承认并补出了卡。次数少，不算根治。上面有没点的卡时，提醒会点名那张，让它照实说或真出新卡。
  - 出卡后告诉行政：这张会替换基础层里的哪一块；同一段对话里上面没点的哪张卡因此失效了（原有规矩：一段对话一次只留一张没处理的卡；行政之前不知道，跟用户说“两张都能点”）。
  - 行政说法：腾讯云要的是一把 API 密钥，不是 SecretId/SecretKey；已登录的工具不用再登录，查不了登录的先接；编号相同才替换。
  - 积木库聊天框、对话区给读屏软件的名字由“调度员”改成“行政”。
  - 方案里“绑定后行政先打招呼”改成不主动打招呼。

- **已声明的边界**
  - agy 现在是“额度不足”（Argon 那档周额度用完）；要它真干活，等能力层能选模型（比如换 Gemini Flash），或等额度恢复。
  - 行政用的 deepseek-flash 会照前几轮的话套说法：走查里说错过 agy 版本（说成 1.0.0，实际 1.5.3），还说“会替换基础层里的 agy”（其实没有）。卡片上显示的是对的。要不要换更强的模型当行政，留给用户定。
  - 接进来后看它有哪些模型（类似 `/models`）：用户 2026-11-09 提出，定为能力层第一项。
  - “额度不足也算接上”只认很明确的说法（余额不足、额度超了、被限流）；参数写错、权限不够、磁盘配额满这类真故障不算，照旧进不了基础层。大模型 API 只在服务商返回 402、429 时判额度不足；有的平台模型名错、密钥无效也可能先回 429，这时“能连上”的说法不一定准，没验证过。
  - “写代码流程不受影响”是用命令行跑的，没在项目窗口里点。
  - 行政假称出卡的兜底只在积木库里；项目窗口的行政没加（那边卡片对话里会把同一条修改记两遍），也没走查。
