## 二、口径和能力层是什么

**口径（用户 2026-11-10 定）：** 基础层里的每一样叫**积木块**（如 Codex、火山引擎、Tavily），能力层里的每一样叫**能力卡片**。这一版要做的，就是从基础层的积木块里提取出可用的能力卡片。

一张能力卡片是某个积木块的**一种固定用法**。一个积木块可以提取出很多张能力卡片，比如火山引擎提取出“写文章”“出图”，Codex 提取出“写代码”“出图”。

能力卡片由积木库管家起草，程序真跑一次试做，你看过结果点头，才放进能力层。做法沿用基础层“出提议 → 检测 → 放进来”。

能力卡片是第 4 步业务流程的材料。这一版只做能力卡片，不做拼流程。

**统一叫法（用户 2026-11-10 定）：** 以后只有两样东西叫“卡片”：积木库里的**能力卡片**，项目窗口里的**任务卡片**（以后串流程、跑任务都靠它们）。其他原来叫“卡”的一律改名：

| 原来叫 | 是什么 | 改成 |
|---|---|---|
| 安装卡、接入卡、提议卡 | 管家在聊天里提出、等你点确认的那个框 | **提议**（安装提议、接入提议） |
| 接法卡 | 一个积木块怎么启动、怎么交代任务、怎么算干完 | **接法说明**（“接法卡全文”→“接法说明全文”，“这张接法卡坏了”→“接法说明有问题”） |
| 体检卡 | 设置页里的环境体检结果 | **体检结果** |
| 管家说的“出卡” | 管家拿出一个提议 | **出提议** |
| 提取时聊天里出的那张 | 还没试做通过的能力卡片 | **能力卡片（草稿）** |
| “那一块”“一家平台一块” | 基础层里的一样 | **积木块** |
| 项目窗口的“需求卡” | 项目窗口里一件要做的事 | **任务卡片**（用户选 1A） |

改的范围：用户看得见的字（积木库窗口、项目窗口的页面）、管家和行政说话时的叫法（规矩和手册）、README 和产品文档。程序内部的名字不强求改。什么时候改：放进能力层第一张施工单一起改（用户选 2A）。

## 三、一张能力卡片写什么

| 项目 | 例子（“豆包写文章”） |
|---|---|
| 用哪个积木块 | 火山引擎（基础层里已接好的） |
| 用哪个模型 | 豆包 Seed 2.1 Pro；可以再写一两个备用模型 |
| 你要填什么 | 主题、大概字数 |
| 交回什么 | 一篇文字 |
| 怎么算干成了 | 程序查：有内容、字数大致对 |

- **交回什么**只能从几种里选：文字、列表、图片、文件。现在定下，第 4 步拼流程时程序才知道哪张卡能接哪张卡。具体几种在《方案》里定。
- **用哪个模型**接住了基础层留给能力层的事：看这个积木块有哪些模型、选哪个模型干活（见 [../需求共识.md](../需求共识.md)“不做”一节）。
- 能力分两种，用同一套卡片格式，只有“怎么执行”那一栏不同：
  - **工具型**（如 Tavily 搜索）：你填什么，程序就照着跑，结果格式固定。
  - **AI 型**（如 Codex、大模型 API）：固定的交代方式 + 指定模型 + 交回格式，结果每次会有差别。

## 四、你会看到什么

1. 在基础层点一个积木块，进入一段新对话。
2. 管家先说这个积木块能提取出哪几张能力卡片（依据它的帮助说明和模型名单）；做不到的直说。
3. 你挑一件，聊天里出一张能力卡片（草稿）。
4. 你填一个试做的例子，程序真跑一次，结果显示在卡片下面。
5. 程序先查格式；格式对了，你看一眼结果，满意就点“放进能力层”。不通过，管家照失败原因改卡，连续 3 次不行就停下，说明卡在哪。
6. 左栏多出“能力层”，列出每张能力卡片：用哪个积木块、哪个模型、能不能用、上次试做时间。
7. 点一张卡看详情，有“用一次”：填内容就跑，结果显示出来。

## 六、第一批三张卡

| 能力卡片 | 用哪个积木块 | 交回 | 说明 |
|---|---|---|---|

## 七、风险（先说在前面）

- 每张卡试做、每次“用一次”都花真实额度。
- AI 型的卡这次过了，下次可能格式不对，所以每次运行程序都检查结果，不只信试做那一次。
- 有些能力只能在 AI 助手的对话界面里用，后台单独调用不了。碰到就直说做不了。
- 管家用的是便宜模型，起草 AI 型的卡（写交代方式）质量可能一般。第二张单先试，不行再定。
- 工作量估计 5 到 7 张施工单，和基础层差不多。

## 八、这一版不做

- 拼业务流程、画布（第 4 步）
- 接进项目窗口（只改项目窗口里“需求卡”的叫法，见第二节）
- 花费统计（第 5 步）
- 定时自动检查：卡坏了是在你用的时候发现，并告诉你是哪张卡
- 模型不通时自动换
- AI 给结果打分
- Claude 订阅

## 九、怎么算验收通过

在真实积木库窗口：

1. 第一批三张卡都在能力层里，各自“用一次”成功：搜资料拿到列表，写文章拿到文字，出图拿到一张能打开的图。
2. 让卡上的模型不通（比如填一个没开通的模型），程序停下来，说清原因，问要不要换备用模型；点换才换。
3. 在基础层点一个积木块进新对话，管家能列出它能提取的能力卡片，照固定格式起草一张新的，试做后能放进能力层（第二张单）。
4. 积木库窗口和项目窗口里看得见的叫法按第二节“统一叫法”表改好：只剩“能力卡片”“任务卡片”带“卡”字；管家和行政说话也照这套叫法。
5. 基础层原有的接入、检测照旧能用，不比现在差。
