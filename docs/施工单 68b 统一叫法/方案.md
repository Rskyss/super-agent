# 拆解方案

## 要做什么（一句话）
按 68b 施工单统一页面和管家、调度员规矩里的叫法，并让“说了出提议却没出”的检查兼容新旧说法。

## 拆成几步，每步做什么、产出什么
1. 先读 68b 施工单和施工单 README 的最新执行约定，核对工作分支及已有改动，再运行现成的 68b 验收测试，记下实际失败项。
2. 测试员沿用已提交的验收测试，只把确实缺少的行为检查补进 tests/test_acceptance_68b_extra.py，不重复已有检查。
3. 按施工单逐句改顺文字，将安装卡、接入卡、提议卡改叫提议，接法卡改叫接法说明，体检卡改叫体检结果，出卡改叫出提议，基础层里的那一块改叫积木块，项目窗口的需求卡改叫任务卡片。
4. 修改 blocks.html、blocks.js 和 chat.js 的可见文字，让详情标题、两处问题提示、换密钥提示和生成任务后的提示都使用新叫法，chat.css 只调整相关注释。
5. 修改积木库管家规矩、三本手册和工具说明、动作名及返回文字，保留“出提议后本轮结束”和“提议上说明替换哪个积木块”等原有规矩。
6. 修改项目窗口的开场交代、调度手册、规则及程序提示，首次提到任务文件时写清“任务卡片（文件 需求卡.md）”，读写文件的代码和 new-card 命令保持原样。
7. 修改积木库底层报错、README 和设计规范中的相关文字，desktop/server.py 只改施工单点名的三类积木块提示及相关注释。
8. 在 chat.js 的动作摘要中把新旧动作名归入同一计数项，让一次“出卡”加一次“出提议”显示“出了 2 个提议”，失败动作同样合并且不计入成功数量。
9. 在 desk.py 的 claims_card 和 points_at_card 中加入“提议”的名词用法，继续识别全部旧说法，并排除“我提议你先装 Node”、问句、未来条件和提议内容出错等情况。
10. 把普通提醒和点名已有提议的提醒改成新叫法，保留原有提醒次数、触发范围及提议成功后的处理方式。
11. 仅在 chat.js 的兼容摘要行和 desk.py 的兼容识别词表行保留旧词并标注“旧叫法”，再按验收测试的范围搜索残留，保留文件名、能力卡片、任务卡片以及“卡住”等正常用词。
12. 运行 test_command 中的相关测试，并单独执行 node tests/naming_check.js 和 node tests/butler_page_check.js，确认新旧摘要、识别规则和原有行为全部通过。
13. 交付前先用 pgrep -fl unittest 确认没有其他测试在跑，再执行 python3 -m unittest discover -s tests，任何失败都查清原因后再交付。
14. 用临时资料和假模型走查积木库详情、提议摘要及项目窗口确认提示，并请独立复查员逐条检查漏改、误改、越界改动、兼容行为和测试结果，按施工单规矩最多返工三轮。
15. 在回执末尾追加本单改动、测试和复查结果及遗留问题，保留旧记录正文，并按施工单整理为标题“施工单 68b：统一叫法”的一个本地提交。

## 你会看到什么结果
积木库详情显示“接法说明全文”“接法说明有问题”，聊天摘要显示“出了几个提议”，项目窗口使用“任务卡片”；旧对话正常显示，管家说提议已弹出却没出时仍会被提醒。

## 明确不做什么
不改文件名、目录名、页面元素编号、函数变量名、工具名和 new-card 子命令；不改已有测试、历史数据、旧施工单、旧方案及旧记录正文；不动 desktop/mac/，不重装窗口，不顺手改团队配置和其他功能，不推送，不提交未命名绘图.drawio。

## 需要你确认的问题
无
