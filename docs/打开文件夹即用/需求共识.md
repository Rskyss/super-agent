# 需求共识：打开文件夹即用（协作包不再装进每个项目）

> 状态：✅ 口径已确认（2026-11-04 用户：“可以”）　方案：⏳ 待批准，见 [方案](方案.md)  
> 讨论过程：[讨论记录](../超级助手桌面版/讨论记录.md) 第 15、16 节

## 一句话

打开超级助手、选一个项目文件夹，就自动关联上：调度员先读交接再开工；协作包只在超级助手里放一份，**不再往每个项目里复制**；记录仍放在项目里，跟着项目走。

## 用户原话

1. “选择一个目录，打开那个目录，然后就会自动会有它的项目文件里面的代码和东西，然后它就进行审查，然后查看。然后在自己这里也会留一个该项目的文件记录……这样就不用每次把这个超级助手放在每个项目里面啦，单独打开它，选择到的一个文件就能自动关联起来了。”
2. “能不能够超级助手一选择那个项目的时候，也会像他们自己用 agent 一样会读取相关的台账、记录什么的。……记录放在项目里面是会好一些的。”

## 已确认的口径

| 项 | 口径 |
|---|---|
| 打开项目时“看”几档 | **每次打开**读交接（调度手册、项目说明、台账最近记录、任务板）；**第一次打开**熟悉项目、起草项目说明给用户确认；**代码体检**只在用户要求时做 |
| 记录放哪 | **结果**（台账、项目说明、做完的需求/方案/验收）放项目 `docs/`，进 git；**过程**（卡片、交接全文、实时输出、页面检查工具）放项目 `.collab/`，写进忽略清单，不进 git；**超级助手自己**只记打开过的项目、每个项目选的调度员 |
| 协作包 | 只在超级助手里放一份，不再复制进项目 |
| 调度员 | 仍由用户亲手选，每个项目分别记住 |

## 怎么算做完

1. 打开一个从没接入过的 git 项目：项目里只多出 `.collab/`（且已在忽略清单里），没有 `collab/`；调度员先读项目、起草项目说明给你确认。
2. 再次打开同一个项目：调度员先读交接，用两三句话说清项目进行到哪、有什么待办，不改任何文件。
3. 打开一个旧方式装过协作包的项目（例如视频项目）：会问你要不要删掉项目里的旧协作包；不同意就不删；协作记录一条不丢。
4. 在新方式下跑一张卡：边干边记照常，右边面板照常；台账和归档写进项目 `docs/`；交接全文和实时输出留在 `.collab/`，不进 git。
5. 不开客户端、只在终端里说“用协作包做……”也照样能用（同样不往项目里复制协作包）。
6. 原有测试全部通过。
