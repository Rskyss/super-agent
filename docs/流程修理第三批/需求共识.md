## 一、修完后你能感受到的变化

1. **返工不再绕圈**：复查退回时，写代码的只收到“要改的这几条”，交代里写明“其他已经验过，不要重新核对，改完跑一次本卡测试就交”；不再附开工时那份整卡交接资料。69 里 agy 改一句提示语花了 30 分钟，主因就是这个。
2. **改完了就往下走**：写代码的被停下（超时、没动静）时，程序先跑一次本卡测试——已经全过就直接交复查，不再派人重写。
3. **停下时判断说对**：复查标了【测试的问题】的，停下时直接说“测试本身写错了，建议让写测试的改”；退回次数用完了，测试的问题也先交写测试的改一次再停。“同一个问题反复出现”不只比措辞，还比复查员写的位置。
4. **Cursor 能把本卡测试跑全**：派活时连同测试要用到的建临时仓库一起放行（69 里它因此没跑全）。
5. **老功能被改坏能早发现**：写代码的交活、本卡测试通过后，程序再跑一遍“和这次改动有关的老测试”（按改动的文件挑），不过就当测试没过退回；不用等 Claude 最后跑全量才发现（68c 里改坏 4 处就是这么漏的）。
6. **“继续改”能顺带多给一个文件**：要改的文件不在允许范围里时，“继续改”框里可以写上要多改的文件，点了就加进范围并记一笔（68c 里只能 Claude 手动改）。
7. **行政少啰嗦**：
   - 你说“按施工单某某路径建卡”时，行政直接按路径建（调度员会去读施工单），不再说读不到、不再先读一遍文件（㉖ ㊴）。
   - 出确认框后只说“点确认就建卡，之后调度员写方案给你批”，不再多问“要不要顺手安排开工和复查”（㊵）。

## 三、拍板的题（用户 11-13 原话“按你推荐的来”：4 题都按推荐）

定下的：相关老测试按改动的文件自动挑（漏的靠 Claude 全量兜底）；“继续改”加文件写了就算点头、记进卡片；被停下但测试已过直接交复查、行政说一句；Claude 直接改、Codex 独立复查。

1. **“相关老测试”怎么挑？**
   - **推荐：按改动的文件自动挑**——哪些老测试用到了这次改的文件就跑哪些（一般几十秒到两三分钟）。挑漏了的，最后 Claude 跑全量兜底。
   - 或：每次都跑全量（约 13 分钟一次，返工几轮就多等几十分钟）。
2. **“继续改”加文件，要不要你再点一次确认？**
   - **推荐：不用**——你在框里写了就算你点头，程序记进卡片记录（谁、什么时候、加了哪个文件）。
   - 或：写完再弹一个确认框。
3. **被停下但测试已过时直接交复查——要不要先问你？**
   - **推荐：不问**，直接交复查，行政在卡片里说一句“写代码的被停下了，但本卡测试已经全过，直接交复查”。
   - 或：停下来等你点。
4. **谁施工？**
   - **推荐：和前两轮一样，Claude 直接改、Codex 独立复查**（改的还是派活程序本身）。
