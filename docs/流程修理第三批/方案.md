# 流程修理第三批：方案（待用户批准）

依据：[需求共识](需求共识.md)（用户 11-13 确认，4 题按推荐）。

## 一、你会看到的样子

| 场景 | 现在 | 改完 |
|---|---|---|
| 复查退回 1 条小问题 | 写代码的收到整卡资料加复查全文，先把整张卡再核一遍（69 里 30 分钟改不完一句提示） | 只收到“要改的这 N 条 + 不要重新核对 + 改完跑一次本卡测试就交”，不附整卡交接资料 |
| 写代码的被停下（超时、没动静） | 直接卡住，你只能“接着跑”再派一次 | 程序先跑本卡测试：全过 → 行政说“写代码的被停下了，但本卡测试已经全过，直接交复查”，交复查；没过 → 照旧卡住 |
| 复查标了【测试的问题】又停下 | 判断说“施工单没写准” | 判断说“测试本身写错了”；退回次数用完时，测试的问题先交写测试的改一次、写代码的再改一次，还不过才停 |
| 同一问题反复出现 | 只比措辞，换个说法就认不出 | 措辞像或者复查写的位置（文件和行）一样，都算同一问题 |
| Cursor 跑本卡测试 | 沙箱不让建临时仓库，跑不全 | 派活时放行本卡测试要用的建临时仓库（施工时实测 Cursor 沙箱到底卡在哪） |
| 改坏老功能 | 只有 Claude 最后跑全量才发现 | 本卡测试过了，程序再跑“用到这次改动文件的老测试”，不过就当测试没过退回写代码的（说明是哪项老测试） |
| “继续改”要多改一个文件 | Claude 手动改卡片 | “继续改”框下面多一栏“还要改这些文件（可不填）”，写了就加进允许范围，卡片记录里记一笔 |
| 让行政按路径建卡 | 先说读不到、或先读一遍文件，出框后还问“要不要安排开工复查” | 直接按路径建卡（路径原样写进卡片，调度员会读）；出框后只说“点确认就建卡，之后调度员写方案给你批” |

## 二、泼冷水

- **“相关老测试”只认 Python 项目的写法**（看老测试里有没有用到改动的文件）。别的语言的项目这一步先跳过，靠最后全量兜底。挑漏的情况会有，比如老测试间接用到改动的文件。
- **跑相关老测试多花时间**：一般几十秒到两三分钟，返工几轮就多几次。
- **Cursor 跑不全测试的原因还没查实**：69 里它说“沙箱禁 git init”，施工时先实测；如果是沙箱写不了你主目录里的 git 设置，放行可能要换办法，做不到就记已知取舍，交代里写“建仓库的测试跑不了就说明，程序会跑”。
- **行政规矩靠话术**：“不读文件”“不多问”写进行政的规矩，模型偶尔仍可能不照办；69b 建卡时看效果。
- **被停下直接交复查**：如果写代码的被停时改了一半、测试恰好过了，复查会兜住；但多了一次“没人确认就往下走”，你说过不用问。

## 三、技术设计（给下一个会话的 AI 看）

| 改动 | 落在哪 | 要点 |
|---|---|---|
| 返工交代收窄 | `collab/dispatch.py::_review_return_prompt`、`_plan_hint` | 退回时交代 = 规则 + 复查结论里的编号条目（全文）+ “其他已验过，不要重新核对；改完跑一次本卡测试就交”；退回轮不带交接资料那句（`_plan_hint(cdir, with_notes=False)`） |
| 被停下直接交复查 | `collab/dispatch.py` 开发员 `not dev.ok` 分支 | 先 `judge_fn(test_command)`：PASS → 记“范围”“判定”，接着照常范围核对、复查；FAIL → 照旧 `_worker_failed` |
| 停下判断 | `_stop_reason` | 先看最后一轮有没有 TEST_PROBLEM；同一问题 = 措辞相似或位置（`文件:行`）相同 |
| 退回用完时测试的问题 | 复查 reject 分支 | `rejects > MAX` 且有 TEST_PROBLEM 条目、本次开工还没为它改过测试 → `_tester_fix` + 再派一次写代码，再复查；仍不过才转人工 |
| Cursor 放行 | `_write_cursor_permissions` / `cursor_command` | 先实测，再定放行 `Shell(git)` 还是别的 |
| 相关老测试 | `collab/dispatch.py` 判定 PASS 之后、复查之前 | 改动的 .py 文件 → 模块名；在 `tests/` 里找引用了它、又不是本卡测试文件的 `test_*.py`，`python3 -m unittest` 跑这些；不过 → 记“判定”FAIL（说明是老测试），走测试没过的返工 |
| 继续改加文件 | `desktop/static/panel.js` 继续改框、`desktop/server.py` revise、`desktop/clerk/tasks.py::apply_revise`、`collab/tasks.py::revise_card` | 多一个 files 字段；校验是项目里的相对路径；追加进需求卡“允许改动的范围”，流转记“追加范围” |
| 行政 | `desktop/clerk/desk.py` 项目窗口行政的规矩、出卡回话 | 规矩加两条；出框后回给模型的话里写明“不要再问开工、复查” |
