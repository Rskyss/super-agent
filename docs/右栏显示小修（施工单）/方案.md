# 拆解方案

## 要做什么（一句话）
调整右栏用量、卡住原因和 Claude 接手后的显示，并新增记录接手情况的命令。

## 拆成几步，每步做什么、产出什么
1. 用户批准方案后开工，先核对现有方案、台账和相关代码的使用位置，明确问题落在页面显示与接手记录上，本卡要求必须改，其他问题暂不处理，并沿用现有流转记录和页面刷新方式。
2. 测试员只在允许的新测试文件中补充用例，覆盖用量换行、原因展开收起、刷新与切卡、接手记录及完成时间，并让 Python 测试调用新增的 JS 检查，先运行本卡测试留下未修复时失败的结果。
3. 在 collab/cli.py 新增 takeover 命令，接收项目、卡号及 --changed、--reviews、--later、--note 参数，沿用现有方式追加来源为 Claude 的“接手”记录，拒绝不存在的卡，并验证记录内容。
4. 在 desktop/view.py 按最新接手记录生成“Claude 接手”格，放在复查与确认之间，写明改动数、Codex 复查轮数和以后再修条数，无接手记录的卡保持原有七格。
5. 按事件先后更新复查结果，接手修好后显示绿勾并保留原退回说明、追加“已由 Claude 接手修好”，接手后再次退回则恢复红叉，并从已放进项目的记录读取完成时间。
6. 调整 panel.js 和 panel.css，让正在干活及已干完步骤的 token 用量独占一行，首次显示、数据刷新和计时刷新保持一致，卡住时顶部只留“卡住了”和原有按钮。
7. 调整 chat.js 和 chat.css，让中间卡片标题下完整保留卡住原因、默认收起一行，文字放不下才显示展开按钮，刷新保留展开状态，换卡恢复收起，文字变短后隐藏按钮。
8. 在 panel.html 只新增一行完成时间容器，由 panel.js 在本卡合计下面显示本机时间格式的“完成于 月-日 时:分”，没有 token 合计也能显示，未完成或切换到未完成卡时清除。
9. 一次完成并验证一个改动，最后运行 test_command 中的本卡验收命令，保留每轮结果，有检查跳过或报错就如实说明，不安排施工方运行全部测试。
10. 交付时说明改了什么、未验证什么和遗留问题，由程序追加台账及卡片归档记录，汇报写清时间、耗时、最慢步骤和报错情况，再交最终验收人员做真实窗口走查。

## 你会看到什么结果
每步 token 用量单独一行；卡住时右栏顶部只显示“卡住了”和按钮，中间标题下可展开完整原因；有接手记录的卡显示“Claude 接手”格，修好后的复查格显示绿勾和说明，已完成的卡显示完成时间。

## 明确不做什么
不改跑卡流程、停下原因的判断规则、窗口外壳、agents 文件夹、卡片列表和合计 token 算法；不改两个验收文件及其他老测试；不猜测或批量补写老卡接手记录；不提交、不合并、不推送、不发版。

## 需要你确认的问题
无

## 做完后怎么看结果
这是桌面应用，打开改好后的“超级助手”，选择本项目和一张卡，查看右栏用量、顶部按钮和中间标题下的原因；点“展开”“收起”，切换卡片检查显示是否残留，再查看有接手记录的已完成卡，核对复查绿勾、接手格和完成时间；真实窗口走查由最终验收的人完成。
