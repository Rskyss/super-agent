# 拆解方案

## 要做什么（一句话）
按已有施工单，把左下角项目名做成切换按钮，并让每个项目记住上次打开的对话、卡片和没发的字。

## 拆成几步，每步做什么、产出什么
1. 先按 docs/切换项目/施工单-切换项目.md 和两个已有验收测试核对要求，只在允许的新测试文件里补充缺失场景并确认功能实现前测试不过，新增 JavaScript 检查由新增 Python 测试调用，保证验收命令能执行到。
2. 在 NavCore 增加 projectName 和 projectItems，处理末尾斜杠、路径去重、当前项目补到顶部、按项目名忽略大小写搜索和空列表，在 ChatCore 增加并导出 restorePlace，按施工单处理正常恢复、对话已删除、新对话草稿和无记录的情况。
3. 保留项目名的 proj 标识和团队按钮，把项目名包进 projBtn 按钮，增加默认隐藏的向上浮层、搜索框、最近项目列表和底部“添加项目”，沿用主题颜色并让列表超过约七行时滚动。
4. 让浮层从地址参数读取项目列表并容忍解析失败，打开时清空搜索并聚焦，使用 textContent 显示项目名，支持搜索、当前项目勾选、点击当前项目只关闭，以及按 Escape 或点击外部关闭。
5. 在 Swift 外壳里把最近项目上限设为二十个，让顶部菜单和浮层共用过滤掉失效文件夹的列表，通过现有页面地址传给左栏，并接上项目切换和添加项目消息，前者只接受最近列表中仍存在的文件夹，后者复用现有文件夹选择器。
6. 按项目完整路径把对话编号、卡片编号和最多两千字草稿存入 UserDefaults，选择卡片时只更新卡片字段，行政对话输入停下八百毫秒或切换对话后上报位置，看卡片时不保存卡片输入框里的字。
7. 切项目时先向旧聊天页读取当前位置并保存到旧项目，再走原有切换流程，读取最多等一秒且后续动作只执行一次，保留原有预览清理和行政配置顺序，拆出的切换函数放在 switchTo 与 remember 之间。
8. 加载聊天页时传入已保存的对话和草稿并通过 restorePlace 恢复，卡片等聊天页加载完成后再打开，启动时没有指定 --card 才恢复旧卡片，保留 --project 和 --card 自测参数以及右栏地址原有的 token。
9. 运行本卡 test_command 中的验收检查和 Swift 编译，交给最终验收方在更新后的真实窗口检查浮层操作、添加项目、跨项目恢复和已删除对话的回退结果，并如实说明未完成的检查和报错。

## 你会看到什么结果
点击左下角项目名，会向上弹出带搜索框、最近项目列表和“添加项目”的浮层；切到其他项目再回来，会恢复原来的对话、卡片和行政对话草稿。

## 明确不做什么
不做项目常驻内存，不做列表移除、改名或手动排序，不改顶部菜单样式、后台 Python 和跑卡流程，不改两个已有验收测试，不给积木库管家和旧调度员聊天增加恢复功能，不安装、提交、合并或推送。

## 需要你确认的问题
无

## 做完后怎么看结果
这是 Mac 桌面应用，验收方准备好更新后的应用后，点按钮打开，查看左下角项目名上方的浮层，检查搜索、当前项目勾选和添加项目，再在两个项目之间来回切换，确认对话、卡片和没发的字各自恢复；已安装应用使用打包时的代码，不能拿旧版本窗口验收。
