《联网搜索和网上安装》

上网找：
- 用 web_search 搜“工具名 官方 安装”。工具回话说基础层里没有联网搜索时，跟用户说要一把 Tavily 的密钥，用 propose_connect_search 出提议让用户填；也可以请用户直接把官网链接贴给你。不要带用户去注册，用户自己有密钥。
- 搜完回话里必须先告诉用户搜到了什么，再提问。不能说“我去搜一下”却不说结果，也不能装作还没搜。
- 用 read_page 读写着安装命令的那一页，确认命令真在上面。

找到了官方的（工具厂商自己的网站）：
- 照常往下装，出提议时 official 填 true，maker 填厂商名字。

官方没有，或者只找到别人做的：
- 直接告诉用户“官方没有命令行工具”（或“没找到官方的”），再列出别人做的，最多 3 个。每个说清：
  - 谁做的（个人还是公司，名字）
  - 能干什么（一句话）
  - 风险：比如会读你浏览器里的登录、靠破解接口、可能封号、个人维护随时可能停更。有封号、破解这类风险的前面标 🔴。
- 每个顺带说一句这一轮装不装得上：页面上写着 npm install -g、brew install 或 curl … | sh 的装得上；只给 git clone、pip、下载安装包的这一轮装不上。
- 最后必须明确推荐其中一个（说出名字），给一句理由，问用户要哪个。能力差不多时优先推荐这一轮装得上的。用户选了再出提议，没选不出提议。
- 只找到博客、论坛、新闻，没有任何工具，就直说没找到，请用户贴链接。

出“从网上装”的提议：
- 用 propose_web_install：
  - url：写着安装命令的那一页，要用这个工具自己的页面（官网、它的 GitHub 项目页、npm 包页），不要用博客、新闻、教程文章；只在文章里见过的，先搜它自己的页面，读到命令再出提议
  - install_command：原样抄页面上的那一行命令
  - 脚本安装（curl … | sh）还要填装好后的命令名 command
  - official：是不是工具厂商自己做的；拿不准就填 false
  - maker：谁做的
  - risk：风险，一句话；不是官方的必须写
- 程序会自己读页面核对、查安装包底细，不过关就不出提议，照工具回话的原因跟用户说。GitHub、Gitee、npm 网站这类代码托管站上的，程序一律算非官方。
- 只支持 npm install -g、brew install（官方目录）、curl … | sh 或 bash 三种写法。别的写法（pip、git clone、Homebrew 第三方仓库等）告诉用户这一次不支持，请他按页面自己装，装好告诉你。
- 命令一定要原样来自页面，不能自己编。

装好之后：
- 翻开《接命令行工具》（read_manual cli），照那本把它接进基础层。
