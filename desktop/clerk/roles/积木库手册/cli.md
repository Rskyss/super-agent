《接命令行工具》

装工具：
- 先 check_installed 查装没装。
  - 已经装了：说出版本，问要不要接进基础层。
  - 没装：调用 install_options 看核实名单里有没有它的安装方式。有，就用 propose_install 提议，只能填名单里的编号。
  - 名单里没有：翻开《联网搜索和网上安装》（read_manual web），照那本上网找。
- 不能自己编安装命令；也不要在聊天里给命令让用户自己运行，一律用 propose_ 工具出提议。

登录：
- 体检里显示“没登录”的工具才要登录：告诉用户在终端里输入哪个命令、浏览器里会弹出什么，登录由用户亲手完成。
- 体检显示已经登录的，接进基础层时不用再登录，不要提登录。
- 显示“查不了”“查不出”的（比如 agy 没有查登录的办法），先接；检测没通过、原因像没登录时再教登录。

接进基础层：
- Codex、Cursor、agy 有现成的接法，用 propose_connect_cli 并填 template（codex、cursor 或 agy），不要自己改。
- 别的工具：先用 read_help 读它自带的帮助说明，判断它是哪一类，照着起草一张接法说明，再用 propose_connect_cli 提议。这种提议没核实过，用户会先看到要运行的完整命令，确认了才检测。
  - 普通工具的接法说明长这样（card 只能有这些项，不要加 type 之类别的项）：
    {"id": "amap-gui", "kind": "cli", "name": "高德地图", "command": "amap-gui", "role": "tool", "probe": ["status"], "ok_words": ["running"], "version_args": [], "secrets": [{"env": "AMAP_KEY", "label": "高德 Key"}]}
  - AI 助手的接法说明长这样：{"id": "my-ai", "kind": "cli", "name": "我的 AI", "command": "my-ai", "run": ["-p", "{prompt}"]}
  - id 是这个积木块在基础层里的编号：小写字母、数字、横线；kind 一律写 cli。
  - AI 助手（交代一句话它自己干活，比如能写代码、能回答问题的）：card 写 run，其中一处是 {prompt}。
  - 普通工具（给它一条具体命令、它返回结果，比如地图、格式转换、查小红书数据）：card 写 "role": "tool" 和 probe（一条只查不改的命令，比如查状态、查一个词；不能删改文件、不能发帖、不能花钱下单），可以写 ok_words（成功时输出里一定会出现的字样）。没有 --version 的工具写 "version_args": []。
  - 要密钥的（官网说要设置某个环境变量，比如 XXX_KEY）：card 写 secrets：[{"env": "环境变量名", "label": "给用户看的名字"}]。只写名字，密钥由用户填在提议的密钥框里，告诉用户去哪申请。要浏览器登录的照旧在终端里登录，不写 secrets。
- 检测没通过：按失败原因改接法说明再提议。连续 3 次不通过就停下，告诉用户卡在哪。
- 检测结果是“额度不足”：工具能连上，只是所选模型没额度，用户可以直接放进基础层（标黄“额度不足”），不用改接法说明；用哪个模型、额度怎么换以后再说。
- 编号相同才会替换基础层里旧的那个积木块，编号不同就是新加一个积木块。会替换哪个积木块提议上会写，不用你说，也不要自己猜。
