# 规则包（agents/）：开发助手里所有大模型要守的规则

- **改规则只改这里，不改代码。** 开发时改完下一次派活就生效；装好的应用里带的是生成时的那份，改完要重新生成应用。
- **程序派活时**，按下表把这个角色要读的文件原样放在派活的话最前面，干活的模型不用自己翻。
- **产品经理、架构师**（不管哪个模型来当）开工前按下表自己读；交接靠这个包和项目文档，不靠哪个模型的记忆。
- 来历：2026-11-20 用户定（CARD-019 复盘后）。原来规则散在 `collab/规则.md` 和跑卡代码里。

## 交代

程序派活时，规则（上表）放最前面，后面跟这里的“交代”：每次不同的部分写成 `{空位}`，程序填。
交代文件的写法：`---` 以上是给人看的说明；以下是发给模型的话——连着的几行直接接起来（中文不用空格），一个空行＝换一行（文件末尾的空行也算）。
空位一个不能删、也不能自己加：程序只填下表登记的空位。改完跑规则包体检，再跑 `python3 tests/prompt_cases.py <角色>` 更新快照（快照防的是搬家时手滑改字，有意改说法时连快照一起更新）。

## 改规则的规矩

1. 同一件事只写一处；别的文件要提到，写“见《某某》”。
2. 每条规则尽量写来历（哪张卡、哪次教训）。不知道一条规则为什么在，就会被后来的人当累赘删掉。
3. 删改之前先看下面“不能删的要点”。要换说法，连清单一起改；要删一条，先想清楚它防的是什么。
4. 改完跑一下规则包体检：`python3 -m unittest discover -s tests -p "test_rulebook_health.py"`（跑全部测试时也会跑）。

## 还在代码里、没搬进来的（第③步搬）

- 行政告诉用户“下一步该点什么”的那几句：它们也显示给用户看，是界面文字，留在程序里。
- 全部测试里老测试被改坏时，交给写代码的那段测试结果说明（它是测试结果的一部分，留在程序里）。
