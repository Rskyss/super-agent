# 测试怎么写（写测试的读；写施工单的人自己先写验收测试时也照这份）

## 页面上的行为，用实跑页面的检查

- 点按钮、切换、记住状态、加载先后这类页面行为，把页面脚本真的跑起来检查：模拟点击、等页面动完、看页面上的结果。
- 不要只查“代码里必须出现某某写法”。这种检查挡不住真错，还会把错误做法钉死。
- 逐字比对代码只用在实在跑不起来的地方（比如 Mac 窗口外壳），并在测试里写一句为什么只能逐字比对。
- 开发助手项目里现成的工具：`tests/ability_69b_dom.js`（提供 page、settle，能在命令行里把页面脚本跑起来）；例子见 `tests/projswitch_extra_claude_dom.js` 和调用它的 `tests/test_projswitch_extra_claude.py`。别的项目先找项目里有没有类似工具，有就用现成的。

来历：CARD-019（切换项目）很多检查是“代码里必须出现某某写法”，Codex 两次证明代码写坏了检查照样过；“停用行政恢复卡”的三条检查还逼着写代码的往错的方向改。改用实跑页面的 8 段检查后，逐处去掉修复都能抓到。

## 假数据要和真的后台一样

- 页面检查里假装后台回的数据，要照真的后台会给什么写：先看后台代码（或用真数据跑一次）再写假数据。
- 假数据给少了（比如真后台给全文，假的只给半句），写代码的就会为了让检查通过，在页面里另想办法“补全”，产品被测试带歪。
- 有数据库的项目：假数据的表和字段照数据库结构定义（迁移文件）写，不许凭想象加字段；查不存在的字段时，假后台要像真库一样报错，不能悄悄放过。来历：外部项目试跑 ⑰，train CARD-001 的假后台虚构了锁定表的 id 字段，109 条测试全过，真课堂里每次保存都失败，复查员对照迁移文件才查出。
- 来历：CARD-020 的补充测试假装后台只给截短的原因，要求页面拿打开卡片时的旧说明补全，结果中间那行同时显示“正在起草”和“已起草好”，复查退回两轮，最后 Claude 接手改假数据才解决。

## 交之前验一下检查真能抓到错

- 想一想：把要求的功能删掉一处，这条检查会不会变红？不会，就是没测到。
- 能做到的话，真的临时删一处跑一下，看它变红，再恢复。
