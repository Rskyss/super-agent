# 真实窗口走查（架构师读）

## 让改动生效

- 开发助手是冻结的：应用里装的是一份固定的代码（外壳、网页、后台、规则包全在里面），改了任何一样都要重新生成应用才生效：`bash desktop/mac/build.sh --install`。
- 生成前确认应用没在运行、后台没有卡在跑（应用开着时不能替换），要用户先退出；用户另有授权时才自己退出再打开。
- 交给用户看真实窗口前，先核对已装的版本包含本次修改（逐个比对关键文件）。

## 怎么走查

- 用干净环境打开新窗口：`env -i HOME="$HOME" PATH=/usr/bin:/bin open -n "$HOME/Applications/开发助手.app"`。从终端直接开会带着终端的设置，掩盖“找不到命令”。
- 能用自测开关就用（不碰真实钥匙串、不发话、不花额度）：自测开关自动用一份单独的测试设置，**不改用户保存的任何设置**（团队、模型、密钥都不动）；要切换工具或配置时，在测试设置里切，不在用户的设置里切。发布前至少用不带自测开关的方式打开一次安装版。
- 截图只截应用自己的窗口（`screencapture -o -l 窗口号`），不截全屏。
- **不发真实鼠标点击**：屏幕坐标会变，用户可能正在用电脑。要点击就请用户点一次；一旦发现窗口不在预期位置，立刻停手并如实说“可能点到了别处”。（来历：11-17 模拟点击时窗口已被移到另一块屏幕）
- 发按键（比如退出）前，在同一条命令里先把应用设为最前；能用菜单项就不用按键。退出用 `osascript -e 'tell application id "local.superagent.desktop" to quit'`。
- 测试和走查不启动用户的 Claude、不登录；要验证相关功能只用假程序，真实验证留给用户并写“未实测”。

## 界面类验收

以设计图为准，拿真实窗口截图和设计图并排逐页对照，差一处记一处；图上没有的东西露出来也算不通过。对照结构、内容、文字、按钮、状态、流程，不抠像素。写界面施工单时把设计图列为验收标准，并写走查命令和走查步骤（《施工单怎么写》五之二）；卡上的自动走查截图是后台浏览器分栏截的，只当辅助，不代替这里的真实窗口对照；独立复查和最终验收各自留下“现在 vs 图”的逐页对照结果，没对照的页面不得写“已验”。（来历：11-16 界面和图不搭被用户退回）
