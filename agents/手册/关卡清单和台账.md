# 关卡清单、台账、汇报（产品经理、架构师读）

## 说“做完了”之前列关卡清单

逐项写“已做”或“未做”：**测试、真实环境走查、独立复查、台账、文档同步**。有未做项不许说“做完了”。不适用的写“不适用 + 理由”（比如纯文档任务没有测试），不能硬写“已做”。

## 台账

- 每个仓库一份：开发助手的事记在 `docs/开发进度跟踪.md`（11-19 用户定：开发助手只记自己仓库，超级玩家另记）。
- 开工前读；设计一经批准立刻建 `docs/任务名/` 并登记 🔄 进行中，不等做完；做一个更新一个；状态用 🔄 进行中 / ⏳ 待验收 / ✅ 已完成。
- 只追加不删除历史；记错了追加一条更正。
- 用产品语言写：“用户点导出会下载 Excel”，不写“新增了 exportExcel 接口”。
- 更新台账是“完成”的硬关卡；别的流程工具自带的文档只是过程记录，不能替代台账。
- 大任务另写验收记录（`docs/任务名/验收记录.md`）。
- 每张卡放进项目后跑 `python3 docs/流程数据/生成表格.py`，记下每步哪个模型用了多久，和卡片记录一起提交；写测试、写代码交活后的点评写进 `docs/流程数据/点评记录.md`；攒几张卡在 `docs/流程数据/README.md` 追加一段观察（哪步最慢、哪个模型交成率低、退回代价）。接手修卡的时间不在自动表里，要在台账里写清用了多久。（来历：11-19 用户“打造一支牛逼的开发工程团队”）

## 给用户的汇报写法

《说话口径》里“每条记录写清时间、耗时……”那条，是干活的模型交活汇报和执行效率汇报用的格式；给用户的日常汇报照这里：
- 产品语言：讲流程怎么走、用户会看到什么、哪里要他拍板；不展示代码和命令。只给用户要打开的文档的位置，不给代码路径和命令。
- 一小段一件事，最后一句结论；事实和推测分开标，不确定就说不确定。
- 涉及执行效率和耗时的汇报，才写时间范围、总耗时、各环节耗时、最慢一步、有没有报错重试，数字说明是否核对过；普通进度消息不必强塞数字。
- 不奉承，对就是对、错就是错。
- 中途发现新问题，先停下说，不自己改方案接着做。
（来历：用户的全局规则、11-04 用户认可的汇报格式）
