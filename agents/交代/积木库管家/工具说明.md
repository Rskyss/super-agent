# 工具说明

积木库管家能用的每个工具、每个参数的说明。参数一栏写“—”的是工具本身的说明。说明里要写竖线时写成 \|。
工具名、参数名程序要认，别改；只改“说明”一栏。改完要重启应用才生效。

---
| 工具 | 参数 | 说明 |
|---|---|---|
| scan_environment | — | 对电脑环境做一次体检：查 Node、npm、Homebrew、git 和各 CLI 装没装、什么版本、登没登录 |
| check_installed | — | 查某个命令装没装、什么版本 |
| check_installed | command | 可执行文件名，例如 codex |
| read_help | — | 只运行 <命令> --help 读这个工具自带的帮助说明，限时 10 秒 |
| read_help | command | 可执行文件名 |
| list_blocks | — | 列出基础层里已经接进来的每个积木块：名字、类型、上次检测结果 |
| install_options | — | 查某个工具在核实名单里的官方安装方式 |
| install_options | tool | 工具名，例如 codex、node |
| propose_install | — | 向用户出示安装提议，用户点确认后才执行安装 |
| propose_install | install_id | 核实名单里的安装编号，例如 codex-npm |
| propose_connect_cli | — | 向用户出示接入 CLI 的提议。codex/cursor/agy 优先传 template；别的工具传起草的 card。AI 助手（交代一句话它自己干活）的 card 写 run（含 {prompt}）；普通工具（给命令返回结果）写 role=tool 和 probe（一条只查不改的检测命令的参数列表），可选 ok_words；要密钥的写 secrets：[{env: 交给工具时的环境变量名, label: 显示名}]，只写名字，密钥由用户在提议上填 |
| propose_connect_cli | template | 预置模板名：codex / cursor / agy |
| propose_connect_cli | card | 自定义的 CLI 接法说明 |
| propose_connect_api | — | 向用户出示接入大模型 API 的提议（含密钥框，密钥由用户在框里填）。按整家接：一家平台一个积木块，不选模型，提议上没有模型一栏，检测时程序自己拿这家的模型名单并试通。腾讯云、阿里百炼都只要一把 API 密钥，提议上只有一个密钥框；不是云账号的 SecretId、SecretKey 那一对。没调用这个工具，用户屏幕上就没有提议 |
| propose_connect_api | provider | tencent / bailian / other |
| propose_connect_api | name | other 时填这家平台的名字（如 DeepSeek）；腾讯云、阿里百炼不用填 |
| propose_connect_api | base_url | other 时必填，https:// 开头 |
| propose_connect_api | model | 一般不填。只有检测结果说“问不到这家的模型名单”时，填用户说的一个模型名，只用来试通 |
| web_search | — | 用基础层里的联网搜索查资料（例如某个工具的官网和安装说明），最多 5 条结果 |
| web_search | query | 搜索词 |
| read_page | — | 由程序打开一个 https 网页，把正文交给你看（只读，最多 8000 字） |
| read_page | url | 完整的 https:// 网址 |
| propose_web_install | — | 核实名单里没有的工具：把官网上那一页的网址和页面上原样的安装命令交给程序，程序自己读页面核对、查安装包底细，都过了才向用户出示安装提议。只支持 npm install -g、brew install、curl … \| sh/bash 三种写法 |
| propose_web_install | url | 写着安装命令的官网页面网址 |
| propose_web_install | install_command | 页面上原样的那一行安装命令 |
| propose_web_install | command | 装好后的命令名（脚本安装必填，例如 agent） |
| propose_web_install | official | 是不是工具厂商自己做的；拿不准填 false |
| propose_web_install | maker | 谁做的（公司或个人的名字） |
| propose_web_install | risk | 风险，一句大白话；不是官方的必须写，例如“读你浏览器里的登录，可能封号” |
| list_models | — | 问这家大模型平台它真有哪些模型（用已经存好的密钥，只读、不花额度）。用户问起这家有哪些模型时用；接入不需要先查，出提议不用选模型 |
| list_models | provider | tencent / bailian（只能查这两家） |
| list_models | keyword | 只看名字里带这几个字母的，例如 hy、qwen、deepseek；不填看全部 |
| read_block | — | 查看基础层里的某个积木块：类别、模型名单、能不能用，以及能力层里有哪些卡片用了它 |
| read_block | block | 积木块编号 |
| read_block | keyword | 可选，只看名字里带这几个字母的模型 |
| list_abilities | — | 列出能力层里已有的所有能力卡片 |
| propose_ability | — | 出示能力卡片（草稿）。card 照《做能力》手册的格式写；程序先查格式，不合格不出草稿、把原因还给你。没调用这个工具，用户屏幕上就没有草稿。 |
| propose_ability | card | 能力卡片 JSON |
| read_manual | — | 翻开一本手册，照着办这一类事：cli 接命令行工具；api 接大模型 API；web 联网搜索和网上安装；ability 从积木块提取能力卡片 |
| read_manual | name | 手册名 |
| propose_connect_search | — | 基础层里还没有联网搜索时，向用户出示接入联网搜索（Tavily）的提议，用户在提议上填 Tavily 密钥 |
