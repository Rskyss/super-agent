# 工具说明

行政能用的每个工具、每个参数的说明，模型靠这些话决定什么时候用哪个工具。参数一栏写“—”的是工具本身的说明。
工具名、参数名程序要认，别改；只改“说明”一栏。新加工具要改程序（工具本身是程序），说明写这里。改完要重启应用才生效。

---
| 工具 | 参数 | 说明 |
|---|---|---|
| read_project_profile | — | 读项目说明 |
| read_project_docs | — | 读项目自带的 README、CLAUDE.md、AGENTS.md、package.json 说明和顶层文件名。不读代码和密钥。 |
| read_ledger | — | 读开发进度台账的最后几行 |
| read_ledger | lines | 读最后几行，默认 40，最多 80 |
| list_cards | — | 列出所有任务卡片 |
| read_card | — | 读一张卡片的详情 |
| read_card | card_id | 卡片编号，例如 CARD-001 |
| read_team | — | 读团队配置 |
| list_installed_tools | — | 查看本机 PATH 里是否装了 codex、agent、agy（只检查，不运行） |
| propose_team_change | — | 向用户出示“改团队设置？”确认框。用户点确认后才写入配置。 |
| propose_team_change | role | tester / developer / reviewer |
| propose_team_change | tool | codex / cursor / agy；复查可选 none |
| propose_profile | — | 向用户出示“保存项目说明？”确认框。用户点确认才写入文件。 |
| propose_profile | profile | 完整的项目说明，含做什么、怎么启动、怎么测试、禁区、技术栈五项 |
| propose_task | — | 向用户出示“变成任务？”确认框。用户点确认才建卡。 |
| propose_task | title | 任务标题 |
| propose_task | do | 要做什么 |
| propose_task | not_do | 不做什么 |
| propose_task | done_when | 怎么算做完 |
| propose_revise | — | 向用户出示“继续改？”确认框。用户点确认后才把新要求交给施工。 |
| propose_revise | text | 要改什么 |
